## 1. 项目是什么

**Palink-AI**：自部署的角色扮演 AI 平台——后端 FastAPI + PostgreSQL，前端 React/Vite，容器化部署（docker compose，5 个容器），深度兼容 SillyTavern（下称 ST）生态（角色卡/插件/正则/世界书），并自研 palink-native 提示词装配管线。

**一句话定位**：让角色扮演 AI 满足「ST 的生态兼容 × Palink 的原生装配能力」，当前主攻 **palink-native** 模式。

### 五种部署模式的状态（关键！AGENTS.md 首要声明）
| 模式 | 含义 | 状态 |
|------|------|------|
| `palink-native` | Palink 原生提示词装配（`build_character_chat_messages`） | **主攻、唯一维护、唯一可达** |
| `st-compat` | 服务端 ST 对齐装配（`build_st_compat_messages`） | **运行时强制封存（MODE-SEALED），代码待删除，勿优化** |
| `st-native` | iframe 嵌入完整 ST | **运行时强制封存（MODE-SEALED），代码待删除，勿优化** |
| `st-vec` 记忆 | ST vectors 插件的向量记忆 | 记忆库前缀 `st-vec::`，常态未启用 |
| 普通聊天 | `build_chat_messages` | 独立于角色扮演的普通对话 |

**封存硬规则**：模块必须封存 = 从各处 `SEALED_ST_MODES`（`roleplay_prompt_assembly.py`、`users.py`、`silly_tavern.py`）移除对应值才能解封。`st-native` iframe 仅在 `getContext.ts` 等前端守卫处隔离。**不要删除封存代码，除非用户明确拍板**（用户计划隐患排除后统一清理）。

### 认证与安全体系（N8 架构，已全部落地）
- **登录双 Cookie**：`palink_session`（HttpOnly、SameSite=Lax、12h）+ `palink_csrf`（非 HttpOnly、随机，双提交用）。响应体不再被前端信任。
- **鉴权双轨**：Bearer 头优先 → `palink_session` Cookie 兜底。显式无效 Bearer 不回退 Cookie。
- **CSRF 双提交**：mutating 请求需 `X-CSRF-Token` == `palink_csrf` cookie；静态值 `palink-csrf` 保留给 ST iframe/bridge 兼容流量（csrf_guard.py 双分支）。带 `Authorization` 头豁免。
- **手动通道**（beforeSend 类 XHR/fetch）：如 CharacterView 导入、tts、usePushToTalk、getContext 同步 XHR + merge-attributes、插件 guardedFetch——都必须自行带 `X-CSRF-Token`（**N8-c 后 Bearer 已退役，不带就 401**）。
- **st_router 认证**：`_token_from_request` 已加 `palink_session` Cookie 兜底（本次 2026-08-28 修复）。
- OAuth 登录回调已补双 Set-Cookie。
- login/jti 黑名单：登出清两枚 Cookie + jti 拉黑。

## 5. 部署与运维（每次改完必做）

### 前端（bind mount 部署，重要！）
- **frontend 容器是 `./frontend/dist:/usr/share/nginx/html:ro` bind mount——重建镜像不更新前端！**
- 唯一正确方式：`cd frontend && npm run build`（卷直挂即时生效）→ `docker compose restart frontend`
- 改完前端必须对比 `formatting.ts` 等源码与 dist bundle 的 LastWriteTime，防止旧产物上线。

### 后端
- `docker compose up -d --build backend` → 等待 `healthy`（healthcheck 有 `start_period: 180s`，别急着判定失败）
- 改后端后必须镜像内核实（`docker exec <container> grep ...` 确认代码在位）。

### 其他
- **改完必须重建/重启使生效**（用户硬性要求）。用户要求自动生效 → 后端重建 or 前端 build+restart。
- 大版本更新前自动备份到 `backup/`（如 `backup/2026-08-26_n8c-frontend/` 带 MANIFEST sha256）。
- 端口统一（2026-08-31）：dev/部署共用 3000（http://localhost:3000），已从 13000 改回；历史 WinNAT 保留段问题见 TODOS.md「环境注意」。

## 6. 向量记忆体系（红线 + 关键机制）

**硬约束**：
- 记忆 = 消息当前内容的镜像。所有内容变化（生成/续写/swipe/重试）统一按 `message_id` upsert。
- 入库前**必须清洗**：剥离 `<UpdateVariable>` 块与 ` thinking` 思维链块（`clean_memory_content`）。
- 注入前按句安全截断，防切在 XML 标签中间，记忆块加边界标记（防模型把记忆当指令）。
- **红线：不改 `turn_hash` 算法、不动 `get_context` 检索逻辑、不碰 st-compat 链路、不做存量 NULL message_id 回填。**

**能力**：编辑消息→删旧重嵌；继续生成→合并全文；swipe 重 roll→跟随；删除消息/角色/会话/分支→级联清理（无孤儿）。

**遗留**：swipe 切换走 `PATCH /messages/{mid}/swipe` 的记忆同步钩子留二期。
