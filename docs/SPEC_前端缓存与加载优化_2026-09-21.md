# SPEC — 前端缓存与加载优化（ST 兼容性安全版）

> 版本：v1　日期：2026-09-21
> 前置报告：`docs/ANALYSIS_前端性能与缓存优化_2026-09-21.md`
> 　　　　　`docs/ANALYSIS_ST兼容性约束下的前端优化_2026-09-21.md`
> 硬约束：**不得影响 ST 兼容性，尤其插件兼容性**

---

## 0. 这份 SPEC 的边界

**做**：缓存层（nginx 响应头）、打包配置层（Vite）、一处路由预取策略。
**不做**：任何改变模块加载时机的改动（dynamic import 化）、任何触碰 ST 契约的改动、任何鉴权面改动。

一句话理由：首屏 541KB(gzip) 里约 266KB 是 ST 兼容层，而它被「插件沙箱 / 插件运行时 / 智能卡渲染」三处**同步**依赖——前一份报告已逐条给出源码证据。剩下的可动空间只在缓存与打包配置。

## 1. 目标与非目标

### 目标

| 编号 | 目标 | 可验证指标 |
| --- | --- | --- |
| G1 | 提高静态资源缓存命中率 | 二次访问时 `dist/assets/*` 返回 `from disk cache`，0 网络请求 |
| G2 | 减少真实传输字节（不改加载时机） | worker chunk gzip 142KB → 83KB |
| G3 | 释放登录后的带宽竞争 | 登录后 3 秒内预取流量 ~1.2MB → ~0.3MB |

### 非目标（明确排除）

- 不改 ST 插件契约（`messageFormatting` 保持同步、`window.$` 保持注入前就位）
- 不改智能卡渲染时序（不引入 Suspense / 占位）
- 不引入 Service Worker
- 不动 `/uploads/`、不动任何鉴权相关逻辑
- 不做 `manualChunks` 之外的 chunk 语义变更

## 4. 逐项规格

### N1　带 hash 的 JS/CSS 改 immutable 长缓存

**现状**（`nginx.conf:52-58`）：

```nginx
    location ~* -[a-zA-Z0-9_-]+\.(js|css)$ {
        root /usr/share/nginx/html;
        include /etc/nginx/security-headers.conf;
        add_header Cache-Control "no-cache, must-revalidate";
        add_header Pragma "no-cache";
        add_header Expires "0";
    }
```

**改为**：

```nginx
    location ~* -[a-zA-Z0-9_-]+\.(js|css)$ {
        root /usr/share/nginx/html;
        include /etc/nginx/security-headers.conf;
        add_header Cache-Control "public, max-age=31536000, immutable";
    }
```

注意：`Pragma` / `Expires` 两行**必须一并删除**，否则与 max-age 语义冲突。

**为什么安全**

- 该 location 只匹配「文件名带内容指纹」的资源。内容一变，Vite 生成的文件名就变，浏览器自然去取新文件；不存在"拿到旧内容"的可能。
- `index.html` 走 `location /`，仍是 `no-store`，不会被这条规则影响。
- 已实测：`dist` 下 88 个 js/css **全部**匹配该正则；不匹配且落到 `location /` 的只有 4 个文件（见 N2 清单），这 4 个单独处理。
- 项目自身已有先例佐证：`vite-plugins/smart-card-runtime-asset.ts` 的 dev 中间件对 hash 资产发的就是 `public, max-age=31536000, immutable`，注释亦写明"命中 nginx immutable 缓存规则"。当前 nginx 的 `no-cache` 与设计意图矛盾。

**已知边界（必须接受）**

- 发版后旧 hash 文件会被 `emptyOutDir` 清掉。任何**手持旧 `index.html`** 的用户会 404。由于 `index.html` 是 `no-store`，正常路径不会发生；但发版时**必须保留上一版 dist 若干天**作为兜底（本仓库已有 `mv dist dist_old_<日期>` 的习惯，正好用上）。

**回滚**：把三行 header 改回原样，restart。

### N2　非 hash 静态资源加缓存

**已实测的 4 个"漏网"文件**（不匹配 hash 正则，当前吃 `no-store`）：

```
dist/bootstrap.js
dist/katex.min.css
dist/st/css/fontawesome.min.css
dist/st/css/solid.min.css
```

另有 `dist/fonts/`（60 个 KaTeX 字体，单文件约 26KB）与 `dist/st/webfonts/`（2 个）。

**新增**（建议放在 `location /icons/` 附近，位于 `location /` 之前以增强可读性）：

```nginx
    location = /bootstrap.js {
        root /usr/share/nginx/html;
        include /etc/nginx/security-headers.conf;
        add_header Cache-Control "public, max-age=604800";
    }

    location = /katex.min.css {
        root /usr/share/nginx/html;
        include /etc/nginx/security-headers.conf;
        add_header Cache-Control "public, max-age=2592000";
    }

    # KaTeX 字体：随 katex 版本升级才变
    location ^~ /fonts/ {
        root /usr/share/nginx/html;
        include /etc/nginx/security-headers.conf;
        add_header Cache-Control "public, max-age=2592000";
    }

    # ST 插件依赖的 Font Awesome（css + webfonts）。非内容 hash，
    # 故用 7d 而非 30d，避免上游更新后长期拿旧版
    location ^~ /st/ {
        root /usr/share/nginx/html;
        include /etc/nginx/security-headers.conf;
        add_header Cache-Control "public, max-age=604800";
    }
```

**注意事项**

- `^~` **必须写**。nginx 的最长前缀匹配若不带 `^~`，仍会被后面的正则 location（N1 那条）抢走；`/fonts/` 下是字体不会命中，但 `/st/css/*.min.css` 虽不匹配 hash 正则（无 `-hash`），写上 `^~` 可杜绝将来文件名变化带来的误匹配。
- `location = /xxx` 精确匹配优先级最高，不受正则影响。
- `/st/` 用 **7d**：这批文件来自 `frontend/public/st/`，是手工维护的第三方资源，不是构建产物，没有内容指纹。

### N3　`/icons/` 重复响应头 + `Vary`

**现状**（`nginx.conf:70-75`）同时用了 `expires 30d` 和 `add_header Cache-Control`，导致输出**两条** `Cache-Control`：

```
Cache-Control: max-age=2592000
Cache-Control: public, immutable
```

**改为**（去掉 `expires`，只留一条）：

```nginx
    location /icons/ {
        alias /usr/share/nginx/html/icons/;
        include /etc/nginx/security-headers.conf;
        add_header Cache-Control "public, max-age=2592000, immutable";
    }
```

**同时在 server 块补一行**（与 `gzip on;` 相邻）：

```nginx
    gzip_vary on;
```

理由：开启 gzip 后同一 URI 有压缩/未压缩两种响应，缺少 `Vary: Accept-Encoding` 会让中间缓存串味。

### N4　角色头像代理缓存

**只做 `/api/st/characters/`**。`/uploads/` **绝对不做**，原因见 §5.3。

**第一步**，在文件顶部（与 `limit_req_zone` 同级，即 http 上下文）新增：

```nginx
proxy_cache_path /var/cache/nginx/media levels=1:2 keys_zone=media_cache:10m
                 max_size=256m inactive=7d use_temp_path=off;
```

> 路径必须在 `/var/cache/nginx/` 之下——Dockerfile 已把该目录 chown 给 `appuser`(uid 1000)，换到其他路径会因权限无法写入缓存。

**第二步**，在 `location /api/` 之前新增：

```nginx
    # 角色头像：后端对该路由不强制鉴权（共享内容），可安全缓存。
    # 注意 /uploads/ 走 N-7 短时效令牌鉴权，不可缓存，切勿并入此块。
    location ^~ /api/st/characters/ {
        include /etc/nginx/security-headers.conf;
        proxy_pass http://backend:8000;
        proxy_set_header Host $http_host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_http_version 1.1;
        proxy_buffering on;
        proxy_cache media_cache;
        proxy_cache_valid 200 206 7d;
        proxy_cache_lock on;
        proxy_cache_use_stale error timeout updating;
        add_header X-Cache-Status $upstream_cache_status;
        proxy_read_timeout 60s;
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
    }
```

**注意事项**

- 必须 `proxy_buffering on`（`/api/` 那条为了 SSE 是 `off`，不能继承）。
- `proxy_cache_valid` 只列 `200 206`：404/5xx 不进缓存，避免故障被缓存放大。
- `X-Cache-Status` 响应头用于验收（`HIT` / `MISS` / `BYPASS`）。
- 已实测后端对该路由**不下发** `Cache-Control` 与 `Set-Cookie`，因此无需 `proxy_ignore_headers`。若将来后端加上了私有缓存头导致始终 `BYPASS`，再补 `proxy_ignore_headers Cache-Control Expires;`（对共享头像资源是安全的）。
- 匹配优先级：`/api/st/characters/`（19 字符）比 `/api/`（5 字符）长，最长前缀胜出，`^~` 再确保跳过正则。

### N5　`gzip_static` 预压缩

**第一步**，新增脚本 `frontend/scripts/gzip-dist.cjs`：

```js
#!/usr/bin/env node
/**
 * 构建后为 dist 下文本类资源生成 .gz 副本，供 nginx gzip_static 直接投递。
 * 只新增文件，从不删除 dist 内任何内容。
 */
const fs = require('node:fs');
const path = require('node:path');
const zlib = require('node:zlib');

const DIST = path.resolve(__dirname, '..', 'dist');
const EXT = new Set(['.js', '.css', '.json', '.svg', '.html', '.xml', '.txt', '.webmanifest']);
const MIN_BYTES = 1024;
const MAX_BYTES = 20 * 1024 * 1024;

if (!fs.existsSync(DIST)) {
  console.error('[gzip-dist] dist 不存在，请先构建');
  process.exit(1);
}

let count = 0;
let saved = 0;
(function walk(dir) {
  for (const entry of fs.readdirSync(dir, { withFileTypes: true })) {
    const full = path.join(dir, entry.name);
    if (entry.isDirectory()) { walk(full); continue; }
    if (entry.name.endsWith('.gz')) continue;
    if (!EXT.has(path.extname(entry.name).toLowerCase())) continue;
    const size = fs.statSync(full).size;
    if (size < MIN_BYTES || size > MAX_BYTES) continue;
    const gz = zlib.gzipSync(fs.readFileSync(full), { level: 9 });
    fs.writeFileSync(full + '.gz', gz);
    count += 1;
    saved += size - gz.length;
  }
})(DIST);

console.log(`[gzip-dist] ${count} 个文件已生成 .gz，较原始体积减少 ${(saved / 1024).toFixed(0)} KB`);
```

**第二步**，`package.json` 的 `build` 脚本末尾追加：

```json
"build": "node scripts/clean-dist.cjs && node scripts/build-vite.mjs && node scripts/gzip-dist.cjs"
```

**第三步**，`nginx.conf` 在 `gzip on;` 附近补两行，并把 `font/woff2` 从 `gzip_types` 里去掉（woff2 本身已是压缩格式，再 gzip 只浪费 CPU）：

```nginx
    gzip_static on;
    gzip_vary on;
    gzip_types text/plain application/javascript text/css application/json application/wasm image/svg+xml application/xml text/javascript;
```

**注意事项**

- `gzip_static` 仅对**磁盘上存在同名 `.gz`** 的文件生效；没有 `.gz` 时自动回退实时压缩，不会 404。
- nginx 会用 `.gz` 文件的 mtime 做 `Last-Modified`/`ETag`，正常。
- 本环境跑 `npm run build` 时，`scripts/clean-dist.cjs` 的递归删除会触发批量删除守卫。构建前先 `mv dist dist_old_<日期>`，构建确认无误后再清理旧目录。

### B1　路由预取瘦身（`src/App.tsx`）

**现状**（`App.tsx:551-574`）：登录就绪后，在 `requestIdleCallback(timeout:3000)` 内一次性预取 5 个路由。

**已核实的安全前提**：`StPluginMountPoints` 位于 `App.tsx:1105`，在 `Route path="*"`（app 外壳层）内，**不在**页面级 `<Routes>`（`App.tsx:1008-1016`）里 → 插件挂载与路由无关，改预取策略不影响插件。

**替换为**：

```ts
  // 空闲时预取路由 chunk：登录就绪、首屏关键请求已发出后，把首次导航
  // 要用的懒加载模块拉进浏览器模块缓存。与上方 lazy() 使用相同模块说明符，
  // 真实导航时直接命中缓存；不挂载任何组件，对现有渲染零影响。
  //
  // [性能 2026-09-21] 原先一次性预取全部 5 个路由（≈1.2MB raw / ≈330KB gzip），
  // 与首屏 API 抢带宽。改为分两梯队：
  //   第一梯队：当前形态必然要用的聊天页（timeout 3s）
  //   第二梯队：次常用的角色页（timeout 15s，且仅在非省流/非慢网时）
  // 设置页与工作空间页不再预取，改为真实导航时按需加载（延迟约 100~300ms）。
  const routePrefetchDoneRef = useRef(false);
  const routePrefetchSecondaryDoneRef = useRef(false);
  useEffect(() => {
    if (!token || !privateConfigReady) return;
    if (routePrefetchDoneRef.current) return;

    const isSlowNetwork = () => {
      const conn = (navigator as any)?.connection;
      if (!conn) return false;
      return conn.saveData === true || /^(slow-)?2g$|^3g$/.test(String(conn.effectiveType || ''));
    };

    const prefetchRoutes = () => {
      if (routePrefetchDoneRef.current) return;
      routePrefetchDoneRef.current = true;
      void import(isMobile
        ? '@/components/views/ChatViewMobile'
        : '@/components/views/ChatViewDesktop');
    };

    const prefetchSecondary = () => {
      if (routePrefetchSecondaryDoneRef.current) return;
      routePrefetchSecondaryDoneRef.current = true;
      void import('@/components/views/CharacterView');
    };

    const idle = typeof window.requestIdleCallback === 'function';
    const handle = idle
      ? window.requestIdleCallback(prefetchRoutes, { timeout: 3000 })
      : window.setTimeout(prefetchRoutes, 1500);
    let handle2: number | undefined;
    if (!isSlowNetwork()) {
      handle2 = idle
        ? window.requestIdleCallback(prefetchSecondary, { timeout: 15000 })
        : window.setTimeout(prefetchSecondary, 8000);
    }

    return () => {
      if (idle) {
        window.cancelIdleCallback(handle as number);
        if (handle2 !== undefined) window.cancelIdleCallback(handle2);
      } else {
        window.clearTimeout(handle as number);
        if (handle2 !== undefined) window.clearTimeout(handle2);
      }
    };
  }, [token, privateConfigReady, isMobile]);
```

**注意事项**

- `isMobile` 已在本组件中定义（`App.tsx:451`），需加入依赖数组。它来自媒体查询 hook，桌面/移动切换时会重跑本 effect；两个 `useRef` 守卫保证不会重复预取。
- **行为等价性**：`lazy()` 的模块说明符与 `import()` 完全一致，命中同一模块缓存。移除 SettingsView/WorkspaceView 的预取**只影响首次进入这两页的加载延迟**，不改变任何功能。
- 若你希望保留"进入设置页零等待"，可把 `SettingsView` 加进第二梯队——但那会重新引入约 116KB gzip 的空闲期下载，不建议。

### B2　Worker 移除重复打包的 KaTeX（`vite.config.ts`）

**问题**：`src/lib/sillytavern/formatting-worker/worker.ts` 只从 `../formatting` 引入了 8 个纯函数（`extractReasoningTags` / `fixMarkdown` / `encodeTags` / `extractHtmlBlocks` / `preprocessMarkdownForShowdown` / `getShowdownConverter` / `restoreHtmlBlocks` + type），**一个都不碰 KaTeX**；但 `formatting.ts` 顶层 `import katex from 'katex'`，而 katex 包**未声明 `sideEffects: false`**，打包器不敢 tree-shake，于是整份 KaTeX 在 worker 里被复制了一份。

**实测数据**（本次已验证，非估算）：

| | 现状 | 修复后 |
| --- | ---: | ---: |
| worker 原始体积 | 513,161 B | **289,727 B**（-43.5%） |
| worker gzip | 142 KB | **83 KB**（-59 KB） |
| worker 内 `mord`（KaTeX 特征） | 43 次 | **0 次** |
| 入口内 `mord` | 43 次 | **43 次（必须保留）** |
| worker 内 `Converter`(showdown) / `Lexer`(chevrotain) | 4 / 36 | **4 / 36（必须保留）** |

**修法**（`vite.config.ts` 顶层，与 `build` 同级）：

```ts
  // [性能 2026-09-21] Worker 是独立的 Rollup 构建，build.rollupOptions.treeshake
  // 对它不生效（已实测：体积不变、mord 仍 43 次），必须写在 worker.rollupOptions 下。
  // 作用：告诉打包器 katex 无副作用，从而把 worker 根本用不到的整份 KaTeX 摇掉。
  // 仅影响 worker 产物；入口 chunk 仍在用 renderMathInHtml，KaTeX 保留（已实测 mord=43）。
  worker: {
    rollupOptions: {
      treeshake: {
        moduleSideEffects: (id: string) => !/node_modules[\\/]katex[\\/]/.test(id),
      },
    },
  },
```

**已实测无效的两条路，不要重复尝试**：

1. `worker: { format: 'es' }` → 产物 517KB，`mord` 仍 43 次。
2. 只写 `build.rollupOptions.treeshake.moduleSideEffects` → 产物 517KB，`mord` 仍 43 次（worker 不吃这个配置）。

**验收硬指标**：`mord` 在 worker 产物中必须为 **0**，在入口产物中必须 **≥1**。两者同时成立才算成功。

**为什么这不碰 ST 兼容性**：worker 里跑的是"正则 → 宏 → Showdown"这段 CPU 密集步骤，KaTeX 渲染本来就在主线程完成后进行（`formatting.ts:248 renderMathInHtml` 由主线程 `formatMessage` 调用）。移除的是一份**根本没被调用**的死代码。

## 5. 明确不做的事（含触发条件）

### 5.1 动态拆包 4 组库 —— 不做

| 组 | 库 | 卡点 |
| --- | --- | --- |
| A | jquery / select2 / toastr / handlebars / marked | `sandbox.ts:163-171` 模块顶层 select2 副作用；`evalLocalFile`(`:2867`) 同步；`sillyTavernPluginRuntime.ts:343` 插件脚本注入前需 `window.$`；`inline-st-globals.ts:380` 在 `useLayoutEffect` 同步调用 |
| B | katex | `formatMessage` 全同步，且是插件 API `messageFormatting` 的实现（`sandbox.ts:3268`） |
| C | chevrotain | `MacroRegistry`/`evaluateMacros` 经 `getContext.ts` 暴露给插件；宏在显示链路同步求值 |
| D | react-markdown 栈 | `smart-card-runtime/shared.ts:12-13` 定义插件常量，是智能卡运行时公共底座 |

**重新评估的触发条件**：出现明确的"首访体积必须下降"的业务诉求，且愿意接受①`npm run test:contract` 全量回归 ②引入"所有插件执行入口必须先 await"的不变量守卫 ③智能卡首帧/公式消息的可见回归。届时应单独立项。

### 5.2 Service Worker —— 不做

收益最大但与 iOS PWA 主题快照、`no-store` 的 `index.html`、插件 `unsafe-eval` 脚本三处耦合。触发条件：前面各项上线稳定后再单独立项。

### 5.3 `/uploads/` 代理缓存 —— 绝对不做

`/uploads/{file_path}` 的鉴权是 N-7 短时效令牌（`backend/app/main.py:448-521`）。
- nginx 默认缓存键含 query → token 每 5 分钟变 → 命中率≈0，做了也没用；
- 若为提命中率把 token 从缓存键剔除 → 知道路径即可拿到他人附件的缓存体 → **安全回归**。

### 5.4 `gzip_proxied`（压缩 API 响应）—— 本版不做

`/api/` 当前 `gzip_proxied` 默认为 `off`，即 API JSON 不压缩。开启能省一点流量，但 `/api/` 同时承载 SSE 流式响应（`proxy_buffering off`），压缩会给流式增加缓冲与 CPU 开销，**可能拖慢对话首字时间**。若将来要开，必须先单独实测流式首字延迟，确认无回归再上。

## 8. 暂缓项：B3 handlebars source-map

`node_modules/handlebars/lib/handlebars/compiler/code-gen.js:9-20` 中，`require('source-map')` 外层**本就有 try/catch**，失败时回退到 handlebars 自带的精简 `SourceNode`。但打包时该 require 被静态解析，`source-map`（105KB 未压缩）仍被塞进入口。

用 `resolve.alias` 把 `source-map` 指向空模块即可触发这个内置兜底，预计省约 12KB gzip。

**本版暂缓的原因**：收益小（12KB），且需要额外验证"模板渲染在缺少 source-map 时行为完全一致"——当前契约测试没有直接覆盖 handlebars 编译路径。建议 B2 上线稳定运行后再单独评估。
