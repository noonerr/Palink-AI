## 1. 目标与非目标

**目标**：让用户在需要时能看到"这条消息背后，副 AI 被喂了什么、返回了什么、有没有降级、为什么降级、花了多久"。典型用途：排查出图提示词为什么怪、变量更新为什么没生效、标题为什么跑偏。

**非目标**：
- 不做交互式面板（无输入框、无重跑/重试按钮、无"改提示词再试一次"）；
- 不做跨消息总览页 / 统计页（留作 §6 可选项，默认不做）；
- 不做插件/ST 工具调用的合并展示（那是另一套 `tool_call` 事件通道）；
- 不进上下文、不进向量记忆、不进世界书检索（硬约束，见 §4）。

**价值前提**：用户判断"约四成人不会看"。因此设计上必须**零存在感**——不看不亏（默认只存几百字节摘要），看了有用（点开即得全貌）。任何让这一行变显眼、变占位的做法都算跑偏。

## 2. 数据结构（复用现有 `extra`，零迁移）

落在消息的 `extra.subtasks`（数组，一条消息可能有多个副任务）：

```jsonc
{
  "kind": "mvu_secondary" | "image_scene" | "title" | "image_tool",
  "model": "deepseek-v4-flash",
  "ms": 320,
  "status": "ok" | "fallback" | "failed",
  "fallback_reason": "unparsable_json" | "not_enabled" | "timeout" | "",   // status!=ok 时必填
  "result_brief": "4 patches" | "tags=23, nl=118词" | "",                   // ≤80 字
  "prompt_sha256": "…",           // 全文指纹（用于"这条轨迹当时喂的是哪版"）
  "prompt_chars": 19384,
  "prompt_head": "Write …的前 200 字…",   // 摘要模式只有这一份
  "prompt_full": "…",             // 仅"完整留痕"开关打开时存在
  "output_head": "…≤500 字…"      // 副 AI 返回原文摘要（排查解析失败必需）
}
```

要点：
- **默认不存 `prompt_full`**（用户拍板：摘要 + 可开全文）。开关放 `image_generation_config.json` 之外的全局用户设置面还是 admin JSON 面，见 §6 待定项。
- `prompt_head` + `output_head` + `fallback_reason` 三者足以回答 90% 的"为什么不对"，这是默认档的价值底线。
- 单条摘要目标 ≤ 600 字节；一条消息最多记 4 个副任务（超出丢弃最旧并在末条标 `truncated`）。

插桩点只调它，别在四处重复拼字典。

## 4. 三条硬约束（必须写成测试，不是写成注释）

1. **只读**：前端组件不得含任何 `input` / `textarea` / 触发后端生成的按钮；只允许展开、折叠、复制文本。
   （给输入框＝长出第二个聊天入口；给重跑按钮＝会在用户没打算花钱时悄悄花网关额度。）
2. **禁入上下文与向量记忆**：轨迹只存 `extra.subtasks`。现状已核：装配取 `m.content`
   （`character_message_builder.py:217-238`）、记忆入库同样只读正文 → 结构上隔离。
3. **守卫测试锁死 2**：新增用例断言
   ①`build_character_chat_messages` 的输出里不含任何 `subtasks` 字段的字符串内容（造一条带轨迹的消息，装配后全文搜索 `prompt_head` 独有哨兵串，必须 0 命中）；
   ②记忆写入/检索路径同样 0 命中。
   理由：提示词本身含世界书与记忆内容，若轨迹被回灌检索，会形成自我污染循环、越聊越脏。**没有这条测试，本功能不许合。**

## 5. 前端展示（T2）

- 位置：助手气泡下方，与现有"深度思考"框同一区域，复用其折叠交互（`ThinkingProcess.tsx` 那套），不新造组件范式。
- 收起态：一行窄横条，例：`副任务 · 出图场景 320ms · 已用副AI` / `副任务 · 变量更新 · 降级：解析失败`。
  多个副任务时合并成一条（`副任务 ×2`），点开列全。**不显示图标动画、不显示进度、不占额外行高。**
- 展开态：每项显示 kind / model / ms / status / fallback_reason / result_brief /
  `提示词 19384 字（sha 前 8 位）` + 前 200 字；`prompt_full` 存在时给"展开全文"（原地展开、超过 30 行再截断）与"复制"。
- 无轨迹时**整块不渲染**（不是渲染成空条）。老消息没有该字段属正常，不得报错。
- 失败态不得用红色告警——降级是设计内的正常路径，用中性文案（否则用户会以为坏了）。

## 6. 存储、淘汰与待定项

- 全文开关默认**关**。开→只影响新产生的轨迹（不回补历史）。
- 淘汰：`extra` 随消息存，无独立表。建议 T3 做"最近 N 条消息保留 subtasks、更旧的自动摘掉"（N=200，
  实现为读取时不摘、写入时顺手清理该会话超出 N 的旧轨迹），避免无限膨胀。
- 待定（施工前问用户）：①全文开关放用户设置页还是管理端出图配置面；②`title` 这类高频小任务要不要默认不记。
