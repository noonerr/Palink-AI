## 〇、一页速览（新对话先读这个）

**核心任务**：实现「角色卡对话下方显示好感度/状态等纯文本/HTML 面板」，让 Palink 与 SillyTavern (ST) 原版一致。

**用户反复强调的核心认知**：
> 「这个角色卡里面的 HTML 面板，是通过这个插件来实现的，显示在这个前端的。你要理解这个。」

即：好感度/状态面板**不是**角色卡里的静态 HTML，而是由 **Tavern Helper 插件**读取角色卡 `extensions.tavern_helper`（zod schema）+ 会话 `stat_data` 后，在前端**动态生成并渲染**的。

**优先级**：先适配 **Tavern Helper 插件**（酒馆助手），**不是** Galgame 界面插件。用户曾因助手误把精力放在 Galgame overlay 上而表达不满。

**方案方向**：用户已确认采用「兼容逆向渲染器」（不导入完整 ST 引擎，前端按 `registerMvuSchema`/`registerVariableSchema` 契约实现），以保证不破坏其他插件。

**当前状态**：数据接线已大部分完成，但**面板渲染尚未实现**（前端缺 `registerMvuSchema` 兼容逻辑 + MagVarUpdate 引擎执行）。

---

## 一、核心结论与难点（务必先理解）

### 1. 面板是插件动态渲染，不是静态 HTML
- 角色卡只定义「变量结构 schema（zod）+ MVU 更新脚本」，不存面板 HTML。
- 面板由 Tavern Helper 插件在运行时读取 schema + stat_data 生成。

### 2. 三个关键阻塞点（未解决）
1. **前端未实现 `registerMvuSchema` / `registerVariableSchema` 兼容逻辑**——插件无法读取 schema 生成面板。
2. **`CharacterCardRenderer.tsx` 的 `getContext()` 覆盖冲突**——它 (L3187) 覆盖 `window.SillyTavern.getContext`，返回的 context 缺少完整 `stat_data`/`character.extensions`，可能覆盖 `sillyTavernPluginRuntime.ts` 已设置好的值。
3. **角色卡 schema 脚本是 ESM**（含 `import { registerMvuSchema }`），会被 `sillyTavernPluginRuntime.isEsmModule()` 跳过，导致 schema 未注册。

## 二、数据链路（完整梳理）

### 1. 角色卡侧（数据源头）
角色卡 `extensions.tavern_helper` 包含两个脚本。本例角色卡「我被猫娘包围了！」（`id=c380f835-3941-4d8e-9c62-25dbcc6cbdae`）：
- **script[0] `变量结构`**（enabled）：用 `registerMvuSchema(z.object({...}))` 定义 schema。字段：
  - `世界信息`：日期时间/天气/风力/地点
  - `桃汐`：好感度(0-100,默认50)/关系(默认'青梅竹马')/性欲值(0-100,默认20)/服饰/内心想法/发情期
  - `苏小兰`：好感度(默认20)/关系(默认'邻居')
- **script[1] `MVU`**（enabled）：导入 `https://.../MagVarUpdate/artifact/bundle.js`（解析 AI 回复 `<UpdateVariable>` 标签更新 stat_data）

### 2. 后端（插件导入 + 变量引擎）
- **导入**：`backend/app/api/plugins.py` 的 `_import_from_character_card_extensions()`（L958）→ 检测到 `extensions.tavern_helper` 后调 `_import_tavern_helper()`（L847），导入为 `tavern_helper` 类型插件（`source_type="character_card_extension"`，默认 `enabled=False`，`config={"character_card_extension": True, "global_runtime": False}`）。
- **运行时下发**：`_plugin_runtime_payload()`（L482）中，`tavern_helper` 类型若 `resources` 无 js，会把 `plugin.scripts` 中所有 enabled 脚本按 `order_no` 用 IIFE 拼接成 `index.js` 入口下发。
- **变量引擎**：`backend/app/services/mvu_engine.py`——**已完整实现**（无状态纯函数，不碰 DB，不依赖外部 CDN）。核心函数：
  - `extract_update_variable_blocks(text)`：正则提取 `<UpdateVariable>...</UpdateVariable>` 块，内部优先取 `<JSONPatch>` 块，否则取第一个平衡 JSON 数组；宽松修复（去尾逗号/单引号转双引号/移除 `${...}` 占位行）；过滤 value 为 `${...}` 未替换占位符的 patch。
  - `apply_patches(stat_data, patches, *, readonly_prefix="_")`：RFC 6902 超集 + delta，支持 `replace/add/insert/remove/move/delta`；深拷贝不原地改；单 op 异常不中断；`_` 前缀路径只读（`_path_readonly`）。
  - `extract_schema_defaults(tavern_helper)`：用正则解析 zod schema 的 `.prefault()` 提取默认值（**未真跑 zod**），支持 `z.string/z.number/z.boolean/z.array/z.object` 嵌套、coerce、无引号 key、嵌套对象字面量。
  - `build_initial_stat_data(character_extensions)`：合成初始 stat_data，优先级（后者深合并覆盖前者）：① schema 默认值 → ② `tavern_helper.variables` → ③ `first_mes`/`alternate_greetings` 内 `<initvar>` 块（支持 JSON 和缩进式）。
  - `MvuEngine` 薄封装：`init_session_variables()` / `update_from_reply()`。
  - 测试在 `backend/tests/test_mvu_engine.py`（含 `_CATGIRL_SCHEMA_SCRIPT` 样例）。
  - **注意**：后端只负责 stat_data 的**生成与更新**，**不含**前端面板渲染——面板由前端按 schema 渲染，这是当前未完成的主线。
- **会话变量下发**：`backend/app/api/character_ext.py` L2764 附近从 chat_metadata 提取会话级 stat_data 下发；`backend/app/api/websocket.py` L536 附近处理 `<UpdateVariable>` 更新 stat_data。

## 六、项目硬约束（Hard Constraints，来自记忆，改动前必读）

- **HTML 消息内联渲染**：角色聊天 HTML 消息必须 `dangerouslySetInnerHTML` 进 `.mes_text`（`sanitizeStCompatHtml`），**不能**进 CharacterCardRenderer iframe。CSS 不重作用域。
- **HTML 检测**：用 `isHtmlCardContent`，**不用** `looksLikeSmartCardHtml`。
- **前端部署**：volume mount `./frontend/dist:/usr/share/nginx/html:ro` 会覆盖镜像层。改前端需：`npm run build`（frontend/ host 上）→ `docker compose restart frontend`。`docker compose build frontend --no-cache` 单独**不生效**。
- **ST 代理**：Palink 自有 ST API 由 Palink 后端处理，非自有 API 透明代理到 SillyTavern sidecar。`/api/st/native/proxy/{path:path}` 需校验 path（拒绝空/`..`/CRLF/绝对 URL/递归代理），不转发 `authorization`/`cookie`/`host`/`content-length`/`connection`/`upgrade`/`transfer-encoding`/`proxy-*`，注入 `X-Palink-User-Id` 等头。
- **`/st/css/user.css` 返回空 CSS**（避免启动噪音）。
- **Nginx 缓存策略**：JS/CSS 用 `no-cache, must-revalidate`（非 `max-age=31536000, immutable`）；hash 正则要匹配 Vite base64（含 `[a-zA-Z0-9_-]+`）。
- **`GET /api/plugins/runtime/config` 用 `get_admin`**（非 `get_current_user`，防配置泄露给普通用户）。
- **iOS WebApp 模式**：`body` 用 `overflow:hidden; position:fixed; top:0; left:0; width:100%; height:100%` + `html{overflow:hidden}` + `#root{height:100%}`；Input `bottom` 用 `var(--palink-dock-height)`（非 `keyboardHeight`）；`apple-mobile-web-app-status-bar-style` 用 `black-translucent` + `env(safe-area-inset-top)`。
- **ST vectors**：存 `conversation_memories` 表，`session_id="st-vec::<集合ID>"` 前缀。检测到 `st-vec::` 数据时 memory 模块跳过注入（`MEMORY_ST_YIELD=false` 可配置）。
- **`/api/settings/save`**：`extension_settings` 做 namespace 级合并（防覆盖其他插件设置）。
- **容器依赖**：前端依赖后端 `service_healthy`（非 `service_started`）；后端 healthcheck `start_period: 180s`（Python ML 库加载慢）+ `interval: 15s` + `retries: 8`。
- **端口**：前端容器绑 `127.0.0.1`（如 `127.0.0.1:3000:8080`），避 Windows 权限问题；避免用 9000 端口。
- **Galgame 插件**：`getContext()` 需返回 `characterId`/`name2`，`window.this_chid` 需设置；每次注入前清理 localStorage `galgame-ui-plugin_char_enabled`。
- **AI 回复**：角色聊天必须显示头像、角色名、`.mes_text` 容器（ST 默认样式）。

## 七、工程规范（Engineering Conventions）

- **Chat 页 TopBar**（ChatViewMobile.tsx / ChatHeader.tsx）：`backdrop-blur(16px) saturate(160%)` + 渐变 `(to top, rgba(base,0) 0%, rgba(base,0.08) 25%, rgba(base,0.25) 50%, rgba(base,0.45) 75%, rgba(base,0.70) 100%)`，实现底部全透明→中部60%→顶部30%透明。
- **SettingsView header**：`backdrop-blur(26px)` + mask-image 渐变 `(to top, rgba(0,0,0,0) 0%, rgba(0,0,0,1.0) 22%, rgba(0,0,0,1.0) 100%)` + background 渐变 `(to top, rgba(base,0) 0%, rgba(base,0.40) 55%, rgba(base,0.80) 100%)`，实现底部全透明→中部60%→顶部20%透明。
- **移动端底部按钮 padding**：`navHeight + 32`（tailwind 阶梯：≤80→pb-20，≤112→pb-28，≤144→pb-36，else→pb-44）。
- **Header 绝对定位**：SettingsView z-20 / Chat z-18，浮于内容上方，内容可从背后穿过。
- **内容区 paddingTop 最小**（仅 safe-area 8px），首元素前加 spacer div（可滚动）。
- **ChatViewMobile header 高度**：`calc(env(safe-area-inset-top) + 3rem + 8px)`，top padding `calc(env(safe-area-inset-top)+4px)`，bottom padding `pb-1`（4px）。
- **ChatHeader（角色聊天）**：与 ChatViewMobile `#mobile-chat-top-bar` 同高、同毛玻璃参数、同 padding、同按钮尺寸。
- **ChatHeader 按钮**：`!h-10 !w-10` + `rounded-full`（左）或 `rounded-[24px]`（右），保证 40px。
- **PresetSelector**：chat header 不再放压缩触发按钮（避免布局冲突）。

## 八、经验教训（Lessons Learned）

- Docker Compose healthcheck 会覆盖 Dockerfile `--start-period`，配置不当会导致过早重启。
- Layer cache / vite 内部缓存可能导致 Docker build 不更新 chunk hash，需手动清缓存 + 本地构建验证。
- spacer 高度过高（60~68px）会使内容进不了 header 覆盖区，毛玻璃失效（修到 18px/20px/0.25rem）。
- `backdrop-filter: blur()` 对纯色/径向渐变背景**无视觉效果**（无法区分相同背景色）。
- Docker 只要一个端口绑定失败，会放弃该容器**所有**端口映射。
- mask alpha 与 background alpha 相乘；mask 在 22% 高度应达到 1.0，避免削弱顶部背景透明度。
- 定位元素（`absolute z-0` 毛玻璃层）会盖住静态元素（按钮），需给按钮容器设 `relative z-10`。
- `Button size="icon"` 默认类会被 Tailwind `data-size="icon"` 规则覆盖，需 `!important` 强制。
- Galgame 插件 `getCurrentCharKeyAliases()` 缺 `characterId`/`this_chid`/`name2` 时回退 `["default"]`，导致 localStorage `galgame-ui-plugin_char_enabled` 意外激活 overlay。
- AI 回复走 FramelessContent 分支（isHtmlOrCard=false）时缺头像/角色名/`mes_text`，违反 ST 默认样式。
- **经典脚本**（非 ESM）通过 `<script>` 标签注入执行，在真实 window 作用域，只能访问 window 全局变量，不走 sandbox IIFE。
- **div 被挡**：z-index 不足；`getChatMessages` 未暴露导致 `gal-dialog-text` 为空。
- Galgame overlay 显示（position:relative; height:70vh）是插件默认内联模式行为，**非 bug**，可用全屏按钮切换。

## 九、用户偏好（User Profile）

- 沟通语言：中文。
- 架构：偏好 WebSocket 实时同步（非轮询）。
- 资源管理：内网穿透服务（如 frpc）需跑在真实内存（非 swap）。

## 十五、完整记忆整合（来自 project_memory.md，全文）

> 以下为项目记忆（project_memory.md）的**完整原文**，含所有硬约束、工程规范、经验教训。改动任何相关代码前务必通读。

### 15.1 Hard Constraints（硬约束，改动前必读）

- **Character chat**（`isCharacterChat && !isUser && !useNativeStRendering`）HTML 消息**必须**用 `dangerouslySetInnerHTML` 内联渲染进 `.mes_text`（`sanitizeStCompatHtml`：剥离 script/iframe/object/embed/base/form，保留 style/div/span），**不能**进 CharacterCardRenderer iframe。ST 插件（如 Galgame）读 `.mes_text` 原始 HTML 渲染 overlay；iframe 隔离会破坏这一点。CSS **不得**重作用域（作者用 `.mes_text .xxx` 选择器，只有 `.mes_text` 本身作为容器元素时才匹配）。
- **Character chat HTML 检测**必须用 `isHtmlCardContent`（检测 `<div>/<span>/<style>` 等），**不能用** `looksLikeSmartCardHtml`（太窄，漏掉无 `<style>` 的内联 HTML div）。用 `looksLikeSmartCardHtml` 会导致含内联 HTML div 的消息落入 FramelessContent 分段分支——该分支无 `.mes_text` 类，会把 HTML 当文本转义渲染，破坏 ST 插件 DOM 读取。
- **前端容器**用 volume mount `./frontend/dist:/usr/share/nginx/html:ro`——docker build 把 dist 拷进镜像但 volume mount 会被宿主 dist 覆盖。部署前端改动：在 frontend/ 宿主上跑 `npm run build`（更新 `./frontend/dist`）→ `docker compose restart frontend`。单独 `docker compose build frontend --no-cache` **不生效**（volume mount 遮蔽镜像层）。
- **Palink 自有 ST API** 由 Palink 后端处理；非自有 API 必须透传到 SillyTavern sidecar。
- **代理端点** `/api/st/native/proxy/{path:path}` 必须校验 path（拒绝空/`..`/CRLF/绝对 URL/递归代理）。
- **代理不得转发** `authorization`/`cookie`/`host`/`content-length`/`connection`/`upgrade`/`transfer-encoding`/`proxy-*` 头。
- **代理必须注入** `X-Palink-User-Id`/`X-Palink-Username`/`X-Palink-Is-Admin`/`X-Palink-Character-Id`/`X-Palink-Session-Id`/`X-Palink-Branch-Id`/`X-Palink-Model` 头。
- `/st/css/user.css` 必须返回空 CSS（避免前端启动噪音）。
- **Nginx 缓存策略**：JS/CSS 用 `no-cache, must-revalidate`（非 `max-age=31536000, immutable`）；hash 正则必须匹配 Vite base64（含 `[a-zA-Z0-9_-]+`）。
- `GET /api/plugins/runtime/config` 必须用 `get_admin`（非 `get_current_user`，防管理员配置泄露给普通用户）。
- **iOS WebApp 模式**：`body` 用 `overflow:hidden; position:fixed; top:0; left:0; width:100%; height:100%` + `html{overflow:hidden}` + `#root{height:100%}`（防页面滚动）。
- **iOS WebApp 模式**：Input 元素的 `bottom` 定位必须用 `var(--palink-dock-height)`（非 `keyboardHeight`，避免虚拟键盘出现时双重偏移）。
- **iOS WebApp 模式**：`apple-mobile-web-app-status-bar-style` 必须 `black-translucent`（全屏模式）+ `env(safe-area-inset-top)` padding（保证交互元素在安全区）。
- **ST vectors** 数据存 `conversation_memories` 表，`session_id="st-vec::<集合ID>"` 前缀隔离普通记忆。
- 检测到 ST vectors 扩展（存在 `st-vec::` 数据）时，Palink memory 模块跳过注入避免双重记忆冲突（`MEMORY_ST_YIELD=false` 可配置）。
- `/api/settings/save` 必须对 `extension_settings` 做 namespace 级合并（防保存时覆盖其他插件设置）。
- **前端容器**必须依赖后端 `service_healthy` 条件（非 `service_started`），确保后端就绪后再启动前端。
- **后端 healthcheck** 必须含 `start_period: 180s`（Python ML 库加载慢，fastembed/numpy）+ `interval: 15s` + `retries: 8`。
- **前端容器端口**必须绑 `127.0.0.1`（如 `127.0.0.1:3000:8080`），避免 Windows 权限问题导致端口映射失败。
- 避免用 9000 端口（Windows 上可能被占用）。
- **Galgame 插件**需 `getContext()` 返回 `characterId` 和 `name2`，`window.this_chid` 需设置，才能正确识别角色。
- **Galgame 插件状态**必须在每次注入前清理（localStorage `galgame-ui-plugin_char_enabled` 重置），防残留状态导致的自动启用 overlay。
- **角色聊天 AI 回复**必须显示头像、角色名、`.mes_text` 容器（ST 原版默认消息样式）。

### 15.2 Engineering Conventions（工程规范）

- **Chat 页 TopBar**（ChatViewMobile.tsx / ChatHeader.tsx）：`backdrop-blur(16px) saturate(160%)` + 渐变 `(to top, rgba(base,0) 0%, rgba(base,0.08) 25%, rgba(base,0.25) 50%, rgba(base,0.45) 75%, rgba(base,0.70) 100%)`，实现底部全透明→中部60%→顶部30%透明。
- **SettingsView header**：`backdrop-blur(26px)` + mask-image 渐变 `(to top, rgba(0,0,0,0) 0%, rgba(0,0,0,1.0) 22%, rgba(0,0,0,1.0) 100%)` + background 渐变 `(to top, rgba(base,0) 0%, rgba(base,0.40) 55%, rgba(base,0.80) 100%)`，实现底部全透明→中部60%→顶部20%透明。
- **移动端底部按钮 padding**：`navHeight + 32`（tailwind 阶梯：≤80→pb-20，≤112→pb-28，≤144→pb-36，else→pb-44）。
- **Header 绝对定位**：SettingsView z-20 / Chat z-18，浮于内容上方，内容可从背后穿过。
- **内容区 paddingTop 最小**（仅 safe-area 8px），首元素前加 spacer div（随内容滚动），确保内容进入 header 覆盖区。
- **ChatViewMobile header 高度**：`calc(env(safe-area-inset-top) + 3rem + 8px)`，top padding `calc(env(safe-area-inset-top)+4px)`，bottom padding `pb-1`（4px），保证按钮垂直居中不溢出。
- **ChatHeader（角色聊天）**：与 ChatViewMobile `#mobile-chat-top-bar` 同高、同毛玻璃参数、同 content padding、同按钮尺寸。
- **ChatHeader 按钮**：`!h-10 !w-10` + `rounded-full`（左）或 `rounded-[24px]`（右），保证统一 40px。
- **PresetSelector**：chat header 不再放压缩触发按钮（避免布局冲突）。

### 15.3 Lessons Learned（经验教训）

- Docker Compose healthcheck 设置会覆盖 Dockerfile `--start-period` 参数，配置不当导致容器过早重启。
- Layer cache / vite 内部缓存可能导致 Docker build 不更新 chunk hash，需手动清缓存 + 本地构建验证。
- spacer 高度过高（60~68px）会使内容进不了 header 覆盖区，毛玻璃失效（修到 18px/20px/0.25rem）。
- `backdrop-filter: blur()` 对纯色/径向渐变背景**无视觉作用**（无法区分相同背景色）。
- Docker 只要一个端口绑定失败，会放弃该容器**所有**端口映射。
- mask alpha 与 background alpha 相乘；mask 应在 22% 高度达到 1.0，避免削弱顶部背景透明度。
- 定位元素（`absolute z-0` 毛玻璃层）会盖住静态元素（按钮），需给按钮容器设 `relative z-10`。
- `Button size="icon"` 默认类会被 Tailwind 内部 `data-size="icon"` 规则覆盖，需 `!important` 修饰强制自定义尺寸。
- Galgame 插件 `getCurrentCharKeyAliases()` 缺 `characterId`/`this_chid`/`name2` 时回退 `["default"]`，导致 localStorage `galgame-ui-plugin_char_enabled` 意外激活 overlay。
- 角色聊天 AI 回复走 FramelessContent 分支（isHtmlOrCard=false）时缺头像/角色名/`.mes_text`，违反 ST 原版默认样式。

## 十六、本次会话详细技术笔记（角色卡面板插件）

### 16.1 角色卡「我被猫娘包围了！」tavern_helper 结构
- 角色卡 `extensions.tavern_helper` 含 2 个脚本：
  - **script[0] `变量结构`**（enabled）：`registerMvuSchema(z.object({...}))` 定义 schema。字段：
    - `世界信息`：日期时间/天气/风力/地点
    - `桃汐`：好感度(0-100,默认50)/关系(默认'青梅竹马')/性欲值(0-100,默认20)/服饰/内心想法/发情期
    - `苏小兰`：好感度(默认20)/关系(默认'邻居')
  - **script[1] `MVU`**（enabled）：导入 `https://.../MagVarUpdate/artifact/bundle.js`（解析 AI 回复 `<UpdateVariable>` 标签更新 stat_data）。
- schema 脚本是 **ESM**（含 `import { registerMvuSchema }`），会被 `isEsmModule()` 跳过。

### 16.2 三个未解决阻塞点（当前主线）
1. **前端未实现 `registerMvuSchema` / `registerVariableSchema` 兼容逻辑**——插件无法读取 schema 生成面板。
2. **`CharacterCardRenderer.tsx` 的 `getContext()` 覆盖冲突**——它（L3187）覆盖 `window.SillyTavern.getContext`，返回的 context 缺顶层 `stat_data` 和完整 `character.extensions`（L2825 characters 只有 `extensions: ctx.characterExtensions`，结构不完整），可能覆盖 `sillyTavernPluginRuntime.ts` 已设置好的值。
3. **schema 脚本是 ESM**，被 `isEsmModule()` 跳过，schema 未注册。

### 16.3 建议实现方案（兼容逆向渲染器）
- 在 `sillyTavernPluginRuntime.ts` setup script 注入 `window.registerMvuSchema` / `window.registerVariableSchema`，拦截角色卡 schema 脚本的 `registerMvuSchema(z.object({...}))`，解析并存储 schema。
- 用 `backend/mvu_engine.py` 的 `extract_schema_defaults` 思路（正则解析 zod）在前端生成面板 HTML。
- 解决 ESM 跳过：剥离/转换 `import`/`export` 行，或先定义 `window.registerMvuSchema` 再执行（去 import/export）。
- 统一 `getContext`：确保 `CharacterCardRenderer.tsx` 与 `sillyTavernPluginRuntime` 的 `getContext()` 都完整暴露 `stat_data` 和 `character.extensions`。
- 面板渲染：按 schema + stat_data 生成 HTML 面板，注入 `.mes_text` 或消息容器。

### 16.4 本次会话已完成的数据接线（勿重复）
1. `sillyTavernPluginRuntime.ts`：`getContext()` 暴露 `character.extensions` 和 `stat_data`。
2. `CharacterChat.tsx`：`stContext` 传 `selectedCharacter.extensions` 和 `sessionVariables.stat_data`。
3. `runtime.ts`：`StCharacter.extensions`、`StContext.stat_data` 接口补充。
4. 后端 `_import_tavern_helper` 合并角色卡 tavern_helper 脚本为单个 IIFE 入口。
5. 后端 `mvu_engine.py` 完整实现（schema 解析 + stat_data 合成 + patch 应用），有测试覆盖。
