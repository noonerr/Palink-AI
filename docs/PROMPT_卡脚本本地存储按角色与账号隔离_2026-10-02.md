> 用法：整段复制给施工 agent。配套详规见 `docs/SPEC_卡脚本本地存储按角色与账号隔离_2026-10-02.md`。

## 任务

修一个数据隔离缺陷：角色卡自带脚本写在本机浏览器里的状态（CG 立绘解锁、图鉴面板位置等）**不带任何角色标识**，导致删卡重导、同名多卡、同浏览器多账号之间互相污染。

要达到的口径（用户原话）：**这玩意跟着卡的 ID 走，卡的 ID 跟着用户走。**
即：换卡不污染 → 换账号不可见 → 换设备能带走。

## 施工顺序

1. **P1** 角色身份改用 UUID 确定性派生（最小最独立，先落）。要求：返回 number、**≠0**、跨会话跨设备稳定、两处重复实现收敛成一个共用函数。
2. **P0** 裸 `<script>` 通道的 localStorage 命名空间。走 SPEC §5「路线甲：源码改写」，**不要走全局劫持（路线乙）**。必须覆盖 `localStorage` / `sessionStorage` / `window.localStorage` / `topWin.localStorage` / `parent.localStorage`。改写不确定的分支一律放行原样并打点，**绝不让卡脚本抛错**。
3. **P2** 服务端落库：新表 `character_plugin_storage`（`character_id` + `user_id` + `ns` + `key`，`UNIQUE(character_id, ns, key)`），端点复用现有认证依赖，越权返 **404 不返 403**。前端本地永远先命中，同步失败**必须静默降级**为纯本地。
4. **迁移**：新键读不到时回读一次旧全局键，命中则写入新键并删旧键。**同名多卡的旧键无法判断归属** → 只迁给该用户最近对话的那张卡，其余视为未解锁。此规则写进 PR 描述。
5. 顺带修 `expressions.py` 的名字查隐患。
