## 2. S-2 收口方案与理由

### 2.1 选了 (a)：直接删掉帧侧回落

`SmartCardCompatController.ts:2053-2058`：

- 删除 `payloadContext` 解析与 `{ ...context, sessionId: context.sessionId || payload.__palinkContext?.sessionId }`；
- 改为 `const requestContext: SmartCardCompatRequestContext = context;` —— dispatcher 里**再没有任何帧侧键**进入会话解析。

**理由（S-1 表就是判据）**：

1. **没有任何动作依赖帧提供会话**。合法帧的 `__palinkContext.sessionId` 来自宿主注入的 ctx，
   与宿主 `selectedSession.id` 同源（§1.1 第 4 条）；宿主没有会话时，合法帧的值是空，非空只可能是伪造。
2. 三类受影响动作在"宿主无会话"时都有明确的无会话语义：
   - 世界书绑定 / 改名：本来就需要一份对话，返回 `no_active_session` / 抛错是正确结果；
   - `generateRaw` / `generateQuietPrompt`：后端 `SmartCardGenerateRequest.session_id` 是
     `Optional[str] = None`（`backend/app/api/character_ext.py:4231`），空会话可正常生成
     （`raw` 本来只读 prompt；`quiet` 不读历史）。
3. 删回落比"打标后再逐个拒绝"更彻底：不会留下"某个新动作忘了检查 `sessionIdFromFrame`"的缺口。
4. 与预设面 P2 的口径完全一致，避免两条会话信任规则并存。

### 2.2 单一解析函数（全链同口径）

新增 `resolveSmartCardHostSessionId`（`SmartCardCompatController.ts:287-309`）：

```ts
function resolveSmartCardHostSessionId(context): string {
  const raw = context?.selectedSession?.id ? String(context.selectedSession.id) : '';
  return raw === '__pending__' ? '' : raw.trim();
}
```

- 只读宿主构造的 `selectedSession`；`__pending__` 视为"还没有会话"。
- 明确不读：`payload.__palinkContext.sessionId`、`payload.sessionId`、`context.sessionId`。
- 原预设面私有实现 `resolveSmartCardPresetSessionId` 已删除，`fetchSmartCardSessionPreset` 改调本函数
  （`SmartCardCompatController.ts:1024-1031`），全仓只剩**一份**会话解析。

## 6. 否证主脑

**结论：没有发现"某个动作确实必须信任帧提供的会话"，不需要停下回报，已按施工件硬改。**

理由：

1. 合法帧的 `__palinkContext.sessionId` 不是"帧独立掌握的信息"，而是宿主渲染时注入的
   `ctx.sessionId`（`part-01.ts:553-557` / `part-a.ts:563-567`），其源头就是 `Message` 的
   `sessionId={selectedSession?.id}`。所以"删回落"在合法路径上**零信息损失**。
2. 唯一会丢失的场景是：宿主已切走/关闭会话，但旧 iframe 仍在发请求（stale frame），
   或卡伪造 payload。两种场景按用户裁定都应拒绝——旧会话不该再被这张卡碰到。
3. `generateRaw` / `generateQuietPrompt` 在无会话时仍可工作（后端 `session_id` 可选），
   不存在"必须由帧补一个会话才能生成"的调用路径。
4. 反证测试里"正向：宿主有会话"全部照旧（世界书绑定、改名、生成、预设），说明收口没有
   把正常链路打死。

**一个必须如实记录的行为变化**：改前"宿主无会话 + 帧塞 id"时，世界书绑定/改名/quiet 生成会
**静默成功**并作用到帧指的那份会话；改后分别变成 `no_active_session` / `{}` 无操作 / 不带
`session_id` 的生成。这是本批次的目的，不是回归。
