## 一、对上一轮结论的重要修正（诚实纠错）

我在上一轮汇报中断言 `escapeQuotedScriptNewlines` 是"正在生效的静默杀手 bug"。
**这个断言不准确，现予以修正。**

### 实测过程

把 `CharacterCardRenderer.tsx` L1258-1333（`escapeQuotedScriptNewlines`）与 L1361-1373
（`loosenSmartCardGlobalLexicalDeclarations`）**原样搬进 Node**，对猫娘卡真实状态栏脚本
（`tmp_statusbar.html` 内唯一 `<script type="module">`，15310 字符）执行：

```
=== 长度对比 ===
原始: 15310 | loosen后: 15310 | escape后: 15310
真实换行数  原始: 324 -> 处理后: 324 | 被吃掉: 0

=== 语法校验（经典脚本语义） ===
[原始脚本] 语法 OK
[loosen后] 语法 OK
[escape后(最终进iframe)] 语法 OK

=== // 注释中含引号的行 ===  合计: 0
=== 正则字面量中含引号 ===   合计: 0
```

### 修正后的结论 ✅ 实证

- 该 bug **客观存在**（解析器确实不识别 `//` 注释与正则字面量），但**对当前这张猫娘卡未触发**——
  脚本里恰好没有含引号的 `//` 注释，也没有含引号的正则字面量。
- 它是**潜在缺陷**，会在其他角色卡上爆发，**但不是当前"好感度为空"的原因**。
- 因此它的优先级应从 P0 降为 **P1（防御性修复）**。

> 这条修正很关键：如果按我上一轮的建议优先去动 sandbox 架构，会在**没有解决用户实际问题**
> 的前提下引入大面积改动风险。

### 2.3 真正的根因：数据链三处断点 ✅ 实证

脚本 L91-96 的取数逻辑：
```js
var vars = getAllVariables();
var stats = _.get(vars, 'stat_data', {});
worldData.date = _.get(stats, '世界信息.日期时间', '');
```

`getAllVariables()` → `clone(allVariables)`（L3026）
→ `allVariables` 源自 `defaultVariables = ctx.variables`（L2597）
→ `ctx.variables` 来自 `buildShim(bootContext)`（L4611）

**断点 #1 — `bootContext` / `liveContext` 丢弃 `variables` 字段** ✅ 实证

我逐行读了 L4509-4531（`liveContext`）与 L4567-4589（`bootContext`）两个 useMemo 的
完整对象字面量，**两者都逐字段列举，均无 `variables` 一项**。
而 `buildShim` L2205 明确读 `context.variables`。
→ 数据在此被 **100% 丢弃**，`getAllVariables().stat_data` 恒为 `{}`。

**这是"好感度为空"的第一根因。**

**断点 #2 — `CharacterChat.tsx` 取值路径错误** ✅ 实证

```ts
// CharacterChat.tsx:661-662
if (!cancelled && res?.data?.variables) {
  setSessionVariables(res.data.variables);
```
但 `api.get` 不是 axios，`services/api.ts:212-215` 明确 `return data`（body 本身）：
```ts
const promise = request<T>(url, {...}).then((data) => {
  if (ttl && genAtStart === _cacheGeneration) _setCache(key, data, ttl);
  return data;      // ← 直接返回 body，没有 .data 包装
})
```
→ `res.data` 恒 `undefined` → `setSessionVariables` **永不执行**（死代码）。

**断点 #3 — WebSocket 不消费 `variables`** 🔍 读码确认

后端 `websocket.py:867-872` 已在 `final_content` 事件中带上 `variables`，
但前端 `useChatWebSocket.ts:207-211` 只透传 `content` 与 `message_id`，`variables` 被丢弃。
→ 一轮对话结束后面板**不会实时刷新**。

### 2.4 CSP 约束（新发现，影响方案选型） ✅ 实证

`frontend/nginx.conf:39` 与 `frontend/vite.config.js:91` 定义了 CSP：
```
default-src 'self';
script-src 'self' 'unsafe-inline' 'unsafe-eval' blob:;
frame-src 'self' http://localhost:8000 http://127.0.0.1:8000 http://localhost:8001 http://127.0.0.1:8001;
```

三条关键推论：

1. `script-src` 含 `'unsafe-inline'` → **内联脚本（含 module）在 iframe 内允许执行**。
2. CSP 策略里**没有声明任何 `nonce-` 源**。因此现有代码给脚本加
   `nonce="palink-smart-card"` 属性**既无害也无用**（有 nonce-source 时才会禁用
   `unsafe-inline`，这里没有）。
3. `frame-src` **不含 `blob:`** → **不能**照搬 JS-Slash-Runner 的 blob URL 方案，
   只能用 `srcdoc`。（srcdoc iframe 按 CSP3 不走 `frame-src` 检查，安全。）

### 2.5 参照实现（JS-Slash-Runner）的做法 🔍 读码确认

- iframe **完全不设 sandbox**（`src/panel/render/Iframe.vue:1-12`，全仓 grep 零命中，dist 亦零命中）
- 默认 `srcdoc`，blob 为可选项
- `predefine.js` 直接赋值父页面引用桥接（`window._ = window.parent._`），**零 postMessage**
- 对 `type="module"` **零转换**——靠同源让 module 天然执行
- 高度同步：iframe 内 `ResizeObserver` → 直写 `frameElement.style.height`

## 四、方案选型

### 方案 B+（推荐）：数据优先，架构后置

分四阶段，**每阶段独立可验收、独立可回滚**：

```
阶段 0  验收现状（不改代码）        ← 强制前置，否则不动手
阶段 1  修数据链 P0（3 个文件，~10 行）  ← 直接解决"好感度为空"
阶段 2  修潜在 bug P1（2 个函数）        ← 防御其他角色卡
阶段 3  清理 P3（日志 + 废弃文件）        ← 零风险
阶段 4  架构对齐 P4（去 sandbox，可选）   ← 需用户明确接受安全取舍
```

**推荐理由**：
1. 阶段 1 改动极小（约 10 行），直击用户实际痛点，风险最低。
2. 阶段 4 是**大面积架构改动**（需删降级/转义/loosen 三件套、重写桥接、改高度同步），
   在阶段 1 未验证前做，会让"到底哪一步修好了"无法归因。
3. 阶段 4 涉及**安全模型变更**（卡片脚本获得与宿主同权），必须用户明确拍板。

### 方案 A（备选）：直接架构对齐

一次性去 sandbox + 删三件套 + 重写桥接。
**优点**：一劳永逸贴近参照。
**缺点**：改动面大、安全模型变更、无法归因、且**不解决数据链断点**
（去 sandbox 后 `getAllVariables()` 照样返回空——因为 P0-1 还在）。

> ⚠️ 重点：**方案 A 单独执行并不能修好好感度**。数据链断点与 sandbox 无关。

### 阶段 2 · 修复潜在 bug（P1-2 / P1-3）

#### 2.1 `escapeQuotedScriptNewlines`（L1258-1333）

**问题**：状态机只跟踪引号，不识别 `//` 行注释、`/* */` 块注释、正则字面量。
**触发条件**：脚本中 `//` 注释含奇数个引号字符（如 `don't`）。
**后果**：解析器误入字符串态 → 后续所有换行被转义为字面量 `\n` → `//` 注释永不结束
→ 余下代码被整段静默注释掉，**无任何报错**。

**改法（二选一，倾向 A）**：
- **A（推荐，最小风险）**：在状态机中补充三种状态识别——`//` 行注释（遇真换行结束）、
  `/* */` 块注释、正则字面量（需前瞻判断除法 vs 正则，可用"前一个非空白 token 是
  `( , = : [ ! & | ? { } ; return typeof` 之一"启发式）。
- **B（更彻底）**：评估这个函数是否还有存在必要。它的初衷是修复"字符串中出现真实换行"
  （JS 语法错误）。但若 HTML 进入 iframe 前未被破坏换行，此函数可完全移除。
  ⚠️ 需先查明当初为何引入——**建议先加日志观测线上是否真有脚本被它改动**
  （实测本卡改动量为 0）。

**验证**：构造含 `// don't do this` 注释的测试脚本，跑 Node 复现，确认处理后语法仍合法、
换行数不变。**沿用我本次的 `verify_bug.cjs` 脚本作为回归测试。**

#### 2.2 module 降级正则（L1351）

**问题**：
```js
!/(^|[^.\w$])import\s*[<(]|[^.\w$]export\s+[{(*]|import\s+[\w*{]|export\s+default|import\.meta/i
```
漏判 `export const` / `export let` / `export function` / `export class` / `import "x"`（副作用导入）。
这些脚本会被**错误降级**为经典脚本 → `SyntaxError` 整段不执行。

**改法**：改为按**行首**匹配 ESM 语句：
```js
/^\s*(import\b|export\b)/m
```
配合排除字符串/注释内的误匹配（或直接用更保守的策略：只要出现 `^\s*export\b` 或
`^\s*import\b` 就**不降级**）。

**权衡**：不降级 → 在 sandbox 下 module 不执行 → 面板脚本不跑。
所以**含 import/export 的卡片在 sandbox 架构下本质无解**，只能靠阶段 4。
本阶段的修复意义是：**把"静默错误降级导致 SyntaxError"变为"明确不降级"**，
并**应加一条控制台告警**提示该卡需要 trusted 模式。

#### 2.3 `loosenSmartCardGlobalLexicalDeclarations`（L1361-1373）⚠️ 待评估

硬编码 5 个变量名白名单（`State`/`GameState`/`CardState`/`CHARACTER_COLORS`/`WEATHER_ICONS`）。
module 降级后顶层 `const`/`let` 泄漏到全局，同 iframe 内重复执行会 `already declared`。
但**每次 iframe 重建都是全新 window**，实际冲突概率低。

### 阶段 4 · 架构对齐（P4，可选，需用户明确拍板）

**仅在用户明确接受安全取舍后执行。**

#### 4.1 安全模型变更说明（必须用户知情同意）

去掉 sandbox 后，角色卡脚本与宿主页面**同权**：
- 可读写 `localStorage`（含用户 token）
- 可发同源请求（携带 cookie）
- 可操作父页面 DOM

JS-Slash-Runner 的隐含前提是「用户自己导入的卡 = 受信任代码」。
**Palink 若面向多用户分发卡片，这是产品级决策。**

**缓解方案**：复用已有的 `writeSmartCardTrustGrant` / `trustedNative` 机制
（L5075-5076），改为"首次渲染前弹信任确认，仅受信卡片去 sandbox"。
即：**默认仍 sandbox，用户显式授信后才同源**。这是我推荐的折中。

#### 4.2 技术改动清单

| 项 | 改动 |
|---|---|
| L5080-5084 | sandbox 计算：受信卡片返回 `undefined`（不输出属性） |
| L5162 / L5305 | `sandbox={sandbox}` → 条件渲染，`undefined` 时不传 |
| L1349-1354 | 受信路径跳过 module 降级 |
| L1355 | 受信路径跳过 `escapeQuotedScriptNewlines` |
| L1361-1373 | 受信路径跳过 `loosen`（module 有独立作用域） |
| nonce 相关 | 可保留（当前 CSP 无 nonce-source，无害） |
| 桥接 | 新增 predefine 等价脚本，直接赋值父引用替代 postMessage |
| 高度同步 | 改为 iframe 内 `ResizeObserver` 直写 `frameElement.style.height` |

#### 4.3 CSP 前置约束 ✅ 实证

- ✅ `script-src` 含 `'unsafe-inline'` → 内联 module 脚本可执行。
- ❌ `frame-src` **不含 `blob:`** → **不能**用 blob URL，**必须**用 `srcdoc`。
- 若后续要引入 blob 桥接脚本（`<script src="blob:...">`），需先在 nginx.conf 与
  vite.config.js 的 `script-src` 中确认 `blob:` 已存在（**当前 `script-src` 确实有 `blob:`**，
  所以 blob **脚本**可以，只是 blob **iframe** 不行）。

#### 4.4 风险

- 改动面大（涉及 srcdoc 组装、桥接、高度同步三大块）
- 需要同时维护 sandbox / 同源两条路径（若采用折中方案）
- 回滚成本高 → **建议单独开分支，独立验收**

## 十一、已批准决策（2026-08-05，用户拍板）

- **Q1 方案选型**：用户关注"对其他插件的兼容性"。结论——**去沙箱对齐 JS-Slash-Runner 兼容性更好**（沙箱 + module 降级对含 `import`/`export` 的 ESM 脚本与含引号 `//` 注释的脚本有硬伤 P1-2/P1-3）。但去沙箱**不解决好感度**（P0-1 仍在），故**数据链修复（阶段1）为共同必做前置**。
- **Q2 阶段4**：用户选择 **执行 + 全量去沙箱**（已知风险：卡片脚本与宿主同权）。合成方案 = 阶段1（数据链）→ 阶段4（全量去沙箱 + 删降级/转义/loosen 三件套 + predefine 式桥接）。阶段4 删除有 bug 的降级/转义代码后，P1-2/P1-3 自然消除，阶段2 不再单独执行。
- **Q3 废弃文件**：用户选择 **保留作降级兜底**（`mvuSchemaParser.ts`/`TavernHelperPanel.*` 标 `@deprecated` 观察，仅删 `Message.tsx.bak`）。
- **安全提示**：全量去沙箱在面向多用户分发不可信卡片时为产品级风险；如需可改回"仅受信卡片去沙箱"。
