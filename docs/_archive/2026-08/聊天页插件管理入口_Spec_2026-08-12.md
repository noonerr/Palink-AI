## 1. 背景

### 1.1 现有插件管理入口
- **设置页 `/settings` → 插件管理标签页**：全局管理（安装/卸载/启用/禁用），组件 [AdminPluginsTab.tsx](file:///d:/项目/Palink-AI/frontend/src/components/views/settings-tabs/AdminPluginsTab.tsx)
- **全屏插件管理器对话框** [PluginManager.tsx](file:///d:/项目/Palink-AI/frontend/src/components/roleplay/PluginManager.tsx)：可在聊天页中独立打开，包含列表、安装、卸载、启用/禁用、设置面板等功能
- **聊天页右下角三点菜单** [ChatMoreMenu.tsx](file:///d:/项目/Palink-AI/frontend/src/components/views/character/chat/ChatMoreMenu.tsx)：当前菜单已包含参数设置、预设管理、世界书、剧情线、对话模式、角色状态、ST预设/ST正则导入、记忆、删除等，过于杂乱

### 1.2 目标
在 ChatMoreMenu 中新增「插件管理」入口，点击打开现有 PluginManager 全屏对话框；同时将 ST 预设导入/ST 正则导入从主菜单收纳到「插件管理」概念下（收进二级菜单或作为插件管理对话框的一部分推出）。

---

## 2. 修改方案

### 2.1 ChatMoreMenu.tsx

#### 2.1.1 新增 props

在 `ChatMoreMenuProps` 接口中新增：

```ts
// 插件管理
onShowPluginManager: () => void;
```

#### 2.1.2 插件管理菜单项

在 `DropdownMenuContent` 中，**ST 预设/ST 正则区域之前**（约 L206 之后），插入新的菜单项：

```tsx
{/* 插件管理 */}
<DropdownMenuSeparator />
<DropdownMenuItem onClick={onShowPluginManager}>
  <Puzzle size={14} className="mr-2" />
  插件管理
</DropdownMenuItem>
```

- 图标：`Puzzle` 从 `lucide-react` 导入
- 点击行为：调用 `onShowPluginManager`（父组件控制打开 PluginManager 对话框）

#### 2.1.3 移除 ST 预设/ST 正则导入

从 L207~L309 完全移除以下区块：
- 「ST预设」导入区域（L207~L250）
- 「ST正则」导入区域（L252~L309）
- 对应的两个 `<DropdownMenuSeparator />`（L207、L252）
- 对应的 `presetFileInputRef`、`scopedRegexFileInputRef`、`presetRegexFileInputRef` refs 声明（L109~L111）
- 对应的 props 类型声明（`presetImporting`、`regexImporting`、`hasPresetData`、`onPresetFileSelect`、`onRemovePreset`、`onScopedRegexFileSelect`、`onPresetRegexFileSelect`）

**注意**：这些功能不是删除，而是从 ChatMoreMenu 移除，**由 PluginManager 对话框接管**。PluginManager 内部已有导入入口（`handleInstall`），因此 ST 预设/正则导入功能在 PluginManager 中仍可通过安装扩展方式使用。若需要保留独立导入入口，可在 PluginManager 底部附加导入按钮，但非本次 spec 范围。

#### 2.1.4 精简 import

- 移除 `FileText`、`Upload` 的 `lucide-react` 导入（如果不再被其他组件使用）
- 新增 `Puzzle` 导入

### 2.2 CharacterChat.tsx（父组件）

#### 2.2.1 新增状态

```ts
// 插件管理对话框
const [pluginManagerOpen, setPluginManagerOpen] = useState(false);
```

#### 2.2.2 回调传递

在 `ChatMoreMenu` 的 props 中新增：

```tsx
onShowPluginManager={() => setPluginManagerOpen(true)}
```

#### 2.2.3 渲染 PluginManager

在 `CharacterChat` 的 JSX 中（与聊天区域同级），新增：

```tsx
<PluginManager
  open={pluginManagerOpen}
  onClose={() => setPluginManagerOpen(false)}
/>
```

- 确保 `PluginManager` 在文件顶部已导入
- 导入路径：`import { PluginManager } from '@/components/roleplay/PluginManager'`

#### 2.2.4 精简 ChatMoreMenu 传入的 props

从 `ChatMoreMenu` 的 props 传递中移除已被移除的 props：
- `presetImporting`
- `regexImporting`
- `hasPresetData`
- `onPresetFileSelect`
- `onRemovePreset`
- `onScopedRegexFileSelect`
- `onPresetRegexFileSelect`
- 对应的相关 state（若有）

## 4. 数据流

```
用户点击三点按钮 → ChatMoreMenu 弹出
  → 点击「插件管理」
    → 调用 onShowPluginManager()
    → CharacterChat: setPluginManagerOpen(true)
    → 渲染 <PluginManager open={true} />
    → 用户管理完毕后点击关闭
    → onClose() → setPluginManagerOpen(false)
```

1. `cd frontend; npx tsc --noEmit`（类型检查无新增错误）
2. `cd frontend; npm run build`（构建成功）
3. `docker compose up -d --build frontend`（重启前端容器）
4. 浏览器验证：
   - 打开角色扮演对话
   - 点击右下角三点菜单
   - 确认「插件管理」菜单项出现
   - 确认原有 ST 预设导入/ST 正则导入已移除
   - 点击「插件管理」，弹出 PluginManager 全屏对话框
   - 确认对话框可正常关闭
   - 确认其他菜单项功能不受影响（参数设置、预设管理、世界书等）

## 6. 风险与回退

- **risk**: 移除 ST 预设/正则导入后，用户可能找不到入口
  - **mitigation**: PluginManager 对话框的安装入口（URL 输入+安装按钮）可接受 ST 扩展 URL；若需保留独立导入，可后续在 PluginManager 底部加「导入预设/正则」按钮
- **risk**: `ChatMoreMenu` 移除 props 后，CharacterChat 中忘记移除对应的 props 传递 → tsc 会报错，构建失败
  - **mitigation**: 确保 `npm run build` 通过后再部署
