## 4. §3 三条实测结论（成立/不成立，各附读数）

### 4.1 两张不同卡的 localStorage / IndexedDB 互相读不到 —— **在卡的正常 API 面成立；同源旁路面不成立**

| 面 | 结论 | 读数（`q1-local-unlock-isolation.test.ts`） |
|---|---|---|
| localStorage 桶 | **成立** | 写卡 A 桶后，卡 B 读同物理 localStorage 得 `{}`；键名各含自己的 `cardId`；A 的键只有 1 条、不含 `card-b`。两卡写同名键（`好感度`）互不覆盖 |
| sessionStorage | **成立** | 同上；且 local/session 两套柜子互不串 |
| IndexedDB | **白名单库成立 / 共用库不成立** | `BubbleDialogueAvatars` 两卡库名不同（`…__card-a` vs `…__card-b`）；**非白名单库**（如 `GalgameUIPluginDB`）两卡库名**相同** ⇒ 共用（这是既有口径：一刀切会打断 Live2D） |
| 同源旁路 | ⚠️ **不成立（命名空间不是边界）** | 同源后卡可走 `window.frameElement.ownerDocument.defaultView.localStorage` 绕过 shim 直接读父站真存储，按 key 就能读到**别的卡的桶**。这是机制事实（同源 ⇒ 可达 DOM ⇒ 可达 `defaultView`），非推断出的"可能" |

⇒ 按执行件 §3.3 的口径：**第 1 条在"卡正常用 `window.localStorage`"这一层成立，在"卡故意绕过 shim"这一层不成立**。

## 8. 与本件描述不一致的地方 / 否证主脑

### ⚠️ 否证 1：放开同源**并没有**让卡"直接用真 localStorage/IndexedDB"

执行件 §0 与 SPEC §2.4 都写"真实收益在**存储通道**……给同源后卡能直接用真 localStorage/IndexedDB"。
**实测不成立**：帧内存储 shim 与 IDB 内存垫片的开关是 **`ctx.trustedNative`**，不是 sandbox 属性：

- `runtime-body/part-01.ts:600-606`：`if (!ctx.trustedNative) { Object.defineProperty(window,'localStorage', …makeCompatStorage…) }`
- `frame-shim/legacy-st-sim-parts/part-a.ts:541-546`：同一条件装 `memoryStorage`
- `CharacterCardRenderer.tsx:373/:446`：`ctx.trustedNative` 取的是 **React state `trustedNative`**，本机档**不改它**

⇒ 本机放开后，卡拿到的仍是**按卡桶 shim**（隔离反而更稳），"真 localStorage/IndexedDB"这条**没有发生**。
本批**只放开了 DOM 读取面**（`retrieveDisplayedMessage` 能用就是证据），存储面零变化。
要不要把 shim 的开关改成"是否同源"，是**另一包的口径决定**（会同时动隔离面、IDB 垫片、以及
"卡数据要不要跨卡可见"的语义），本批不动。

### ⚠️ 否证 2：卡间隔离的边界比执行件预期的更薄

执行件 §3 期望"两张不同卡的 localStorage / IndexedDB 互相读不到"能作为放开的**充分条件**。
**在卡的正常 API 面成立，在安全意义上不成立**：同源后卡可经
`window.frameElement.ownerDocument.defaultView.localStorage` 绕过 shim，直接读父站真存储里的
**所有卡的桶**（key 里就带 `cardId`）。命名空间是命名，不是隔离墙。
⇒ 请主脑定口径：(a) 接受"防的是误伤不防恶意卡"，(b) 把卡存储搬出 localStorage（IDB + 每卡独立库/Worker），
(c) 只在本机档放开但加 CSP/权限边界。本批按指令**不加层**。

1. **返回值 `null` vs ST 的"空 JQuery"**：执行件 Q1-3 两处都写"读不到就诚实返回 `null`"，
