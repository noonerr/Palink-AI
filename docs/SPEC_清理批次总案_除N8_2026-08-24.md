## §1 批次 A：ST 世界书与示例域兼容债（7 子项）

### A1 useProbability 接线（D-4/a-2）

**现状**（worldbook_service.py 实证）：L926 `prob = entry.probability if ... else 100`
只看 probability 值就滚动——**条目级 `useProbability` 开关全线缺失**（DB 列/导入映射/
扫描判定均无）。ST 语义：`useProbability=false` 时无视 probability **必现**；
true 时按 probability% 滚动。

**改动**：
1. DB 列：WorldBookStage 加 `use_probability Boolean default true`（迁移模式照抄
   既有 ADD COLUMN 先例；PG IF NOT EXISTS + SQLite 判列）；导入映射两侧补齐
   （api/worldbook.py 导入端点 + silly_tavern.py 对齐路径若存在同映射则**只读不改**，
   发现必须改 silly_tavern.py 时停止上报）
2. 扫描判定 L926：`use_probability=False → 视为 probability=100 必现`；
   true → 现行滚动逻辑不变
3. 报告/调试字段顺带带出该开关状态

**测试**：useProbability=true 按 % 滚动（回归）；false 必现（新增）；导入往返保真。

### A2 mes_example `<START>` 拆块移植到 palink-native（B-2/D-3 合并）

**现状**：拆块逻辑只存在于 st-compat 函数族（character_message_builder.py:421-432），
palink-native 路径（:144-147 附近）把示例整条单注入。

**改动**：将 `<START>` 分隔的示例对话组织语义移植到 `build_character_chat_messages`
的示例注入段（对齐 st-compat 行为：多组示例对话按 ST 方式呈现）。**红线：不得修改
`build_st_compat_messages` 函数体本身**（封存函数族原样保留）。

**测试**：含多组 `<START>` 的 mes_example 在 palink-native 装配产物中的形态断言；
无示例/单组回归。

### A3 prevent_recursion 语义修正（D-3/b-4）

**现状**：worldbook_service.py:733-742 递归轮把 prevent_recursion 条目**整条跳过**。
**ST 语义**：该标记只表示"本条目内容不进入其他条目的递归扫描 buffer"，条目本身
正常激活注入。

**改动**：递归扫描时将 prevent_recursion 条目内容排除出递归匹配源，但不抑制其自身
激活与注入。同步修理由此暴露的相关契约测试（test_p1_worldbook_delay.py 等）。

### A4 WI 全局设置补接线（D-5 部分）

**现状**：roleplay_prompt_assembly.py:4585-4599 仅透传 min_activations×2 + strategy +
chat_length；`world_info_depth` 默认 4（ST 为 2）、recursive 开关固定开等不可调。

**改动**：从 WI 全局设置读取并接线剩余项——至少 `world_info_depth`（默认对齐 ST=2，
存量用户显式配置过的不受影响）、recursive 总开关；发现其他 ST 全局字段一并列表报告
（能接则接，量力标注）。

### A5 世界书百分比预算基数修正（D-6/e-2）

**现状**：build_worldbook_context 调用未传 max_context，百分比预算回退 16000。
**改动**：装配处传入真实模型上下文上限（装配内已有 effective_max_tokens/model 上限
来源，取同源值），回退值保留为最后兜底。

### A6 V3 卡独立 jailbreak 消费（B-3）

**现状**：palink-native 不消费 V3 卡自带 jailbreak/post_history_instructions
（仅 context_template.jailbreak 有处理 :329-342）。
**改动**：角色卡携带独立 jailbreak 时消费进 jailbreak 槽位（优先级：context_template >
卡片自带 > 无），与 ST prompt manager 语义一致。

### A7 creator_notes 退出 system prompt（B-5）

**现状**：default_prompts.py 把 creator_notes 拼进 system prompt，ST 不这么做。
**改动**：从三层模板拼装中移除 creator_notes 注入（ATTRIBUTE_LABELS 相应调整）；
前端展示不受影响（仅 prompt 装配层）。自查既有测试是否断言其存在并同步更新。
