## 1. T1：读完 checkpoint 列表要回填，出图前要校验（最高优先）

**现状（已核）**
- 设置页点「读取列表」只 `setModels(...)`，**不回填** `checkpoint_name`
  （`ImageGenerationTab.tsx:125-130`），下拉框 `value={activeProvider.checkpoint_name ?? ''}` 仍是空。
- 空值时三套内置模板各自回落**占位文件名**：`model.safetensors` / `flux1-dev.safetensors` /
  `qwen_image_bf16.safetensors`（`image_prompt_service.py:337-342`）。这些名字在用户机器上通常不存在
  → ComfyUI 直接报找不到模型。
- 「检测本机 ComfyUI」探针**只打 `/system_stats`**（`comfyui-client.ts:68,76`），
  它能变绿不代表能出图。
- checkpoint 清单读取已兼容 `input`/`inputs` 两种字段（`comfyui-client.ts:150-168`），可复用。

**要做**
1. 拉到列表后**自动回填**：`checkpoint_name` 为空或不在清单里 → 取清单第一项并明确提示
   「已默认选中 xxx，可换」；已有值且在清单里 → 不动。
2. 出图前校验：`checkpoint_name` 不在该设备读到的清单里 → **在派单前**返回可读错误
   （文案含"当前选中的模型名在本机 ComfyUI 里不存在，请在设置页重新选择"），
   不要等 ComfyUI 报错再回传。清单读不到时（首次/未探测）不拦，只记一条提示。
3. 家族识别随回填自动命中（启发表已在 `image_prompt_service.py:99` 等），用户不必再手选家族。

**测试**：回填三分支（空 / 值不在清单 / 值合法保留）、出图前校验拦截与放行、清单不可用时不误拦。

## 2. T2：45 秒回收与后台节流的冲突（会画两遍）

**现状（已核）**
- 任务 `dispatched` 超 `_CLAIM_TTL_SECONDS = 45.0` 未回传即回收、可被再次认领
  （`local_image_bridge.py:37` 及 `claim_pending_tasks` 的 reclaim 分支）。
- 同设备重复认领只续期不重派（`claimed_device_id` 比对）——这是上一批 R2 的成果，别破坏。
- 但浏览器把后台页定时器节流后（Chrome 常见钳到约 1 次/分钟），**心跳间隔 > 45 秒**，
  正在渲染的任务会被判失联并二次派发；provider 超时默认 120 秒（`_validate_provider` clamp 5~600），
  两者之间就是"重复出图窗口"。设备表 TTL 已取 90 秒（只用于内存清扫，不参与在线判定）。

**要做（选①，别改认领语义）**
- 把回收判定从"单看 45 秒"改为**连续两次心跳缺失**才回收：即
  `now - dispatched_at > max(_CLAIM_TTL_SECONDS, 2 × 前端轮询间隔)`，前端轮询间隔随认领请求上报
  （新增可选 query `poll_ms`，缺省按 2500 计算）；或等价地把 TTL 抬到 120 秒并注释写明理由。
- 注释里写清：这是"后台节流导致误判失联"的修复，不是负载均衡调整。

**测试**：①同设备心跳正常 → 不被回收；②心跳停一次（<2×poll）→ 不回收；③停够两次 → 可被别的设备认领；
④旧客户端不带 `poll_ms` → 行为与改动前一致（向后兼容）。

## 3. T3：安全上下文提示（几行文案）

**现状（已核）**：向导已写 CORS 启动参数（自动填 `window.location.origin`，
`ImageGenerationTab.tsx:179-180,500-501`）、已写 Safari 不支持（:505）、探针能分
`unreachable / cors_blocked / ok`（:519-524）。**缺 `window.isSecureContext` 判定**。

**要做**：非安全上下文（局域网 IP 走 HTTP）时，向导顶部给一条明确提示：
「当前是 HTTP 且非本机地址，浏览器不会允许页面访问本机 ComfyUI —— 请改用 HTTPS 域名，
或在本机用 http://localhost:3000 打开」。同时在 base_url 输入框提示里强调
**必须用 `http://127.0.0.1:8188`，不要填 `192.168.x.x`**（回环被浏览器视为可信，内网 IP 会被混合内容拦截）。

## 5. 为什么是这个顺序

家用 1~3 台算力设备时轮询折算 <1 次/秒，**不是问题**；用户回来第一次点出图必然撞上的是
"checkpoint 没回填 → 拿占位名 → ComfyUI 报找不到模型"，其次是"后台页被节流 → 同一张图画两遍"。

## 6. 本单明确不做

- **WebSocket 唤醒式派单 / 自适应退避轮询**：推迟。理由：家用规模收益近零；且后台页
  WebSocket 消息同样会被浏览器延后，唤醒式必须再配慢速兜底轮询才可靠，复杂度不值。
  若将来设备数上百再立项。
- 不改 `_validate_provider` 白名单以外的配置面；不动提示词装配链；不碰其他会话未提交文件。
