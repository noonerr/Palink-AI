## 2. 两条 P1 缺陷（主脑实机查出，两份施工报告都没有）

### 2.1 三键返回 Promise，而 ST 契约是同步
`.tmp_probe/PQ_preset_shape.js` 实测（同一帧）：

```
A=getPresetNames:type=object tag=[object Promise] thenable=true len=n/a
B=getLoadedPresetName:type=object tag=[object Promise] thenable=true len=n/a
C=getPreset:type=object tag=[object Promise] thenable=true len=n/a
AWAIT_NAMES=ok isArray=true n=0
AWAIT_PRESET=keys=extensions,prompts,prompts_unused,settings
```

权威契约一手核到：`st-plugins/third-party/JS-Slash-Runner-main/@types/function/preset.d.ts:150`
—— `declare function getPresetNames(): string[];`（**同步、返数组**）。

⇒ 真卡按 ST 写法 `getPresetNames().length` 只会拿到 `undefined`；`getPreset('in_use').prompts` 直接 `undefined`。
**这不是"还没接"，是"接成了另一种形状"**，比 D 类更难发现：卡不报错，只是拿不到东西。
为什么 24 条单测没抓到：用例 `await` 了返回值（`await` 对同步值同样成立），于是同步与 Promise 两种实现都能绿。
⇒ 修法必须把"**不得是 thenable**"写成断言，而不是断"值对不对"。

### 2.2 这三个键接的是**一张空表**，而用户界面上那份在另一张表
- 库里实测：`select count(*) from prompt_presets` = **0**；`select count(*) from generation_presets` = **27**。
- 后端实测：`GET /api/prompt-manager/presets` → `[]`（HTTP 200），
  `GET /api/prompt-manager/presets/selection` → `{"selected_name":null,…,"source":"none"}`。
- 前端实测：全仓唯一消费 `/api/prompt-manager/presets*` 的代码是**本次新加的卡片桥本身**；
  用户看得见的预设界面是 `PresetManager.tsx` / `PresetSelector.tsx`，走
  **`/api/roleplay/presets`** → `backend/app/api/presets.py:12` 的 `GenerationPreset`（另一张表）。

⇒ 包P 的覆盖层 + P2 的选中名 + P2-3 的三键，整条链**建在一张没有一行数据、也没有第一方界面的表上**。
实机表现就是 §2.1 里的 `n=0 / source=none`。

**责任在派单人**：我上一轮把 `preset_prompt` 族从"乙类 XL"改判成"只差桥、有现成落点"，依据是
"`prompt_presets` 表存在 + `/presets` 四件套存在"——**我只核了存在性，没核行数和消费方**。
这正是本仓已记过的那类可行性坑（原料够不够），第二次犯在同一件事上。已写进 §4 教训。

## 4. 教训回写（写给下一个读这份文档的人）

1. **"表存在 + 端点存在"不等于"功能可达"**。判断某个族是不是"只差桥"，必须同时核三件：
   表里有几行、哪个第一方界面在读写它、`grep` 有没有除新代码之外的消费者。三件缺一就别说"便宜"。
2. **跨帧桥接的键，验收要断"形状"而不是只断"值"**：`await` 会把同步值和 Promise 一并喂饱，
   于是"接错成异步"能一路绿到实机。判据写成 `thenable=false`。
3. **上线前先取改前基线**：不然"实机生效"这句话永远无法事后证明。本次两份探针就是干这个的。
