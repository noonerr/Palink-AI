## 3. 环境规矩（搞错会得到假结论）

- 后端全量测试**必须进容器**：`MSYS_NO_PATHCONV=1 docker exec -w /app palink-ai-backend-1 python -m pytest tests/ -q`。
  宿主机跑会静默少若干用例。容器内没有 pytest-timeout，别加 `--timeout`。
- 容器代码是**烤镜像**：改了后端代码不 `docker compose build backend && up -d` 就是测旧代码。
  容器内文件常带 CRLF，比对 `git show HEAD:<path> | md5sum` 要先 `tr -d '\r'`，否则会误判"容器不是这份代码"。
- `:3000` 是 nginx 挂 `frontend/dist` 的**构建产物**，不是 dev server；改前端不 build 页面永远不变。
- `RUN_MIGRATIONS_ON_STARTUP=false`：**alembic 不会自动跑**，新迁移要手动
  `docker exec palink-ai-backend-1 sh -c "cd /app && alembic upgrade head"`。
- Docker Desktop 可能没在跑（本项目这几天已遇到两次 daemon 瞬断）。连不上先确认进程，别当成代码坏了。
- 可复用的测试账号：`qa_pluginsmoke_0923`（普通用户，无服务商密钥，走它不会花用户的钱）、
  `perfprobe`。真实生成要付费，需 admin 且要用户授权。
- 数据库：`docker exec palink-ai-db-1 psql -U ai_user -d ai_hub`（用 `postgres` 会报 role 不存在）。

## 5. 交付格式

**开头三段"回来须知"**（给人看的，不许出现 commit 号/文件路径/术语堆砌）：
① 现在整体能不能正常玩；② 这半个月你回来会发现的**行为变化**（哪里少了个开关、哪里变样了）；
③ 最该你拍板或配合的三件事。

**正文**：
- 表 A：§2 的功能地图，逐项红绿灯（🟢 实测可用 / 🟡 代码在但本轮没验到 / 🔴 实测不可用 / ⚪ 必须你在场才能验）。
- 表 B：🔴 与 🟡 的明细——现象、复现步骤、影响面、你判断的根因方向（**不许顺手修**）。
- 表 C：**要你配合清单**——每项写"要验什么 / 要你做什么（开机？开 ComfyUI？点几下？）/ 付费几次 / 不做的后果"。
- 表 D：仓库卫生——未提交代码、未跟踪文档、测试残留数据（消息 id、测试卡 id、临时目录），
  只登记不删。
- 末尾：本轮**测不到的东西**和原因（别用"应该没问题"糊过去）。
