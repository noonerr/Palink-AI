## 1. 问题现象（一手实测，2026-10-05）

测试方式：写了一个临时限速代理（并发共享令牌桶 + 固定延迟）转发 `14000 → 14100`，
参数 **300kbps + 300ms 延迟**，再用浏览器访问代理地址。测完已删除该脚本。

| 指标 | 实测值 |
|---|---|
| 首屏入口 JS（gzip 后） | **638 KB** |
| 首屏入口 JS（raw） | **1782 KB** |
| 入口 JS 传输耗时 | **26 秒** |
| 60 秒时页面状态 | **完全白屏**（`document.body === null`，`readyState: complete`） |
| 60 秒内实际下载量 | **仅 5 KB** |

最后一行是关键：6 个首屏请求并发抢 300kbps 带宽、互相排队，**没有任何一个能先完成**，
所以浏览器连首帧都渲染不出来。

### 已确认不是问题的部分（别再提）

`index.html` 里那 3 个 CSS **已经是异步加载**：

```html
<link rel="stylesheet" href="/katex.min.css" media="print" onload="this.media='all'"/>
<link rel="stylesheet" href="/st/css/fontawesome.min.css" media="print" onload="this.media='all'"/>
<link rel="stylesheet" href="/st/css/solid.min.css" media="print" onload="this.media='all'"/>
```

`modulepreload` 标签数量 = **0**。⇒ **唯一的真阻塞项就是那一个 638KB 的入口 JS。**

## 2. 体积归因方法论（照抄这段，别重造）

minify 后无法按模块名归因（标识符被改名）。**唯一可靠锚点是字符串字面量**。

**取入口文件**（入口是产物里 raw > 1MB 的那个）：

```js
const a = 'dist/assets';
const e = fs.readdirSync(a).find(f => /^index-.*\.js$/.test(f)
  && fs.statSync(path.join(a, f)).size > 1000000);
```

**KaTeX 的精确计量**（字体度量表，形如 `{32:[0,0,0,0,.25],65:[...` 的长连续块）：

```js
const METRICS_RE = /\{(?:\d+:\[-?[\d.]+(?:,-?[\d.]+)*\],){20,}\d+:\[-?[\d.]+(?:,-?[\d.]+)*\]\}/g;
// 实测：入口内 16 块，53KB
```

**其他可用锚点**：`dompurify` → `ALLOWED_TAGS`；`sonner` → `dismissible`；
smart-card-runtime → `data-palink-smart-card-frame`；lucide → `lucide`；
路由 → `RouterProvider`；floating-ui → `autoUpdate`。

⚠️ 用这些锚点定位后**按偏移切分区间**估算区块体积（相邻锚点之间的字节数）。
⚠️ **不要**用 `buildSillyTavernCompatRuntimeV2Shim`、`wrapperRef`、`displayedMessages` 这类
标识符当锚点 —— 全部 0 命中（被terser 改名），我在这上面浪费过一轮。

## 4.⛔ 已否决：KaTeX 改为动态加载（实施后回退）

### 4.1当时的依据（都成立，但不足以支撑改动）

1. 全项目仅一处使用 KaTeX —— `formatting.ts:225` 的 `katex.renderToString()`
2. `renderMathInHtml:269` 有守卫：无 `$` / `\(` / `\[` 直接返回 ⇒ 多数消息不进数学分支
3. `katex@0.16.45` package.json **未声明 `sideEffects`**，主入口为 CJS（`dist/katex.js`）
   ⇒ 打包器不敢摇树，只能改代码延后

### 4.2 实施内容（已回退，仅存档）

```ts
// 静态 import 已移除；改为：
let katexInstance: KatexModule | null = null;
let katexLoading: Promise<KatexModule | null> | null = null;
function preloadKatex() { /* import('katex') 并缓存 */ }
function renderSingleMath(tex, displayMode) {
  const katex = getKatex();
  if (!katex) { void preloadKatex(); return displayMode ? `$$${tex}$$` : `$${tex}$`; }
  try { return katex.renderToString(tex, {...}); } catch { /* 回退原文 */ }
}
```

### 4.3 回退的三个理由（**这是本文档最重要的部分**）

**① 破坏同步渲染契约 ⇒ 公式视觉抖动**
`renderMathInHtml` 是**同步导出**，唯一调用点在同文件 `formatting.ts:1224`
（已 grep 确认：**无任何外部调用方**）。同步函数无法等待异步加载，
于是「首次遇到公式 → 未加载完 → 显示原文 `$x^2$` → 加载完后重渲染才变公式」。
用户看到的是公式先闪一下原文再跳变 —— 比慢一点更糟。

**② 恰好重新引入了该修复要消除的老问题**
`formatting.ts:1220-1223` 的原注释写着：

> F-1 修复（2026-08-23）: 完成态 LaTeX 渲染——在 DOMPurify 之前把 `$$..$$` / `$..$` 片段
> 预渲染为 KaTeX HTML，消除**"流式可渲染、完成态塌回原文"的引擎切换突变**。

动态加载让「完成态塌回原文」**重新出现**，等于把F-1 修复倒退回去。

**③ 触碰了防静默回退的守卫（本项目最敏感的一类测试）**
`src/lib/__tests__/formatting-katex-contract.test.ts` 的文件头注释原文：

> `renderMathInHtml` + KaTeX MathML DOMPurify 白名单**曾两次被其他批次**
> 以"整文件按旧版覆写"的方式静默回退（2026-08-24 两次拦截）。本测试锁定
> 该修复的源码契约，任何回退立即红灯。

该文件 `:29` 断言源码含 `from 'katex'` 字面量。**动态加载会让它变红。**
让它变绿的唯一方式是改断言 —— 而那正是它被设计来阻止的行为。
本次改动导致 **6 个测试变红**（failed=0 是硬门禁）：

- `formatting-latex-contract.test.ts` — 4 个（`$$`/`$`/`\()`/`\[\]` 各自应产出 `class="katex"`）
- `formatting-katex-contract.test.ts` — 1 个（`from 'katex'` 源码契约）
- `formatting-math-script-guard.test.ts` — 1 个（script 段外公式仍应渲染，守卫不应恒真）

### 4.4 回退状态

已从 `_BACKUPS/2026-10-05_KaTeX延迟加载前/files/formatting.ts` 还原，
`git diff` 为空，`tsc --noEmit` 0 错，`vitest run` **60 文件 / 781 passed + 3 skipped**。

## 5. 项目已有的正确经验（vite 配置注释原文，勿推翻）

`vite.config.ts:91-105` 记录了一次成功瘦身（844KB→597KB gzip，-29%），并写明了踩过的坑：

> 原先这里是对象式 manualChunks：`{ recharts:['recharts'], mermaid:['mermaid'], ... }`
> **对象式写法会把「目标包的依赖」一并吸进该命名 chunk**：mermaid chunk 吸走 dompurify（126KB）、
> recharts chunk 吸走 clsx、framer-motion chunk 吸走 react 运行时。
> 而 entry 静态 import 了这些，于是被迫静态依赖这三个巨型 chunk，
> Vite 随之在 index.html 里对它们发 modulepreload ⇒ 本应懒加载的库进了首屏关键路径。

**硬约定**：若需切分，只能用**函数式** `manualChunks` 且只匹配目标包自身的 node_modules 路径，
**切勿**把 dompurify / clsx / react / katex 等共享依赖纳入命名 chunk。

⚠️ `vite-plugins/asset-content-hash.ts` 是必查护栏（曾被误删且无测试守卫，删了会导致
iOS 永远收不到 CSS 更新）。本次议题未触碰它，改 chunk 策略时别顺手删。
