## 5. 踩过的坑（**这一节是换会话后最该读的**；每条都是我自己交过学费或亲眼否证过的）

1. **智能卡运行时是模板字符串**（`runtime-body/part-01..08.ts`）：只能 ES5、禁反引号、禁 `${`、**单反斜杠转义会被求值吞掉必须成对写**；`tsc` 看不见里面；执行型测试必须用**求值后的载体** `COMPAT_V2_RUNTIME_ARTIFACT`，拿源码文本测 = 方向相反的假结论；行号一律用函数名锚点。守卫：`runtime-body-template-literal-guard.test.ts` + `generated-script-parse-guard.test.ts`。
2. **`window.TavernHelper` 是 Proxy**：`typeof === 'function'` 不证明成员存在；只认 `Object.keys()` 命中，或看有没有 `missing_api` / `tavern_helper_key_unimplemented` 留痕。
3. **指标会被自己的修复打到"满分而作废"**：`covered_in` 注入权威名单后恒 289，不再证明命令实现（真实现 ≈93）。**引用任何覆盖率前先问它是被满足还是被作废**。
4. **判定"文件不存在所以跳过"的测试等于没测**：禁止 `pytest.skip` 占位、禁止 import 失败整文件 skip（历史上覆盖 38 个文件 = 把编译错误降级为静默消失）。**真跑不了就删用例**。
5. **门禁**：`gate.sh` 是唯一入口；`|| true` / `continue-on-error` / `--continue-on-collection-errors` 一律禁止（谁加回去谁就是把门禁变回安慰剂）；后端 pytest **必须 `cd backend`**（根 `.env` 有 22 个未建模键 ⇒ `Settings() extra_forbidden`）；`--basetemp` 永远不要指进仓库（历史上一次产生 1 个 SystemExit + 83 个 AssertionError）。
6. **提交 ≠ 上线**：改后端要 `docker compose build backend && up -d backend`（容器约 1 分钟才 healthy，期间 `/api/token` 502 属正常）；改前端要重建 dist。**半成品构建会产生多组指纹而入口只引用旧的** ⇒ 验产物**只能 grep 字符串字面量**（标识符/路径被压缩抹掉）。
7. **临时索引提交法**（多人合住工作区）：`GIT_INDEX_FILE` → `read-tree HEAD` → 逐项 `git add <pathspec>` → `write-tree` → `commit-tree` → **`unset GIT_INDEX_FILE`** → `update-ref <新> <旧>` → `git reset -q HEAD -- <那几个路径>`。
   ⚠️ 最后一步不能省：**临时索引提交"新增文件"后主索引没有条目，`git status` 会假装它是被删除（`D `）**，别人随后一次 `git commit -a` 就把这文件真删了（今天踩在 `BACKUP_INFO.md` 上）。禁止 `git add -A`；`--stat` 看不出夹带，要 grep 对方的标记。
8. **子 agent 中断有三种形态**（今天遇到两种）：① 留半成品 → 备份现场 + 逐文件标归属 + 串行收尾，⛔ 禁止整包 `git apply -R`；② 预算全花在读码、零产出 → 派单时写死"前 10 次工具调用内落地第一个可执行文件"；③ **修复写成 `if (false && …)` 死码** ⇒ `tsc` 全绿但测试红（今天就是这个），接手段要先查"新 helper 有没有真调用点"。半自动判据：`Tests 0` / "no tests" 的文件**等于不存在**。
9. **`style_removal` 刷屏：我错了两次。** 第一次以为是"卡删我们的插件 CSS ⇒ 功能失效"；实测证明：搬家的执行体是**我们自己的兼容层**（`part-04.ts:875 node.appendChild?.(item)`，jQuery `append` 的移动副作用），而"搬回 head"那半程是只带 addedNodes 的记录，被 `part-08.ts:1817 if (!removed || !removed.length) continue` 跳过 ⇒ **上报天然只有前半程**。稳态 5 条插件 CSS 实测 5/5 健在、字符数与上线判据逐条相同，两层样式守护这次一条都没参与。840 = 35 次帧装载 × 每帧顶格 24（`part-08.ts:1767`）。**教训：取证面报"我看到删除"不等于"东西丢了"，要查谁搬的、有没有搬回。**
10. **A/B 双臂同 0 ≠ 修复生效**（今天 [P2-14] 验收①）：必须先确认**基线还能复现**。插件 `enabled=false` 时它根本不发请求，"错误消失"是假阳性。
11. **响应信封形状坑**：`/api/settings/get` 顶层**没有** `extension_settings`，整份设置塞在 `data["settings"]` 这个 **JSON 字符串**里（实测 25 个键）；后端内部读的是 DB blob，两者**不是同一个形状**。我第一版测试因此差点把"自己的读法错"报成"代码回归"。
