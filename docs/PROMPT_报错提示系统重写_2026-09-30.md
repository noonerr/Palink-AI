### 1.3 底部遮挡（这条被纠正过，务必按纠正后的版本理解）

- 【已核】根因是 **`fixed` 被祖先 transform 劫持**：角色页四个 tab 由 `MobilePager` 渲染，槽位 div 带 `willChange:'transform'`（`App.tsx:436`）+ 内联 `translate3d`（`App.tsx:407`）。带 transform 的祖先会成为 fixed 子元素的包含块并另起层叠上下文 → `ErrorToast` 的 `z-50` 只在槽位内部有效，而 dock（`App.tsx:1141` / `Sidebar.tsx:492`，同为 `z-50`）是 `main` 的兄弟节点，无条件压在它上面。
- 【已核】**同一个坑本项目已经解决过一次**：`ChatInputArea.tsx:102-127` 注释原话「Portal 到 body 是为了逃离 MobilePager 槽位的 transform/will-change 包含块（否则 fixed 会锚到槽位而不是视口）」，且其位置由 JS 按 `--palink-kb-vh` 写入（另见 `index.css:1360`、`:1464`）。**输入框两步都做了，错误卡（`CharacterChat.tsx:2106`）和超时条（`:2117`）两步都没做。**
- 【实测】**「按钮被 dock 压住」这个说法是错的，不要重复它。** 实测：错误卡底边距屏 96px、dock 上沿 103.7px → 只咬到卡片下沿 **7.7px**；「重试/关闭」按钮行在 108–140px，**差 4.3px 没被 dock 盖**；浏览器模式（`safe-area-inset-bottom=0`）下 dock 上沿约 78px，**完全不重叠**。
- 【实测】真正的致命项是**键盘**：iOS 键盘只缩 visual viewport、布局视口恒不变（WebKit Bug 304976，`ChatInputArea.tsx:102-106` 与 `index.css:1360` 已记录）。卡锚在布局视口底部，键盘约占底部 336px → 卡片（96–284px）连同按钮 **100% 落在键盘后面**。用户踩到的时机正是"点完发送就失败"，那时键盘还开着。
  - ⚠ 这条的**数字**是实测的，但其**前提**（键盘不缩布局视口）来自项目既有实测记录，**尚未在本机 iOS 真机复核**。交付时不得声称已真机验证。
- 【已核】超时条 `CharacterChat.tsx:2116-2130` **完全没有关闭按钮**，只能等 `useCharacterChat.ts:1490` 的 finally 自清；且它与 `ErrorToast` 在 `sm` 断点以上 `bottom-4 right-4 z-50` **像素级重叠、同 z**。
- 【实测】`ErrorToast.tsx:35` 的 `w-full max-w-md right-4` 使卡片左边缘落在内容区 **−16px**（裁出屏外）。
