**`ChatViewDesktop.tsx`（在 `:35` 之后、`:41` 早退之前新增 hooks —— 早退分支在 hooks 之后，hooks 规则要求必须在其前）**

```ts
const messagesRef = useRef(chat.messages); messagesRef.current = chat.messages;
const handleRegenerateRef = useRef(chat.handleRegenerate); handleRegenerateRef.current = chat.handleRegenerate;
const handleEditMessageRef = useRef(chat.handleEditMessage); handleEditMessageRef.current = chat.handleEditMessage;
const handleDeleteMessageRef = useRef(chat.handleDeleteMessage); handleDeleteMessageRef.current = chat.handleDeleteMessage;
const toggleMessageSelectRef = useRef(chat.toggleMessageSelect); toggleMessageSelectRef.current = chat.toggleMessageSelect;
```
+ 4 个 `useCallback(..., [])`：`handleRegenerateAt(id?)`、`handleEditAt(content, id?)`、`handleDeleteAt(id?)`、`handleToggleSelectAt(id?)`，内部 `findIndex(m => String(m.id) === String(id))` 取下标。

> 关键：`chat.handleRegenerate` 本身 deps 含 `chatMessages` 对象（每次 render 新引用），所以**必须走 ref**，不能 `useCallback([chat.handleRegenerate])` —— 这正是 `CharacterChat` 用 `wrappedHandleRegenerateRef` 的原因。

传点改为（`:148/:150/:151/:156`）：
```tsx
onRegenerate={msg.role === 'assistant' && !chat.streaming ? handleRegenerateAt : undefined}
onDelete={msg.id != null ? handleDeleteAt : undefined}
onEdit={msg.id != null ? handleEditAt : undefined}
onToggleSelect={msg.id !== undefined ? handleToggleSelectAt : undefined}
```
条件式 `undefined` 保留原样（这是可见行为，不能改成恒传）。

**`ChatViewMobile.tsx`**：同样在 hooks 区（`:177` 附近）新增，替换 `:493-496` **与 `:617-621`** 两处；`onDelete` 走本地 `handleDeleteMessage`（`:177`，包装 `chat.handleDeleteMessage` 并转 number）—— 包一层 ref 后由 `handleDeleteAt` 调用，保持 `messageId as number` 原语义。

**逐 prop 过比较器**：改完后按 `:1825-1897` 清单逐条核对两个视图传入的全部 prop（`message`/`userAvatar`/`userName`/`models`/`streaming`/`isLast`/`t`/`tokens`/`memoryStats`/`onCompress`/`compressing`/`onRegenerate`/`canRegenerate`/`onDelete`/`onEdit`/`canEdit`/`onGenerateImage`/`isGeneratingImage`/`isSelected`/`onToggleSelect`/`showSelect`/`isCharacterChat`/`memoryMode`/`showModelReasoning`），输出一张「prop → 引用来源 → 是否稳定」表作为物证附件。

## 5. 验收物证方案（与任务书的一处偏差）

**任务书要求**：React DevTools Profiler 录制流式输出，读单次 commit 内 `Message` render 次数。

**问题**：DevTools Profiler 的 per-component 计数没有稳定自动化出口（需 CDP + React 内部 fiber 协议），本环境无法可靠采集、也无法存档进 commit body。

**替代（推荐，物证等价且可存档）**：临时插桩 + 真实浏览器跑一次流式。
1. `MessageInner` 顶部插入标记块：
   ```ts
   // [PERF-PROBE-BEGIN] 验收后整块删除
   (window as any).__palinkMsgRenders ??= {};
   const __k = String((message as any)?.id ?? 'anon');
   (window as any).__palinkMsgRenders[__k] = ((window as any).__palinkMsgRenders[__k] || 0) + 1;
   // [PERF-PROBE-END]
   ```
2. 起 dev server，用浏览器自动登录 `admin` → 进 `/chat` → 造 20 条历史 → 发一条触发流式 → 等结束 → `evaluate` 读 `window.__palinkMsgRenders`。
3. **改前跑一次、改后跑一次**，两个数字写进 commit body；验收后整块删除插桩并复跑 `tsc` + `build` 确认零残留。

备选 B：`vitest@4.1.10` 已在 devDeps，可配 jsdom 写 harness 断言 render 次数（可进 CI、可重复），但需装 `jsdom` —— 本环境 `npm install` 会触发批量删除守卫 SIGKILL，需走垫片绕法，成本较高。备选 C（纯静态论证）不满足"必须给物证"的要求，不采用。

## 6. 风险与回滚

- **P0 最大风险**：`handleRegenerate(idx)` 的 `idx` 语义。`handleRegenerate` 内部要求 `messageIndex >= 1` 且 `messages[idx-1].role === 'user'`（`:209-216`）。改为按 id 反查下标后，若 id 在列表中不存在（临时 id / 并发删除）会 `findIndex < 0` → 静默不执行，而现状是必然执行。**对策**：`handleRegenerateAt` / `handleDeleteAt` 内 `idx < 0` 时 `return`，与 `CharacterChat` 样板完全一致；并在手动回归中重点验「删除后立刻重生成」。
- **P1-A 风险**：见 §4，可能暴露此前被漏掉的更新（属修正）。
- **回滚**：每批独立 commit；批次 0 的 patch + 文件本体备份在 `backups/2026-09-22-在途UI改动/`，可整批 `git revert` 或按目录拷回。
