顶部：报错被灵动岛吃掉，是因为项目主动铺到了它背后

index.html:12 的 viewport-fit=cover 加 index.html:43 的 black-translucent，让页面延伸到状态栏底下；那块由系统盖毛玻璃，Web 压不住 —— App.tsx:1111-1114 的注释自己承认了这点。顶栏全做了安全区避让（全项目 20 多处）， 但报错浮层是漏网的：主气泡没传任何 offset，网络横幅写死 top-0。

2

底部：fixed 被祖先的 transform 劫持，所以层级失效

角色页四个 tab 由 MobilePager 渲染，槽位 div 带 willChange:'transform' （App.tsx:436）+ 内联 translate3d（App.tsx:407）。带 transform 的祖先 会变成 fixed 子元素的包含块，并另起层叠上下文 —— 于是错误卡的 z-50 只在槽位内部有效， 而 dock 是 main 的兄弟节点，无条件压在它上面。

同一个坑本项目已经踩过并解决过一次：ChatInputArea.tsx:106-107 注释原话「Portal 到 body 是为了逃离 MobilePager 槽位的 transform/will-change 包含块」。 输入框两步都做了，错误卡和超时条两步都没做。

但「按不到关闭」的真凶不是 dock，是键盘

我先前那句「按钮被 dock 压住」说过头了，量完自己的图已更正：按钮行在 108px、dock 顶在 103.7px， 差 4.3px 没被盖；浏览器模式（inset=0）更是完全不重叠。真正吃掉它的是键盘 —— iOS 键盘只缩 visual viewport、布局视口恒不变，卡锚在布局视口底部，键盘一开整张卡连按钮 100% 落到键盘后面。而你踩到的时机正是"点完发送就失败"，那时键盘还开着。

后端侧实证：我复核了自己上一轮的断言

我说过 ⑩「会被持久化、回喂模型、被 TTS 朗读」，那是读码推断。三条里两条说过头了 —— 但复核时挖出一个更靠得住的坑。以下每条我都自己打开源文件核对过原文。

订正：⑩ 那条 ⚠️ 文本其实不入库

A 不成立B 不成立

两处写入点（useCharacterChat.ts:540-548、:1459-1467）函数体内没有任何落库调用， 被覆盖 content 的那条消息用的是本地临时 id（messageUtils.ts:11-13 的 Date.now()-random 串）。 只有成功路径 :1352-1375 才把 id 换成数据库返回的 persistedMessageId，错误分支永不换 id。

  • 连"用户手动编辑这条 ⚠️ 再保存"都存不进去 —— PUT 有 Number.isInteger(persistedMessageId) 门禁（:1653-1654），临时串转成 NaN 被挡。
  • 装配链取历史只从数据库读（character_message_builder.py:166-183），不在库里 → 进不了提示词。
  • TTS 那条成立：Message.tsx:1120-1129 取 assistant 正文，tts.ts:208-220 的清洗不认识 ⚠️；需用户点该条朗读键，无自动播放。

但 B 不成立的原因是 A 不成立，不是装配链有防护。 装配层对 assistant 正文只做 strip_inline_think（:227-231）与剥标签清洗，⚠️ / ** / 💡 一律原样通过； :238 直接按 m.role 入 prompt，连 role 白名单都没有。插件调一次 setChatMessages → POST /api/chats/save（整表重建落库，silly_tavern.py:2957-2993）， 这段文本就会原样进提示词。

真坑：SSE 那一轨的 "Error: …" 确实在落库

A 成立B 成立

项目早就知道这类污染：WS 轨 websocket.py:663-670 明确拒绝把 Error: 开头的正文入库， 注释留着一条 2026-08-18 实测 ——「2175/2177/2181 三条 Error 消息入库后该会话连续失败」「越重试越失败」。SSE 轨没有这道守卫。

  • character_ext.py:4649-4658 的 persist_snapshot 只守 has_content；而错误分支 :4955 / :4961 / :4970 是先把 full_content = "Error: …" 再调落库 —— 赋值动作自己让守卫条件为真，守卫形同虚设。
  • 更糟：:4963 / :4973 在已经出了一半内容时走 full_content += f"\n\n[{e.message}]" —— 报错文案被拼进真回复正文一起落库，比占位行难发现得多。
  • 装配侧的兜底过滤 startswith("Error:")（character_ext.py:592-594）只挂在有分支的历史查询上； character_message_builder.py:174-183 的无分支回退查询没有它。而建行侧确有 branch_id=active_branch.id if active_branch else None（:3076 / :3110 / :3143）→ 无分支会话可达，此时这些 Error 行会回喂给模型，正是那条注释描述的恶性循环。

好消息：不用加字段、不用迁移，判据也已经写好了

extra.ignore === true 在装配层已实现并生效（character_message_builder.py:205-216， 注释写明对齐 ST 1.18.0 的 IGNORE_SYMBOL），写路径也早就支持 dict：MessageAppendRequest.extra （character_ext.py:2935-2954）、PUT 的 edit_extra（:3252）、前端类型上 extra? 与 is_hidden? 都在（types/index.ts:465-494）。 "可见但不回喂"这个能力是现成的 —— 我上一轮写的"要先确认落库字段"那个前提作废。

StreamResult.is_error_only() 也已存在（stream_builder.py:26-34）， 文档串写明「"Error:" 是本项目所有错误注入点的统一前缀」，且 tests/test_user_quota.py:252,264 有覆盖。 它目前只用在一处：token 计数（:47）。所以修法不是新写逻辑，是把它接到那两处落库上。

三个候选标记的取舍：extra.ignore（语义最贴、已生效，推荐）＞ is_hidden（过滤在 :188 也生效，但语义是"用户可见的隐藏"且已有 PATCH 界面，混用会撞车）＞ role='system'（不能用，:238 会原样投进 prompt，它不是排除开关）。

顺带一条约定违背：前端 ⑩ 用 ⚠️ 开头，而项目既有约定是统一 Error: 前缀 —— 这正是它躲过所有现存守卫的原因。

05

收敛方案：三批，顺序不能换

批 1 止血（改动小、可当天验收）→ 批 2 归一（先立入口再迁移）→ 批 3 结构性（含两处要你拍板）。

批 1止血：两个遮挡 + 一条数据污染≈6 个文件，不动架构

1.1

主气泡让开灵动岛

改 App.tsx:1150 一行：给 <Toaster> 传 mobileOffset/offset = calc(env(safe-area-inset-top) + 8px)，并开 closeButton。

sonner 把 offset 写进 CSS 变量 --offset-top 再 top: var(--offset-top)， env() 理论可用，但必须实测；不行就退回在 index.css 覆盖 :root{--mobile-offset-top}。

1.2

网络横幅让开灵动岛

NetworkStatus.tsx:32 的 top-0 → top-[env(safe-area-inset-top)]。 彻底做法是把红/绿/黄三态并进 ① 的 toast，本批先只加偏移、不动结构。

1.3

底部两张卡：Portal 到 body 并且接键盘变量

(a) Portal 到 document.body，逃离槽位 transform 包含块，让 z-index 能真正和 dock 比大小 —— 治 dock 那 7.7px。
(b) bottom 改由 --palink-kb-vh / keyboardHeight 驱动 —— 只做 (a) 不够：Portal 之后卡仍锚在布局视口底部，键盘一开照样整张埋掉。 输入框两步都做了，所以它一直贴键盘上沿没事。
(c) bottom-24 换成 calc(env(safe-area-inset-bottom) + var(--palink-dock-height) + 12px) （dock 高度 index.css:97 已有运行时变量），别再硬编码 6rem。

我更推荐的省事解法：把 ② 直接改成 sonner 的常驻不自动消失 + 带关闭钮 （duration: Infinity）一条 toast，归到顶部通道、与 1.1 共用同一套安全区偏移 —— 底部这片键盘/dock/输入框交战区一次都不碰。代价是丢掉"重试"按钮的形态，得用 action 补。

1.4

超时并进错误卡

③ 降级成 ② 里的一行状态。少一个浮层、少一处 bottom-4 right-4 z-50 坐标冲突， 顺手补上它现在完全没有的关闭能力。

1.5

失败不再伪装成 AI 回复

改成带 extra.ignore=true 的消息节点：可见、可重发、不回喂模型、不被 TTS 朗读。 复核确认不用加字段、不用迁移（见第 04 节）。剩下的只是渲染层 —— 现在它和普通回复只差一个 ⚠️ 表情，形同 AI 自己承认失败。

1.6

把已有的判据接到 SSE 落库处优先级不低于 1.5

  • (a) character_ext.py:4649 的 persist_snapshot 开头加 if result.is_error_only(): return，与 WS 轨拉平；顺带把 WS 那里手写的 startswith("Error:") 也换成同一个谓词，消掉重复实现。守卫必须用 is_error_only() 而不是 has_content —— 后者会被"先赋值"的写法自己满足。
  • (b) :4963 / :4973 停止把报错 += 拼进已生成的真回复正文。 文档串自己承认这种"真实输出后追加错误后缀"不算 error-only（stream_builder.py:30）， 所以它必然落库并污染真内容。报错另存到 extra。
  • (c) character_message_builder.py:174-183 的无分支回退查询补上与 :592-594 相同的过滤。
  • (d) 前端别再造第三种前缀：要么遵守 Error: 统一约定，要么用 extra.ignore 显式标记。

动 (c) 之前先跑那条 SQL 量影响面（见第 04 节末）。

06

等你拍板的三件事

iOS 还要不要铺到灵动岛背后

沉浸式靠 viewport-fit=cover + black-translucent，代价是顶部永远有一条 Web 管不着的毛玻璃带， 所有浮层都得手动避让 —— 本次两个遮挡都源于"漏了谁"。

替代做法是退回系统保留不透明状态栏：顶部避让代码可大面积简化、浮层不可能再被挡， 但失去沉浸观感，且 K18 / K19 / K20 一串真机校准（index.html:24-64、index.css:1375、 Sidebar.tsx:501-517）都要重测。

我的建议：保留现状、只做避让。改动面小得多。但这是产品观感决策，该你定。

卡内脚本报错要不要给可见入口

现在它是 0 层提示。给它入口要占屏，而 K15 诊断角标当初正是按你的要求删掉的 （App.tsx:476 注释留痕）。

我的建议：不占屏的形式 —— 收进设置页一个"卡与插件诊断"列表，只在有错误时显示未读点。

底部错误卡走哪条修法

1.3 的两条路：跟输入框一样 Portal + 键盘变量（保住"重试"按钮形态，改动更局部）， 或改成顶部常驻气泡（一次绕开键盘/dock/输入框三个对手，但重试要换成 action）。

为什么 4 类会长成 11 类

你感觉到的"乱"是三件独立的事：

一、同一时刻叠多层。角色页超时再失败 = 黄条 + 橙卡 + 正文 ⚠️ 三层，其中两层同坐标自己打架。

二、同一种错误在不同页面表现不同。角色页 3 层、普通聊天页 1 层；插件报错走三条不同出口； 崩溃有两套完全不同的红卡；卡内脚本报错则一层都没有。

三、根本没有统一入口。不存在 lib/toast.ts / useToast / showToast （文件名、导出符号、函数名三个层面都搜过，全 0 命中），index.css 里对 sonner/toastr 的定制样式 0 命中， 主气泡是纯库默认皮肤；名义统一的 ui/alert.tsx 复用率 = 1 处。 所以"绕过率 100%"其实是因为无处可绕 —— 每个组件只能自己写一个。 这才是 4 变 11 的机制，也是为什么批 2 必须"先立入口再迁移"，反过来做就是白搬。
