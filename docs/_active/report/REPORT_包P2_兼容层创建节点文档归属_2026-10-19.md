## 0. 一句话结论

卡帧内 `$('<div>…</div>')` 造出的节点确实**不属于帧自己的 document**，但**这不是样式失踪的直接原因**——
直接原因是兼容层 `appendTo`/`prependTo` 的**静默空转**：它们把整条集合交给 `append`，
而集合是 `nativeFallback` Proxy（取任何未知属性都返回一个函数），于是 `value?.nodeType` 恒为真，
代码把 **Proxy 本身**丢进 `node.appendChild(...)` → TypeError 被 `catch {}` 吞掉 → 什么都没发生。
卡侧「建容器 → 把 head 的 style 塞进容器 → appendTo('head')」这条链因此把样式关进了
一个永远回不到生效文档的容器里 ⇒ 用户看到的「卡自带样式整段裸奔」。

创建路径的归属问题（`<template>.content` 子节点属于「模板内容文档」）是**第二处**与真 jQuery 不一致，
本身不致命（原生 `appendChild` 跨文档会自动 adopt，实测成功），但按任务书判据一并归一。

这一条既是异常的来源，也是它被静默吞掉的证据。

`runtime-body/part-04.ts` 的 `createParentDollarCollectionCompat` 里 `collection.append` 的
`if (value?.nodeType)` 分支 + `collection.appendTo`/`collection.prependTo` 的 `targets.append(this)`；
`runtime-body/part-05.ts` 的 `nativeFallback = new Proxy(collection, …)`（未知属性一律返回函数）。

## 4. 段② 改了什么（两处，都在兼容层的创建/搬运路径）

坐标用函数名锚点，都在 `runtime-body/part-04.ts`（注入 iframe 的模板字符串内，新增代码一律 `var`/`function`）：

1. **`createElementsFromHtmlCompat`（创建归属）**：`template.content.childNodes` 里筛出的元素
   若 `ownerDocument !== document`，改用 `document.importNode(node, true)` 归入本帧文档。
   标了 `[P2-CREATE-OWNERDOC]`。效果：`$('<div>')` 的 `palinkCreated.sameDoc` 由 false 变 true，
   与真 jQuery 的创建归属一致。
2. **`collection.append` / `collection.prepend`（搬运落点）**：新增三个小工具
   `isDomNodeLikeCompat`（**nodeType 必须是数字**才算节点，专治 Proxy 取未知属性返回函数）、
   `dollarMoveTargetsCompat`（集合一律摊平成节点数组，字符串原样，null 变空表）、
   `dollarMovedItemMarkupCompat`（父文档桩仍按 innerHTML 走 markup，保持包N 之前的行为）。
   `append`/`prepend` 改为「先摊平、再逐项判定」，`appendTo`/`prependTo` 本体不动
   （它们内部就是 `targets.append(this)`，摊平后自然修好）。标了 `[P2-MOVE-ARG-KIND]`。
   节点**不克隆**（真 jQuery 也不克隆），跨文档由 `appendChild` 自己 adopt。

没动的东西（红线逐条核对）：`STYLE-GUARD` 恢复范围（`guardSnapshot` 仍是 8）、`sanitizeStCompatCss`、
包I 的错误分类与 toast、包N 的取证面、iframe sandbox、`frontend/dist`、后端镜像。未 `npm run build`。
