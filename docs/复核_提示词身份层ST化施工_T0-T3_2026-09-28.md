## 附录 A：ST 1.18.0 到底怎么放注入（源码核对，2026-09-28）

权威文件：`D:\SillyTavern-release\public\scripts\openai.js`

### A.1 注入分成两条完全不同的通道

| 通道 | 判据 | 落点 | 源码 |
| --- | --- | --- | --- |
| Relative（相对主提示词） | `injection_position === 0` | 插在 **main 槽内部**（start/end），与主提示词同属一个块 | openai.js:1256-1275 `injectToMain` → `chatCompletion.insert(message, 'main', position)` |
| In-chat @ Depth（绝对） | `injection_position === 1` | 插进 **聊天历史数组内部** | openai.js:1324 `messages = await populationInjectionPrompts(absolutePrompts, messages)` |

枚举定义：`PromptManager.js:37-40`（RELATIVE: 0 / ABSOLUTE: 1）。

### A.2 关键：In-chat 注入操作的数组里根本没有主提示词

`populationInjectionPrompts(prompts, messages)`（openai.js:800-866）里 `messages` 是
**倒序（最新在前）的聊天历史**，主提示词/世界书/角色卡字段全在另一个容器 `chatCompletion` 里，
两者直到 `populateChatHistory(messages, prompts, chatCompletion, ...)`（openai.js:1331-1336）才合流。
旁证：`populateChatHistory` 内部 `const chatPool = [...messages].reverse()`（:939）
与标识符 `chatHistory-${messages.length - index}`（:945）—— 说明传进来时是倒序。

**所以 ST 结构上不可能出现"注入块排到主提示词前面"**：它压根不跟主提示词竞争同一个数组的下标。

### A.3 depth 的确切语义

```js
for (let i = 0; i <= maxDepth; i++) {            // :811  depth 升序
    ... roleMessages.push(system) ... push(user) ... push(assistant)   // :832-853
    const injectIdx = i + totalInsertedMessages; // :858  倒序数组的第 i 位
    messages.splice(injectIdx, 0, ...roleMessages);
}
messages = messages.reverse();                   // :864  转回正序
```

官方 UI 文案（index.html:7337）：**"0 = after the last message, 1 = before the last message, etc."**

倒序数组下标 i == 正序"距末尾第 i 条"。当历史条数比 depth 短（`i > len`）时 `splice` 只会在末尾追加，
转回正序后 = 落到**聊天历史的第一条之前**——**仍然是主提示词之后**。
这就是 ST 的天然下限：锚点是"聊天历史头部"，不是"整个 prompt 数组头部"。

同 order 桶内 role 顺序 `['system','user','assistant']` 正序入块 + 整体 reverse，
净效果（正序读）= assistant → user → system，**system 最贴近最新消息**；
order 组按 `+b - +a`（高 order 先处理 → 更靠后/更贴近最新消息），默认扩展 order=100。

### A.4 Palink 现在的实现与差在哪

`roleplay_prompt_assembly.py:5097`
```python
insert_index = max(0, len(next_messages) - head.depth)
```
- `next_messages` = `[system_prompt] + 历史 + …`，**把主提示词一起算进锚点**（ST 不这么做）；
- 下限只钳到 `0`，锚点跑到主提示词之前（ST 钳到"聊天历史头部"）；
- depth 降序处理 + `len - depth`，与 ST 的"倒序 + depth 升序 + 偏移"在长度充足时等价；
  role 顺序注释（:5067-5071）对 ST 净效果的理解正确。

结论：`depth=4` 且总长 4 时被钳到 0 = 排到 main 之前。T2 删掉尾部 2 条 system 只是把总长缩短、
让这条错误分支变成常态可达，**不是 T2 写错了**；缺的那道下限本来就该有。

### A.5 对齐 ST 的改法（一行 + 探针）

```python
# ST: in-chat injections 只锚在聊天历史上，永不越过主提示词块
_floor = 1 if next_messages and next_messages[0].get("role") == "system" else 0
insert_index = max(_floor, len(next_messages) - head.depth)
```

改完预期：A/B 实验里的块回到 `[1]`、main 回到 `[0]`，与 ST 语义一致；
`max(0, …)` 那条越界分支不再有可达路径。
