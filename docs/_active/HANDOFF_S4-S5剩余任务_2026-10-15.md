## 6. 红线与本机坑（干活前必读，血泪清单）

**代码与删除类**
- 不按文件名删任何东西；删前 grep 全仓消费链（已栽过：文件名像就删，结果漏消费方）。
- **存储迁移只加不删**，旧键一律保留（双写窗口已知，S5 也不许删旧轨回退能力）。
- `SillyTavernCompatRuntime.ts` / `legacy-st-sim.ts` / `api/silly_tavern.py`：**只拆不改语义**。
- `legacy-st-sim.ts` 内禁止反引号和 `${`（整文件是模板字符串）；改完必须
  `node scripts/verify-shim-identity.mjs`。
- ⚠️ **模板字符串内的注释也不能写反引号**（10-14 实踩：一个反引号截断模板，
  esbuild 报错指向注释行，极易误判成"配置坏了"）。
- 不动 admin 的真实角色/会话数据；插件注册一律用测试数据。
- 不准改 `TODOS.md`、`docs/_CATALOG.md`、`.workbuddy/`、别人的文档。

**git 纪律**
- 提交一律 `git commit -o -m "..." -- <pathspec>`；**禁 `git add -A`**。
  ⚠️ `-m` 必须放在 `--` 前，否则被当 pathspec（实踩）。
- **禁** `git stash -u`（本机会被 SIGKILL 且永久损坏 .git）、`fetch` / `clone`（对象下载阶段被杀）、
  整树 `tar`、跨机器 `merge` / `rebase`、在主工作区切分支。
- worktree 的 `node_modules` 是目录联接，**绝不能 rm -rf**（会顺联接删主工作区 469M 依赖）；
  断联接只能用 `cmd //c "rmdir <path>"`。
- bundle 打完**必须 grep refs/heads 确认目标分支在内**（`git bundle verify` 只校验结构）。

**真机与构建**
- 前端 `http://localhost:14700`（**不是 14000**）；本机 curl 必须 `--noproxy '*'`（Clash 拦 localhost）。
- 改了 `frontend/src` 必须重建 dist：`VITE_OUT_DIR=dist_new node scripts/build-vite.mjs`
  → `cp -r dist_new/. dist/` → `node scripts/gzip-dist.cjs` → 删 `dist_new`；
  ⛔ 禁 `mv` 重命名（dist 是 bind mount）、⛔ 禁 `npm run build`。
- **容器 healthy ≠ 代码最新**：改完请在 `frontend/dist` 里 grep 你的新标记确认产物已换。
- 登录态：容器内签 admin JWT 注入 `palink_session` cookie（6 小时过期）。

**门禁与查询**
- 门禁基线：前端 `npx vitest run` = **1000 / 0 / 3**，`npx tsc --noEmit` = 0；
  后端 `cd backend && py -3 -m pytest tests/ -q` = 1999 / 51 / 0。
  ⛔ 禁 `|| true` / `continue-on-error` 掩盖失败。
- 并行纪律：两个任务同时跑会让双方数字都不可信 ⇒ 需真机的任务一律串行。
- 查库前先 `\dt` 确认真表名（曾有表不存在的教训）。
- 动 `docs/` 必须 `py scripts/docs/gen_docs_catalog.py` 再 `--check`。
