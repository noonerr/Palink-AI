## 2. 分期方案

### P0 — sysprompt 接入（建议做，风险最低）
- **改哪**：`api/character_ext.py::_build_char_system_prompt` 附近（`:2132-2150` 分支）+ 读取 `user_setting.power_user.sysprompt`（`enabled`/`content`）。
- **行为**：当 `power_user.sysprompt.enabled=true` 且 `content` 非空 ⇒ 按 ST 语义注入；`content` 为空或 enabled=false ⇒ **逐字节不变**（零回归硬线）。
- **选中通道**：预设库数组（`sysprompt_presets`）是「可选集合」，ST 的 `power_user.sysprompt` 是「当前选中值」。
  P0 需要在模板库面板加一个「设为当前」，写 `POST /api/settings/save` 的 `power_user.sysprompt`（后端已有整块读写与保留键保护，见 `api/silly_tavern.py:2356-2371`）。
- **判据**：三卡（露缇雅/猫娘/Seraphina）装配导出逐段对比——enabled=false 时必须与改前**逐字节相同**；
  enabled=true 时只在指定位置多出该 system 段，其余段落顺序/内容不变。
- **必跑守卫**：depth 锚点探针（记忆「Depth anchor has no floor」：装配尾部加减 system 会整体平移注入落点）。
  本次是**头部**注入，仍须复跑，确认 MVU 块/世界书落点没被顶移。

### P1 — reasoning 接入（建议缓做）
- 真实成本不在「读三个键」，而在**三处硬编码标签要收口成配置**（`compact_title_service.py:50`、`status_bar_detector.py:485-503`、
  `character_ext.py:4946-4947` 的 `⋇…⋑` 内联协议），且会同时牵动 SSE 契约、落库前剥离、前端 `ThinkingProcess.tsx` 显示。
- 记忆在册的两条历史坑直接适用：「落库前剥标签」与「SSE 轨 `Error:` 真落库」——动解析链容易把思考链原文写进正文。
- 若只做「用户选了 `<thinking>` 就按它剥」，收益是外观一致性，风险是思考链污染正文。**建议排 P2 之后或不立项**。

### P2 — instruct 接入（建议明确不做）
- 原生管线是 chat-completion，`inference_dispatcher/stream_builder` 零命中即证据；
  为一条不存在的路径造注入点，属于「看起来像补齐、其实是自发明」。
- 现状保留即可：instruct 序列已服务 ST iframe 与卡片插件面，`instruct_templates` 的字段补齐（本批 `f67aa52`）已经把导入面打通。

## 3. 需要用户拍板（四条，按重要性）

1. **sysprompt 注入位置**：作为**独立的前置 system 消息**（贴 ST），还是并进现有 main 段？
   ⇒ 主脑建议：**独立前置 system**，且 `enabled=false`/空内容时逐字节不变。并进 main 会改动现有 system 结构，回归面大得多。
2. **默认值**：新接入的 sysprompt 开关默认**关**（选了才生效）还是默认开（所有人提示词立刻多一段）？
   ⇒ 主脑建议：**默认关**。这既守住「零回归」，也符合本仓既有裁定「兼容目标优先于我们自己的旧行为，但不可逆项等用户点头」。
   ⚠️ 与「提示词层照抄 ST 默认、不加 Palink 自有护栏」的裁定不冲突：那是"别加 ST 没有的东西"，这里是"补 ST 有而我们没有的槽位"。
3. **reasoning 要不要做**：收益偏外观、风险在解析链。⇒ 主脑建议**本轮不做**，等 P2-24/采样类验收跑完再评估。
4. **instruct 要不要做**：⇒ 主脑建议**明确不做并写进台账关闭**，避免后人反复重提。
