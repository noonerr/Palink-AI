## 4. 🔴 经验教训全集（最重要的一节）

这些是本轮**实际踩过并付出代价**的坑。按"代价从大到小"排。

### 4.1 判「API 契约形状」的证据优先级：真机产物 > 类型声明 > 注释
我判错过一次 `getCharWorldbookNames`：依据源码注释写的"ST 语义是 Promise"，断言契约是
`Promise<string[]>`，还写进了交接文档。结果另一位 agent 用真机证据推翻了我：
- `st-plugins/third-party/JS-Slash-Runner-main/@types/function/worldbook.d.ts:32` 声明返回
  `CharWorldbooks`（**非 Promise**）
- `backend/data/smart_card_assets/` 三个真机 MVU bundle 原文：
  `getCharWorldbookNames('current').primary ?? 'unknown'`（**不 await**）
⇒ 真缺陷是"三处都返回 Promise 而消费者不 await"。**注释是上一任的推断，不算证据；
真机 bundle 就在本仓，先 grep 再下结论。**

### 4.2 判测试覆盖面：`grep "it("` 不够，要看 `it.each`
我一度判定某测试"只覆盖主页面轨、单间轨裸奔"——因为只看到 6 个 `it` 且标题都写"主页面轨"。
实际是 `it.each(FRAME_TRACKS)` 展开了另两轨。**必须看有没有参数化展开。**

### 4.3 共享工作区里 `git checkout -b` **不能**隔离（已致一次污染）
git 分支是**工作区级**状态，不是进程级。实测：丙1 执行 `checkout -b ro-survey` 时工作区已被
S2 agent 留在 s2 分支上 ⇒ ro-survey 从 0738300 切出，**把别人的生产提交带进自己分支**。
✅ **正解：`git worktree add <独立目录> -b <分支>`**（已实测可用）。
⚠️ 但**需真机的任务不能用 worktree** —— 容器 bind mount 指向主工作区，`frontend/dist`
本身是 bind mount，在 worktree 里构建产物落不到容器看的路径 ⇒ 这类任务**主工作区串行**。

### 4.4 worktree 的 node_modules 是目录联接，**`rm -rf` 会删掉真实依赖**
`node_modules` 469M，不能每个 worktree 重装（本机 `npm install` 会被 SIGKILL），
用 `cmd //c mklink /J` 联接共享。**清理时只能用 `cmd //c rmdir` 断联接**，
`rm -rf` 会顺着联接删掉主工作区真实的 469M。

### 4.5 性能测量：必须同页面连测 ≥3 轮、待内容高度稳定后取中位
S3 报告写了 **119.1 ms/1000px**（对照基线 28.1 = 4.2 倍劣化），据此"不宣称通过"。
我复现了同一个坑：刚 `goto` 后内容高度仍在变，`maxScroll` 在 9472/14035/42267 之间跳
⇒ **归一化分母不稳**，单点采样会算出 31.2 甚至 81.6。
改用同页面连测三轮：27.2 / 28.9 / 25.6 ⇒ **中位 27.2 vs 基线 28.1 = −3.2%，达标**。
⇒ **单点采样的性能数字一律不可信。**

### 4.6 `git bundle verify` 通过 ≠ 内容含目标分支
verify 只校验**结构完整**。S3 那轮 verify 通过了，但 bundle 里只有主分支，
S3 的 `fcac95b` 压根不在里面 ⇒ 磁盘事故会丢整个 S3。
⇒ **打完必须 `git bundle verify <f> | grep refs/heads` 确认目标分支在内。**

## 7. 本机坑速查（会让命令静默失败）

| 坑 | 正确做法 |
|---|---|
| `python` / `python3` 是微软商店空壳 | 一律用 **`py`** |
| git 重型操作会被 SIGKILL | `fetch`/`clone`/`stash -u`/整树 `tar` 全中招，**`stash -u` 还会永久损坏 .git** ⇒ 本仓禁用。分支出仓只用 `git bundle create` |
| 提交会吞别人暂存区 | 一律 `git commit -o -- <pathspec>`；禁 `git add -A` |
| git bash 无 `curl` | `/c/Windows/System32/curl.exe`，且**必须 `--noproxy '*'`**（Clash 拦 localhost） |
| 前端端口 | **14700**（不是 14000，那是废端口） |
| 动了 `docs/` | 必须 `py scripts/docs/gen_docs_catalog.py` 再 `--check` |
| 改前端 src | 必须重建 dist 容器才看得见：`VITE_OUT_DIR=dist_new node scripts/build-vite.mjs` → `cp -r dist_new/. dist/` → `node scripts/gzip-dist.cjs` → 删 dist_new。⛔ 禁 `mv` 重命名、⛔ 禁 `npm run build` |
| 真机登录态 | 容器内签 admin JWT：`docker exec palink-ai-backend-1 python -c "import os,jwt,datetime;print(jwt.encode({'sub':'admin','exp':datetime.datetime.utcnow()+datetime.timedelta(hours=6)},os.environ['SECRET_KEY'],algorithm='HS256'))"`，注入 cookie `palink_session` |
| 滚动容器 | `.rp-chat-area`（不是 `document.scrollingElement`） |
| 控制台中文是 GBK | 判定只认 ASCII 结构化行和退出码 |
