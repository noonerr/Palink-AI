# 三轨行为对照表（S0 交付物 · 18 条契约测试的输入源）

> 日期：2026-10-12
> 方法：纯代码勘察（只读），三轨 10 个维度逐项对比，全部结论带 file:line；注释自述与代码不符处单列（第 5 节）。
> 用途：S1 补功能的施工清单 + 18 条契约测试的用例来源。

## 0. 总体结论

覆盖度差异最大的三个维度：**① 存储桥**——三轨三套键规则、三种隔离机制（大堂卡脚本改正文换钥匙 / 单间整体替换 localStorage / 帘子 Proxy 视图），只有单间按「卡+会话+源码指纹」隔离；**② 插件 UI 挂载点**——帘子轨有约 50 个 ST 挂载点 id 白名单 + 惰性创建的成熟策略（S2 直接抄它），单间轨被 iframe 结构锁死只能虚拟挂载，大堂轨直落主页面；**③ 隔离与手势闸门**——仅单间轨有 opaque-origin iframe + 帧内密钥手势闸门，大堂/帘子均无隔离无闸门。

**对上游方案的两处实质修正**（详见第 5 节）：
- 「N 消息 = N 份插件执行」**不成立**：同会话内消息走 postMessage 热更新不重建 iframe；真实形态是「N 张带卡消息 = N 个 iframe = N 份全量执行」。性能基线的建模口径要按此修正。
- `sillyTavernPluginRuntime.ts:1615-1620` 的「大堂漏配世界书」自述是**修复前状态**：大堂轨 getCharWorldbookNames 已于 2026-10-05 实现（:1625-1657）。
