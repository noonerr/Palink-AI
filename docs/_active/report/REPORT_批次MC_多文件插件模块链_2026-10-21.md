## 2. ② 断点定位

### 2.1 真包侧：导出本身没问题

把真 `macros.js` **直接当入口**执行（真 `constants.js` 作本地模块）验证：

```
[macros-entry] typeof registerSmartMemoryMacros = function
[macros-entry] typeof MACRO_NAMES = object keys= 12
```

⇒ 转译器规则 9（`export function` 提升到末尾挂 `module.exports`）在该真文件上是**正常的**。
问题不在「函数没导出」，而在**宿主 require 没把 `./macros.js` 交给这个文件**。

### 2.2 宿主侧：相对导入被 ST 同名模块顶替

修复前调用链（`git show HEAD:frontend/src/lib/plugin-system/sandbox.ts`）：

1. `sandbox.ts:5586-5623` `makeRequire(baseDir)`：
   - `:5591` `// 1. ST 模块白名单优先`
   - `:5592` `const normalized = normalizeModulePath(importPath);`
   - `:5593-5594` `const stMod = moduleMap[normalized]; if (stMod) return stMod;`
   - `:5597-5601` 只有 ST 查不到时才解析插件本地文件。
2. `sandbox.ts:2433-2446` `normalizeModulePath('./macros.js')` → 剥掉 `./` → **`'macros.js'`**。
3. `sandbox.ts:5378` `moduleMap['macros.js']` = ST `macros.js` shim（只有 `MacrosParser`，
   **没有** `registerSmartMemoryMacros`）⇒ `:5594` 直接返回它，本地 `macros.js` **从未被执行**。
4. 转译器规则 5 把 `index.js:127` 变成 `var { registerSmartMemoryMacros } = require("./macros.js");`
   ⇒ 解构得到 `undefined`。
5. `index.js:1934` 在 `jQuery(async function(){...})` 里调用 ⇒
   `TypeError: registerSmartMemoryMacros is not a function`，异步回调 ⇒ 真机表现为 unhandled rejection。

同一断点还顶掉了 `./constants.js`：`normalizeModulePath` → `'constants.js'` → 命中
`sandbox.ts:5144` 的 ST `constants.js` shim（只有 `debounce_timeout` 等），
`MODULE_NAME` / `META_KEY` / 13 个 `PROMPT_KEY_*` 全部 `undefined`。
探针修复前 `MODULE_NAME = undefined` 即此。

**一句话**：断点不是导出写入，而是 `makeRequire` 的**解析优先级**——相对路径先被抹平再撞上 ST 白名单，
本地文件被同名 ST shim 遮住。

### 2.3 循环依赖不是本 bug 的成因

对真包 28 个 `.js` 做静态图扫描（只统计 `from './x.js'`）：**0 个环**。
所以本次不是「早引用撞 TDZ」的 E2b 同形问题，也不是循环快照问题。

## 3. ③ 修法与覆盖面

### 3.1 改动位置（`frontend/src/lib/plugin-system/sandbox.ts`）

| 位置 | 改动 |
|---|---|
| `:2474-2491` `joinLocalPaths` | 返回 `string \| null`；`..` **越过插件根**时返回 `null`（旧实现空数组 `pop()` 是 no-op，会静默把越界路径当成插件内路径） |
| `:5621-5668` `makeRequire` | 解析顺序改为：**相对且未越界的本地文件优先 → ST 白名单 → 非相对本地回退 → 空对象留痕** |
| `:5623-5636` `loadLocalModule` | 抽出本地模块加载/缓存；预置的占位 exports **不再在求值后换成新对象**（见 §3.3） |
| `:2799-2807` `buildWrappedCode` prelude | `var module = { exports: __sandbox.__moduleExports \|\| {} };`（入口不传，行为不变） |
| `:2974-2998` `evalLocalFile` | 新增可选 `initialExports`，写入 `globals.__moduleExports` |

### 3.2 解析规则（通用，不是 Smart Memory 专用补丁）

```
相对路径（以 . 开头）
  ├─ joinLocalPaths(baseDir, spec) 不越界 且 pluginLocalFiles 命中 → 本地模块
  ├─ 否则 ST 白名单（normalizeModulePath 后查 moduleMap）
  ├─ 仍未命中且不越界 → 本地回退（保留旧行为，兼容历史路径）
  └─ 仍未命中 → recordStubHit + console.warn + 返回 {}
非相对路径（'foo.js' / '/scripts/foo.js' / '@sillytavern/...'）
  └─ 沿用旧顺序：ST 白名单 → 本地表 → 留痕
```

**语义依据**：ST 里相对 import 按真实文件系统解析。扩展目录下的 `./macros.js` 永远是插件自己的文件；
只有 `../../../extensions.js`、`../../../../scripts/macros.js` 这类**越过插件根**的路径才指向 ST scripts。
本修法把这条边界做成显式判定，覆盖同类的两类历史事故：

- 插件根 `./macros.js` 撞 ST `macros.js`；
- 插件根 `./constants.js` 撞 ST `constants.js`。

同时**不误伤**越界导入：真 `macros.js:40-41` 的 `../../../../scripts/macros.js` 仍走 ST shim
（否则会把插件根同名 `macros.js` 当成 ST 模块，反向故障）。这一点有 MC-2 用「本地放一个同名
`extensions.js` / `macros.js` 作为诱饵」专门反证。

### 3.3 顺带加固：循环依赖的 exports 身份

旧实现：`pluginLocalExports.set(key, {})` 预置占位 → 求值结束后 `set(key, 新对象)`。
循环链上先拿到占位对象的模块会**永远持有空对象**（对象身份被换掉）。

新实现：把占位对象直接作为 `module.exports` 传入模块求值（`__moduleExports`），导出写在同一个对象上；
仅当模块自行 `module.exports = ...`（CJS 形态）时才以返回值为准。真包无环，此改动不影响它，
但让「多文件插件 + namespace 循环」这一类不再静默丢导出（MC-3 覆盖）。

### 3.4 覆盖面与未动项

- 入口与**所有本地模块**共用同一解析器（`makeRequire(dirOf(localKey))`），支持子目录入口
  （`entryPath='core/main.js'`，MC-2 覆盖）。
- 未改 `transpileEsmToCommonJS` 任何规则：规则 8/8b/9/11 与 E2b 活绑定原样保留。
- 未改 `moduleMap` 任何 shim、未改 134 键 TavernHelper。
- 真包生产输入（31 modules）实测 27 个模块全部求值、宏注册成功。

## 7. ⑦ 否证主脑

1. **否证「函数导出根本没挂上」的字面理解**。
   真包 `macros.js` 单独当入口执行时 `typeof registerSmartMemoryMacros === 'function'`，
   `MACRO_NAMES` 12 键齐全 ⇒ 转译器规则 9 的导出写入是好的。准确结论是：
   **导出挂了，但宿主 require 没加载这个文件**——`./macros.js` 被 ST 同名 shim 顶替。
   因此不需要动规则 8/8b/9/11，也不该按「导出丢失」去改转译器。

2. **否证「E2b 同形（早引用撞 TDZ）」**。E2b 是同一模块内 export 列表早于声明；
   本 bug 是**跨模块解析**，真包静态图 0 环，与 TDZ 无关。E2b 的活绑定一行未动。

3. **主脑只点名了 `registerSmartMemoryMacros`，漏了同一根因的 `./constants.js`**。
   真包 21 个模块从 `./constants.js` 导入 13 个常量，修复前 `MODULE_NAME = undefined`。
   只修 macros 这一条会立刻在下一步撞上 `extension_settings[undefined]` 一类的静默失效；
   本批按类修，两条一起消失。

4. **「31 个模块」是存储数，不是运行数**。站点库里 31 modules 含 `eslint.config.js`、
   `test-harness.mjs`、`tests/*.test.js`；真实 import 链只求值 **27** 个。
   验收时别把「加载了 31 个」当指标，应以「入口无 unhandled、宏注册成功」为准。

5. **主脑提示的「循环/顺序敏感」在本真包里不成立（0 环）**，但仍按任务书补了 MC-3 并加固
   占位 exports 身份；这是防御性改动，不是本 bug 的成因，避免报告里把因果说反。
