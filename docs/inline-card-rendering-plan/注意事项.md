# 智能卡完全内联改造 — 注意事项速查（Handover 前必读）

> 这是执行 agent 最容易踩坑的点。详细论证见 spec.md §4。

## 1. 最关键的冲突：卡片 JS vs sanitize

- 现有 `sanitizeStCompatHtml`（Message.tsx L177）**FORBID script/iframe/object/embed/base/form**
- smart-card **必须保留 script**（用户明确要求卡片 JS 执行，MVU/状态栏依赖）
- 结论：**必须新建** `sanitizeInlineCardHtml`（允许 script），不能复用旧的
- 也不能让 smart-card 简单走现有的 `isHtmlCardContent` 分支——那条会用 FORBID script 的清洗器

## 2. 脚本执行时机（对齐 ST）

- 参考 `frontend/public/st/palink-smart-card.js`：ST 用 fetch 拦截 + MutationObserver 延迟执行
- 内联后 `<script>` 由浏览器自动执行；`DOMContentLoaded` 可能已过，需替换为 `palink-card-init` 事件
- 验证 `document.currentScript` / 相对路径引用在内联后仍正确

## 3. 样式隔离（CSS 污染）

- 内联后卡片 `<style>` 作用整个聊天页（ST 同样如此，**不 scope**）
- 作者用 `.mes_text .xxx` 自约束——绝不能重新 scope
- 不同卡片 class 冲突 = ST 固有行为，接受

## 4. 多租户安全（已降级，不可逆）

- 用户接受放弃沙箱（来源可信、威胁低），spec 记录在案
- 内联后卡片脚本能读 `localStorage.palink_token`——已知取舍，不要试图"修复"它

## 5. 沉浸式 launcher 不能随 iframe 一起删

- `id="launcher"` / `mg-launcher` 家族必须保留 portal overlay
- 判定仅基于显式 launcher 元素，**绝不能用 body{height:100vh}/flex 居中/fixed 样式特征**
- 高度 `Math.max(visualHeight, innerHeight, 320)`，不用硬编码 760

## 6. 插件兼容红线（历史踩坑总结）

- HTML 消息必须内联进 `.mes_text`（Galgame 读原始 HTML 渲染 overlay）
- CSS 不重新 scope（`.mes_text .xxx` 选择器只有 .mes_text 是容器本身才匹配）
- HTML 检测用 `isHtmlCardContent`，不要单独用 `looksLikeSmartCardHtml`（太窄漏判）
- 用户消息气泡 bubbles 分支固定 `bg-slate-900 text-white`

## 7. 部署（必踩坑）

- volume mount `./frontend/dist:/usr/share/nginx/html:ro` 覆盖镜像 dist
- 部署 = host `npm run build` → `docker compose restart frontend`
- `docker compose build frontend --no-cache` 单独执行**不生效**
- 调试时对比源码 vs dist `index-*.js` LastWriteTime，防 stale dist
- 若改动了构建产物 hash，记得验证线上 serving 的 bundle 字节数匹配

## 8. 删除时别误删共用

- `looksLikeSmartCardHtml` / `looksLikeRenderableCardHtml` / `isHtmlCardContent` / `SmartCardAction` / `InlineHtmlRenderer`——**html-display 分支和 Message.tsx 还在用，不能删**
- 删 iframe 相关代码前先 grep 全局确认无残留引用
