### 🟡 B1 — 世界书向量召回：机制可用，但双开关都关（非 bug）
- **现象**：`world_book_entry_vectors` 全库 **0 行**；263 条世界书条目里 `vectorized=true` 为 **0**；全局 `vectorized_enabled` 默认 `False`（`roleplay_prompt_assembly.py:4156`）。
- **正向验证（零成本，已做）**：在容器内用 ORM 建一条 `vectorized=true` 中性世界书条目 → 调 `WorldBookVectorService.sync_worldbook_vectors` → 返回 `{'synced':1,'skipped':0,'deleted':0}`，向量表成功写入 1 行；清理后库回到 0 行。证明嵌入（本地 ollama bge-m3）与写入链路均正常。
- **结论**：这是**两道独立开关的选择性功能**（条目级 `vectorized` + 全局 `vectorized_enabled`），现网 0 行 = 两个开关都没开 = "没人在用"，**不是坏了**。关键词/选择性召回（非向量）走另一条路，不受影响。
- **待你拍板**：是否要让导入世界书时默认开启向量化、并把全局开关默认打开（表 C 第 3 项）。这决定世界书向量召回"默认生效"还是"保持 opt-in"。
