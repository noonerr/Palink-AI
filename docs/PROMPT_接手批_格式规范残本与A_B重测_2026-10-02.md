## 1. 一句话任务

角色卡的「对话渲染格式规范」现在**每轮都注入**了，但注入的是被自家降级逻辑啃剩的 **31.5% 残本（237/752 字符）**，主段整段消失。你的活：**修掉吞段 → 用 A/B 实验分离真因 → 按结果决定是否需要助手预填**。

## 2. 现象与影响面（用户实测）

Palink 是面向外部用户的 iPhone PWA + Web 角色扮演产品。使用带「对话渲染系统 v7.1」脚本的角色卡（样本卡：`露缇雅1.2`，char id `4af0c6d3-4fc8-4ad0-b22f-8ce64f52eb44`）时：

- 会话首轮 AI 回复：**有排版框**，但正文上下各露出一对 `<content>` 记号；
- 之后每一轮：**无框、无任何记号**，且同一 prompt 反复重试（swipe）**结果一模一样** → 确定性，不是采样抖动。

卡自带的显示侧正则（`characters.extensions` → `regex_scripts` 中名为「正文美化」）：

```
/<(story|Lnterleaving|now_plot|content|正文)>([\s\S]*?)<\/\1>/gi
```

单层反向引用，要求**同名闭合**。匹配不到 → 不出框。

## 4. 你要修的缺陷（已实测定位）

`roleplay_prompt_assembly.py` 的 `_strip_bubble_marker_instructions` 用**段落标题字面量**做整段跳过：

```python
_BUBBLE_SECTION_HEADING_RE = re.compile(r"^\s*\[\s*(?:对话渲染格式规范|情绪词约束)")
```

设计假设是「这两段只讲 @bubble」。这个假设在该卡**运行时上报的 752 字文本**上不成立——两段里装着非 @bubble 的格式规则。

逐跳实测（真实 DB 行 + 真实函数，容器内离线跑）：

```
原始上报        752 字符  段落: [对话渲染格式规范] [正文标签规则] [背景标签规则（强制）] [情绪词约束]
经 _strip_bubble_marker_instructions → 265 字符（−487，−65%）
   段落只剩: [正文标签规则] [背景标签规则（强制）]      ← 主段与情绪词段整段被吞
经 _downgrade_two_layer_shell_to_single → 237 字符，<content> 归零
```

⇒ **每轮到场的规范 = 原规范的 31.5%**，最可能写着「整体输出结构 + 示例」的 `[对话渲染格式规范]` 根本没到场。

### 4.1 施工要求

1. **判据从"标题"改成"内容"**：先按 `^\s*\[` 切段；某段**只有当其全部非空行都含 `@bubble`** 时才允许整段丢弃；否则保留该段、仅逐行剔除含 `@bubble` 的行。标题字符串**不得**再作为丢弃条件（现有常量至多用于日志归类）。
2. **⑤ 与新判据共存回归**：`[对话渲染格式规范]` 段回到场后，确认 `_downgrade_two_layer_shell_to_single` 仍把双层要求改写成单层，**终态文本不得残留字面 `<content>`**（否则卡正又会把内层记号漏进框里，就是第 2 节那个"上下露一对记号"的成因）。
3. **证据双计数**：`extra.ext_prompts.applied` 现在只有一个 `chars`。改成同时记 `chars_reported`（原始上报）与 `chars_injected`（降级后注入），再加 `dropped_sections`（被丢段落的标题列表）。**这是防复发的核心**——今天这个吞段问题之所以拖了一轮，就是因为只有一个数。

## 5. 前人结论作废清单（照抄会带偏）

- ❌「降级链不吞规范，`now_plot`/`<content>` 全保留」——**错**。该结论是用 `plugin_scripts` 里那份 **242KB 脚本源码全文**跑剥离函数得出的，口径选错：应当用**运行时上报的那 752 字**。真实上报文本里恰好带着被硬编码点名的两个标题，所以吞段在真实路径上大规模生效。
- ❌「多轮裸文历史的近因模仿压过了规范，所以需要 P3 预填」——**归因未成立**。对照实验没做：拿去对抗历史近因的规范本身是 237 字残本。首轮遵从、后续跳壳，用"残段太弱"同样解释得通。
- ❌「模型遵循度随机抖动」——已被"重试一模一样"否掉。
- ⚠️ 已驳回的两个设计，别重新提：① 用 `frame:<uuid>` 当保活键（`CharacterCardRenderer.tsx:53` 每次挂载 `crypto.randomUUID()`，新键永远不等于旧键 → 复活分支永不进入、`_dormantSources` 无限堆积）；② 缺席检测走 `toast`（`SmartCardCompatController.ts:965-976` 对 `severity!=='info'` **无任何门控**，会直接弹给外部用户；缺席只允许 `console.warn` + 落 `extra`）。

## 6. 修完必做的 A/B（这是本批唯一"结论产出"）

同一张卡、同一个克隆会话、同一模型，两组条件各跑：

| 条件 | 注入内容 | 采样 |
|---|---|---|
| A | 完整规范（修好吞段后的到场文本，≈752 字降级为单层） | 首轮 5 次 swipe + 第 3 轮 5 次 swipe |
| B | 残本（临时强制走旧段落吞并逻辑，≈237 字） | 同上 |

**判据必须是机器断言，不许人眼**：把每次输出喂给该卡「正文美化」的真实 `find_regex`，断言命中次数 ≥1（=出框），并统计成对外壳率。

结论分支：
- A 遵从、B 跳壳 → 真因是规范强度，**P3 预填不立项**，收工。
- A 也跳壳 → 才是历史无外壳参照的问题，此时提 P3（预填 `<now_plot>` 开头 + 输出侧闭合校验），并附本实验数据。

约束：**不许对真实记录 `character_chat_messages.id=2468` 做任何重生成**（swipe 会被覆盖，用户正在看）；克隆会话必须沿用同一 char id（`plugin_scope_mode='allowlist'` 与门控判定按卡走，换卡结果不可比）。

## 8. 仓库铁律（违反=事故）

- **禁止** `git add -A` / `git add .`（多 agent 合住仓库），一律逐项 pathspec。
- **别动** `frontend/dist`（容器 nginx bind mount 的在用产物，删/改名即前端白屏；且 build 第一步就清空它在用的 dist）、`backend/data`。
- **本批不要重建前端 dist**：工作区有并行会话未提交的前端改动，build 会把它们一并烤上线。重建时机由用户单独拍板。
- 备份只进 `_BACKUPS/YYYY-MM-DD_主题/`，必须带 `BACKUP_INFO.md`（日期/原始来源/原因/后续待办四要素）并更新 `_INDEX.md`；禁止改写存量备份内容。
- 清理走三步：列清单 → 隔离到 `_BACKUPS/_QUARANTINE_<日期>/` → 门禁通过且用户确认后再删。不许直删。
- 统计未提交**只用 `git status --porcelain`**。`git ls-files -o` 在本项目极慢（`_BACKUPS` 内有超 Windows MAX_PATH 的自嵌套 node_modules，会刷出百万行警告）。
- 装配链属 `palink-native` 唯一模式，改动前尊重 `AGENTS.md`；`st_groups.py` 名字带 st_ 但**是 Palink 自有群聊后端，勿删**。

## 9. 环境与取证手法（省你半天）

- 栈在用户本机 docker：`palink-ai-backend-1` / `palink-ai-frontend-1` / `palink-ai-db-1`（pgvector pg15，`ai_user/ai_password/ai_hub`）/ `palink-ollama` / `palink-new-api`。
- `docker exec` 需 `MSYS_NO_PATHCONV=1`；后端容器里**没有** ps/git/wget。
- SQL 走文件 + stdin：`MSYS_NO_PATHCONV=1 docker exec -i palink-ai-db-1 psql -U ai_user -d ai_hub -A -F'|' -t < /c/.../q.sql`。别在 Git Bash 用 printf 拼多层引号造脚本（`\s` 会被吃掉）。
- 跑 Python 探针：把脚本写到 `C:\Users\Pall\AppData\Local\Temp\` 再 `docker exec -w /app -i palink-ai-backend-1 python - < 该文件`。Git Bash 的 `/tmp` 对 Windows 侧 python 不可见；某些写文件操作会被本机代理拦截。
- **绝不在容器里跑全盘 grep**（会打挂 Docker VM，恢复要重启 Docker Desktop）。
- **隐私红线（用户明确要求）**：不许读取、打印、贴出聊天正文/生成内容。取证只允许输出**长度、标签名骨架、布尔判定**。注意自闭合标签 `<X/>` 用 `</?[a-zA-Z_][\w:-]*>` 这种模式**匹配不到**，必须用 `</?([a-zA-Z][a-zA-Z0-9_]*)[^>]*/?>` 取名字。
- 判定行输出用 ASCII 标记（终端中文会乱码，但判定行可信）。
