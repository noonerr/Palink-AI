### 2.2 iframe 内部状态机

每个卡 iframe 在 t=2s → t=9s 之间发生以下变化（probe2 全量抓帧）：

| 帧                 | 0      | 1      | 2      | 3      | 4      | 5      | 6      |
| ----------------- | ------ | ------ | ------ | ------ | ------ | ------ | ------ |
| t=2s `<style>` 数  | 8      | 8      | 8      | 9      | 8      | 9      | 8      |
| t=2s `<script>` 数 | 8      | 8      | 8      | 9      | 8      | 9      | 8      |

| t=8s `bodyLen`    | 61 985 | 61 985 | 61 985 | 79 145 | 61 985 | 79 593 | 61 985 |

关键观察：

1. **`<style>` 不是被选择器删的**。probe3 给 `Node.prototype.removeChild` / `Element.prototype.remove` 装上拦截，统计"删除的 STYLE/LINK 节点"，8 秒内**零记录**。
2. **`<style>` 不是被 `head.innerHTML = …` 整体换的**。probe4 给 `Element.prototype.innerHTML` setter 装拦截，并在 documentElement 装 `MutationObserver`，8 秒内**零记录**。
3. iframe DOM 元素**没被 React 重挂**。probe6 给每个 iframe 打 `data-palink-probe-marker`，8 秒后 7 个 marker **全部存活**。
4. probe6 在父页直接读 `iframe[4].contentDocument.head.childNodes`，结果是**空串**——配合 `page.frames()` 抓的"`<style>` 数 0 / `<link>` 数 2"对照，可推断：少数帧的 `head` 已被掏空成"几乎空白"（只剩 link + 注入脚本），多数帧的 head 也只剩运行时的脚本，**卡片自己的 `<style>` 都没了**。

综合 1+2+3+4：**`<style>` 既不是被 DOM API 删的、也不是 head 被赋值整体换的；iframe 没换；只剩两种可能 —— ① 该帧的 `document` 被 `document.open()/write()` 重置过 ② 帧的 srcdoc 被父侧改写了但又写回来**。

进一步看：probe2 t=2 / t=8 的 srcdoc 长度完全一致（≈ 893 600 字节），说明 srcdoc 字符串没换，但 document 仍可能是被 `document.write` 整页重写过。负责"重置 document"的嫌疑代码来自两处：

- **插件 bundle `palink-st-extension-…js`（4MB 级）**——错误堆栈反复出现在该 bundle 的 78619 行；
- **card-script-runner 下发的卡脚本**——`相册` 脚本里有一段 `destroyAll()`，会从 `topDoc`（父页）移除 `tavern-cg-album-style` 与 `floatBtn` / `modalEl` / `lightboxEl` / `tcg-toast-container`：
  ```js
  const styleEl = topDoc.getElementById('tavern-cg-album-style');
  if (styleEl) styleEl.remove();
  ```
  注意 `topDoc` 拿的是**父页**——但卡脚本在 iframe 里跑，`top` 就是父页。这条清理**不该动 iframe 的 `<style>`**。如果清错了 `topDoc`（父页），不会让 iframe 失样式。

所以 C1 的头号嫌疑落在 **插件 bundle 在 iframe 里跑起来后动了 `document.head`**。ST 1.18 风格的扩展脚本在初始化后期做"清理 head"是常见动作（为了塞自己的 UI），4MB 解析+执行正好 3~5 秒完成，与现象完美吻合。

### 3.3 [方案选型] iframe `<style>` 被插件重置（C1 / C3）

下面是按工作量从小到大排序的三种方案；**C1 是用户主诉，必须选一个**。

#### 方案 A：黑名单 + 周期守门（最小手术）

`CharacterCardRenderer.tsx` 在 frame 挂载后：

1. 抓取 srcdoc 里所有 `<style>` 节点的 `outerHTML`（用 `frameDoc.querySelectorAll('style')` 一次快照）；
2. 用一个 `MutationObserver` 监听 `frameDoc.head` 的 `childList`，一旦发现某个 `style` 节点消失（matched `outerHTML` 命中快照），立即克隆一份补回去；
3. 守门在 frame 卸载时清掉。

**代价**：≈ 30 行代码 + 1 个测试。**风险**：插件若把整张 head 一起换（包含快照里的 style），快照会作废——可降级为每次 head childList 全清就 re-inject 一次。**最坏情况**：性能开销 < 1ms/次。

#### 方案 B：把卡 CSS 搬进 Shadow DOM（中等手术）

- 解析 srcdoc，把其中所有 `<style>` 内容抽出 → 合成 1 个 `<style>` → 塞进**挂在某个 host 元素上的 Shadow DOM**；
- 卡片 HTML 主体进 Shadow DOM 的 body；
- 父页 → iframe 的 postMessage 路径不变（iframe 还在，只是内部多一层 Shadow）。

**代价**：≈ 200 行代码，HTML 解析器要稳健（DOMPurify 已经做了大部分）；需要新增 1~2 个测试覆盖"主样式卡内的 img/script 与 Shadow 边界"。

**收益**：插件对 light DOM head 做任何事都不影响卡样式；`destroyAll()` 误清也不会清到卡样式。

#### 方案 C：分轨，插件仍跑主页面 / 卡片仍跑 iframe（架构调整）

回到 S3 之前的方案：插件保留在主页面注入（`palink_st_plugin_main_page_injection=1` 默认开），卡继续在 iframe 跑。**相当于 S5 退一步**。会牺牲"三轨并一轨"的清理成果，但短期最稳。

> 决策点交回用户：保三轨合一，还是短期保卡样式？

### 3.4 [顺带] 噪音改善（C3）

- part-08 的 `unknown error` 兜底字符串可加 `stack` 前 80 字符进 toast，定位"是哪个 URL 加载失败 / 哪个 frame"更具体；

### 7.1 C1 —— 帧内样式守护

**文件**：`frontend/src/components/ui/custom/smart-card-runtime/runtime-body/part-08.ts`（新增 IIFE，约 115 行）  
**辅助**：`frontend/src/components/ui/custom/smart-card-runtime/style-guard.ts`（父侧版本，保留给 trusted-native 卡；对 opaque origin 卡返回 null）

实现要点：

1. `DOMContentLoaded`（或已 ready 时立即）拍 `document.head` 里 `style, link[rel="stylesheet"]` 的 `outerHTML` 快照；
2. `MutationObserver(document.documentElement, { childList: true, subtree: true })`，**只在 `removedNodes` 出现 `STYLE` / `LINK` / `HEAD` 时才做恢复**（避免卡片高频 DOM 更新时每次都跑全量比对）；
3. `setInterval` 700ms × 60 次（约 42s）自愈，兜住 observer 失效 / head 整体替换；
4. 恢复时只补"快照里有、当前文档里没有"的节点，幂等；
5. 重复安装先调 `window.__palinkStyleGuardDispose()` 卸掉上一份，防 observer/定时器叠加。

观测面（与 `__palinkFrameErrors` / `__palinkIframeLru` 同口径）：

| 变量                                  | 含义                      |
| ----------------------------------- | ----------------------- |
| `window.__palinkStyleGuardSnapshot` | 快照条数（0/undefined = 没装成） |
| `window.__palinkStyleGuardRestored` | 累计补回节点数                 |
| `window.__palinkStyleGuardLastAt`   | 最近一次补回时间戳               |
