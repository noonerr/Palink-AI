## 2. 改了什么（逐条 + 证据）

### 2.1 批次 0 · 缺口可见化

#### ① 修 `registerSlashCommand` 的 ReferenceError（顺手发现的真 bug）

| 项 | 内容 |
|---|---|
| 现象 | setup 脚本模板内**裸调** `recordStubHit(...)`（原 `:1196`） |
| 根因 | `recordStubHit` 是本模块的 `import`，而 setup 脚本是**注入页面的独立 `<script>`**（页面全局作用域），里面根本没有这个名字 |
| 后果 | 每次调用 `window.registerSlashCommand` 都抛 **ReferenceError**，**既不执行命令也不留痕迹** → 缺口不可见 |
| 修法 | 仿照既有 `__palinkGetCsrfToken` 模式，经 `window.__palinkRecordStubHit` 转交 |
| 守卫 | 测试「② registerSlashCommand 调用不抛错」+「③ 降级被真正登记进 `__palinkCompatStats`」 |

> 这条是 `SOP_Agent交付自查清单.md` §9「反向证据」的镜像：**「有这个函数」≠「这条链路通」**。

#### ② 经典轨加 `window.TavernHelper` 命名空间 + Proxy 兜底

此前经典轨**完全没有** `window.TavernHelper`，且没有 Proxy 兜底（对比 iframe 轨 `SillyTavernCompatRuntime.ts:5441`）→ 卡脚本写 `TavernHelper.xxx` 一律 undefined，且**不进降级统计**。

Proxy 行为（三档）：

| 情况 | 行为 |
|---|---|
| 经典轨已实现的 API | **转发到同名 window 全局**（同一引用） |
| 未实现的 API | 返回**记桩函数**：调用后登记进 `__palinkCompatStats`，返回 undefined |
| `Symbol` / `then` / `constructor` | 放行 undefined（不污染 await、JSON 序列化、devtools 展开） |

**刻意不做宽的边界**（三思后的取舍）：

- ❌ **不给 `window` 套 Proxy** —— 那会让任意未定义全局变成"假函数"，插件的能力探测全面失真。只代理 `TavernHelper` 这一个命名空间。
- ❌ **`has` trap 不骗人** —— 只对真能取到的名字返回 `true`，插件用 `in` 做能力探测时不误导它。（iframe 轨是恒 true，本轨故意不同）
- ✅ 记桩函数**按名字缓存**，同名取两次拿到同一引用（否则插件做函数比较/去重会不一致）。

#### ⚠️ 本条的**副作用风险**（写报告时漏记，补）

「让缺口可见」不是没有代价的。**行为变化前后对比**：

| | 改之前 | 改之后 |
|---|---|---|
| 插件调 `TavernHelper.foo()`（未实现） | → `undefined is not a function` 或 `typeof` 守卫**跳过整段逻辑** | → 拿到函数 → 守卫**通过** → 真的调用 → 返回 `undefined` |

**风险**：原本会被守卫跳过、安全降级的分支，现在会**走进去**。如果那段逻辑后续对返回值做了非null假设（如 `.length`、解构、`await` 后取属性），就可能**从"静默不生效"变成"报错"**。

- 已缓解：返回值是 `undefined` 且 `typeof` 是 `function`，大多数 ST 脚本的写法能扛住。
- **未验证**：真机上这条会怎样 —— 属于 §4「没做到的」第 2 条，**必须真机跑一遍才能下结论**。
- 若真机发现某插件因此崩：退路是把 `TavernHelper` 的记桩改成「登记但不返回函数」（回到改前行为，只保留可见性）。**这个开关值得预留。**

### 2.2 批次 1 · L1 设置 facade

#### ③ 挂载设置 facade（4 个成员）

| 成员 | 挂法 | 为什么这么挂 |
|---|---|---|
| `SillyTavern.extensionSettings` | **同一对象引用**（= `runtime.getExtensionSettings()`） | 插件是「原地改 + 事后落盘」（`_.set` → `saveSettingsDebounced`）。**拷一份就等于永远写不回去** —— 这是本批最容易做错的地方，专门写了测试钉住 |
| `SillyTavern.saveSettingsDebounced` | 委托（不快照） | `window.saveSettingsDebounced` 可能被后置覆盖，委托才拿得到最新 |
| `SillyTavern.chatMetadata` | = `window.chat_metadata`（同一对象） | 经典轨此前完全没有 chat_metadata |
| `SillyTavern.saveMetadata` | 记桩 + resolve | 经典轨暂无 chatId→后端桥。**不做静默 no-op** —— 显式登记「仅本次会话有效」 |

#### ④ 🔴 **修那个 404 死路径**（本次最实质的修复）

| 项 | 内容 |
|---|---|
| 现象 | `saveExtensionSettings()` POST `/api/plugins/runtime/settings` → **后端从未注册过该路由** → 被 fallback 接成 404「插件不存在」 → 前端 catch 掉只打一行 console.error |
| 后果 | **「设置保存」从上线起就是死路径**：插件改了设置，刷新即丢 |
| 修法 | 新增 `POST /api/plugins/runtime/settings`（`plugins.py`），落点 = `UserSetting.silly_tavern_settings.extension_settings` |
| 落点选择 | **与 ST iframe 轨 `/api/settings/save` 同一个家**，避免三个家分裂（SPEC §4.3） |
| 合并语义 | **namespace 级整体替换**，未带来的 namespace 原样保留（与 `/api/settings/save` 同口径） |
| 限额 | namespace 数 64 / 单个 256KB / 总量 2MB；超限的键**跳过并列入 `skipped`**（不静默丢数据） |
| 归属权 | `user_id` **从 token 取**，绝不接受前端传参 |

#### ⑤ 打通读路径（否则存了拉不回来）

⚠️ **这一步差点漏**：`GET /api/plugins/runtime/config` 原本只聚合**插件 config** 的 extension_settings，不含 UserSetting。
只加写端点不改读路径 = 存了但下次拉回来还是旧的 = **等于没保存**。

已改：在 `_build_sillytavern_runtime_config` 里合并用户级设置，**放在插件 config 之后**（用户改过的值优先于插件导入时的默认值）。

#### ⑥ 补只读项（A1/A3/A4/A5/A6）

| API | 数据源 | 状态 |
|---|---|---|
| `getLorebookEntries` | 别名到已有 `getWorldbook`（`/api/worldinfo/get`） | ✅ **真数据** |
| `getPresetNames` | `/api/roleplay/presets`（注入时预取到缓存） | ✅ **真数据** |
| `getCharLorebooks` | `GET /api/worldbooks?character_id=..&type=character_book`（后端已带 `user_id` 过滤） | ✅ **真数据**（同步读缓存 + 惰性刷新） |
| `getCurrentCharPrimaryLorebook` | 同上取 primary | ✅ **真数据** |
| `builtin` | `saveSettings` 真落盘 + `uuidv4` 真实现 + 其余记桩 | ✅ |
