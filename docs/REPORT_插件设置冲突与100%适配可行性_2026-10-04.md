## 1. 口径：先澄清一个必须先说清的事实

### 1.1 当前 Palink 里跑的是**卡脚本**，不是「酒馆助手」扩展本体

这一条决定了后面全部讨论的落点，必须先钉死。

| 项 | 值 | 证据 |
|---|---|---|
| DB 里那条插件记录 | `酒馆助手`（`plugin_type=tavern_helper`，`source_type=character_card_extension`） | 上位报告 §1 |

### 3.1 B 层（插件本体 4 作用域）

| 作用域 | 插件走的 API | Palink 经典轨 | 判定 |
|---|---|---|---|
| **global** | `extension_settings['tavern_helper']` + `saveSettingsDebounced()` | ❌ 无 `window.extension_settings`；`saveSettingsDebounced` 打**不存在的端点**（§6） | 🔴 断 |
| **character** | `character.data.extensions` + `POST /api/characters/edit` | ⚠️ 端点**存在**且接受 `extensions`（`silly_tavern.py:2536-2544`）；但 `characters[id].data` **不存在**（§3.3） | 🟡 半断 |

### 3.2 A 层（卡脚本真正在用的）

| API | Palink 经典轨 | 后果 |
|---|---|---|
| `SillyTavern.extensionSettings` | ❌ **未挂载**（全仓 `SillyTavern.extensionSettings =` 零命中） | MVU 设置**读不到也写不进**（lodash `_.get/_.set` 对 undefined 静默 no-op）→ 设置面板恒为默认值、改完刷新即丢 |
| `SillyTavern.saveSettingsDebounced` | ❌ **未挂载** | 即使能写也无处落盘 |
| `SillyTavern.chatCompletionSettings` | ❌ **未挂载**（只在 iframe 轨 / `getContext.ts` 有） | 脚本 `if (!Aa(e)) throw new Error('openAiSettingsUnavailable')` → 「额外模型解析配置」**抛错** |
| `getLorebookSettings` / `setLorebookSettings` | ❌ **全仓零实现** | MVU 的世界书设置读取失败、推荐设置写不进（对应缺口报告 A2/A8） |

| `saveSettingsDebounced`（裸全局） | ✅ 有（`sillyTavernPluginRuntime.ts:1206`） | 但**打不存在的端点** → 死路径（§6） |

### 3.3 一个易被漏掉的细节：`characters[id].data` 不存在

插件 `writeExtensionField`（`src/util/tavern.ts:194-262`）的实现假设 ST 的 `v1CharData` 结构（**有嵌套 `data`**）：

```js
let character = characters[Number(id)];
if (_.isEqual(_.get(character.data.extensions, field), value)) return;   // ← data 为 undefined，静默通过
_.set(character.data.extensions, field, value);                          // ← lodash 对 undefined 静默 no-op
...
const payload = { ch_name: character.name, character_version: character.data.character_version, ... };
//                                                              ^^^^^^^^^^^^^^^^^ TypeError
```

而 Palink 经典轨的 `ctx.character` 是**扁平**的（`CharacterChat.tsx:1712-1726`：`name/description/personality/scenario/first_mes/mes_example/creator_notes/tags/avatar/extensions`，**没有 `data` 键**），`characters[id] = Object.assign({}, ctx.character, { avatar })`。

→ **`character.data.character_version` 会抛 TypeError**。

**但这是「潜伏缺口」不是「现症」**：卡脚本里 `writeExtensionField` 命中数为 **0**（§2.4），所以当前没有触发。一旦有卡脚本调用它，就会炸。

## 4. 不可调节的冲突（真正的红线）

### 4.1 ★ 控制权冲突 —— **唯一真正「不可调节」的一类**

插件的「优化」面板（`src/panel/Optimize.vue`）会**直接改写宿主的全局运行参数**。这不是「功能没实现」，是「插件想夺取宿主的控制权」。

| 开关 | 上游实现 | 干了什么 |
|---|---|---|
| `maximize_preset_context_length` | `panel/optimize/maximize_preset_context_length/index.ts` | `oai_settings.max_context_unlocked = true; oai_settings.openai_max_context = 2000000` |
| `force_recommended_worldbook_global_settings` | `panel/optimize/force_recommended_worldbook_global_settings/index.ts` | `setLorebookSettings({ scan_depth:2, context_percentage:100, budget_cap:0, min_activations:0, max_depth:0, max_recursion_steps:0, insertion_strategy:'character_first', include_names:false, recursive:true, case_sensitive:false, match_whole_words:false, use_group_scoring:false, overflow_alert:false })` |
| `disable_incompatible_option` | `panel/optimize/disable_incompatible_option/index.ts` | `power_user.auto_fix_generated_markdown=false`、`encode_tags=false`、`trim_sentences=false`、`allow_name1_display=true` … |
| `better_message_to_load` | `panel/optimize/better_message_to_load/index.ts` | 读 `power_user.chat_truncation`，直接操作 `#chat > .mes` DOM |

**为什么这是「不可调节」**：

1. **它不是兼容性缺口，是授权边界**。补 `oai_settings` / `power_user` 的等价物，等于**把 Palink 的生成参数控制权交给第三方卡脚本**。
2. **后果不可接受**。卡脚本一句 `oai_settings.openai_max_context = 2000000` 就能把上下文顶到 200 万 token——直接冲击成本与稳定性，而 Palink 是**多用户服务端**（ST 是单用户单页）。
3. **两条路都通不了**：
   - **照做** → Palink 的模型/上下文/世界书参数被卡脚本任意改写，且无审计。
   - **不做（返回 no-op）** → 插件 UI 显示「已启用」，实际什么都没发生 → **静默降级**（比报错更糟，用户与开发者都看不见）。
4. **第三个选项才是正解**：**显式拒绝 + 可见登记**（返回 `false` + `recordStubHit`），并把「为什么不给」写进文档，防止后续 agent 误以为遗漏而"顺手补上"。

> 这一条与上位报告 §9.12.3「权限模型被绕过」同源，但**更隐蔽**：`installExtension` / `deleteCharacter` 那种"管理员能力下放"容易看出来；`oai_settings.openai_max_context = 2e6` 长得像"一个普通设置项"。

### 4.2 数据模型冲突（可调节，但需重构）

| 冲突点 | ST 的模型 | Palink 的模型 | 可调节性 |
|---|---|---|---|
| **预设** | `preset_manager`（`getPresetManager('openai')`），预设对象带 `extensions.tavern_helper.{scripts,variables}` | `prompt_presets` 表（`entries` / `config` / `prompt_order` / `prompt_active` / `prompt_disabled`），**无 `extensions` 概念** | 🟡 可调节：加一个 sidecar JSON 字段 + 实现 `getPresetManager` facade。但**语义不同**（ST 预设 = 一堆采样参数；Palink 预设 = 提示词条目顺序），不是映射而是**新建** |
| **世界书全局设置** | `world_info_settings` **全局单例**（`scan_depth` / `context_percentage` / `insertion_strategy` / `recursive` / …） | **按条目**存：`WorldBookStage.scan_depth / case_sensitive / match_whole_words / …`（`app/models/worldbook.py:52-84`）；`context_percentage` / `insertion_strategy` / `overflow_alert` **全仓零命中** | 🟡 可调节：新增一张全局设置行并让世界书引擎真正消费。但**这是一次引擎改造**，不是补个 API |

> 口径提醒：`min_activations`(36) / `budget_cap`(11) / `max_recursion_steps`(5) / `use_group_scoring`(15) 在后端**有命中**，但都在**按条目/按世界书**的语义上，**不是全局单例**。

### 4.3 单源真相冲突：`extension_settings` 在 Palink 有 **3 个候选家**

| # | 家 | 位置 | 谁在用 |
|---|---|---|---|
| 1 | `silly_tavern_settings.extension_settings` | `UserSetting.silly_tavern_settings`（`POST /api/settings/save`） | ST iframe 轨 |
| 2 | `config.extension_settings`（按插件） | `Plugin.config`（`/api/plugins/runtime/config` 下发） | 经典轨 / 沙箱轨 |
| 3 | `__palink_extension_settings`（localStorage） | `frontend/src/lib/sillytavern/extension-settings-store.ts` | `PluginSettingsPanel` / 沙箱轨 |

**这个冲突是代码自己承认的**——`extension-settings-store.ts:17-19` 原文：

> 后端同步：**暂不在此处调用 `/api/settings/save`** —— 该端点会**整体覆盖** `silly_tavern_settings`，直接携带 `extension_settings` 会**破坏 ST iframe 的完整设置**。后端持久化在 **Phase 3 统一设计**。

→ **可调节**（`/api/settings/save` 已实现 namespace 级合并，`silly_tavern.py:2246-2256`），但**设计未收口**。三条链路并存期间，「在 A 处改了 B 处不生效」是必然的。

## 6. ⚠️ 缺口报告未记录的真问题：`saveExtensionSettings()` 打的是**不存在的端点**

### 6.1 事实

`frontend/src/utils/sillyTavernPluginRuntime.ts:1206-1210`：
```js
window.saveSettingsDebounced = function() {
  if (runtime.saveExtensionSettings) runtime.saveExtensionSettings();
};
```
`:1943-1949`：
```js
async saveExtensionSettings() {
  try { await api.post('/api/plugins/runtime/settings', { extension_settings: this.extensionSettings }); }
  catch (e) { console.error('Failed to save extension settings:', e); }
}
```

**后端有没有这个端点？**

```
grep -rn "runtime/settings" backend/app --include=*.py | grep -v mimosa   # → 0 命中
grep -n "@router\.\(get\|post\|...\)" backend/app/api/plugins.py
```

`plugins.py` 只有 `@router.get("/runtime/config")`（:1466）。`POST /api/plugins/runtime/settings` 会被 fallback 路由 `@router.api_route("/{plugin_id}/{endpoint_path:path}")`（:1959）接住 → `plugin_id="runtime"` 查不到 → **404「插件不存在」**。

全仓 `runtime/settings` 字面量**只有 1 处**（就是那个调用点本身）；前端也没有任何 fetch 拦截层处理它。

### 6.2 后果

| 链路 | 表现 |
|---|---|
| 经典轨 `saveSettingsDebounced()` | 请求 404 → `catch` 吞掉 → `console.error` → **设置永不落盘** |
| 卡脚本 `SillyTavern.saveSettingsDebounced()` | 未挂载（§3.2），**连调用都到不了** |
| 缺口报告的记录 | §5 把 `saveSettingsDebounced` 列入「C 类：经典轨已实现 ✅ 可用」——**口径需修正**：它**存在但无效** |

## 7. 「100% 适配」可行性判定

必须先把「100% 的什么」拆开，否则这个问题无解。

| 口径 | 可达性 | 理由 |
|---|---|---|
| **① 100% 复刻插件声明设置的完整 API 面**（114 成员 facade + 134 TavernHelper） | ❌ **不可达，也不应承诺** | 其中约 45 项是 ST 私有「管理器」API（角色/预设/人设/世界书 CRUD、扩展安装、音频），Palink 有自有实现，硬对齐 = **双写 + 权限下放 + 任意代码执行**（上位报告 §9.12.3） |
| **② 100% 复刻插件设置**的**行为**（含「优化」面板真的改写宿主参数） | ❌ **原理性不可行** | 这不是兼容问题，是**控制权归属**问题（§4.1）。要做到 100% 行为一致，必须把 Palink 的生成/世界书配置控制权交给卡脚本——与「多用户服务端 + 成本可控」直接冲突 |
| **③ 100% 覆盖实装卡脚本真正需要的设置** | ✅ **可达，且是一张有界清单** | §5 的 #1–#6，全部是「接线」或「薄实现」。当前实装 2 条脚本的设置需求已**穷举**（§2.4） |

### 7.1 一句话结论

> **「100% 适配」在口径 ③ 上可达（有界、可验收）；在口径 ①② 上不可达，而且其中一部分（控制权）是「不该做」而非「做不到」。**
> 正确的对外表述是：**「实装脚本的设置需求全兼容 + 明确的不支持清单」**，而不是「插件设置 100% 适配」。

### 7.2 与既有结论的一致性

| 既有文档 | 结论 | 本报告 |
|---|---|---|
| `docs/REPORT_ST插件全兼容可行性评估_2026-09-05.md` §一 | 「100% 全部插件」是伪命题 | **一致**，本报告把「设置轴」单独拆出来验证 |
| `docs/st_plugin_full_compat_feasibility.md` §6 | 原理性不可行；可达上限 = 数据面高兼容 + 前端代跑 | **一致** |
| 缺口报告 §9.12.5 | 补：只读 + 事件 + 常量；不补：CRUD + 导入 + 扩展安装 | **一致**，本报告补充：**「优化」面板的宿主参数改写属「不补」且需显式登记** |
