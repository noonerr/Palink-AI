## 5. 新缺陷与对包E 的否证

### 5.1 K-1（🔴 P1 · 新缺陷）卡侧自有 CSS 在 t8→t16 被抹，守护不覆盖
- **现象**（露缇雅主卡，7/7 帧，复跑一致）：帧内 `<style>` 9→8（F3/F5 10→8）。丢失项按身份列出：
  - `tavern-cg-album-style` **12,140B**：**7/7 帧全丢**（`:root{--tcg-bg-main:#F7F…}`，卡的 CG 相册样式）
  - `galgame-ui-plugin-styles` **440,740B**：**F3、F5 两帧丢失**（galgame 面板整套样式）
  - 同期帧文档字节 176,003→163,703（F3/F5 1.36M→1.04M），与丢失量级吻合。
- **对照包E F-1**：E 丢的是 Palink 自家 5 条插件 CSS（5→0）。J-1 修好后自家 5 条**恒在**（`guardPluginCss=5`、
  `guardRestored=8`），但**卡自己注入的样式**同样被 `head` 整体重写抹掉，且守护**不认识它们** ⇒ 病灶没消失，只是从
  "Palink 的样式"转移成了"卡的样式"。**用户可见后果**：富卡的 galgame/CG 界面在 8–16 秒后失去样式（440KB 整套 CSS 归零）。
- **根因（file:line，函数名锚点为准；`part-*.ts` 是模板字符串，行号会随改动漂）**：
  - `frontend/src/components/ui/custom/smart-card-runtime/runtime-body/part-08.ts:1661 startCardStyleGuard()`
    → `:1663 if (styleSnapshot) return;`（**只拍一次**）
  - `:1596 takeStyleSnapshot()` → 只收 `GUARD_SELECTOR` 命中的 head 节点，**卡脚本在 DOMContentLoaded 之后
    注入的样式不在快照内**
  - `:1556 styleGuardAddNode()` → **只给 Palink 自家插件 CSS 开追加登记口**（`:1571` 记 `__palinkStyleGuardPluginCss`），
    卡侧样式没有登记通道 ⇒ `:1609 restoreCardStyles()` 只会补回快照里的 8 条
- **修在哪**：同一守护。二选一或并用，**~15–35 行**：
  (a) `GUARD_SELECTOR` 之外，把**带 `id` 的 head `<style>`**（卡的样式块几乎都有稳定 id，如 `tavern-cg-album-style`）
  也纳入 MutationObserver 的恢复集；(b) 让 `restoreCardStyles()` 按 `id` 找回（`getElementById` 语义正好适配），
  而不是按快照文本匹配。
- **值不值得修**：**值得**。丢 440KB 是肉眼级塌陷，且**凡卡侧自己重写 head 的富卡都中招**（本仓 n=1，
  生态命中率待扩样）。

### 5.2 K-2（🟡 P2 · 对包E 的否证 + 生态面真缺口）
**(a) 否证包E「克隆差异坐实竞态」**：三实例的插件 CSS 是**确定性的 5/0/0**，不是竞态。
读 `GET /api/characters/<cid>/plugin-state`（实现在 `backend/app/api/character.py:64 get_character_plugin_state`）：
- 主卡 `c28061bb`：5 个插件 `enabled=True`（id 与包E 点名的 5 条 CSS 一一对应：`…2e1fa886b439` Chat Translation、
  `…4d61e879d0c5` Quick Replies、`…43ef24b1a3ba` Regex、`…01db1f12ddd0` Summarize、`…ca0611884034` Token Counter）
- cloneA `7a3a5dfc` / cloneB `c44f2ae6`：同样 5 个插件 `enabled=None`（未启用），只有 `eb1d50e9…` 为 True
⇒ 帧内 `pluginCss=0 / guardSnapshot=3 / guardPluginCss=undefined` 是**状态正确反映**，包E 的"竞态"读法作废；
**J-1 的验收应当在"已启用插件的角色"上做**（本包就是这么过的：恒 5/5）。

**(b) 真缺口：富依赖卡不开帧 ⇒ tavern_helper/MVU 运行时根本不启动**。
猫娘（`78faa27a`）依赖面与露缇雅同级：`tavern_helper.scripts=2`、jsdelivr CDN import、`regex_scripts×6`、
卡体 `palink_raw_card_data` 内含 **`[initvar]` 块（世界观条目 `<initvar>…`）**、greeting 尾部有真 HTML
（`<div style="text-align:center…"><span style=…>`）。但实测 **iframe=0 / srcdoc=0 / 帧内运行时全为 0**。
- 显示层**没坏**：greeting 的 HTML 走了内联轨，父文档实测 `div[style]` **40 个**、居中 div 的
  `getComputedStyle().textAlign = "center"`、`innerText` 里**转义残留 `<div` 计数 = 0**、
  美化 `.custom-nk-msg` 1 份 3,156B 生效、`/api/image-proxy?url=…jsdelivr…` 图片代理正常。
- 坏的是**能力面**：ST 里 `tavern_helper` 脚本在页面加载即全局执行，与"消息是否含 HTML"无关；
  Palink 的卡脚本**只在智能卡 iframe 内 bootstrap** ⇒ 没有 HTML 完整文档就不开帧，脚本/MVU/regex 全部休眠。
- **根因链（file:line）**：

    —— 唯一消费点 `frontend/src/components/ui/custom/CharacterCardRenderer.tsx:482`
    **（只有渲染出 iframe 宿主才走到）**
  - 宿主产生条件：`frontend/src/components/ui/custom/smart-card-runtime/html-extract.ts:215 extractHtmlRenderParts()`
    —— 需要 `<palink-html>` / ```html 围栏 / **完整 HTML 文档**（`findNextHtmlBlock` 三路候选），
    猫娘 greeting 是 `<猫神>…</猫神>` + 尾部 `<div style>`，三路全不命中 ⇒ 全量落 markdown 轨。
