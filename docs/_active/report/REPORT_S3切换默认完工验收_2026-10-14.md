## 5. 真机验收

### 5.1 三张代表卡

后端列出的 3 个角色记录均包含 6 条 regex、3 条卡脚本（MVUbeta、露缇雅变量结构、相册）以及 HTML 内容标记；三条 iframe 运行时均报告 scriptNodes=3，且 getScriptId、getVariables、setVariables、eventOn、Vue、lodash、YAML、showdown、z 均存在。

当前浏览器 localStorage 同时存在旧键和新键，解锁值一致：

旧键 palink:card-storage:v1:<character>:local:tavern_cg_album_unlocked
值   [露出魔纹1, 摸脸]
新桶 palink:smart-card-storage:v1:localStorage:<character>:<session>:...
值   tavern_cg_album_unlocked = [露出魔纹1, 摸脸]

### 5.2 双写窗口实测

首次加载后单间读到 [露出魔纹1, 摸脸]。随后只把旧键改为 [__s3_old_key_only_probe__]，重载页面后单间仍读新桶原值 [露出魔纹1, 摸脸]。结论：旧轨后续写入不会被单间读取，存在用户可见的解锁态/CG 进度丢失窗口；S5 不应提前删除旧轨或旧键兼容。

### 5.3 Kill switch

- 默认状态：主页面无 #palink-st-plugin-host，无大厅插件脚本；卡脚本在 iframe 内执行。
- 设置 palink_st_plugin_main_page_injection=1 后：大厅 host 存在，包含 runtime setup 和插件脚本节点。
- 清除该键后重新进入角色页：大厅 host 再次消失。

### 5.4 真实插件清单限制

st-plugins/ 下已确认存在 quick-reply、translate、token-counter、memory、regex 五个目录；挂载点 qr_container、translate_wand_container、token_counter_wand_container、summarize_container、regex_container 均存在。模板渲染探针结果为 32 通过、1 个既有模板标记问题（expressions/add-custom-expression），quick-reply 为 DOM 挂载型。

当前运行实例 /api/plugins 只有一个已注册插件“酒馆助手”（source_type=character_card_extension），因此本次没有把五个目录写成“五个真实插件功能均已通过”；五插件的端到端可用率在该实例上未达到可宣称条件，需主控决定是否在独立测试数据上注册后补测。

### 5.5 失败隔离与降级统计

现场控制台出现外部资源 404、opaque iframe /version CORS 和测试角色世界书缺失等已有环境噪声；卡脚本资源失败被记录为 iframe 卡内错误并继续渲染其他帧。代码路径仍通过 recordStubHit 写入兼容降级统计。插件管理页可见性未在当前只注册“酒馆助手”的实例上完成五插件逐项确认，标记为未核实。

## 6. 性能

按 S0 要求使用 .rp-chat-area/#chat 和 CDP TaskDuration，不使用 headless FPS。当前单间默认 7 个 iframe，冷加载后滚动实测：scrollHeight 6965px，viewHeight 587px，iframes 7；heap 99.5MB -> 102.1MB；nodes 4618 -> 4620；TaskDuration 759.6ms；主线程占用 119.1ms / 1000px。

S0 对照为首屏 iframe 就绪 823ms、7 iframe 约 113MB、滚动代理 28.1ms/1000px（S0 档案 §6.1）。由于本次浏览器会话的消息窗口/DOM 高度与 S0 采样不同，不能把这次单点数值直接宣称为“劣化 ≤15%”；应在同一会话、同一消息窗口和同一采样脚本下复测后再签收性能项。原有探针曾把秒值换算成毫秒时少乘一次 1000，本报告采用修正后的换算。

## 7. 后续决策

1. 保留 palink_st_plugin_main_page_injection 到 S5 之后的下一个版本。
2. S5 前不得删除旧键兼容：双写窗口已被真机复现为可见数据丢失风险。
3. 若要关闭 S3 验收缺口，需在独立测试数据上注册五个 st-plugins 扩展，并用同一真机脚本逐项操作 quick-reply、translate、token-counter、memory、regex。
4. 性能签收需复用 S0 的同一会话和同一 CDP 采样口径。
