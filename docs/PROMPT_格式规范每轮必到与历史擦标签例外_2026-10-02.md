## 0. 先补铁证，别直接改

现象（用户真机复现，同会话同卡）：
- 开场白与第一条 AI 回复**有排版框**，但正文上下各露出一对 `content` 记号；
- 之后每条 AI 回复**彻底无框、无任何记号**，重试（同一 prompt 的 swipe1）结果**一模一样**。

反推依据：`character_chat_messages` 中 id=2466 的 `prompt_tokens=2854`，id=2468 的 `prompt_tokens=2775`——2468 多背一整轮历史（约 940 字回复 + 两条用户消息）却**少 79**，缺口量级 ≈ 800~980 token，恰是一条「对话渲染格式规范」的长度。

**第一步（必做）**：把这个反推变成直接证据——记录每轮请求实际收到的 `extension_prompts` 条数与字符量，落到消息 `extra`。
- 若 2468 那类轮次记为 0 条 → 主因确认，进入 P1；
- 若条数非 0 → 主因不成立，回来重判，不要继续按本文件施工。

## P1 格式规范每轮必须到场，且缺席可见（主因）

链路现状：插件 `setExtensionPrompt` → `frontend/src/services/prompt-injection.ts:81` 的 `_sources` 分区 → 同文件 `:90` `getPromptsForGeneration()` 聚合 → `frontend/src/hooks/useCharacterChat.ts:1211` 每轮写进请求体 `extension_prompts` → 后端 `roleplay_prompt_assembly.py` 的 `_collect_extension_prompts` 合并。

要做的两件事：
1. **重挂**：卡片 iframe / 卡脚本运行体重建或卸载后，格式规范必须重新登记回来（`prompt-injection.ts:11` 注释明确 `removeSource()` 是给 iframe 卸载做清理用的；上报口在 `CharacterCardRenderer.tsx:1080` 的 `data.type === 'extensionPrompts'`）。同一 identifier 重挂时保持覆盖语义，别重复堆叠。
2. **可见**：规范缺席不得静默。落库 `extra` 记本轮命中的 identifier 列表与字符量，前端诊断面板显示一行（沿用现有面板，不新开 UI）。用户侧最低要求：掉线时能一眼看出"这轮没带格式规范"。

**禁止**：
- 不得用「往历史里补写外壳记号」来兜底（用户已明确否决，见决定②）。
- 不得放宽 `ST_DOMPURIFY_CONFIG.FORBID_TAGS` 里的 `iframe`（那是 `@bubble` 宿主议题，另开，见决定⑥）。
- 不得改第三方卡的内嵌正则来迁就规范（见决定⑤）。

## P2 历史擦标签：外壳继续擦，变量块必须放行

现状：`backend/app/services/character_message_builder.py:229` 对每条 assistant 历史调用 `clean_display_markup_for_prompt()`，该函数最后一条规则 `:77` 是 `re.sub(r"<[^>]+>", "", value)`——**把所有尖括号记号一律清空**。

实测（把真实落库原文离线喂进该函数）：id=2464 原文含 `<story> <cg> </cg> </story> <UpdateVariable> <initvar> </initvar> </UpdateVariable>`，过函数后**一个标签都不剩**，长度 2385→2123。

要做：把 `:77` 那条"全删"改成**只删已知 HTML 显示标签**（style/script/br/p/div/span/section/article/li/tr/h1-6 等白名单式），保留自定义变量块 `UpdateVariable`/`initvar` 一类。

- 外壳类（`now_plot` / `content` / `story` / `Lnterleaving` / `正文` / `cg` / `background`）**按用户决定继续擦**，不要顺手"恢复原样"。
- 函数 docstring 写的是清 display-only HTML 遗留，别扩大成格式治理，也别加新清洗。
- **连带核对**：本项目 2026-09-30 做过「MVU 初始变量断链」修复（commit `0ce1760`）。变量块被这道清洗吃掉，很可能与该断链同源；一并确认修完后初始变量链路真的能靠历史读到 `initvar`。

## P3 预填代替历史示范（可选，需用户拍板后再做）

既然历史不带外壳（P2 保留擦除），唯一稳定锚是发送前在末条 assistant 预填外壳开头，让模型"接着写"而非"自己想起要套壳"。成本几个 token，远低于留一条完整示范。

风险：预填必须与卡正则的配对要求配套。id=2468 的 swipe0 正是「只开 `<now_plot><content>`、不闭合」，而卡正则 `/<(story|Lnterleaving|now_plot|content|正文)>([\s\S]*?)<\/\1>/gi` 用反向引用 `\1` 要求同名闭合 → 配不上就整块不出框。做 P3 必须同时加"输出侧闭合校验/补闭合"，否则别做。

## 验收线（全部要跑并贴结果）

1. 同会话连续 ≥3 轮，每轮 `extra` 里规范 identifier 都在、条数不降；第 0 步的证据字段有值。
2. 对 id=2468 那条重生成：输出的标签骨架出现**成对** `<now_plot>…</now_plot>`；把该输出喂给卡正则真实 `find_regex`，断言命中 ≥1 次（不出框=没过）。
3. 开场白回喂后：`<UpdateVariable>`/`<initvar>` 仍在，外壳类已被擦净（两个方向都要断言，防止顺手改过头）。
4. 反例守卫：手动停掉该插件 → `extra` 记为 0 条且诊断面板显示缺席，**不得静默**。
5. 门禁：`cd frontend && npx tsc --noEmit` 0 错 + `npx vitest run` failed=0（用例数会随并行会话涨，只认 failed=0）；后端跑相关 pytest。

## 我替用户定的决定（逐条可否决，先确认再动工）

① 主路线只修"每轮到场"，**不走**"让历史带外壳当示范"。
② 历史里的外壳记号**继续擦**（用户意见），但**变量块例外**——这条是我的判断，用户只说了"擦掉比较好"，未区分变量块；若他认为变量块也该擦，P2 作废。
③ 缺席检测手段=落库 `extra` + 现有诊断面板显示，**不加**用户可见弹窗/toast。
④ P3 预填默认**不开工**，等他拍板。
⑤ 规范要求的"两层外壳"与卡正则"单层反引用"错配（就是上下多出一对 `content` 的成因）→ 改**装配层**把 `content` 降为单层要求，不改第三方卡。
⑥ 不动 `PALINK_BUBBLE_IFRAME_HOST`，`@bubble` 宿主可用性另开议题。
