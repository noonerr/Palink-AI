## 八、给接手 Agent 的纪律

1. **§一（标签/插件适配）优先级最高，其余全部让路**。
   用户原话与理由见 §零 与 §一 开头。**别把它降级成"顺手修一下"。**
2. **别把本文当诊断**。除标注「已查证」的部分外**全部待现场复验**。
   用户口述的现象可能与真实成因有偏差（历史多次如此）。
3. **§一 的排查方向是「接收端」，不是「提示词」**。
   用户已明确定位为"我们注入成功、也生成了，但系统接不住"。
   历史上已因往提示词方向用力而误判过（见 `TODOS.md` 2026-10-02 四组 A/B/C/稳态实测）。
4. **「如实分类」优于「全部标成已支持」**。适配体检表里标假的兼容，
   比标缺失更危险 —— 它会让下一个接手人以为这块没问题。
5. **复现优先于改码**。每条都要先拿出**可复现的证据**（浏览器读数 / 截图 /
   Network 记录 / 容器日志），再动手。改完要给**改前改后的对照读数**。
6. **前端改动记得重建 dist**。`npm run build` **已禁用于上线**
   （其 `clean-dist.cjs` 第一步会清空在用 dist）。正确姿势：
   `VITE_OUT_DIR=dist_new_N` 构建 → 校验（入口引用文件均存在 + 无 0 字节 + 无孤儿）
   → 原地覆盖 → `gzip-dist` → 清孤儿。⚠️ **覆盖前必须先物理备份 dist 到 `_BACKUPS/`**
   （`frontend/dist` 是容器 nginx bind mount 的在用产物且不入 git，git 不是回滚路径）。
   ⚠️ 后端改动是**烤进镜像**的，须 `docker compose build backend && up -d`。

## 九、⚠️ 全局已知坑（省你时间）

| 坑 | 说明 |
|---|---|
| 智能卡运行时是**注入 iframe 的大字符串** | `tsc` 不检查、注释里都不能有反引号/`${}`、禁 `@` 别名。**改它 tsc 过了不代表对** |
| 帧内 shim **不向子帧传播** | 别把"帧内能用"当"全页能用" |
| `docker exec` 要 `MSYS_NO_PATHCONV=1` | 否则 `/app/...` 会被 Git Bash 转成宿主路径 |
| DB 用户是 `ai_user` / 库 `ai_hub` | 不是 `palink`；`character_chat_messages` 用 `session_id` 关联（**无 `character_id` 列**），会话表名是 `character_chat_sessions` |
| 卡内正则存在 `characters.extensions.regex_scripts` **JSON 里** | 卡插件原文在 `plugin_scripts.content` 字段 |
| 隐私红线 | **不要打印消息正文 / 卡内容**，只取 length / 位置 / 标签骨架 / 键名 |
| 备份规矩 | 新备份必须进 `_BACKUPS/YYYY-MM-DD_主题/`，含 `BACKUP_INFO.md` 四要素，并登记 `_INDEX.md`；清理走「列清单→隔离→用户确认→删」三步 |
