## 1. 坑① 插件管理接线（方案 A，纯加法）

### 1.1 后端（plugins.py）

1. **新增 `POST /api/plugins/import-url`**（admin-only，与 import 同权限口径）：
   - 请求体 `{ url: str }`；**SSRF 硬约束**：仅允许 http/https；发请求前校验 host，拒绝 localhost、环回、私有与保留地址段；重定向逐跳复检——**复用仓库现成先例** `character_import_service._PublicUrlRedirectHandler`（commit 3710837）。
   - 下载内容走限流读取（对齐 `_read_upload_limited` 思路）+ ZIP 魔数（PK\x03\x04）校验后直接喂 `_import_sillytavern_extension_zip(db, content, filename_from_url)`；非 ZIP 报 400（URL 安装只吃扩展 ZIP 包，与本地导入的 JSON 分支无关）。
   - 返回结构与 `/import` 的 zip 分支一致（message + plugin dict）。
2. **不动** `toggle`/`delete`——它们已经存在且行为正确（1433/1530）。
3. 测试：新增 `test_plugin_import_url.py`——① http/https 白名单 ② localhost/127.0.0.1/10.x/172.16-31/192.168/169.254 等 host 拒绝 ③ 重定向到私网被逐跳拦截 ④ 正常 zip 走通到 `_import_sillytavern_extension_zip`（mock 下载）⑤ 非 zip 400。

### 1.2 前端

1. **`PluginManager.tsx`**：
   - `handleInstall`（:153-173）：`/api/extensions/install` → `/api/plugins/import-url`，body `{ url }`；成功后 `refreshPlugins()` 保留。
   - `handleUninstall`（:133-150）：改为 `api.delete('/api/plugins/' + backendId)`（需把后端 id 从 manager 层透传到 PluginInstance），**去掉吞异常的 try/catch**——失败就 toast.error；成功 toast 文案按后端返回；`pluginManager.unload(name)` 前置保留。
   - `handleToggle`（:100-116）：enable/disable 后**追加** `api.put('/api/plugins/' + backendId + '/toggle')`（或先调后端、成功后再动内存，二选一以「后端权威」为准）；失败回滚内存态并 toast。
   - 卸载确认框文案（:510-513）按 DELETE 实际行为校准（DB 记录删除/文件是否清理）。
   - 头部注释 API 清单更新（:9,13-17）；「安装来源」提示文案（:327）改为「扩展 ZIP 包直链 URL」。
2. **`manager.ts` + `types.ts`**：PluginInstance 增加后端插件 id 透传（discover() 构造处从 PluginRuntimePayload.id 带上）。
3. build 后 dist 直挂生效（顺带治愈体检 R1 的坏 dist）。

## 5. 施工顺序与验收

**顺序**（一次会话可完成，前端 build 收尾）：
1. 后端：import-url 端点 + SSRF 测试 → pytest 绿。
2. 前端：三处接线（install/uninstall/toggle）+ PluginInstance id 透传 → tsc 绿。
3. 坑②摘除（两条链）→ tsc 绿 + 浏览器确认聊天页无残留空 chips 布局位移。
4. 坑③ + 附带 1（纯删除）。
5. `docker compose build backend && up -d` + 本地 `npm run build`（治愈 R1）→ 起容器冒烟。
6. 附带 2（需容器活着）：curl 实证 ADAPTATION 四端点后改文档。

**验收标准**：
- pytest 全绿（含新 import-url 用例）；tsc 干净。
- 浏览器（admin 账号）：① 贴一个 ST 扩展 ZIP 直链 → 安装成功且刷新后仍在；② 卸载 → 刷新后**不复活**（DB 记录消失）；③ 启用/禁用 → 刷新后状态保持；④ 聊天页无建议回复 chips、无 console 报错。
- dev：`docker compose -f docker-compose.dev.yml config` 校验通过。
- grep 收尾：`api/extensions` 在 frontend/src 零命中；`suggestions` 在 useCharacterChat/CharacterChat/CharacterView 零命中。

**红线**：
- 不碰 `/api/plugins/import` 既有 8 类文件导入分支；不碰 `/api/recommendations/starters`；不碰 st-plugins/ 第三方插件本体；`_import_sillytavern_extension_zip` 只复用不重写；普通聊天链摘除时若发现 suggestions 在别处有正向赋值来源（与核实结论矛盾），停下回报不要硬删。
- 多 agent 环境惯例：分批 commit（后端+测试 / 前端接线 / 摘除 / 杂项删除 / 文档），勿 `git add -A`。
