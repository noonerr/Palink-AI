## 0. 一句话问题

世界书"按意思找设定"这条路，代码全在、后端可写可读，**唯独两个开关前端没做**（全局 `vectorized_enabled`、词条 `vectorized`），所以永远不执行。但直接"把开关一开"会踩三个实测过的坑，本 SPEC 的重点不是加开关，而是**先关掉污染和延迟风险**。

## 1. 决策点

- **D1 修还是砍**
  - **A 修（推荐）**：接通它。真实损失是——从酒馆导入的卡里常有"只标向量、没写关键词"的条目，这类条目在当前实现里**永远不注入**（无关键词就匹配不到）。成本约 1~1.5 天。
  - **B 砍**：把 `entry.vectorized` 在装配里当普通关键词条目处理（删掉 V-2 接管分支与检索分支），省维护。代价是那类"纯语义条目"依然不注入，且丢掉一项已写完的能力。
  - 判据：如果我们要接外部用户导入的 ST 卡，选 A；如果确认世界书只服务自建关键词条目，选 B。
- **D2 默认值**：向量匹配默认**关**（与 ST 1.18 一致，存量零突变）。只做"用户可开"，不做"默认开"。

### 2.1 施工前复核勘误（2026-09-29 第二轮，覆盖下方两处原文）

- **勘误①（词条侧写通道只对导入路径成立）**：原写"词条侧 `api/worldbook.py:522` 已接收 `vectorized`，保存后 `:126/_schedule_worldbook_vector_sync` 会触发后台同步"——`:522` 仅存在于**导入**路径（import commit 后 `:574` 触发同步，书级 PUT `:333` 同样触发）。**词条编辑端点 `PUT /{world_book_id}/stages/{stage_id}`（`:583-635`）的 `WorldBookStageUpdate`（`schemas/worldbook.py:114-130`）不收 `vectorized`，commit 后也不触发同步**；前端 `worldbookApi.updateStage`（`services/worldbookApi.ts:70`）全前端零调用方、`WorldBookManager.tsx` 无任何 API import（纯展示，连关键词都保存不了）。→ §4 词条增量实为：schema 加字段 + update_stage 接收与触发 + WorldBookManager 新建保存链（工作量按此估）。
- **勘误②（行号漂移）**：`_collect_vector_hits` 内 `query_entries` 调用实为 `:1436`（原写 `:1469`）；`_fire_vector_sync` 实为 `:63`（原 `:62`）；`OLLAMA_TIMEOUT` 实为 `config.py:13`；`WORLD_INFO_GLOBAL_KEYS` 实为 `:34-43`。均 ±1~2 行不影响定位，施工以实读为准。
- **勘误③（P5 实弹缺陷，e2e 探针发现）**：原文"写入链路已实测可用"是**假象**——ORM 模型 `WorldBookEntryVector.embedding` 声明为 `Text`，而真 PG 表列是 `vector(1024)`，ORM INSERT 把参数显式绑定成 `::TEXT`，PG 拒绝 text→vector 隐式转换（`DatatypeMismatch`），**`sync_worldbook_vectors` 在真 PG 上从未成功写入过一行**（0 行表佐证；此前的探针应走了原生 SQL 而非 ORM）。修复 = 写入改原生 SQL：PG 走 `CAST(:v AS vector)`、SQLite（单测）按方言回退原样文本（SQLite 会把 CAST 到未知类型名按数字亲和性吞成 0），见 `worldbook_vector_service._write_vector_sql`。读取侧原生 SQL 本就带 CAST，不受影响。模型 docstring 的错误断言已同步勘正。
- **其余全部核实无误**：开关链 4156/4196/4305、接管分支 931-956、检索与同步 1390/1427、参数解析 1362/1373（env 两键无任何 env 文件设置）、向量服务 71/147-248/276-299、bge-m3 分数注释（config.py:18-22）、前端 8 键/ readOnly / types.ts / getContext.ts 硬编码 false。
- 后台通道现成：`api/worldbook.py:43 _vector_sync_worker` / `:62 _fire_vector_sync`（独立线程 + 新 `SessionLocal`，fire-and-forget）。

## 3. 三个必须先修的坑（这是本 SPEC 的主体）

**P1 阈值 0.25 会让提示词被无关设定污染（最高优先）**
本项目自己测过 bge-m3 的分数分布，结论写在 `memory_module/config.py:19-23`：无关查询 top1 = **0.459**，阈值 0.3 时 77 条里 **75 条过阈**（阈值形同虚设）；0.5 才把无关查询清零。世界书这条用的是**更低的 0.25**，一旦开关打开就是"每轮无脑塞 5 条不相干设定"。
→ 改：默认阈值提到 **≥0.55**（世界书条目短、误召代价高，比记忆的 0.5 更保守），`top_k` 默认 **3**；两者都改为读 `world_info_settings`（`vector_threshold` / `vector_top_k`），env 仅作兜底；换嵌入模型必须重测（沿用 `config.py` 那条注释的告诫）。

**P2 首次开启会把整本书的嵌入压在对话请求里**
`_collect_vector_hits` 在装配路径内**同步**调用 `sync_worldbook_vectors`，脏条目一次性全嵌入、无上限。几百条目的卡首轮就是"点发送后长时间不出字"；且嵌入客户端超时是 30s（`memory_module/config.py:12` `OLLAMA_TIMEOUT`，`embedder.py:231`）。
→ 改（**触发点已拍板，2026-09-29**）：装配路径**零 sync、只查**。就绪检测 = 每书两次计数比对（该书向量行数 vs vectorized 条目数，ORM 跨方言）**不就绪 → 服务层 daemon 线程懒触发后台 sync**（模块内 in-flight 单飞去重，等价 `_fire_vector_sync` 的 fire-and-forget 语义）；书级 PUT（`:333`）与导入（`:574`）的既有触发保留。**"用户开启全局开关"不做 silly_tavern.py 挂钩**（该文件保持零接触）：无 UI 时代开关经 API/直写打开后，首轮检索的懒触发自然补齐；§4 UI 落地后由 `RoleplayEngineTab` 开关切换时显式触发一次。原"兜底同步 ≤50 条上限"随之取消（装配路径已无同步）；后台 sync 改**分块嵌入（32/批）**防 30s httpx 超时。

**P3 嵌入服务不可用 = 该设定彻底消失，且没有任何提示**
V-2 语义 + `query_entries` 静默返回 `[]` 叠加，结果是勾选了向量但 Ollama 挂了 → 条目既不关键词匹配也不向量命中，**用户只觉得设定丢了**。
→ 改：检索降级时，**有关键词的条目回退关键词匹配**（report 记 `reason="vectorized_degraded_keyword_fallback"`），无关键词的条目如实记 skipped（`reason="vectorized_degraded_no_keywords"`）；降级计数走既有世界书 report/调试面板，不新增 toast。
**施工要点（复核补充）**：现状"降级"与"真未命中"不可区分（`query_entries` 异常与空结果同样返回 `[]`）——需把 `query_entries` 返回改为 `(hits, degraded)`、`_collect_vector_hits` 返回 `(hits, degraded_books)`，经 `_recursive_scan`/`_scan_entries` 与 `vector_hits` 同路透传。降级判定 = 该书检索异常 / 向量行数 < vectorized 条目数（未就绪）/ 维度门禁拒绝。回退条件 = 该书 degraded **且条目有一级关键词**（`_parse_json_list(entry.keys)` 非空）；constant 条目在接管分支之前已激活（`:891`），不受降级影响。

**附带的部署陷阱 P4（不修就反复自毁）**：`.env.example:104-106` 是 `fastembed/512`，`docker-compose.yml:150-156` 是 `ollama/1024`，而 `embedder.py:47 SimpleHashEmbedder` 兜底是 **384 维**。三者任一漂移，`_reconcile_vector_dimension` 就会 ALTER 整表把向量作废重来。
→ 改：启动时用"实际 embedder 维度"与声明维度比对，不一致则告警并**拒绝为世界书建表**（拒绝即自然降级为关键词召回，不污染）；`.env.example` 与 compose 对齐；三档维度写进注释。
