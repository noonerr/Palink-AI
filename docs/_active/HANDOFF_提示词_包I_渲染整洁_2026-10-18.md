## 1. 背景：两个缺陷的实测证据（2026-10-18 真机）

### 1.1 P2-1：内联渲染把同一份 CSS 重复注入 15 份

猫娘卡（`78faa27a-a2c9-45a8-a951-861920ebea43`，走内联 html-display 路径）实测：

```
document.querySelectorAll('style').length            = 22
其中含 nk-msg 的                                      = 15
  uniqueContents = 1        ← 15 份内容完全相同
  perCopyBytes   = 3,156
  totalBytes     = 47,340   ← 白烧 44KB
  parentElement  全部为 BODY（无 id / 无 class）
t≈8s / t≈23s / t≈29s+滚动 三次采样恒为 15 ⇒ 一次性重复注入，非持续泄漏
露缇雅（iframe 路径）无此问题：主文档 6 个 <style>，dupStyles = []
```

**根因已定位**（`frontend/src/components/ui/custom/Message.tsx:1007-1031`）：

```js
const detachStyleFromMesText = () => {
  const styles = Array.from(container.querySelectorAll('style'));
  for (const styleEl of styles) {
    if (styleEl.getAttribute('data-palink-mes-style-moved') === '1') continue;  // ← 去重靠这个标记
    ...
    const clone = document.createElement('style');
    clone.setAttribute('data-palink-mes-style-moved', '1');
    document.body.appendChild(clone);   // ← 每次都新造一份
    movedStyles.push(clone);
  }
};
```

去重标记打在**源** `<style>` 元素上，但 `.mes_text` 的 innerHTML 每次被 React/正则/流式
重建时**源元素是新的、标记丢失**；而已移走的 clone 在 `document.body` 里，
`container.querySelectorAll` 看不到 ⇒ 无从去重。该 useEffect 依赖 `[]`，cleanup 时
`movedStyles` 只删自己追加的那些 ⇒ 每轮渲染净增。

### 1.2 P2-2：卡外链资源加载失败弹 error toast（露缇雅实测）

露缇雅帧内一个死链（`https://drive.baibai.cv/f/ZKEBuW/Music.js`，第三方 CDN 不可达）
在主页冒出 Sonner toast：`error @ https://drive.baibai.cv/f/ZKEBuW/Music.js`。
**ST 里这类失败只落 console，不弹 toast**（见实测报告 §6）。这就是用户最初反馈
「顶部弹出很多报错」的一个来源。

**完整链路（今天逐段验证，照这个改）**：

```
卡在帧内注入 <script src="...Music.js"> → 加载失败
  → 帧内 unhandledrejection（reason 是 Event，target.src = 死链 URL）
  → part-08.ts:1095-1105 的 unhandledrejection handler
  → formatRejectionMessage（part-08.ts:926-948）的 Event 分支产出
    "error @ <url>"（reason.type + ' @ ' + src）
  → reportDiagnostic({severity:'error', code:'unhandled_rejection'})
  → post({type:'st:diagnostic'}) → 父侧 CharacterChat.tsx:1227
  → handleSmartCardCompatDiagnostic（SmartCardCompatController.ts:1052-1063）
  → toast.warning(...)（12s 同 key 去重）
```

另有 `part-08.ts:1079-1091` 的 window error handler → `formatWindowErrorMessage`
（`:904-924`，`msg + ' @ ' + filename:line:col`）——**这条要保留**（真脚本错误），
只处理"资源加载失败"这一类。

## 2. 任务 I-1：CSS 按内容 hash 去重（`Message.tsx:1007-1031`）

### 2.1 修法（路线图 §3.2 已给设计，照做）

在 `document.body` 端按 CSS 内容 hash 去重 + 引用计数：

```js
const key = cssHash(cleanCss);   // 简单稳定的字符串 hash 即可（如 FNV-1a），不需要加密强度
let slot = document.body.querySelector(`style[data-palink-css-hash="${key}"]`);
if (!slot) {
  slot = document.createElement('style');
  slot.dataset.palinkCssHash = key;
  slot.textContent = cleanCss;
  document.body.appendChild(slot);
  slot.__palinkRefCount = 0;
}
slot.__palinkRefCount += 1;      // 本轮渲染持有
```

- **cleanup 语义**：`movedStyles` 改为记录 `{slot, key}`；unmount 时对每个 key 递减
  `__palinkRefCount`，归零才 `slot.remove()`。⚠️ 同一消息内多份同 hash CSS 只加一次计数，
  别按 clone 次数加（否则永远归不了零）。
- **源元素仍要 remove**（原始行为：`.mes_text` 不留 `<style>`，插件读 innerHTML 得纯净正文）。
- `sanitizeStCompatCss` 净化保持不变（安全兜底，别动）。
- MutationObserver 兜底保留（流式期间新 style 出现仍要移出），只是移到 body 时走 hash 复用。

### 2.2 验收

- 测试（`components/ui/custom/__tests__/`）：同一份 CSS 经 `detachStyleFromMesText`
  模拟执行 5 轮（每轮换一个新源元素，模拟 innerHTML 重建）⇒ `document.body` 里该 hash 的
  `<style>` **恒为 1 个**；cleanup 后归零移除。
- 真机探针（猫娘卡）：含 nk-msg 的 style **15 → 1**，字节 **47,340 → 3,156**；
  且 `.custom-nk-msg` 美化**仍然生效**（判据 `[class*="nk-msg"]` 存在，类名带 `custom-` 前缀）。
- 露缇雅（iframe 轨）行为零变化。

## 3. 任务 I-2：资源加载失败降级为 console（`part-08.ts` 两个全局 handler）

### 3.1 分类规则（唯一切分口径）

在 `part-08.ts:1079-1106` 两个 handler 里加**资源加载失败**判定：

| 形态 | 判定 | 处置 |
|---|---|---|
| unhandledrejection 且 reason 是 Event（有 `target.src`/`target.href`） | `formatRejectionMessage` 的 Event 分支 | `logCardError` + `console.error` + 进 `__palinkFrameErrors`（父侧已有通道，`CharacterCardRenderer.tsx:890-902`）**保留取证**；**不调 reportDiagnostic**（不弹 toast）；code 记 `resource_load_failed` |
| window error 且 `event.target` 是资源元素（SCRIPT/LINK/IMG 且有 src/href） | 同上口径 | 同上 |
| 其余（真脚本错误：ReferenceError/TypeError/语法错） | 走现有 `formatWindowErrorMessage`/`refMatch` 逻辑 | **完全不变**（含 `undefined_global` 的 severity 降级逻辑） |

### 3.2 红线

1. **取证不丢**：父侧 `window.__palinkFrameErrors`（上限 50 条）必须仍收录资源失败
   —— 排查死链就靠它。只是不打扰用户。
2. `part-08.ts` 是模板字符串：禁裸反引号、`${}`、注释里裸 `\n`（写 `\\n`）；
   改完必须过 `generated-script-parse-guard.test.ts`。
3. **不许一刀切吞掉所有 error**：真脚本错误（卡代码写错）的诊断/toast 行为不变。
4. ST 对齐口径出处：`REPORT_真实角色卡兼容性实测_酒馆助手卡_2026-10-18.md` §6
   （"ST 里这类失败只落 console"）。

### 3.3 验收

- 契约测试：对 `part-08.ts` 两个 handler 做源码文本契约 —— Event 形态 reason 不得进入
  `reportDiagnostic` 调用；非 Event 形态必须进。
- 真机探针（露缇雅，含死链）：页面加载 14s 后
  `document.querySelectorAll('[data-sonner-toast]').length` **= 0**；
  同时 `window.__palinkFrameErrors` 里有 Music.js 那条（取证在）。
- 反向证明：在探针里向帧内 `import('data:text/javascript,throw new Error("x")')`
  （真脚本错）⇒ toast 仍出现（证明没有一刀切）。
