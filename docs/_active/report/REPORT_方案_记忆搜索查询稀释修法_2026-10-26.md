### 3. 施工方案

#### 方案 A（推荐）：零码改，只订正台账 + 可选复测

**理由**：现部署的 current 模式已**严格满足**任务推荐口径的实质——「问题置尾且不参与截断」：

- 问题全文进查询、**任何截断都不触碰问题**（`:5962-5964`；`:5980` 的 120 字截断只作用于历史尾巴）；
- 「查不到退回单句」兜底原样健在（兜底①②③，§1）；
- 且比任务推荐的「历史部分单独截断（保留历史）」**更进一步**：平时不带历史。
  数据依据（复核报告 §二，同库同题 n=48）：窗口拼接 top1 6.2% / 中位排名 17 →
  只用问题 top1 22.9% / 排名 4；历史上文 96% 是上一条 assistant 回复的尾巴，
  **保留历史只会把稀释请回来**（复核报告变体②「只清洗查询」排名也只到 13，不如③）。

**剩余动作（非码改）**：
1. `OPEN_ISSUES.md` P2-6 条目加订正说明：「已于 2026-10-09/10 施工入库（`b6fdd58`），
   默认 current 模式 + `MEMORY_QUERY_MODE=window` 一键回退」，引用本报告；
2. 顺手项（可选）：调用点上方注释 `roleplay_prompt_assembly.py:6340-6341` 仍写
   「普通轮次改用最近几条消息拼出的窗口查询」——**已过期**（普通轮次现走 current），可一并订正；
3. 可选：按 §5 口径复跑一次探针验收（需主脑安排，注意 P2-26 冷启动会污染嵌入耗时读数）。

#### 方案 B（备选，待主脑裁定）：「问题置尾 + 历史永远单独截断」的混合查询

仅当主脑裁定「≥15 字但指代依赖上一条的追问」必须永远带历史语境时才做（A→B 的动机，见 §3.3 边界讨论）。
**改动点唯一**：`roleplay_prompt_assembly.py:5961-5985`（current 分支内部），window 分支与三个兜底**一律不动**。
建议带独立 env 开关（`MEMORY_QUERY_HIST_ALWAYS`，默认 `0`=维持现状 A，`1`=启用 B），
使 A↔B 双向可回退，符合装配链「最小改动+可回退」红线。

伪代码（替换 `:5962-5985` 中「过短才补」的逻辑为「总是补」）：

```python
cleaned = _clean_query_text(base)                 # 问题：清洗后全文，永不截断（置尾）
if _memory_config.HIST_ALWAYS:                    # B 案开关；A 案等价于仅在 len(cleaned)<MIN_CHARS 时进入
    hist = _fetch_prev_tail(...)                  # 复用 :5966-5976 的查库（最近 1 条，含兜底① prev=None）
    hist_tail = _clean_query_text(hist or "")[-_memory_config.QUERY_FALLBACK_CHARS:]  # 历史单独截 120
    if hist_tail and cleaned and hist_tail.endswith(cleaned):                          # 去重（:5981-5983 原样）
        hist_tail = hist_tail[: -len(cleaned)].rstrip()
    return (hist_tail + "\n" + cleaned).strip() if hist_tail else cleaned             # 问题置尾
```

**边界情形（任务点名三条）：**

1. **问题本身超长**：A/B 两案都不截断问题（与任务口径一致）。嵌入模型输入端的自身上限由
   memory_module 嵌入调用负责，600 字上限属 window 分支、与问题无关；生产用户消息中位 29 字
   （`config.py:116` 注释），超长问题罕见。若主脑坚持给问题设上限，须新实测取值，**不要沿用 600**
   （那是被实测推翻的窗口口径）。
2. **本轮为空**：`base=""` → `cleaned=""` → `:5963` `not cleaned` 命中 → `:5964` `return base`（空串）。
   与改前行为一致，本函数不新增行为；空查询的处理责任在上游 `mem_svc.get_context`。
   智能卡触发轮不走本函数（`:6343`）。
3. **多轮追问指代为什么可接受（A 案口径）**：
   - <15 字的短追问（「后来呢」「他为什么这么做」）已由 `QUERY_MIN_CHARS` 兜底**自动补上一条尾部 120 字**
     （`:5966-5985`），指代语境不丢——有测试钉住（§4 `test_too_short_falls_back_to_previous_tail`）；
   - ≥15 字的指代问题：复核报告整批实测证明**去掉历史后召回反而大幅变好**（top1 6.2%→22.9%、
     排名 17→4），稀释的伤害远大于丢指代的损失；且现链路已有关键词路 RRF（专名/数字/改口字面锚点，
     落地报告 §一 #2）兜底；
   - 若主脑不放心：方案 B 开关正是为该场景保留的实验位，可开关对照复测后再定。
