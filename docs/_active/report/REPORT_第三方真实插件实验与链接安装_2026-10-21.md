> 本文全部为一手实测：**真实 GitHub 仓库**、**真实安装接口**、**真实页面执行**。零付费 API 调用。

| 插件 | 仓库 | 版本 | ZIP 大小 |

## 1. 安装通道

### 1.1 链接安装（`POST /api/plugins/import-url`）——**用真实仓库直链跑通**
请求 `{"url":"https://github.com/Rurijian/KimiThinkingPrefill/archive/refs/heads/main.zip"}` →
`200`，`{"message":"SillyTavern 扩展包导入成功","plugin":{…}}`；
解析结果：`name=Kimi Thinking Prefill`、`version=1.1.0`、`author=Rurijian`、`enabled=true`，
`id=e7f62410-703c-4980-bdec-372763b094ad`。资源也进了库：`resources.css` 1 条（329 字符）、
`resources.js` 1 条、`assets` 1 条。

### 1.2 文件上传（`POST /api/plugins/import`，multipart）
ComfyInject（`0108b6a2-…`）与 Smart Memory（`3bdb0b2a-…`）各 `200` 导入成功；
Smart Memory 的资源量级：`modules=31`、`assets=34`、`css=46110 字符`。

### 1.3 护栏负向测试（都跑了）
| 输入 | 结果 |
|---|---|
| `http://localhost:16000/` | **400**「仅允许公网 http(s) URL（localhost/内网/保留地址一律拒绝）」 |
| `http://127.0.0.1:8000/x.zip` | **400** 同上 |
| `https://github.com/Rurijian/KimiThinkingPrefill`（仓库主页） | **400**「URL 内容不是 ZIP 包（仅支持扩展 ZIP 直链，不支持仓库主页链接）」 |
| `https://github.com/…/raw/main/README.md` | **502**「扩展下载失败: …」；容器日志原文：`<urlopen error _ssl.c:1000: The handshake operation timed out>` |

⚠️ 最后一条是**环境**（容器直连 `raw.githubusercontent.com` TLS 握手超时），不是代码缺陷；
但它说明两件事：① `github.com/.../archive/...` 这条路可通、`raw.githubusercontent.com` 这条路可能不通
（本机代理不覆盖容器）；② 502 的用户文案只写"扩展下载失败"，没暴露"超时"（日志里才有）。

## 2. 宿主侧真实加载结果（页面级控制台，一手）

| 插件 | 结果 | 证据 |
|---|---|---|
| ComfyInject 0.3.0 | ✅ **无报错，加载成功** | 控制台无相关错误；功能需生成内容才触发（`[[IMG: …]]`），本次**未验证**实际注入 |
| Kimi Thinking Prefill 1.1.0 | ❌ `ReferenceError: SillyTavern is not defined`（`initSetting` 与 PAGEERROR 各一） | 源码第一行就是 `const { eventSource, event_types } = SillyTavern.getContext();` |
| Smart Memory 1.8.3 | ❌ `TypeError: registerSmartMemoryMacros is not a function`（两处） | 其 31 个模块的导出链里有一个函数没挂上 |

**Kimi 的缺口是"ST 全局对象"**：我们只提供模块化 shim + `TavernHelper`，**没有 `SillyTavern` 这个全局**
（`SillyTavern.getContext()` 是 ST 生态里最常见的入口之一）。这不是某个插件的写法问题，是通用缺口。

**Smart Memory 的缺口是"模块导出链"**：与 E2b 刚修的规则 11/8b 属同类但**不同形态**——
这次不是"早引用撞 TDZ"，而是"函数导出根本没挂上"，需要按它自己的 31 个模块定位。

## 3. 卡片帧内：**装上了，但卡里用不上（设计如此 + 没有 UI）**

- 该测试角色（露缇雅1.2）库内实测 `plugin_scope_mode = **allowlist**`。
- 7/7 卡片帧实测：`pluginCss=5`（allowlist 里带 CSS 的 5 个）、
  新装的三个 `hasNewCss=0`（**不进帧**）；但 `isInstalledExtension(<新 id>)` 三个都返回 `true`
  （读的是全局安装表，不是帧内清单）。
- 后端逻辑（一手读码）：`_filter_runtime_config_for_character` 的 allowlist 分支只保留
  "allowlist ∪ exempt"，其余一律剔除 ⇒ **新装插件不会自动进任何卡的帧**。
- ⚠️ **前端没有任何 `plugin_scope_mode` / 每卡插件清单的入口**（`grep frontend/src` 0 命中，
  后端 `character.py:150` 可写）。⇒ 用户装完插件，在卡里**用不上，也没有界面能把它加进某张卡的允许清单**。
  这与之前盘点的"接上了但改不了"是同一类问题。

## 4. 结论

1. **链接安装 + 上传安装都能用真实插件跑通**，元数据/资源解析正确，护栏（内网、非 ZIP）有效。
2. **真实生态适配度：3 个里 1 个干净加载**（ComfyInject），2 个撞在通用兼容缺口上
   （`SillyTavern` 全局、模块导出链）。
3. **"装了能不能在卡里用"取决于每卡 allowlist，而那个开关没有 UI** ⇒ 当前安装功能对"卡内使用"不可达。

## 5. 收尾（已执行）

三个测试插件**已全部禁用**（`PUT /api/plugins/{id}/toggle` 各 200）；
`runtime/config` 回到 6 个（禁用项不下发）。**没有删除**——删除是破坏性写，等用户点头再说。
⚠️ 这三个插件是**全局插件**（导入接口不带 user 作用域，`user_id IS NULL`），即所有用户可见；
它们现在处于禁用态，不影响任何人。

## 6. 建议的后续（按性价比）

1. **补 `SillyTavern` 全局对象**（`SillyTavern.getContext()` / `libs` 等常用入口）。
   ⚠️ 不能直接把宿主对象暴露给沙箱——要按现有 shim 口径包一层，评估对沙箱红线的影响。
2. **定位 Smart Memory 的 `registerSmartMemoryMacros`**（31 模块导出链的具体断点）。
3. **给每卡插件 allowlist 补 UI**，或改成"导入时询问加入当前卡"——否则安装功能在卡内不可达。
4. URL 安装失败文案区分"超时 / 非 ZIP"（低优先，日志已有细节）。

## 7. 订正（2026-10-21 傍晚 · 主脑复查）

> 本报告 §3 写的"前端没有任何 `plugin_scope_mode` 入口"**是错的**，原文保留，以本节为准。

- 每卡插件白名单**有 UI**：**角色编辑器 → 「插件」Tab**
  （`frontend/src/components/views/character/CharacterPluginsTab.tsx`，挂载于 `CharacterEditor.tsx:476`），
  走 `GET/PUT /api/characters/{id}/plugin-state`，支持 `inherit` / `allowlist` 与逐插件勾选。
- `grep plugin_scope_mode` 0 命中是因为**前端用的是 `mode` 字段名**、不是 DB 列名——我搜错了关键词。
- 所以"装上的插件在卡里用不上"的真实原因不是缺界面，而是：**那张卡处于 allowlist 模式，且没有把新插件勾进去**。
  用户自己就能在角色编辑器里勾。若要做体验优化，只该做"导入后提示加入当前卡"，不是补界面。
