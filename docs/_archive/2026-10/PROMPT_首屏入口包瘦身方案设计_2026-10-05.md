## 一、问题现象（实测，一手证据）

在网络受限条件下访问首屏，页面长时间白屏。实测环境：300kbps 限速 + 300ms 延迟 + 共享带宽。

| 指标 | 实测值 |
|---|---|
| 首屏入口 JS（gzip 后） | **638 KB** |
| 首屏入口 JS（raw） | **1782 KB** |
| 入口 JS 传完耗时 | **26 秒** |
| 60 秒时页面状态 | **完全白屏**（`document.body === null`） |
| 60 秒内实际下载量 | **仅 5 KB**（6 个请求互相排队抢带宽） |

`index.html` 首屏引用的资源：

```html
<link rel="stylesheet" href="/katex.min.css" media="print" onload="this.media='all'"/>
<link rel="stylesheet" href="/st/css/fontawesome.min.css" media="print" onload="this.media='all'"/>
<link rel="stylesheet" href="/st/css/solid.min.css" media="print" onload="this.media='all'"/>
<script type="module" crossorigin src="/assets/index-XXXX.js"></script>
<link rel="stylesheet" crossorigin href="/assets/index-XXXX.css">
<script src="/bootstrap.js"></script>
```

**注意**：那 3 个 CSS 已经是异步加载（`media="print"` + `onload` 切换），
`modulepreload` 标签数量为 **0**。所以**唯一的真阻塞项就是那一个 638KB 的入口 JS**。

## 三、项目已有的正确做法（请对齐，不要推翻）

vite 配置注释里记录了一次成功的首屏瘦身：曾用「移除对象式 manualChunks」把首屏从
844KB→597KB（gzip，-29%），并明确记录了踩过的坑：

> 对象式 `manualChunks: { mermaid:['mermaid'], recharts:['recharts'] }` 会把「目标包的依赖」
> 一并吸进该chunk —— mermaid chunk 会吸走 dompurify（126KB），recharts chunk 吸走 clsx，
> framer-motion chunk 吸走 react 运行时。而 entry 静态 import 了这些，于是被迫静态依赖，
> Vite 在 index.html 里对它们发 modulepreload ⇒ 本应懒加载的库进了首屏关键路径。

**硬约定**：若需再切分，只能用函数式 `manualChunks`，且只匹配目标包自身的 node_modules 路径，
**绝不能**把 dompurify / clsx / react / katex 等共享依赖纳入命名 chunk。

## 四、我尝试过的方案，以及它为什么被我自己否掉

### 方案：KaTeX 改为动态 import（❌ 已实施并验证，发现真实缺陷）

**依据**（都验证过）：
1. 全项目仅一处使用 KaTeX：`src/lib/sillytavern/formatting.ts:225` 的 `katex.renderToString()`
2. `renderMathInHtml:269` 已有守卫：无 `$` / `\(` / `\[` 直接返回 ⇒ 多数消息不进数学分支
3. `katex@0.16.45` 的 package.json **未声明 `sideEffects`**，主入口是 CJS（`dist/katex.js`）
   ⇒ 打包器不敢摇树，只能改代码延后

**我实施的代码**（`formatting.ts`）：
```ts
let katexInstance: KatexModule | null = null;
let katexLoading: Promise<KatexModule | null> | null = null;
function preloadKatex() {
  if (katexInstance) return Promise.resolve(katexInstance);
  if (katexLoading) return katexLoading;
  katexLoading = import('katex').then(mod => { ... }).catch(() => null);
  return katexLoading;
}
function renderSingleMath(tex, displayMode) {
  const katex = getKatex();
  if (!katex) { void preloadKatex(); return displayMode ? `$$${tex}$$` : `$${tex}$`; }
  try { return katex.renderToString(tex, {...}); } catch { return /* 回退原文 */; }
}
```

**为什么否掉**：
`renderMathInHtml` 是**同步导出**，被同文件 `:1184` 同步调用，签名不能改。
于是「首次遇到公式 → KaTeX 未加载完 → 显示原文，加载完后重渲染才变公式」。
后果有两个，都不可接受：
1. **公式显示抖动**（先原文后跳变）
2. **6 个既有测试变红**（`failed=0` 是本项目硬门禁）：
   - `src/lib/sillytavern/__tests__/formatting-latex-contract.test.ts` — 4 个
   - `src/lib/__tests__/formatting-katex-contract.test.ts` — 1 个
     （`:29` 断言源码含 `from 'katex'` 字面量）
   - `src/lib/sillytavern/__tests__/formatting-math-script-guard.test.ts` — 1 个

这些测试守的是**真实功能契约**（公式能正常渲染、script/style 段的 `$` 不被误当公式）。
改断言让自己通过是我明确要避免的做法。

⚠️ **当前工作区就停在这个半成品状态**：`formatting.ts` 的静态 import 已移除、动态加载器已写入，
6 个测试是红的。你可以基于这个现状继续，或建议回退
（原件在 `_BACKUPS/2026-10-05_KaTeX延迟加载前/files/formatting.ts`）。

## 五、我考虑过但认为收益不足的方案

**加载态/骨架屏**：`index.html` 里目前只有空的 `<div id="root"></div>`。
加静态"正在加载"提示，成本极低、零风险，但**只是改善观感，不减少要下载的字节**。
在 638KB 的前提下，弱网下仍是 26 秒。

**HTTP preload 提示**：入口 JS 本身就是阻塞资源，`preload` 对它几乎无增益；
能省的只是几个小 CSS 的发现延迟（几秒量级）。我判断收益太小。

## 六、真实约束（方案必须满足，否则落不了地）

1. **测试门禁**：`npx vitest run` 必须 `failed = 0`。不许通过削弱/改写断言来让自己通过。
2. **类型门禁**：`npx tsc --noEmit` 退出码 0。
3. **同步契约不可破坏**：`renderMathInHtml` 是同步导出且被同步调用。
   如果你认为必须改签名，请把**所有调用方**和改动范围列清楚。
4. **构建流程特殊**：`npm run build` 已禁用于上线（`clean-dist.cjs` 第一步就清空在用的 dist，
   而 dist 不受 git 跟踪 ⇒ 无回滚点）。正确顺序是：
   ```
   VITE_OUT_DIR=dist_new_X node scripts/build-vite.mjs   # 试构建，不动在用 dist
   # 校验：① index.html 引用的资源全部存在 ② assets/ 里 index-*.js 只有一个指纹
   cp -r dist_new_X/. dist/        # 原地覆盖，不删 dist 本身
   # 清孤儿（逐个删，不要 rm -rf）
   node scripts/gzip-dist.cjs       # 必须最后跑，它固定对 ./dist 动手、不认 VITE_OUT_DIR
   docker compose restart frontend
   ```
5. **验收只能 grep 字符串字面量**（terser 改标识符，函数名/路径两边都是 0 命中）。
6. **验证改动是否真的进首屏**：入口文件是产物里 raw > 1MB 的那个 `index-*.js`；
   KaTeX 的可靠特征是字体度量表，形如 `{32:[0,0,0,0,.25],65:[...` 的连续数据块
   （可用正则 `\{(?:\d+:\[-?[\d.]+(?:,-?[\d.]+)*\],){20,}\d+:\[-?[\d.]+(?:,-?[\d.]+)*\]\}` 精确计量）。
7. **有并行 agent 在改同仓库**：`Message.tsx`、`card-script-runner.ts` 已被改动，
   `VariableChangePanel.tsx` 等新文件是别人的在途工作。**方案应尽量避开这些文件**。
8. 项目未上线，**不需要向后兼容**，可以自由改。
