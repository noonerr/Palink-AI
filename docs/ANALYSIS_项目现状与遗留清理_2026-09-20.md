### 6.3 发现并修复的产物层影响

- **症状**：删除 `public/st/` 后跑的那次 build，产出的 `dist/st/` 是**空目录**，而 `dist/index.html:90-91` 仍引用 `/st/css/*`。由于 `frontend/dist` 是 bind mount 到 nginx 的线上产物，这会直接导致 Font Awesome 404、ST 插件（酒馆助手 Galgame 组件）窄视口下按钮空白。
- **修复**：重跑 `npm run build`（41.29s，先 `mv dist dist_verify_<date>` 绕开批量删除守卫）。全量校验 `dist/index.html` 的静态引用逐条命中：`/st/css/fontawesome.min.css`、`/st/css/solid.min.css`、`webfonts/fa-solid-900.{ttf,woff2}`、`/bootstrap.js`、`/icons/*`×8、`/katex.min.css`、`/manifest.json`、`/manifest-dark.json`。
- **附带收益**：`public/st` 原先**未被 git 跟踪**，意味着"git 干净部署"本来就会 404（e7c12ab 提交信息亦证实）。还原 + 入库后，这个更老的隐患被一并消除。
- **教训已登记**：源码还原 ≠ 产物恢复；删改 `public/` 静态资源后必须重跑 build 并逐条校验 `dist/index.html` 的引用命中。
