# REPORT — 移动端 UI 精致度调研与提升方案（2026-09-06）

> **范围**：仅移动端（`<768px` / PWA）。桌面端零波及（`DESKTOP-DO-NOT-TOUCH` 红线全遵守）。
> **方法**：前端全量代码样式模式扫描（TSX/TS/CSS）+ 头条结论逐条人工复核（tailwind.config / ChatInput / index.html / App.tsx 均已亲验）+ grep 计数复核（duration-400=15、active:=23、text-[10px]=95）。
> **局限**：调研当日 docker 未运行，未做实弹视觉走查；本文结论基于代码证据，施工后以 IAB 393×852 实测为验收口径。
> **地位**：移动端精致度议题的唯一权威底稿。拍板后施工记录回填本文或 TODOS.md。

## 一、TL;DR

「不精致」的根因不是缺某个炫技效果，而是**三层欠账**：

| 层 | 一句话 | 代表证据 |
| --- | --- | --- |
| ① 移动端基本功缺口 | 真机可感的硬伤 | 主输入框 14px 触发 iOS 聚焦自动放大；全项目触控反馈仅 23 处；15 处动画类根本不存在（CharacterList 顶栏塌缩零动画）；toast 出在桌面位 |
| ② 设计基线缺失 | 每个组件各自为政 | 浅色画布三个色值打架（#F8FAFC/#f5f5f5/#FFFAFA）；圆角 9 种混用；图标 8~28px 十几档；Manrope/Sora 声明了但从未加载——「设计感」目前是系统字体碰运气 |
| ③ 状态设计与对标缺口 | 精致感的另一半在「状态」 | 加载 43 个 spinner vs 1 个骨架屏；空态裸文本 ~20 处；无侧滑返回/长按菜单/下拉刷新 |

修复策略 = 三档施工：**P0 快修批（~1 天）→ P1 设计基线批（~2-3 天）→ P2 质感升级批（逐项拍板）**。P0/P1 全部低风险、可独立验收；P2 每项单独立项。

## 二、P0 快修批（~1 天，高收益零风险）

### P0-1 主输入框 14px → 16px（消灭 iOS 聚焦自动放大）
- **证据**：`ChatInput.tsx:301`，`mobile-demo` 变体 textarea 为 `text-sm`（14px），该变体被**所有**移动端 composer（`ChatInputArea.tsx` / `ChatViewMobile.tsx`）使用。
- **机制**：`index.html:11` 注释自己确认 `user-scalable=no` 在 iOS 10+ 被忽略 → iOS 对 <16px 输入框聚焦时强制缩放整页。现象 = 点输入框瞬间页面放大抖动，且会干扰 K 系列键盘布局假设。
- **修复**：mobile-demo 分支 `text-sm` → `text-base`。**一行**。
- **验收**：IAB 393×852 聚焦输入框，`visualViewport.scale` 恒 1 不跳变。

### P0-2 duration-400 死类 ×15（现在根本没有动画）
- **证据**：全仓 `duration-400` ×15（grep 复核）。Tailwind 3 默认时长表（75/100/150/200/300/500/700/1000）没有 400，`tailwind.config.js` 亦未 extend（已亲验）→ 这 15 个类**不产生任何 CSS**。
- **现象**：`CharacterList.tsx:633-725` 整个顶栏滚动塌缩动画是**状态瞬跳**，无过渡。
- **修复**：`tailwind.config.js` transitionDuration 补 `'400': '400ms'`（一处，零回归——该类此前不存在，补上只恢复原作者意图）。
- **验收**：CharacterList 滚动时顶栏高度/透明度平滑过渡。

### P0-3 触控反馈铺底（全项目仅 23 处 active:）
- **证据**：全仓 `active:` ×23（grep 复核）——仅 dock（`Sidebar.tsx:557`）与发送/停止（`ChatInput.tsx:318,337`）有按压缩放；大量卡片、列表行、头部按钮只有 `hover:` 效果，**手机上没有 hover，点了毫无反应**。这是「不精致」感知的最直接来源之一。
- **修复**：做一个 `.pressable` 工具类（`active:scale-[0.98] + active:opacity-80`，~100ms），铺到移动端可点面：CharacterList 卡片、ChatSessionList 行、设置入口行、头部图标钮。hover-only 的桌面组件不动。
- **红线**：不加毛玻璃、不改布局，纯反馈层。

### P0-4 Toaster 移动端位置
- **证据**：`App.tsx:1102` `position="top-right"`——桌面位；窄屏贴着灵动岛/顶栏按钮，且遮挡顶部内容。
- **修复**：sonner 的 `position` 不支持响应式，用 CSS media query 覆盖 `[data-sonner-toaster]` 在移动端改 top-center（桌面字节不动）。

### P0-5 无效渐变 + 顶栏 blur 配方分裂
- **证据**：`ChatViewMobile.tsx:536` `bg-gradient-to-t from-transparent via-transparent to-transparent` 是零效果渐变（三档全透明）；顶栏毛玻璃两套配方——`TopBar.tsx:25`（blur 22px saturate 180%）vs `ChatViewMobile.tsx:348` 内联副本（16px/160%），且两者用**同一个元素 id** `mobile-chat-top-bar`，`index.css:470-481` 还有一段指向该 id 的死 CSS。
- **修复**：删无效渐变；两套 blur 统一为一套配方（保守取现有 16px/160%，**不新增模糊层**）；死 CSS 段删除。

### P0-6 漏网小触达按钮
- **证据**：`ChatInput.tsx:237` 附件删除钮 24px 等。消息操作行已有 44px 补丁（`index.css:2197-2216`），但散点仍有 <44px 无补偿点击区的。
- **修复**：逐个加 padding 补足 44px 命中区（视觉尺寸不变）。

## 三、P1 设计基线批（~2-3 天）

> 原则：**只新增语义变量/类，不重定义 Tailwind 全局 scale**（重定义 rounded-lg 会波及桌面，超范围）。迁移以移动端高可见面为主（dock/顶栏/输入区/消息操作/列表/设置入口），不做全仓大扫除。

### P1-1 画布色统一（三色打架 → 一份变量）
- **现状**：浅色画布三个色值并存——`#F8FAFC`（MobilePager 容器 `App.tsx:433` + K19 manifest 主题色）、`#f5f5f5`（`index.css:1304` `--mobile-shell-background`）、`#FFFAFA`（暖白，侧栏/输入框 `ChatInput.tsx:261`、`ChatHeader.tsx:118`、`CharacterList.tsx:680` 等四处复制）；暗色画布 `#020617` 在 JS 写死（`App.tsx:657`）。
- **修复**：定义 4-6 个移动端语义变量（`--palink-canvas` / `--palink-surface` / `--palink-surface-warm` / 暗色对应），组件 hex 换 `var()`；`App.tsx` JS 写死处改启动时读一次 computed style。
- **红线**：`manifest.json` / `manifest-dark.json` 的 theme_color 字面量**不动**（K19 双 manifest 口径，静态快照机制）。

### P1-2 字体拍板（二选一，见 §七）
- **现状**：`--font-sans` 首选 Manrope、`--font-display` 首选 Sora（`index.css:45-46`），但 `index.html` 只加载 KaTeX/FontAwesome，**两个品牌字体从未加载**——全项目实际渲染 = 系统字体（PingFang SC / 微软雅黑），数字与英文的「设计感」是碰运气。
- **选项 A（推荐）**：加载 Manrope Latin 子集 woff2（~25KB，`font-display: swap`），英文/数字立刻换气质，中文继续系统字体零成本。
- **选项 B**：删虚假声明，明确纯系统字体栈，零体积。

### P1-3 圆角语义档
- **现状**：`rounded-*` 794 处、9 种变体混用（lg 145 / full 140 / md 115 / xl 75 / 2xl 59 / 裸 rounded 49…）+ 特例胶囊（dock 35px、composer 26px、按钮 28px）。`--radius` token 派生链基本被绕过。
- **修复**：定四档语义（控件=full、卡片=xl、面板=2xl、大胶囊=特例常数），P1 批内迁移移动端高可见组件；dock/composer 的大胶囊作为「品牌特例」保留常数并加注释。

### P1-4 图标规格
- **现状**：lucide 尺寸 8→28px 十几档混用（`size={14}`×155、`size={16}`×113、`size={12}`×39）+ 内联手绘 SVG（`ChatInputArea.tsx:78`、`ChatEmptyState.tsx:49-53`）混入。
- **修复**：16/20/24 三档 + strokeWidth 恒 2（激活态 2.5 保留为唯一例外），内联 SVG 换 lucide 等价物。

### P1-5 微字号收敛
- **现状**：`text-[10px]` ×95（grep 复核）、`text-[11px]` ×40——10px 在手机上接近不可读，是「廉价感」来源。
- **修复**：收敛到 11/12 两档（移动端高可见面优先）。

### P1-6 数字排版
- **现状**：`tabular-nums` 全仓仅 5 处，token 计数/字数等数字用比例字型，跳动。
- **修复**：所有动态数字处补 `tabular-nums`。

### P1-7 死代码清场（精致度的维护面）
- `NativeRoleplayChat.tsx`（1243 行，仅 `roleplay/index.ts:5` 导出、零视图引用的死文件，还带 emoji 图标/hover-only 等旧模式）。
- `index.css:1411-1453` K9/K12 休眠 CSS（`palink-kb-open` 类已无 JS 写入方；**保留** `palink-dock-kb-hide` 新链路与 K13 `:has(:focus)` composer 落底规则）。
- `index.css:470-481` `#mobile-chat-top-bar` 死 CSS（见 P0-5）。
- `ui/empty.tsx`、`ui/drawer.tsx`(vaul) 已安装从未用 → 在 P2 接线或删（登记，不盲删）。

## 五、对标定位（一句话版）

- **ChatterUI**（移动优先的 ST 客户端）：触控反馈/骨架屏/底部 sheet 齐全 = 同类**及格线**。

- **LobeChat / Open WebUI**：`index.css:41` 自述灵感来源——目前只借了色板，没借状态设计。
