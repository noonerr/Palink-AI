## 4. 环境与工程纪律（踩过坑，务必遵守）

### 4.1 仓库 LF/CRLF 混存

- 同一文件内都可能混。用 Python 批量改代码时，**不能** `replace("\n", "\r\n")`——那会把正则量词 `\n*` 破坏成 `\r\n*`，表现为「import 加了但函数没删」的假成功。
- 正确写法：正则统一用 `(?:\r?\n)`，替换串按命中处实际的换行来。
- **改完必须干跑**：先打印每个文件的行数变化，确认每个目标函数都被匹配到，再 `--apply`。今天第一版干跑就暴露了 8 个文件未匹配。

### 4.2 两个会让测试变红的守卫

- **静默失败守卫**（`test_silent_failure_guard.py`）：新增任何 `try/except` 必须走 `core.silent_failure.record`（或 `swallow`），否则报 `utils.py: N > 允许 M`。今天中了两次。热路径用 `record(..., once=True)`。
- **safe-delete 守卫**（Mimosa）：按「agent 轮次」计数，阈值 50。同一轮里跑多轮 pytest 后删除预算耗尽，它会**吞掉 pytest 汇总行并让 exit=1**，但实际 0 FAILED / 0 ERROR。要拿干净数字：`CODEBUDDY_SAFE_DELETE_ENABLED=0 py -3 -m pytest tests/ -q`，或开新回合。

### 4.3 命令与环境

- 后端测试必须 `cd backend && py -3 -m pytest tests/ -q`（系统 Python 有 pytest；WorkBuddy 托管 python 没有）。
- `docker exec` 前 `export MSYS_NO_PATHCONV=1`；`docker cp` 的宿主路径**不能加**。
- 不要用 `py -3 - <<'PY'` 的 heredoc 跑含反斜杠/正则的脚本（管道会吃反斜杠）。写文件再 `py -3 <file>`。
- `raw.githubusercontent.com` 本机 **DNS 失败**；`git clone github.com` 会被 reset。可用：`api.github.com`（repo/contents 接口，返回 base64）、`codeload.github.com` zip 直链。ant-design/x 的默认分支是 **main**。
- `npm run build` 禁止直接跑（会删 dist 半截导致白屏）。要重建走 `VITE_OUT_DIR=dist_new_xxx node scripts/build-vite.mjs` → `cp -r dist_new_xxx/. dist/` → `node scripts/gzip-dist.cjs`，用完 `mv` 进 `_BACKUPS/_QUARANTINE_<日期>/`。
- 容器 `/tmp` 不可删（`rm: Operation not permitted`），临时脚本留在容器里，重建即消失。

### 4.4 提交与备份纪律

- 逐项 `git add -- <path>` / `git commit -o -- <pathspec>`；禁 `add -A` / `commit -a`。
- commit message 用 `-F <消息文件>`（反引号会被 bash 吃），`-F` 须在 `-o -- <paths>` 前。
- 备份必须放 `_BACKUPS/YYYY-MM-DD_主题/`，含 `BACKUP_INFO.md`（四要素）并登记 `_BACKUPS/_INDEX.md`；改动类用 `pre/` + `_manifest.tsv`(sha256)。
- 动 `docs/` 后必须 `py scripts/docs/gen_docs_catalog.py` 再 `--check`。
- 提交 ≠ 上线：改后端要 `docker compose build backend && up -d`；改前端要重建 dist。
- 容器内文件是 CRLF，与 `git show HEAD:` 比 sha256 必然不等，必须 `diff --strip-trailing-cr` 比内容。

## 6. ant-design/x 调研结论（源码级，2026-10-23）

### 6.1 打字机效果 = 四个设计，没一个是 setInterval

1. **`requestAnimationFrame` + 时间闸门**：`if (now - lastActivedFrameTime < interval) { raf(fn); return; }`。高刷屏不会变快，掉帧不会失控。
2. **`step` 支持随机区间 `[min,max]`**：`Math.floor(Math.random()*(max-min))+min`，默认每帧 3~6 字符——**不均匀才像人打字**。
3. **`keepPrefix` + `getLCP`（最长公共前缀）**：新内容到来先算「已渲染文本」与「新全文」的公共前缀并钉住开头，上游改写开头时不闪回。
4. **`output` 是分段数组**：每帧那一小段是独立 `{text, id, taskId, done}`，**未完成的段**套 `<span className="fade-in">`——淡入单位是「这一帧新增的碎片」而非整段。另有 `taskId` 防竞态、`streamingRef` 让无新内容时空转等下一块。

### 6.2 流式不卡的真因 = Section 化 + React.memo

文档按块切分，每段用**源字符串**做 memo key。流式时只有最后一段字符串在变，前面每段字符串一模一样 ⇒ React 整段跳过，marked/DOMPurify/HTML 解析只跑在正在长的那一段。

配套：`injectTail`（默认字符 `▋`）让未闭合块可被解析；`incompleteMarkdown:'complete'`；`AnimationText` 支持 `splitBy:'sentence'` 按句合段。

### 6.3 思考链 = 极克制，无动画库

`items[{key, title, description, status, icon, blink}]`；状态机只 4 态 `loading/success/error/abort` → 4 个 antd 图标；`blink` 只是一个 CSS class；`line` 布尔画连接线；可折叠用 rc-motion；**Item 组件不含任何流式逻辑**。
