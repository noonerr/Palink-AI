## 0. 分类定义与判据

分类不是按"难不难"，而是按**一条判据**：

> **Palink 有没有这个东西的对应实体？**

| 类 | 判据 | 数量 | 处置 |
|---|---|---|---|
| **A 必须挂载** | 缺了会**崩**或**核心功能不生效**；Palink 有数据，只是没接出来 | **5** + 1 项整体 | 立即做 |
| **B 可投影** | Palink **有对应实体**（后端 API + 前端封装都在），接一层映射即可 | **71** | 分批做，只读优先 |
| **P 变量写（需拍板）** | Palink **刻意关闭**的写入边界，开了要改产品策略 | **4** | 等用户授权 |
| **C 完全不做** | Palink **没有对应实体**，或开洞风险 > 收益 | **19** | 明确不补，写清理由防后人误补 |
| **D 已完成** | 实测已在主页面可用 | **35** | 只登记，不动 |

> 🔴 **「可用」有两种，别混为一谈**（本次复核最大的教训）：
> - **真可用**：函数体真读数据 / 真调后端
> - **假可用（降级桩）**：`typeof === 'function'`，但函数体只 `recordStubHit()` 然后返回空值。
>   实测有 **5 项**属于此类（见 §10.2）。**探针只测 `typeof` 会把它误判成「已适配」。**

**校验**：5 + 71 + 4 + 19 + 35 = **134**，与权威清单**无遗漏、无重复**（用脚本验过，见 §7.3）。

### 0.1 关键前提：先搞清"投影"是什么意思

本项目已有的标准做法（`sillyTavernPluginRuntime.ts:760-851`）是**两段式**：

```
┌─ TS 侧（palinkBridge 对象，可用 async/await、可用 api 服务）────────┐
│  refreshXxx: async () => { const r = await api.get(...); cache = r; } │  ← 异步拉真数据
│  xxx:        () => cache                                              │  ← 同步读缓存
└───────────────────────────────────────────────────────────────────┘
                              ↓  window.__palinkBridge
┌─ 注入脚本侧（模板字符串，同步，无 async）──────────────────────────┐
│  window.getXxx = function() {                                        │  ← 插件同步调用
│    var b = window.__palinkBridge;                                    │
│    return b && typeof b.xxx === 'function' ? b.xxx() : 默认值;        │
│  };                                                                  │
└───────────────────────────────────────────────────────────────────┘
```

**为什么必须这样**：ST 脚本大量**同步**调用（`TavernHelper.getVariables()` 直接拿值），
而 Palink 数据来自后端 HTTP。所以只能"TS 侧预取缓存 + 脚本侧同步读"。

⚠️ **缓存惰性陷阱（10-06 已踩）**：MVU 在**模块顶层 `await`**，桥接缓存此时是**冷的**。
⇒ 只读桥接**第一次被调用时必须自己触发一次 refresh**，不能只返回缓存。
（`sillyTavernPluginRuntime.ts` 的 `getLorebookEntries` 已是这个写法，照抄。）

    var src = MAP[k];
    Object.defineProperty(window.SillyTavern, k, {

⚠️ **三条纪律**：
1. **只投影 `getContext()` 真有的字段**。清单里写多不会凭空造数据（getter 读不到就是 undefined），
   但会让 `in` 探测失真，所以清单要准。
2. **不投影 `generate` / `stopGeneration` / `callGenericPopup`** —— 这三个不是数据字段，
   `getContext()` 里没有，投影会得到 undefined，反而比"未定义"更迷惑。它们属 §4 单独处理。
3. **`characters` 投影出来后是个稀疏数组**（见下条 A-1），要一并处理。

### A-1 `getCharData` / `getCharacter` / `getCurrentCharacterName`

三项同源，一次做完。沙箱轨**已有真实现**（`sandbox.ts:3703-3736`），但**不能直接照搬**。

🔴 **必须先避开这个坑**：

```
getContext().characters  →  Array.isArray = true
                            .length        = 1450532750     ← 按 characterId 当索引填的稀疏数组
                            实际可枚举 key  = ['1450532749'] ← 只有 1 个
```

沙箱轨的 `getCharacterNames` 是这么写的：

```ts
// sandbox.ts:3723-3728  ← 不要照搬这段
getCharacterNames: () => ctx?.characters?.map((c: any) => c.name) || []
```

**`characters.map()` = 遍历 14.5 亿次 = 浏览器冻结。**

✅ 正确写法（只遍历真实存在的索引）：

```js
// 注入脚本侧
window.getCharData = function (nameOrId) {
  var ctx = window.SillyTavern && window.SillyTavern.getContext
    ? window.SillyTavern.getContext() : null;
  if (!ctx || !ctx.characters) return null;
  var chs = ctx.characters;
  // ① 先试按 id 直接取（稀疏数组的正常用法，O(1)）
  if (nameOrId === undefined || nameOrId === 'current' || nameOrId === null) {
    if (chs[ctx.characterId]) return chs[ctx.characterId];
  } else if (chs[nameOrId]) {
    return chs[nameOrId];
  }
  // ② 按名字找 —— 只遍历真实索引，绝不 .map()/.forEach()
  var target = String(nameOrId || '').trim().toLowerCase();
  if (!target) return null;
  var keys = Object.keys(chs);                       // 只有真实 key，不是 14.5 亿
  for (var i = 0; i < keys.length; i++) {
    var c = chs[keys[i]];
    if (c && String(c.name || '').toLowerCase() === target) return c;
  }
  return null;
};

window.getCharacter = function (nameOrId) { return window.getCharData(nameOrId); };

window.getCurrentCharacterName = function () {
  var ctx = window.SillyTavern && window.SillyTavern.getContext
    ? window.SillyTavern.getContext() : null;
  return (ctx && ctx.name2) || null;
};
```

三轨全无，需新写。**是写操作**，但语义很窄（更新角色字段），Palink 有 `PUT /api/characters/{id}`。

  var cur = window.getCharData(nameOrId);
  if (!cur) return Promise.reject(new Error('character not found: ' + nameOrId));

  // 经 bridge 落库；bridge 侧走 PUT /api/characters/{id}

    return b.updateCharacter(cur.id || cur.avatar, next).then(function () { return next; });

### A-4 `TavernHelper` Proxy 白名单 —— ⚠️ 只补 `getVariables` 一项

> **订正**：初版说「补 2 项」是错的。复核后发现 `replaceVariables` **加了也没用**，理由见下。

`SUPPLIED` 白名单（`sillyTavernPluginRuntime.ts:2077-2097`）漏了 `getVariables`。
`window.getVariables` 是**真实现**，但脚本写 `TavernHelper.getVariables()` 会拿到记桩函数（返回 undefined）。

**改法**：在 `SUPPLIED` 数组里加一个字符串即可。

```js
// 现有数组里补：
'getVariables',
```

🔴 **为什么 `replaceVariables` 不能只加白名单**：

复核发现 `window.replaceVariables` **存在但不是真实现** —— 它是
`card-script-runner.ts:354-366` 补的**写口降级桩**：

```ts
const ASYNC_WRITE_NAMES = ['setVariables','setVariable','replaceVariables',
  'updateVariablesWith','insertOrAssignVariables','setChatMessage'];
for (const name of ASYNC_WRITE_NAMES) {
  if (typeof w[name] !== 'function') {
    w[name] = degradedWrite(name, () => Promise.resolve());   // 只登记，不写入
  }
}
```

⇒ 加了白名单，`TavernHelper.replaceVariables` 会返回一个**永远 resolve、什么都不做的函数**。
这比「undefined」更危险：**插件以为写成功了**。

⇒ `replaceVariables` 要真做，得走 **§3（P 类变量写）** 的通道，不是白名单能解决的。

> ⚠️ 白名单只决定 Proxy **认不认**这个键，不负责实现。
> 名字加进去但 `window[name]` 不是函数时，`lookup()` 会返回 null → 仍走记桩。安全。

## 10. 复核订正记录（2026-10-06 第二轮）

初版结论做过一轮**自我证伪**，以下三处是**错的、已订正**。保留原文以便追溯。

### 10.1 ❌ 错：「实际调用面 24 项」→ ✅ 正确：**47 项 / 208 调用点**

**错因（两条）**：

1. **漏了第二条执行链路**。项目里跑 ST 脚本的有**两条独立链路**，初版只扫了第一条：

   | 链路 | 脚本来源 | 注入方 | 规模 |
   |---|---|---|---|
   | ① 插件轨 | `plugin_scripts` 表（酒馆助手的 2 条脚本） | `SillyTavernPluginRuntime` | 4,276,579 B |
   | ② 卡脚本轨 | 角色卡 `extensions.tavern_helper.scripts` | `card-script-runner.ts` | MVU 框架 307,179 B |

   链路 ② 的调用面是 **29 项 / 102 调用点**，与链路 ① 重叠不大。
   合并去重后 = **47 项 / 208 调用点**。

2. **漏了 5 个不在 134 项名单内的 API**。脚本还调了
   `eventOn`(6) `getCurrentChatId`(4) `getRequestHeaders`(3) `getButtonEvent`(1) `openCharacterChat`(1)
   —— 它们不在 `TavernHelper` 命名空间里（是 ST iframe 全局），只按 134 项扫必然漏。
   （好消息：这 5 项主页面**全都有**。）

> **教训**：判断「插件需要什么 API」时，执行链路要先数清楚有几条，
> 扫描词表不能只用命名空间清单。

### 10.2 ❌ 错：「缺失 5 项」→ ✅ 正确：**缺失 8 项**，另有 **5 项假可用**
