## 1. 背景知识：架构与状态栏渲染机制

### 1.1 整体架构
- **前端**：React + TypeScript（`frontend/`），经 nginx 暴露于 **http://localhost:3999**（容器 `palink-ai-frontend-1`，`127.0.0.1:3999->8080`）。
- **后端**：Python + FastAPI（`backend/`），容器 `palink-ai-backend-1` 暴露 `8000/tcp`（代码打包进镜像，**未挂卷**，改代码需 `docker compose build backend` 重建）。
- **nginx 双 server**：`server1`(listen 8080, SPA 前端) + `server2`(listen 8081, ST-native 代理)。**新路由必须放 server1**；改后需 `docker compose up -d frontend` 重建容器（仅 `docker start` 不重读卷挂载）。
- **辅助端口**：`127.0.0.1:9061->8081`（原 9001 落入 Windows 保留段 `8958-9057` 被系统占用，已改 9061）。**所有旧文档 localhost:3000 / localhost:9001 均过时。**

### 1.2 状态栏从哪里来、怎么渲染
- 状态栏 HTML 来自**角色卡** `data.extensions.regex_scripts[4]`：`findRegex:/<StatusPlaceHolderImpl\/>/gs` 的 `replaceString`，约 49KB 完整 `<!DOCTYPE html>` 文档（即 `tmp_statusbar.html` 内容）。
- 渲染链：`Message.tsx` 检测到 `findStatusPlaceholderRegexScript` → 在 AI 输出末尾追加 `\n<StatusPlaceHolderImpl/>` → 交给 `formatMessage(runRegex:true)` 执行正则替换 → 产出完整 HTML 文档 → smart-card 分支 → `CharacterCardRenderer` 用 **iframe 内联**渲染（`presentationMode:'inline'`）。
- iframe 隔离：`mode='iframe-js'`，sandbox = `allow-scripts allow-same-origin`（同源，模块脚本可跑）。`<script type="module">`（无 import/export）被降级为经典 `<script>`。
- DOMPurify 黑屏已修：完整 HTML 文档整体跳过父文档消毒（`formatting.ts` L240/L1023、worker L331）。

### 1.3 数据链（这是状态栏能显示动态文本的关键）
```
后端 roleplay/mvu_engine 生成 stat_data（扁平复合 key，如 "桃汐.好感度"）
  → 后端 final_content 带 variables（含 stat_data）
  → useChatWebSocket.ts:209 透传 variables
  → useCharacterChat.ts:385-401 写入 message.extra.variables
  → Message.tsx:966 context.variables
  → CharacterCardRenderer bootContext.variables / liveContext.variables
  → buildSillyTavernCompatRuntimeV2Shim 的 ctx.variables
  → 序列化进 iframe → chatVariableStore 合并
  → shim mvuGetAllVariablesFinal 把扁平 stat_data 重组为嵌套
  → 面板 tmp_statusbar.html:959 refreshFromMVU() 调 getAllVariables().stat_data 填充
```
**stat_data 形状**：后端发**扁平混合**（角色名与属性名同级，约 16 键，含 `世界信息.日期时间`）；面板 `refreshFromMVU()` 按**嵌套** `stats['桃汐']['好感度']` 读取。因此 shim 必须做**扁平→嵌套重组**（按 `.` 第一段分组），并对头像 UUID 绝对化。

### 1.4 头像链路
- 头像值 = `Character.id` 裸 UUID（如 `f8138a6d-f9b5-4719-b2cd-265c3febb0b2`）。
- shim 重组时把 UUID 绝对化为 `SMART_CARD_ORIGIN + '/characters/' + uuid`。
- nginx `server1` 用前缀 `location /characters/` 代理到 `backend:8000`（**免 auth_request**，因为 iframe 是 opaque-origin、无 cookie）。
- 后端 `st_character_avatar` 路由（silly_tavern.py:2116）已改**匿名放行**：`_optional_user_from_request` 不强制登录、`_character_for_avatar` 签名 `Optional[User]`、`_character_id_from_avatar` 识别裸 UUID。

## 2. 调试时间线（做了什么 · 修了什么 · 第几轮）

> 每一轮都对应一个用户症状 + 一个根因 + 一个修复。以下按时间顺序。

### 第 1–5 轮：字体污染 + 面板不内联 + 被截断
- **症状 A（字体污染）**：AI 正文用了面板字体 `MaokenAssortedSans`。根因：状态栏 `<style>`（含 `body{font-family:...}`）被注入**同一个 iframe** 与正文混在一起 → 正文继承面板字体。
- **症状 B（面板不在下方）**：整段（正文+文档）被 `extractHtmlRenderParts` 的"整体当 html"短路分支塞进**同一个 iframe**。
- **修复（第 1 轮）**：改 `extractHtmlRenderParts`——仅当内容"本身就是一个完整文档"才合并，否则拆成 `[markdown(正文), html(面板)]`。正文走 ReactMarkdown（父文档，正文字体正确），文档走 iframe 隔离（在下方）。
- **症状 C（正文 HTML 源码当文本）**：拆出 markdown 后用自带 ReactMarkdown（无 rehypeRaw）渲染 → `<p>/<q>` 当纯文本。修复：Message.tsx 给 `<CharacterCardRenderer>` 传 `renderRemaining={(remaining)=> <div dangerouslySetInnerHTML={{__html: sanitizeStCompatHtml(remaining)}} />}`。
- **症状 D（面板底部被截断）**：iframe 高度测量不足 + 内部 measure 把父页面轮询撑开的高度压回去。
  - 修复 1：measure 改用 `Math.max(visibleBottom, naturalHeight, fixedBottom, 96)` 兜底。
  - 修复 2：`IframeRenderer` 加父页面轮询（同源直读 `contentDocument.scrollHeight`）兜底高度。
  - 修复 3：内部 `resize` 消息对 inline 模式改为 `setHeight(current=>Math.max(current, measuredHeight))`，只接受更高值。

### 第 6 轮：照片/服饰/内心想法不显示（数据链断点）
- 根因：shim 的 `contextJson` 序列化时**漏了 `variables` 字段** → iframe 内 `ctx.variables` 为 undefined；且 iframe store 初始化只从 localStorage 读（空），未合并 `ctx.variables` → `getAllVariables()` 恒空。
- 修复：① `contextJson` 增加 `variables: context.variables ?? {stat_data:{}}`；② 把 `ctx.variables` 深合并进 `chatVariableStore`。

### 第 7 轮：仍不显示（getAllVariables 未暴露为 window 全局）
- 根因：shim 从没把 `getAllVariables` 暴露为 window 全局，面板脚本裸调用 `getAllVariables()` 命中 `requiredApis` 空桩 → 返回 undefined → stat_data 恒空。
- 修复：`setCompatFunction('getAllVariables'|'getVariable'|'setVariable'|'replaceVariables', window.Mvu.xxx)` 显式暴露。

### 第 8 轮：还是不行（init 从未执行）
- 根因：面板脚本 `$errorCatched(init)`，`errorCatched` 只在父页面定义、iframe 内缺失 → 命中空桩（返回 promise、不执行 init）→ `refreshFromMVU()` 永不跑。
- 修复：shim 内补充真实 `errorCatched`：`fn=>{try{return fn()}catch(e){warn}}`，对齐 SillyTavern 行为；`$` 先求值真正调用 `init()`。

### 第 9 轮：构建/部署卡点（非功能 bug）

### 第 10 轮：数据链通了，但结构/头像仍坏

## 6. 高频踩坑与必读规则（避免重蹈覆辙）

1. **⚠️ TS 模板字符串内禁用含转义反斜杠的正则字面量** —— 在 `SillyTavernCompatRuntime.ts` 的 shim 模板字符串里写 `/^\/characters\//i`，模板会吞 `\/` 反斜杠 → 编译后变 `/^/characters//i` → `Invalid regular expression flags` 整段 shim 崩溃（状态栏全崩、FINAL 日志消失）。**一律用 `new RegExp('^/characters/', 'i')`**。
2. **⚠️ 状态栏 HTML 含 `position: fixed`/`height:100%` → 会被 `htmlPrefersImmersive` 误判为沉浸式全屏覆盖层**。任何状态栏渲染都必须强制 `presentationMode:'inline'`，绝不能用"按 extensions 是否存在"来条件开关（硬刷新 race 必触发全屏）。
3. **⚠️ nginx 正则 `{n}` 量词静默失效** —— `[0-9a-fA-F]{8}` 即使加引号也匹配不上（curl 实测无命中），不加引号更 `[emerg]` 容器循环。一律用**前缀 `location /xxx/`**。
4. **⚠️ production 构建剥离 `console.log`** —— `vite.config.ts` `pure_funcs:['console.log','console.info']` → terser 把 console.log 当纯函数整条删除。调试一律用 `console.warn` + 写 `window.__STATUSBAR_DBG` 累积数组。
5. **⚠️ `grep` 新包里我加的"注释"会返回 0** —— 生产构建 minify 剥离注释；验证改动应查逻辑或确认 `index.html` 引用的 bundle 名是构建后新产物。
6. **⚠️ 构建绕过 safe-delete 护栏** —— 默认 `node scripts/build-vite.mjs` 清空 dist/assets(>50文件) 被拦；用 `VITE_OUT_DIR=dist_fix_<ts>` 写新目录。
7. **⚠️ Windows 保留端口段** —— `8958-9057` 被系统占用（netsh 可见），别用 9001；前端辅助端口用 9061。
8. **⚠️ `sleep` 在 Git Bash 不可用**（command not found）；等容器用 `docker ps` 轮询或 `node -e "setTimeout"`。
9. **⚠️ 抽取 shim 校验** —— 从 bundle 提取 shim 时若带着 `<script>` 标签 `node --check` 会报 `Unexpected token '<'`；须只抽 `<script>` 与 `</script>` 之间的 JS 再校验。
10. **⚠️ 后端改代码必 rebuild** —— `backend/app/**` 代码打包进镜像、未挂卷；改动后 `docker compose build backend && docker compose up -d backend`。
