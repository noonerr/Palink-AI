## P-1【N-9】会话切换不 abort —— 切走后旧流继续烧钱污染新会话

### 现状（useCharacterChat.ts）

- `abortControllerRef` 仅在 `handleStopGeneration` 中触发；用户直接切换到另一个会话时，
  进行中的 SSE 流**继续扣费、继续写库**，且 `isGenerating`/超时 toast/
  `palink:mvuVariablesUpdated`（携旧 sessionId 的 variables）会污染新会话视图。

### 方案（双保险）

1. **切换即中止**：新增 effect 监听 `selectedSession?.id` 变化——变化时若
   `abortControllerRef.current` 存在则 `abort()`；若 `wsAssistantMessageIdRef.current`
   存在（WS 路径）则发 `wsSendCancel()`；随后复位生成态
   （`isGenerating=false`、`requestStartTime=null`、`setTimeoutWarning(false)`、清 timer、
   `regeneratingMessageIndex=null`）。注意跳过首次挂载（ref 记录 prevSessionId，
   仅在有 prev 且不同时动作）。
2. **回调代次比对**：发起请求时快照 `requestSessionIdRef = selectedSession.id`；
   SSE onMessage/done/error 与 WS done/error 处理入口先比对
   `requestSessionIdRef.current === selectedSession?.id`，不一致直接 return
   （不 setMessages、不 toast）。防止 abort 到达前的最后几个 chunk 写入新会话 state。

### 测试

- 提取可测的最小逻辑或在报告中给出手动验证步骤（切会话 → 网络面板旧流 cancelled /
  新会话无旧内容闪现）；tsc 通过为准。

## P-2【N-3】长会话流式卡顿 —— 三重 memo 击穿修复

### 现状（实证链）

1. `CharacterChat.tsx` smartCardChatMessages 的 useMemo 依赖 displayedMessages
   → 每个 SSE chunk 产生新数组引用；
2. 该数组经 prop 下发 → `Message.tsx` memo 比较器引用比较失效 → 每条历史消息的
   `pipelineResult`（三层正则全量执行）与 `parseContentSegments` 每 chunk 重算；
3. `sanitizeStCompatHtml` 位于 render 体而非 useMemo（Message.tsx 约 L1288）→
   每次重渲染裸跑 DOMPurify。

长会话（百条级）+ 多正则脚本卡片，打字机阶段明显卡顿；编辑单条/切换会话同样全列表重算。

### 方案

1. **稳定切片**：smartCardChatMessages 拆两层——历史部分（index < len-K，K=2）缓存于
   `useRef` 快照（仅在会话切换 / 消息数量变化 / 正则脚本集变化时重建），尾部 K 条参与
   实时更新。对外仍输出完整数组，但历史元素引用恒定。
   实现提示：用 `useMemo` 依赖 `[messages.length, sessionId, regexVersion]` 产出版本号，
   配合 ref 存上次快照拼接尾部切片；**禁止**把 displayedMessages 整体放依赖。
2. **sanitize 入 useMemo**：`sanitizeStCompatHtml(...)` 移入该消息现有 pipelineResult
   同一个 `useMemo`（输入：content/正则脚本集），render 体只读结果。
3. Message memo 比较器维持现状——上游引用稳定后自然生效，不改比较器。

### 验收锚点（审计线抽查）

React DevTools Profiler：流式期间历史消息组件 re-render 次数 ≈ 0；
长会话（50+ 条）打字机阶段无可感知卡顿。

## P-3【N-12】出视口智能卡 iframe 休眠

### 现状

mes-render-skip 体系明确排除智能卡/HTML 消息 → 长会话数十个存活 iframe 常驻
（内存 + 合成层开销）。

### 方案

1. 智能卡/HTML 容器外包一层 `IntersectionObserver`（rootMargin 一屏缓冲）；
2. **出视口**：记录容器当前 `offsetHeight` → 卸载 iframe（srcDoc 置空/条件渲染移除）
   → 渲染同高占位 div（保持滚动位置不跳动）；
3. **重新入视口**：按原 srcDoc 恢复渲染；
4. 用户普通消息（文本/图片）不参与休眠；休眠状态不持久化（刷新即全部恢复）。

### 约束

- 不与 N-1 冲突（消毒已在上游完成，休眠只是挂载/卸载）；
- Observer 实例按消息组件生命周期清理（对齐 CodeBlock 的 timer 清理模式，呼应 U 系列 N-21）。
