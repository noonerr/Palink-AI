## 2. 待办#2：后端依赖审计补跑（此前因网络超时未完成）

### 2.1 命令与结果


**Fix Versions 两列全空** = 上游无已修复版本可升，升级路径不存在，只能靠「降暴露面」或「证明不可达」处理。

### 2.2 逐条定性

#### ① `ecdsa==0.19.2` — CVE-2024-23342（Minerva 侧信道，P-256）

| 项 | 值 |
|---|---|
| 别名 | CVE-2024-23342 / GHSA-wj6h-64fc-37mp |
| 摘要 | python-ecdsa 在 P-256 曲线上受 Minerva 计时攻击：对 `sign_digest()` 计时可泄露内部 nonce，进而恢复私钥。签名生成 / 密钥生成 / ECDH 受影响，**签名验证不受影响** |
| CVSS 3.1 | `AV:N/AC:H/PR:N/UI:N/S:U/C:H/I:H/A:N` = **7.4 High** |
| 上游态度 | 官方认定侧信道**不在项目范围内，无修复计划**（这是 Fix Versions 为空的原因） |
| 影响范围 | `ranges: [{"introduced": "0"}]` = 全版本 |

**本项关键结论：它是死依赖。**

| 证据 | 结果 |
|---|---|
| `requirements.txt:17` | `ecdsa==0.19.2` —— 是**直接依赖** |
| 全仓源码 grep `^import ecdsa` / `from ecdsa` | **零命中**（backend/ 与 scripts/ 全扫） |
| 容器内 `pip show ecdsa \| grep Required-by` | **空** —— 没有任何已安装包声明依赖它 |
| 运行时是否可达 | **不可达**。项目 JWT 走 `PyJWT[crypto]`（底层用 `cryptography==50.0.0`，不是 ecdsa） |

→ 风险 = 0（代码不调用该函数族）。**建议：从 requirements.txt 摘除**（需重 build 后端镜像 + 全量回归，待用户拍板，见 §5）。

#### ② `diskcache 5.6.3` — CVE-2025-69872（默认 pickle 反序列化）

| 项 | 值 |
|---|---|
| 别名 | CVE-2025-69872 / GHSA-w8v5-vhqr-4h9v |
| 摘要 | DiskCache ≤ 5.6.3 默认用 pickle 序列化；**能写缓存目录**的攻击者可在**受害者应用读取缓存**时任意代码执行 |
| CVSS 4.0 | `AV:L/AC:L/AT:N/PR:L/UI:A/VC:H/VI:H/VA:H` —— **本地向量 + 需已有写权限 + 需用户交互** |
| 影响范围 | `introduced: 0` ~ `last_affected: 5.6.3`（= 当前已是最新受影响版，无版本可升） |

**本项关键结论：传递依赖 + 代码路径不可达。**

| 证据 | 结果 |
|---|---|
| 容器内 `pip show diskcache \| grep Required-by` | **llama_cpp_python**（传递依赖，不在 requirements.txt，无法直接摘除） |
| 应用侧引用 grep | **零命中** |
| llama 缓存是否启用 | **未启用**。`backend/app/llama_service.py` 与 `backend/app/services/llama_runtime.py` 中 grep `cache=`、`LlamaDiskCache`、`set_cache`、`use_cache` 全为 **NO_CACHE_USAGE** —— 从不创建任何缓存对象 |
| 触发前提 | 需攻击者先能写进程缓存目录（本地/CVSS `AV:L`），且应用随后读取该缓存 —— 后者永不会发生 |

→ **登记豁免**（不可达 + 无版本可升 + 摘除会牵连 llama-cpp-python）。
