## 4. 失效机制（本轮已复现，替换原「待定位的核心问题」）

定位方法受限说明：本轮**docker 未启动**（`docker ps` 连不上 daemon），既跑不了容器、也读不了库；
`_BACKUPS` 与 `docs/` 内也没有该卡脚本的副本。因此改用**等价静态法**：把返工前后的正则与闸门逐字复刻成
独立脚本，用**中性样本矩阵**逐类判定（与用户红线一致：不读卡正文）。

### 4.1 三条机制（各自独立可复现）

**机制 A —— 正则的链式宿主盲区（原单完全没提到，且可能是主因）**

旧正则的宿主段只允许**一层**：`(?:window|self|top|…)\s*\.\s*`。
而前导守卫 `(^|[^\w$.])` 明确排除了 `.`，所以「宿主名」必须直接出现在非 `.` 字符之后 ——
`window.top.localStorage` 里 `top` 前面是 `.`，**一处都匹配不上**。

| 写法 | 返工前 | 返工后 |
|---|---|---|
| `window.top.localStorage.getItem('k')` | ❌ 零匹配 | ✅ 改写 |
| `window.parent.localStorage.getItem('k')` | ❌ 零匹配 | ✅ 改写 |
| `window.frames[0].localStorage.getItem('k')` | ❌ 零匹配 | ✅ 改写 |
| `topWin.localStorage.getItem('k')` | ✅ 改写 | ✅ 改写 |
| `var w = window.top; w.localStorage…`（变量中转） | ❌ 零匹配 | ❌ 零匹配（静态改不了，属已知缺口） |

> 「爬到顶层窗口再取 Storage」正是这类卡的典型写法（SPEC §2.2 已证卡脚本里有 `topWin`）。
> 只认一层前缀，等于把主目标漏掉——**这条一旦命中，逐处回退改了也没用，线上仍然不生效**。

**机制 B —— 全有或全无的语法闸门（原单已猜到，本轮实测确认）**

旧实现：`改写后编译不过 → 整条退回原文，且不打任何日志`。
只要脚本里有**一处**关键词落在改写后会破坏语法的位置，整条脚本（含所有正常访问）全部不改写。

已复现的三类破坏形态（中性样本，3 行即可触发）：

| 形态 | 样本 | 后果 |
|---|---|---|
| 文案里的关键词（尤其中文） | `console.warn('localStorage 不可用')` | 字符串被劈断 → SyntaxError → 整条回退 |
| 字符串中段 + 尾随标点 | `console.log('read localStorage, ok')` | 同上 |
| 对象字面量键位 | `var o = { localStorage: 1 }` | `{ __palinkCardStorage('local'): 1 }` → SyntaxError → 整条回退 |

复现（返工前的实现）：

```
hits = 2  改写后与原相同 = true   ← 整条回退
输入：var KB='tavern_cg_album_unlocked'; var v=localStorage.getItem(KB); console.warn('localStorage 不可用');
```

**机制 C —— `activeStorageCharacterId` 从不复位（本轮新发现的真 bug）**

`runCardTavernHelperScripts` 里，`activeStorageCharacterId` 是**模块级变量**，旧实现只在
`if (characterId)` 分支里赋值 —— 拿不到 id 时不覆盖，于是**沿用上一张卡的 id**。
后果与本次要修的现象方向相反但同样严重：从卡 A 切到卡 B、而这一步没拿到 id 时，
**B 的解锁会被写进 A 的命名空间**（反向串卡 + B 自己反而"丢进度"）。

已修（§5），并有回归锁：`card-script-runner.test.ts` 的「切卡防串」用例。

### 4.2 定位手段的结论（对原单 §4「定位方法」的答复）

原单建议「加临时诊断，只输出形态统计」或「离线打指纹」——方向正确。
本轮用等价的**独立复刻 + 中性样本矩阵**替代（连 docker 都没起，临时诊断改了也跑不到），
结论：**不是二选一，三条机制都在**，所以修复必须三条都堵，只堵闸门仍会漏。

### 4.3 为什么"连着两个构建都没人发现"——`console` 在生产产物里是不存在的

本轮实测 `frontend/vite.config.ts:61-69`：

```js
minify: 'terser',
terserOptions: { compress: { drop_console: true, drop_debugger: true,
                            pure_funcs: ['console.log', 'console.info'], passes: 2 } }
```

`drop_console: true` 剥掉的是**全部 `console.*`**，不只是 `pure_funcs` 里列的 `log`/`info`。
产物里还能 grep 到的 `console.warn` 字样全部位于**字符串字面量**内（插件运行时给别处生成的脚本源码），
不是可执行的调用；我们这段 P0 分支在产物里被压成了 `n.rolledBack` 这种空表达式。

结论两条：

1. **原单 §5.2「加 `console.warn` 响亮诊断」在线上不可达** → 已改为写 `window.__palinkCompatStats`
   （项目既有降级登记通道，插件管理页降级统计读的就是它）。
2. 任何"靠控制台观察"的现场排查手法，在本产品**生产环境**都只能靠 `window` 上的对象或降级登记；
   `console.*` 仅 dev 可见。

> 这条同时纠正了一条流传中的经验口径：**不是"只有 `console.log` 会被清掉、`console.warn` 能留"**，
> 而是 `drop_console` 一律清掉。

## 5. 修复内容（本轮已实施）

落点：`frontend/src/lib/sillytavern/card-script-runner.ts`

1. **宿主段改成允许任意链（堵机制 A）**
   `STORAGE_HOST_NAME` / `STORAGE_HOST_UNIT` / `STORAGE_HOST_ACCESS`：每段宿主名后跟 `.` 或 `[下标].`，
   上限 6 段（只为压住回溯量），从而覆盖 `window.top.localStorage`、`window.parent.localStorage`、
   `window.frames[0].localStorage`。
2. **前导守卫追加引号（`'` `"` `` ` ``）（缩小机制 B 的触发面）**
   字符串字面量里的关键词不再被改写 —— 这是最高频的破坏形态来源。注意它**不能替代**第 3 条：
   字符串中段（`'read localStorage, ok'`）前缀是空格，仍会命中，必须靠逐处回退兜住。
3. **闸门从「整条回退」改成「逐处回退」（根治机制 B）**
   从后往前逐处替换，每处替换后单独验证 `new Function` 可编译性；过不了只回退这一处，其余保留。
   原文本身编译不过仍原样放行（口径不变）。
4. **响亮诊断（消灭静默面）**
   新增 `CardStoragePatchStats { keywordHits, applied, rolledBack }` 与 `CardScriptRunResult.storagePatchFailed`；
   「提到关键词却一处没改写成功」（含"没拿到 id"）时登记降级：
   `recordStubHit('card-script:storage-namespace', '关键词 N 处 / 已改写 0 处 / 回退 M 处')`
   → 落进 `window.__palinkCompatStats` + 插件管理页降级统计（仍不报正文）。
   该面板（`CompatStubStatsCard.tsx`）按 `name` **通用渲染**，新增 key 不需要改 UI；
   行内会显示 `脚本名: 关键词 N 处 / 已改写 0 处 / 回退 M 处`。
   （面板抬头文案是 ST 兼容口径，读起来略泛 —— 已知的轻微语义混用，换取"零 UI 改动 + 复用既有降级通道"。）

   ⚠️ **原单 §5.2「加 `console.warn` 响亮诊断」在线上是无效的**，本轮实测：
   `frontend/vite.config.ts:65` 有 terser `drop_console: true`，而它剥掉的是**全部 `console.*`**
   （不只 `pure_funcs` 列的 `console.log`/`console.info`）—— 产物里剩下的 `console.warn`
   全是别处**字符串字面量**里的文本，不是调用。所以：**任何只靠 console 的现场诊断都到不了线上**，
   这正是"静默失效连过两个构建没人发现"的机制。留痕必须走 `window` 上的统计对象/降级登记。
   （`console.warn` 仍保留在源码里，dev 环境照常可见，不作为验收判据。）
5. **`activeStorageCharacterId` 每次调用无条件覆盖（堵机制 C）**
   包括覆盖成 `null`；拿不到 id 时不再沿用上一张卡。
6. **`ActiveStorageCharacterId` 相关语义补文档**：`CardScriptRunResult` 里新增字段已注明两种成因。
7. **`lookahead` 补 `$` 分支**：覆盖 `var x = typeof localStorage` 这类正文收尾写法。

### 为什么不采纳原单 §5.4（排除「关键词后紧跟 `:`」）

`flag ? localStorage : null` 是**合法且常见**的三元写法，关键词后面就是 `:`。
在正则里排除 `:` 会把这一处漏掉 → 该卡仍然读全局键。对象键位那一类**靠逐处回退兜底就够**，
不需要（也不应该）用正则做词法判断。原单第 4 条建议**不要实施**。

```js
             .map(s => s.split('/').pop())[0],

    cgTags: cgTags.length,                          // ← 必须 > 0（本次就是靠它选中问题脚本）
    cgScriptRewritten: cgTags.length > 0 && cgTags.every(s => (s.textContent || '').includes('__palinkCardStorage')),
    // 链式宿主是否被改写（机制 A 的直接判据；图鉴脚本用 window.top.* 时这一条最容易先红）
    chainedHostRemained: /window\s*\.\s*(?:top|parent|self)\s*\.\s*localStorage/.test(
      cgTags.map(s => s.textContent).join('')),
    nsKeyCount: ls.filter(k => k.startsWith('palink:card-storage')).length,
    legacyStillThere: ls.includes('tavern_cg_album_unlocked'),
    storagePatchMiss: miss ? miss.count : 0,        // ← 必须为 0
  });
})();
```

> **对原单探针的两处修正**：
> 1. 原判据用 `tags.filter(...).every(...)`，而 `[].every()` 恒为 `true` —— 一旦选择器没选中任何脚本
>    （正是本次的形态之一），它会给出"已隔离"的**假绿**。必须先用 `cgTags.length > 0` 兜住，
>    再加链式宿主判据。
> 2. 原判据把"控制台 warn"当验收信号 —— **在生产产物里这条恒为空**（`drop_console: true`，见 §4.3），
>    判据必须是 `window.__palinkCompatStats` 里的计数。

判据：

1. 进入新导入卡的对话页后跑上面这段 → **`cardScripts > 0`、`cgTags > 0`、`cgScriptRewritten` 为 `true`、`chainedHostRemained` 为 `false`、`nsKeyCount` ≥ 1**。
2. **新导入一张同款卡 → 图鉴必须是空的**（用户唯一在意的那条）。
3. 同名不同 id 的两张卡并存，一张解锁不影响另一张。
4. 回归：CG 悬浮按钮、图鉴面板拖动位置、状态栏、MVU 面板仍正常；含全屏 launcher 的智能卡不白屏；Live2D 绑定不失效。
5. **反例检查（新增）**：`storagePatchMiss` 必须为 **0**。
   一旦 > 0，`window.__palinkCompatStats.get('card-script:storage-namespace').lastDetail` 自带
