## 1. 要解决的问题

现在用户装好 ComfyUI、登录网站、点了出图，会撞上三种"看不懂为什么失败"：
① 我们模板里的模型文件名在他机器上不存在（占位名直接发过去）；② 他的 ComfyUI 版本没有我们用的节点
（Flux / Qwen 那几套依赖较新的自带节点）；③ 想给参考图，但 ComfyUI 三套模板根本没有图片入口。

本单目标：把这三件事变成**下发之前就告诉他、并且自动选到他机器跑得动的最好那一档**。

## 2. 现状事实（Qoder 已逐条核过代码，别重复调查）

- 三套内置模板全是纯文生图：起点是空白潜变量、去噪写死 1.0、无 `LoadImage` / `VAEEncode`
  （`backend/app/services/image_prompt_service.py:433,437,475,486,519,523`）。
- **SD WebUI 侧已经有图生图**：`_generate_sd_webui_img2img`（`image_generation_service.py:1166-1186`，
  `denoising_strength` 默认 0.75）→ 产品层"参考图"概念已存在，只是 ComfyUI 这条没接。
- 探针只打 `/system_stats`（`frontend/src/lib/image-gen/comfyui-client.ts:68,76`）→ **探针绿不代表能出图**。
- 节点与模型清单**可读**：`/object_info/CheckpointLoaderSimple` 已兼容 `input`/`inputs`
  （`comfyui-client.ts:150-168,189`）；服务端模式有 admin 端点
  （`api/image_generation.py:126-137`，带 SSRF 守卫并显式拒绝 browser 模式）。全量 `/object_info` 同一条路可取。
- 模型名硬编码不止 checkpoint：`_DEFAULT_FLUX_UNET` / `_DEFAULT_QWEN_UNET` / `_DEFAULT_QWEN_VAE` /
  `_DEFAULT_QWEN_CLIP`（`image_prompt_service.py:338-344`）——修复批 T1 只管了 checkpoint，**本单要把
  校验范围扩到 unet / clip / vae 三个槽**。
- 聊天请求已能带图（`schemas/character.py:182 images: List[str]`），参考图有现成入口候选。
- 配置字段是白名单逐字段重建返回的（`image_generation_service.py:251` 起）→ 新字段必须同步三处，
  否则保存即丢（上一批实测踩过的坑）。

## 3. T-A：能力预检（下发前体检，不跑图）

1. **模板声明依赖**：每套模板附一份清单——需要的节点类名 + 需要填的模型槽（checkpoint / unet / clip / vae）。
   放在模板定义旁边，别散在渲染逻辑里。
2. **一次采集**：对该设备拉一次全量 `/object_info`（节点类名集合）+ 各模型槽的可选清单，
   结果按 `(user_id, device_id)` 缓存，TTL 5 分钟；缓存未命中才发请求。浏览器模式由前端直发、
   服务端模式走后端端点——**两条传输都要有，复用 checkpoint 清单那两条现成路径**。
3. **判定与文案**：
   - 缺节点 → 该模板标"这台机器跑不了"，人话说明「你的 ComfyUI 版本过旧，缺 X 类节点，升级到 … 起可用」，
     并给"复制诊断详情"（把类名列表放折叠区，别糊在正文里）。
   - 模型槽名字不在清单 → 「你机器上没有这个模型文件，请在设置页重选」+ 直接给该槽的下拉。
   - 全齐 → 放行，并把"实际用的模型名"记进出图记录。
4. **出图路径上的开销**：预检走缓存，命中即纯内存判定；**不许每张图都额外打一次 /object_info**。
5. **不做**：不因为预检失败就自动改用户配置（只提示 + 让他选）。

## 4. T-B：参考图档（只用 ComfyUI 自带节点）

1. **模板加分支**：有参考图时走 `加载图片 → VAE 编码 → 采样器按重绘幅度部分去噪`，
   替换掉空白潜变量；三套模板（sdxl / flux / qwen_image）分别加分支，
   ⚠️ flux 与 qwen 的潜变量与 VAE 解码结构不同，**必须逐套真机或假上游验证**，不许一份模板改完就照抄。
2. **关键实现约束**：ComfyUI 的加载图片节点吃的是**它自己 input 目录里的文件名**，
   所以要先 `POST /upload/image`（或等价接口）把图送上去，拿到返回的 `name/subfolder` 再填进工作流。
   浏览器模式由前端上传、服务端模式由后端上传，两条都要实现，且服务端那条要过 SSRF 守卫。
3. **重绘幅度**：新增配置项（默认 0.65，范围 0.2~0.95），走白名单三处同步 + 往返测试。
4. **入口（待用户拍板，见 §7）**：候选 A＝点"配图"时弹窗里可选一张参考图（本机上传或从聊天已有图里挑）；
   候选 B＝自动把"该条消息里已有的图/用户刚发的图"当参考图，无需弹窗。
5. **失败回退**：参考图上传失败或该模板不支持图片分支 → **自动退回纯文生图档**并记一行原因，
   不要整单失败。

## 5. T-C：强档（本单不做，只留位）

角色一致性更强的玩法依赖 IPAdapter / ControlNet 等**自定义扩展**。本单只要求：预检的节点清单里
顺带记录这些扩展是否存在；将来若要启用，必须满足"检测到 + 用户在设置页明确勾选"双条件，
**绝不允许默认依赖**（否则一半用户直接失败，违背底线）。

## 6. 分档决策表（写进代码注释与设置页）

| 档位 | 前置 | 用什么 |
| --- | --- | --- |
| 文生图（基础，永远可用） | 自带节点齐 + 选定模型 | 现有三套模板 |
| 参考图重绘（中档） | 自带节点含加载图片/VAE 编码 | T-B 分支 + 重绘幅度 |
| 一致性增强（强档） | 检测到 IPAdapter/ControlNet 且用户勾选 | 以后另单 |

同一张卡、不同用户 → 各自拿到自己机器跑得动的最高档。

## 7. 测试与门禁

  `/history`，覆盖：缺节点、缺模型、参考图上传失败、三套模板各自的图片分支结构。
- 单测必含：模板依赖清单与模板体一致（防漂移）、预检缓存命中不再发请求、
  新配置字段往返、自动退回文生图档。

- 真机：需用户在场 + 批准才跑；默认不跑。

## 9. 非目标
