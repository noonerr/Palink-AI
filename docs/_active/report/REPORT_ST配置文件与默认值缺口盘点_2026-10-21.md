# REPORT — ST 配置文件/默认值缺口盘点（2026-10-21 · 主脑一手比数）

> 触发：真实第三方插件实测时，Kimi 报 `SillyTavern is not defined`、Smart Memory 报导出链断裂；
> 用户问"我们还缺 ST 的什么配置文件"。本文以 ST 1.18 参照树
> （`d:\SillyTavern-release`，已授权只读）为准，逐项比我们**库里的实际行数/长度**。
> 所有"我们"的数字都是主脑在容器 DB 里 `count(*)` / `length()` 查出来的，不是看代码猜的。

## 0. 一句话结论

**不是"少一个文件"，是三类东西缺**：
① ST 的**默认状态对象**（`power_user` 83 键、`extension_settings` 21 个命名空间）；
② ST 的**预设内容**（context 34 / instruct 38 / sysprompt 13 / reasoning 5 / openai 提示词预设 1 / themes）；
③ ST 的**全局入口对象**（`SillyTavern.getContext()`，已在 [P2-13] 立项）。
前两类里①是纯结构、风险最低、收益最大；②是**内容**，涉及版权，建议做"导入器"而不是把 ST 原文抄进仓库。

## 1. 默认状态对象（影响每一张插件）

| 项 | ST 1.18 | 我们 | 差距 |
|---|---|---|---|
| `power_user` 键数 | **83** | 端点里硬编码 **8** 个；DB 列 `user_settings.power_user` **全用户为空**（`length=0`） | **75 键缺失** ⇒ 插件读 `power_user.context / tokenizer / prefer_character_prompt / stscript / personas / movingUI …` 全部拿到 `undefined` |
| `extension_settings` 命名空间 | **21** | **5**（`quickReply / quickReplyV2 / translate / memory / regex`）+ `regex_presets` / `disabledExtensions` | **16 个缺失**：`apiKey, apiUrl, autoConnect, caption, cfg, chromadb, dice, expressionOverrides, expressions, note, objective, randomizer, rvc, sd, speech_recognition, tts` |
| 类型正确性 | `regex` / `expressionOverrides` / `disabledExtensions` 是**数组**，其余多为对象 | E2b 已把 `regex` 改正为数组 | 新增的 16 个也要按 ST 类型给（`note/objective/caption/sd/rvc/tts/speech_recognition/chromadb/dice/randomizer/expressions/cfg` 是对象；`expressionOverrides` 是数组；`apiKey/apiUrl` 是字符串；`autoConnect` 是布尔） |

⚠️ 这解释了真实插件为什么一上来就炸：它们的 `loadSettings()` 普遍直接 `Object.keys(extension_settings.sd)` 或
`power_user.xxx.yyy`，我们给 `undefined` 就整条 init 死掉（与 E2 修的 Chat Translation 完全同源）。

## 2. 预设内容（影响"能不能选到 ST 那套预设"）

| 预设族 | ST `default/content/presets/` | 我们（库内实测） |
|---|---|---|
| context 模板 | **34** 个 | **4**（ChatCompletion / Classic / Default / Instruct） |
| instruct 模板 | **38** 个 | **17** 行，但其中 **13 行是 `TestInstruct`**（测试污染，见 §3）⇒ 真实只有 **5**（Alpaca / ChatML / Llama 2 / Llama 3 / Mistral） |
| sysprompt 预设 | **13** 个 | **0**（没有对应的表/端点） |
| reasoning 预设 | **5** 个 | **0** |
| openai 提示词预设 | **1**（`Default.json`，含完整 prompts 数组） | `prompt_presets` **0 行**（批次P2 已记过：空表） |
| themes | 随包附带 | `themes` 表 **0 行** |
| quick-replies 预设 | **1** | 无（且 `/api/quick-replies/save` 本就没有路由） |

⚠️ **版权边界**：预设文件里装的是**提示词原文**（ST 是 AGPL-3.0）。把这些文本整包抄进本仓，
和"我们自己的提示词体系"混在一起，法律与可维护性都不划算。
⇒ 建议：**做导入器**（用户从自己的 ST 安装目录/压缩包导入，落到自己的库里），
而不是仓库内置 ST 原文。**这一条需要用户拍板**；本批不做。

## 3. 数据卫生（顺带查出来的，跟 ST 无关但必须处理）

`instruct_templates` 里有 **13 行 `TestInstruct`**——这是测试数据落进了**生产库**。
（历史病灶：容器内跑 pytest 会直连生产库并建表/写数据。）
⇒ 建议清理（`DELETE FROM instruct_templates WHERE name='TestInstruct'`），属破坏性写，**等用户点头**。
在此之前，界面上会看到 13 个同名干扰项。

## 4. 修复计划（主脑已派/待派）

| 序 | 项 | 谁做 | 风险 | 判据 |
|---|---|---|---|---|
| 1 | **补 `power_user` 83 键 + `extension_settings` 16 个命名空间**（结构级默认） | 子 agent（本轮派出） | 低：只加默认值，不改装配 | ST settings 端点返回的 `power_user` 键数=83；`extension_settings` 21 个命名空间且类型正确；插件读取不抛；反证：删默认 ⇒ 测试红 |
| 2 | 导入器（context/instruct/sysprompt/reasoning/openai 预设） | 待用户拍板（版权） | 中 | 用户自己的 ST 目录可导入，且导入后能选中 |

## 5. 证据出处（可复跑）
- ST 侧：`default/content/settings.json`（19 顶层键 / `power_user` 83 / `extension_settings` 21 / `oai_settings` 34）、
  `default/content/presets/*` 计数见 §2。
- 我们侧：`docker exec palink-ai-db-1 psql -tAc "select count(*) from …"`（context_templates=4、instruct_templates=17、
  generation_presets=27、prompt_presets=0、themes=0）；`power_user` 全用户 `length=0`。
- 硬编码默认只 8 键：`backend/app/api/silly_tavern.py` 的 `_default_st_settings()`（`_power_user_defaults`）。
- `extension_settings` 现名单：`frontend/src/lib/sillytavern/extension-settings-store.ts` 的 `ST_EXTENSION_SETTINGS_PRESET_NAMESPACES`。
