## 1. 两次自我推翻（重要，避免重复犯）

### 1.1 错误 A：「`<cg>` 规范没进提示词」

- **当时依据**：`build_worldbook_context()` 的 `result.text` 里搜不到 `<cg`。
- **为什么错**：该条目 `position=4`（at-depth），按 ST 语义**本就不进 `text`**，走 `depth_entries`。只看 `text` 必然误判。
- **实测反证**：`debug_report` = `activated`；`depth_entries` 含 `<cg>`，`depth=0`，`len=1034`；`_insert_depth_prompt` 实测落在 messages 末尾（紧贴生成前）。

### 1.2 错误 B：「卡内 promptOnly 正则把规范删了」

- **当时依据**：容器内 `_apply_regex_scripts(SAMPLE, ext, placement=2, is_prompt=True)` → `has_cg=False`。
- **为什么错**：**placement 用错**。ST 对世界书内容用 `WORLD_INFO(5)` 过滤（`d:/SillyTavern-release/public/scripts/world-info.js:5086`），不是 `AI_OUTPUT(2)`。
- **实测反证**（同一份 ext，只换 placement）：

  | placement | `<cg>` 存活 |
  | --- | --- |
  | `AI_OUTPUT=2` | False |
  | `WORLD_INFO=5` | **True（1034→1034 长度不变）** |

  卡作者写 `placement=[2]`（脚本名「对ai隐藏cg标签」）= "只对 AI 输出生效，不碰世界书"，是**正确写法**。我们与 ST 行为一致，无需改。

### 1.3 附带排除

- `balance_custom_tags`（`backend/app/utils.py:286`）：实测喂入含 `<cg>…</cg>` 的规范 `UNCHANGED=True`，无罪。
- MVU 报错的 `getCharWorldbookNames is not defined` 与本条无关，是另一处真 bug（见 §3）。

## 2. 回忆相册：爱意 ≥ 200 是硬门槛（真机实测闭环）

卡内 `相册` 脚本（`tavern_helper.scripts[2]`，45948 B）的 `isChatActive()` 逐层门槛：

1. `getCurrentCharacterId()` 非空 ✅（修复前 undefined，**已修**，见 §3）
2. `SillyTavern.getCurrentChatId()` 非空 ✅（`palink-session-40d9b7cc….jsonl`）
3. `getContext()`：`characterId=1342361359`、`chatId` 非空、`chat.length=10` ✅
4. DOM `#chat` 存在且可见 ✅（`display:flex / visibility:visible / 529×820 / 12 子节点`）
5. **爱意 ≥ 200** ← 真正的门

### 决定性实验（真机，改完即还原）

把爱意从 0 提到 250（≥200 阈值），相册面板随即从 `收集进度：1 / 205` 变成 **`205 / 205`**，
浮动按钮角标同步 `1 → 205`，全部图鉴解锁。实验后爱意已还原为 0。

```
爱意=0   → 收集进度：1 / 205   （仅卡自带 first_mes 给的那 1 条）
爱意=250 → 收集进度：205 / 205 （全解锁）
```

**结论**：相册不解锁**不是适配缺陷**，是卡作者的设计——好感度不足 200 不开放相册。
解锁本身无需模型产出 `<cg>`：面板按 `CG_DICT`（140 项字典）＋ 爱意门槛整体放行。

### 与「模型输出 `CG:` 后曾能解锁」的旧记忆如何共存

查了**全部 git 历史**（`git log --all --name-only` + `git grep` 逐提交）：
仓库里**从未存在过**任何相册/解锁代码（无 `*cg*` / `*album*` / 图鉴 相关文件）。
所以「早期输出 `CG:` 就能解锁」**一直是卡脚本自己在做**，不是 Palink 的功能 ——
我们改的是**运行环境**（把卡脚本真正跑起来 + 喂对 API），不是解锁逻辑本身。

推论：早期能解锁，是因为当时**爱意已经 ≥ 200**（变量链路能用），而不是因为模型输出。
「模型输出 `CG:` 就解锁」这个印象，与卡脚本的实际机制（爱意门槛 + `<cg>` 标签扫描）不吻合，
建议按「刷爱意」验证，而非等模型输出。

补充：解锁的标签路径确实是 `/<cg\b[^>]*>(.*?)<\/cg>/gi` 扫最新消息，且
`unlockCgList` 会用 `CG_DICT[name]` 校验名字（字典外的名字不入列）。
该会话 52 条消息含 `<cg>` 的只有 1 条，是卡自带 `first_mes`。

⚠️ 教训：上一轮我把「爱意=0」直接判成「卡设计如此、非 bug」而**没有做升到 250 的对照实验**，
差点让用户拿不到「刷爱意就能开」这个可操作结论。**门槛型条件必须做越过阈值的实测，不能只读源码。**

## 3. 面板变量 + MVU 报错：两处真 bug（已修已上线）

### 3.1 Bug ①：主页面缺三个 ST 全局

**现象**（真机 console）：
```
[MVU]读取角色世界书绑定失败  ReferenceError: getCharWorldbookNames is not defined
Unhandled promise rejection: TypeError: Cannot read properties of undefined (reading 'length')
```

| API | iframe 轨 | 主页面（修复前） |
| --- | --- | --- |
| `getCharWorldbookNames` | ✅ `legacy-st-sim.ts:1372` / `SillyTavernCompatRuntime.ts:5315` | ❌ undefined |
| `getCharWorldbook` | ✅ 同上 | ❌ undefined |
| `getCurrentCharacterId` | ✅ | ❌ undefined |

`sillyTavernPluginRuntime.ts:1969` 的 `SUPPLIED` 白名单**只用于 `lookup()` 过滤「实际挂没挂」，不负责实现**。卡脚本跑在主页面（`card-script-runner.ts`），所以受害的正是主页面轨。

**修复**：`sillyTavernPluginRuntime.ts` 新增三个 API，数据源接既有 `__palinkBridge.charLorebooks`（真查 `/api/worldbooks?character_id=…&type=character_book`）。

⚠️ **关键细节**：MVU 在模块顶层 `await` 这些 API，而桥缓存是惰性的（`CharacterChat.tsx:1746` 注释：注入时角色 id 未必已进 context）。首版实现直接读缓存 → 返回 `[]` → 真机实测 `count=0`。改为**冷缓存时自己 `refreshCharLorebooks` 拉一次再答**，实测 `["露缇雅1.2"]`。

⚠️ 不要改用 `messageManager.getCurrentCharacterId()`：全仓零调用方、恒返回空串（`CharacterChat.tsx:1579` 注释已核实）。唯一真源是 `runtime.context.characterUuid`。

### 3.2 Bug ②：`/api/worldinfo/get` 对角色绑定书恒空

**现象**：真机 `POST /api/worldinfo/get {name:'露缇雅1.2'}` → `{"entries":{}}`，但该书有 19 条 stage。

**原因**：`backend/app/api/silly_tavern.py:4453 _resolve_worldbook` 硬过滤 `WorldBook.character_id.is_(None)`，只查全局书。ST 侧不是这样 —— `src/endpoints/worldinfo.js:71` 的 `/get` 走 `readWorldInfoFile(dirs, name)`，**按名字从用户书库取，不分全局/绑定**。

**连锁**：`worldbookGetEntries` 拿 0 条 → `getLorebookEntries`/`getWorldbook` 对该卡恒空 → MVU 初始化读不到角色世界书内容 → 抛 `reading 'length'`。

**修复**：加 `include_character_bound` 开关，**只开在读端点**（`:3388`）。`/edit`（:3424）与 `/delete`（:3503）保持默认全局语义 —— 否则会顺带把「删角色绑定书」变成可达操作，那不是本轮要修的。越权口径两条路径一致（均按 `user_id` 过滤）。

| 项 | 修复前 | 修复后 |
| --- | --- | --- |
| `getCharWorldbookNames()` | `undefined` | `["露缇雅1.2"]` |
| `getLorebookEntries('露缇雅1.2')` | 0 条 | **19 条** |
| `getCurrentCharacterId()` | `undefined` | `c44f2ae6-…` |
| console `getCharWorldbookNames is not defined` | ❌ 有 | ✅ **消失** |

⚠️ console 里仍有 `TypeError: … reading 'length'` 与 `不存在任何一条消息，退出` —— 二者**同源**且发生在 MVU 初始化时点（彼时消息尚未注入主页面），属独立议题，未在本轮处理。
