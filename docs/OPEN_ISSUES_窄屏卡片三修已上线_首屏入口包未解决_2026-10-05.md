## ❌ 未解决 #4：首屏入口包 638KB 阻塞，弱网下 60 秒白屏

### 现象（2026-10-05 一手实测）

测试方式：临时写了一个限速代理（并发共享令牌桶 + 固定延迟）转发 `14000 → 14100`，
参数 **300kbps + 300ms 延迟**，浏览器访问代理地址。测完脚本已删除。

| 指标 | 实测值 |
|---|---|
| 首屏入口 JS（gzip） | **638 KB** |
| 首屏入口 JS（raw） | **1782 KB** |
| 入口 JS 传输耗时 | **26 秒** |
| 60 秒时页面状态 | **完全白屏**（`document.body === null`） |
| 60 秒内实际下载量 | **仅 5 KB** |

### 已排除的因素（别重复建议）

- `index.html` 里 3 个 CSS **已是异步加载**（`media="print"` + `onload` 切换）
- `modulepreload` 标签数 = **0**
- ⇒ **唯一真阻塞项就是那一个 638KB 入口 JS**

### 入口构成（用字符串字面量锚点切分实测；terser 只改标识符故只能用字符串归因）

| 区块 | raw | 可否延后 |

| ST getContext 兼容层 | ~257KB | ❌ 渲染链路依赖 |
| sonner / 图标 / 路由等 | ~150KB | **未逐项验证，可能有干净收益** |

### ⛔ 已否决的方案：KaTeX 动态加载（实施后已回退）

**实施后 6 个测试变红**，`failed=0` 是项目硬门禁。三个回退理由：

1. **破坏同步渲染契约** —— `renderMathInHtml` 是同步导出（唯一调用点 `formatting.ts:1224`，
   无外部调用方），同步函数无法等异步加载 ⇒ 首条公式消息**先显示原始符号、再跳变成公式**。

   "流式可渲染、完成态塌回原文"的跳变；动态加载恰好把该跳变重新引入。
3. **触碰防静默回退守卫** —— `formatting-katex-contract.test.ts` 文件头明写该修复
   **曾两次被静默回退**故立此守卫，其 `:29` 断言源码含 `from 'katex'` 字面量。

## ✅ 已修完 #1~#3（本轮，均已重建 dist 并重启容器上线）

**门禁**：`tsc --noEmit` 0 错；`vitest run` 60 文件 / 781 passed + 3 skipped。

### #1 窄屏正文被截断

`IFRAME_MAX_HEIGHT` 5000 → 50000（`smart-card-runtime/shared.ts`）。
窄屏折行暴涨导致长卡超5000 后被 `overflow:hidden` 永久裁掉，且完整网页文档卡
走 `injectIntoFullDocument`、**没有**片段卡那条 `body{overflow-y:auto}` 兜底。
实测：原卡在 5000px 的 iframe 现长到 5545px。

**用户裁定**：拒绝"卡内滚动"方案（手感差），选"抬高上限"。

### #2 窄屏正文列与卡片太窄

396px 屏下正文列原仅 276px（70%）。三处固定 padding 改百分比：
正文列 `px-5`→`px-[5%]` / `px-3`→`px-[3%]`；头像居中补偿 `36px`→`9.2%`；
聊天区 `px-1`→`px-[1%]`。另按用户裁定在窄屏（<768px）**隐藏头像列**
（`.rp-mes-avatar`），并同步关掉补偿（否则退化成气泡偏左，单边内缩）。

结果：正文列 **316→388px（80%→98%）**，卡片 iframe **285→349px（72%→88%）**。

### #3 卡片样式离屏后消失变纯文字

**现象**（用户提供关键线索）：同一段内容，上滑看是纯文本、点进对话看则带格式。

**根因**：`index.css` 的 `.mes-render-skip` 用 `content-visibility: auto`
跳过视口外消息绘制，但规则挂在**消息行**上 ⇒连行内卡片 iframe 一起跳过绘制。
且跳过条件依赖 `isHtmlOrCard` → `isHtmlCardContent`（`Message.tsx`）只认
`div`/`span`/`iframe` 等**渲染后**标签、**不认 `<now_plot>` 包裹**，
而判定跑在渲染**之前**（输入是模型原文）⇒ 所有带卡片 AI 消息被误判为「纯文本」而跳过。
已用生产库真实消息（`character_chat_messages` id=2638）离线喂该函数验证返回 `false`。

**ST 侧对照**（`d:\SillyTavern-release` 已授权可读）：`.mes` **无任何虚拟化**；
唯一的 `content-visibility: auto` 挂在 `.auto_hide` 类上，而全项目无处给它加类（死规则）。
⇒ ST 刻意不做。

**处理**：整条链路删除（CSS 规则 + `canSkipOffscreenRender` 判定 + 临时取证测试）。
离屏休眠由既有 `SmartCardDormancyGate` 独占（IntersectionObserver + 上下各一屏缓冲，
只隐藏 DOM 不卸载）。实测 5 卡中 4 卡正常 `sleeping`。

⚠️ **风险未消**：删除后长对话滚动可能变慢（原开销确实省掉了一点）。
若滚动发卡，正确做法是**加大休眠门缓冲**（一屏→两屏），⛔不要恢复跳绘机制。
