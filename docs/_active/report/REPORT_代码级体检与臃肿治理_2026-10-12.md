## 1. 核心判定

**不是"纯屎山"，也不是健康系统——是「为 SillyTavern 兼容性付出巨额架构税、核心链路局部已屎化」的系统。**

它有真实的产品命题、真实的安全工程、真实的测试与 CI；但兼容层（6,961 行 runtime shim + 2,452 行 legacy sim + 73 个端点）已经反客为主，把架构压成了"上帝函数 + 上帝组件 + 双真源"的形态。

## 2. 危害排序

### P0（会造成真实事故）

1. **插件/卡片脚本执行面**：`legacy-st-sim.ts:1730`、`sandbox.ts:2694,2913` 用 `new Function` 在主 realm 执行第三方脚本，防御靠"逐一遮蔽危险全局"黑名单（`sandbox.ts:2859-2888`）。黑名单是**默认放行**，漏一个全局即沙箱逃逸——唯一可造成跨用户会话外泄的面。
2. **Schema 双轨**：73 个 alembic 版本与启动时 f-string `ALTER TABLE ADD COLUMN`（`core/migrations.py:167-178`）并存，库结构真相分叉，回滚/重建不可控；该文件 `:14-16` 自己记着"补列清单把已删列重建回来"的陷阱。
3. **数据双真源**：`api/silly_tavern.py:1345-1347`，同一逻辑数据两个写入点、优先级曾翻转 → 典型静默数据丢失。

### P1（持续放血）

4. **异常吞噬**：604 处 `except Exception`，67 处 `pass` → 故障被降级为"看起来正常但功能没了"。
5. **上帝组件 / 无状态管理**：`CharacterChat.tsx` 2,294 行 + `contexts/` 只有 1 个文件。
6. **构建与部署卫生**：`frontend/` 下 **9 个 `dist_*` 目录（约 93MB）**；`dist` 是 nginx bind mount，而 `npm run build` 第一步 `clean-dist.cjs` **先删后建**（`package.json:8`）→ 中断即白屏；宿主端口已被迫漂移 4 次（3000→13000→14000→14700，`docker-compose.yml:5-25`）。
7. **历史依赖未清**：`jquery`(7 文件) / `toastr`(8) / `showdown`(6) / `handlebars`(5) / `select2`(2) 仍在使用。

### P2（需收口）

8. 限流覆盖不足；`verify=False` 两处；59 个上传点分散校验。
9. 仓库卫生：git 跟踪 1,610 文件中 `docs/` 110、`_BACKUPS` 68（本应 ignore）、媒体 36。

## 3. 臃肿治理方案（前提：尽量不影响兼容性）

### 3.0 先立一条铁律：兼容面 = 冻结的公共契约，**不得按"grep 不到引用"删除**

实测证据：插件运行时**动态拼接** API 路径——

```
lib/sillytavern/*、lib/plugin-system/* 中出现：
  /api/plugins/{pluginId}/{name}
  /api/worldinfo/get
  /api/worldinfo/*（运行时构造）
```

因此：`api/silly_tavern.py` 的 73 个端点里，只有 **15 个**能在前端源码里静态 grep 到；其余 58 个属于"第三方插件运行时动态消费"。**它们不是死代码，是对外契约。**
同理，`jquery` / `select2` / `toastr` / `showdown` / `handlebars` 是 ST 插件生态的事实依赖，**删了就断兼容**。

> 结论：**减脂的对象不是兼容层本体，而是兼容层之外的负重 + 兼容层的边界化。**

### 3.1 第一层 · 零兼容性影响（纯负重）—— 立即做，约 1.5 人日

| # | 项 | 现状证据 | 收益 | 代价 |
|---|---|---|---|---|
| A1 | 清 8 个冗余 `dist_*` 目录（~93MB）+ `dist` 内 5 份重复 `index-*.js`（各 1.8M） | `frontend/dist_fix_bubble{,2,3}`、`dist_new*`；`dist/assets/index-*.js` 5 份 | ~100MB + 消除白屏风险 | 0.5 人日（隔离到 `_BACKUPS/_QUARANTINE_<日期>/`，构建改 `VITE_OUT_DIR` 增量合并） |
| A2 | `_BACKUPS`（2.4GB，68 个文件误入库）移出 git 索引 | `git ls-files \| grep -c _BACKUPS` = 68 | 仓库体积 | 0.2 人日（`git rm --cached`，**保留磁盘**） |
| A3 | 根目录 33 个 `*.md` + 26 个 `_tmp*` 归档 | `ls *.md \| wc -l` = 33 | 可读性 | 0.3 人日 |
| A4 | `backend/scripts` 104 个脚本中 38 个一次性探针隔离 | `ls backend/scripts \| grep -cE "^_probe\|_tmp\|probe"` = 38 | 心智负担 | 0.3 人日 |
| A5 | `backend/models/fastembed` 91MB 缓存（未入库） | 该目录仅 fastembed；`requirements.txt` 注释自承"无 Ollama 时才降级 fastembed" | 91MB | 0.2 人日（仅当 Ollama 常驻；缓存删了会自动重下，风险最低） |

### 3.2 第二层 · 低风险代码减脂（逐条 grep 引用链后做）—— 约 5 人日

| # | 项 | 做法 | 代价 |
|---|---|---|---|
| B1 | 三套 tokenizer 合一（1,124 行） | 以 `tokenizer_service`(5 引用) 为主合并，保留原函数签名做薄适配层 | 1.5 人日 |
| B2 | 僵尸模块：`llama_runtime`(1) / `local_model_registry`(6) / `inference_queue`(8) 的**本地分支** | ⚠️ 动刀前须逐条查引用链并经确认；`inference_queue` 有 8 处引用，不能按名字删 | 2 人日 |
| B3 | 67 处 `except Exception: pass` 改为 `logger.warning` + 计数指标 | 只改 pass 的，不动其他 537 处 | 1 人日 |
| B4 | `mermaid`(1 文件引用) / `recharts`(1) 改**动态 import 懒加载** | 不删除包，只改加载方式 → 零兼容影响，减首屏体积 | 0.5 人日 |

**注意**：`vite.config.ts:99-112` 显示 `manualChunks` 曾因 bug 被整段摘除，现 `chunkSizeWarningLimit: 500`。恢复切分时必须用**函数式** manualChunks 且只匹配目标包自身路径，否则会重演历史事故。

### 3.3 第三层 · 冻结而非删除（兼容层本体）

`SillyTavernCompatRuntime.ts`(6,961) / `legacy-st-sim.ts`(2,452) / `api/silly_tavern.py`(73 端点) 的处理方式是**边界化**，不是删：

- 定为「冻结契约」：新功能一律不得进入这三个文件；
- 对外只保留插件面（`st-plugins/`，157 个文件入库、55MB third-party，属兼容性资产，**保留**）；
- 用契约测试锁定行为，而不是靠人肉回归。

**为什么不能直接删兼容层**：删掉 = 失去 ST 插件/角色卡/世界书/MVU 生态 = 本项目的产品命题消失。真正该做的是**停止它继续膨胀**。

### 3.4 治理的优先级顺序

```
A1/A2（零风险、立即可见收益）
  → B3（消除静默故障）
  → S1 冻结运行时补列 + S2 收口变量真源（P0 稳定性）
  → A3/A4/A5（卫生）
  → B1/B2/B4（代码减脂，需引用链复核）
  → L1 拆 1,295 行装配函数 / L3 前端状态治理 / L4 插件真隔离（根治，1-3 月）
```

## 4. 验收与红线

- 门禁只认 `failed = 0` 且 `errors = 0`（`bash scripts/gate.sh`），**passed 数字不是验收线**。
- 所有清理走「隔离 → 门禁 → 确认」，**禁止直删**；`frontend/dist` 是 nginx bind mount，动它前先整份备份。
- 改 `docs/` 后跑 `python scripts/docs/gen_docs_catalog.py`（`--check` 必须 OK）。

## 5. 防止继续臃肿的三条硬门禁（建议进 CI）

1. 单文件 > 800 行、单函数 > 150 行 → 告警；
2. 禁止新增 `except Exception: pass`；
3. 禁止新增运行时补列（新列一律走 alembic）；新增端点必须挂限流。
