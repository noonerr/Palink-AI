## 0. 结论速览

| 项 | 内容 |
|---|---|
| **现象** | 长对话滚到倒数第二条（N-1，一条 `pipelineResult.kind === 'smart-card'` 的助手消息）时，卡片**外框位置与高度不变**，但框内正文在「有 → 无 → 有 → 无」之间反复跳；停在原地也持续闪。最后一条（N）停在视口内时完全正常 |
| **真根因** | `SmartCardDormancyGate` 的 `repaintKick()` 把**被 IntersectionObserver 观察的那个元素** `display: none` 一帧再恢复。高度瞬间归零 ⇒ 观察器立刻报「离开视口」⇒ 走休眠分支（此刻 `offsetHeight` 为 0，`dormantHeight` 被置 `null`）⇒ 高度恢复后观察器又报「进入视口」⇒ `dormantRef.current` 仍为 true ⇒ 再次 kick。**自激闭环，不依赖用户滚动** |
| **为什么是 N-1** | `SmartCardDormancyGate` 只包裹 `smart-card` 分支。N 若始终停在视口内，从未休眠过，`dormantRef.current` 恒为 false，**永不进入 kick 分支**；N-1 是「先休眠、再被滚回视口」的那一条，是唯一满足 kick 触发条件的消息。⇒ 这不是"某一条消息坏了"，而是**任何曾休眠过的智能卡消息在被滚回视口时都会闪** |
| **为什么是回归** | `d436a7e`（2026-10-07 02:35）把唤醒踢从 `transform: translateZ(0)` 翻转改成 `display` 双帧切换。`transform` 不破坏布局，所以自激环不会形成；`display` 破坏布局，于是引爆 |
| **附带结论** | `repaintKick` 本身就是误判产物（见 §3），在结构上不可能修好它声称要修的东西 |
| **修复** | 删除 `repaintKick`；观察器回调加两条守卫（状态未变则忽略 / 测不到高度则不进入休眠） |

## 1. 现象取证（真机录屏抽帧）

对用户提供的录屏抽帧（`ffmpeg`，20fps，3.4s–5.0s 段）：

- 卡片**外框**（灰色圆角容器）的位置与高度**逐帧稳定**，与消息行在文档流中的占位一致；
- 框内正文（红色文字）在「完整 → 大块空白/仅剩局部 → 完整」之间周期跳变；
- 空白段持续约 **150–200ms**，且周期性复现，**不是单次抖动**；
- 时间戳连续、页面未滚动 —— 即用户手指已停，仍在闪。

> 判据意义：外框稳定 + 内容消失 = 排除"布局跳动 / 滚动锚定"类成因，指向**重绘/显隐被反复触发**。

## 2. 自激闭环的机制

生产代码（修复前，`Message.tsx`）：

```ts
const repaintKick = () => {
  requestAnimationFrame(() => {
    const host = containerRef.current;            // ← 这个元素就是被 IO 观察的目标
    const inner = host.firstElementChild;         // ← display 改在它的内层
    inner.style.display = 'none';                 // 一帧
    requestAnimationFrame(() => { inner.style.display = ''; });
  });
};

const observer = new IntersectionObserver((entries) => {
  for (const entry of entries) {
    if (entry.isIntersecting) {
      if (dormantRef.current) repaintKick();      // ← 唤醒即踢
      dormantRef.current = false;
      setDormant(false);
    } else {
      const measured = el.offsetHeight > 0 ? el.offsetHeight : Math.round(entry.boundingClientRect.height);
      setDormantHeight(measured > 0 ? measured : null);
      dormantRef.current = true;                  // ← 一离开就置回 true
      setDormant(true);
    }
  }
}, { rootMargin: `${buffer}px 0px ${buffer}px 0px` });
```

闭环（每轮约 2 帧 ≈ 32ms）：

```
① 唤醒 → dormantRef=true → kick → 内层 display:none
② 该元素高度归零 → IO 立刻报 not-intersecting
   → 走休眠分支：measured=0 → dormantHeight=null → dormantRef=true → setDormant(true)
③ rAF 恢复 display → 高度回来 → IO 又报 intersecting
   → dormantRef 仍为 true → 再 kick → 回到 ①
```

关键点：**踢的目标与被观察的目标是同一棵树**。IO 用"相交状态是否变化"来驱动副作用，
而 kick 恰好制造了一次真实的相交状态变化 ⇒ 副作用自己触发自己。

`display: none` 的元素在 IO 里相交比为 0、`isIntersecting=false`，所以这一帧必然被上报为
"离开视口"，闭环必然闭合。

## 3. 为什么 `repaintKick` 本来就是多余的（两重理由）

**理由一：它声称要修的现象不存在。**

`REPORT_历史消息样式丢失_深度窗根因_2026-10-07.md` 已用生产库取证 + 受控实验证明：
「历史消息样式丢失」的真根因是角色卡「露缇雅1.2」显示正则脚本自带的 `maxDepth = 3` 深度窗，
**窗口外的消息压根没有生成 iframe**（产物是 24 字符纯文本）。

```
显示管线 → 正则是否命中？
   ├─ depth ≤ 3 → 产出 30180 字符卡片 HTML → 才有 iframe → 才谈得上休眠/重绘
   └─ depth ≥ 4 → 产出 24 字符纯文本       → 压根没有 iframe → 休眠门控无事可做
```

没有 iframe，就没有"iframe 休眠后不重绘"这回事。该踢在结构上不可能修好它要修的东西。

**理由二：触发它所需的前提已被移除。**

`d436a7e` 同一批已经删掉 `content-visibility: hidden`。该属性才是"浏览器跳过整棵子树渲染"
的载体（即"唤醒后不重绘"的物理原因）。只剩 `visibility: hidden` 时，从 hidden 切到 visible
**必然走主线程重绘**，无需任何外力踢一脚。

> 换言之：这一批提交一边拆掉了病症的载体，一边把治病的药改成了致病的毒。

## 4. 离线实证（真实 Chrome + Playwright，最小复现）

装置：复刻 `SmartCardDormancyGate` 的真实结构 —— 外层 gate 被 IO 观察
（`rootMargin = max(innerHeight, 480)`），内层 800px 模拟卡片；前后各 2000px 可滚动内容。
唯一用户动作：从"gate 远离视口（休眠态）"滚到"gate 明确进入视口"，随后**手指停下静置 1.5 秒**。

| 版本 | 休眠后 | 唤醒瞬间(+300ms) | 静止 1.5s 后 | 静止期间新增 |
|---|---|---|---|---|
| **A. 现状（保留 repaintKick）** | io=1 kicks=0 | io=47 **kicks=23** | io=265 **kicks=132** | **io=218 kicks=109 ❌ 自激未停止** |
| **B. 修复后（删除 repaintKick）** | io=1 kicks=0 | io=2 kicks=0 | io=2 kicks=0 | **io=0 kicks=0 ✅ 已静止** |

- A 版每轮约 2 帧一次 kick ⇒ 视觉上就是**每帧消失一次**，即用户描述的"一直一闪一闪"；
  静止 1.5s 内又自激 109 次，与"停下也还在闪"完全吻合。
- B 版唤醒一次后彻底静止，且休眠/唤醒语义（`dormant` 切换、占位高度）**未受影响**。

## 5. 修复内容

`frontend/src/components/ui/custom/Message.tsx` → `SmartCardDormancyGate`：

1. **删除 `repaintKick` 函数与其调用**（连带删掉 `dormantRef`，改用与 state 同源的本地变量 `dormantNow`）。
2. **观察器加守卫**：
   - `shouldSleep === dormantNow` 时直接 `continue` —— 状态未变化不上报副作用。
     IO 在 `rootMargin` 边界附近会因布局微小变化反复上报同一状态，无守卫时每次都走一遍 setState。
   - 休眠前 `measured <= 0` 时**不进入休眠** —— 测不到高度就休眠 = 消息行在文档流里塌陷，
     滚动条长度突变（配合 `#chat` 的 `overflow-anchor: none`，滚动位置不会被浏览器补偿）。

3. 代码内留了明确的反向警告：若将来真机复测发现"休眠唤醒后正文空白"回归，
   **禁止再用 display 切换**（必然重新引爆本闭环），改用不改变几何的手段。

门禁：`npx tsc --noEmit` exit 0；`npx vitest run` 65 文件 / 810 passed / 3 skipped / 0 failed。
