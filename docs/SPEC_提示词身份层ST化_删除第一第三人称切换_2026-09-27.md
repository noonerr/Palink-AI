## 3. 陷阱清单（会让改动静默失效或静默错乱）

**T1 — 位置形参三重耦合，删参数会把后面的参数往前顶，且不报错。**
`roleplay_prompt_assembly.py` 里调用 `deps.build_system_prompt(...)` 是**全位置实参**：
```python
system_prompt = deps.build_system_prompt(
    req.char, user_nickname, req.dialogue_mode or "first_person", prompt_lang, user_setting,
)
```
只删第 3 个 → `prompt_lang` 顶到第 3 槽、`user_setting`（一个 ORM 对象）顶到第 4 槽 → `prompt_lang == "auto"` 永假 → **整个系统提示词语言档位静默错乱，测试不一定红**。
→ 施工第一步：把这类调用全部改成关键字传参，跑一遍门禁确认无行为变化，**再**删形参。
`default_prompts.build_default_character_prompt`（第 3 位）、`_replace_character_card_placeholders`（第 4 位，`test_d_batch_fixes.py` 按位置传）同理。

**T2 — 列源自 ORM `create_all`，不是迁移。**
`dialogue_mode` 列在 `backend/alembic/versions/` **零命中**，它由 `main.py` 的 `Base.metadata.create_all` 从 ORM 声明生成。所以：只删 ORM Column 而不 drop → 下次启动不会重建（create_all 只加不删），但**只加 alembic drop 而忘删 Column → 下次启动 create_all 把列建回来**。
`migrations.py:14-15` 的注释正是 `silly_tavern_mode` 踩过的这个坑，并明令"禁止回填本清单"。**两者必须同一 commit。**

**T3 — `{{charIfNotGroup}}` 会被字面量泄漏进提示词。**
`_replace_placeholders` 支持 `{{char}}/{{character}}/{{name}}/{{角色}}`，**不支持** `{{charIfNotGroup}}`；而 `\{\{char\}\}` 匹配不到 `{{charIfNotGroup}}`（后面不是紧跟 `}}`），且它也不在"不支持宏清理"列表里 → 直接原样进 prompt。
→ 本次 main 槽用 `{{char}}`。若将来要支持 `{{charIfNotGroup}}`，另立议题并先补宏实现。

**T4 — 删了值但留下小节标题。**
`{dialogue_mode}` 是三层模板里的独立小节。若只删 `DIALOGUE_MODE_*` 字典而留下 `【扮演方式】\n{dialogue_mode}` 模板行，`.format()` 会 KeyError，或渲染出一个空悬的标题。**整块删除。**

**T5 — 前端孤儿与依赖数组。**
删 `ChatMoreMenu` 菜单项后，`CharacterChat.tsx` 的 `handleToggleDialogueMode` 与传参变未用变量（`noUnusedLocals` 会 fail build）；`useCharacterChat.ts` 的 useCallback 依赖数组里也有 `dialogueMode`。

**T6 — 命名陷阱（AGENTS.md 已列，勿连带误删）**
`synthesize_tts_st_compat`（Palink TTS 端点，在用）、`'st-compat-v2'`（智能卡 runtime 版本标签）、`st-vec::`（记忆向量前缀）、`get_st_current_user`（共享认证依赖）、`lib/group-chat/`（第一方 UI 已删但经 `getContext.ts:21` 活着）、`st_groups.py`（Palink 自有群聊后端）。
