## 2. 架构背景：为什么同一插件"宿主报错、帧内成功"

本页面上 ST 插件被**两套运行时各加载一遍**（一手：回归日志时间轴 + 两处源码）：

1. **宿主 PluginSandbox**（`frontend/src/lib/plugin-system/manager.ts` + `sandbox.ts`，产物在 `index-*.js`）：主页面加载 6 个 DB 插件；`manager.ts:261` `executePluginCode` → `manager.ts:266` `callActivateHook(name, hooks.activate)`（manifest 里 `"activate": "init"`）。**B3/B5 只死在这条轨**。
2. **卡片帧内 runtime**（`smart-card-runtime/runtime-body/part-01/02.ts`，产物在 `palink-smart-card-runtime-*.js`）：每帧再跑一遍同批插件，诊断码 `st_plugin_script_executed`（`part-02.ts:873`）→ `st_plugin_activate_hook_ok`（`part-02.ts:892`）。回归日志里 Chat Translation 与 Summarize 各 **7/7 帧 activate_hook_ok**——**帧内全部成功**。

帧内成功的原因 = 帧内 runtime 早已把这两个坑修掉并留了注释：
- `part-01.ts:746-755`：**明文写着** "Palink 的 settings.json 从来没有这些键 => translate loadSettings 的 `Object.hasOwn(undefined)` / memory loadSettings 的 `Object.keys(undefined)` 全抛"，随后对 `['quickReply','quickReplyV2','translate','memory','regex']` 逐个种子 `{}`，`regex_presets` 种子 `[]`。
- `part-02.ts:704-707`：**明文写着** "memory/index.js:34 `export { MODULE_NAME }` 早于 :36 const，ES module 语义是懒绑定，立即赋值会撞 TDZ（'Cannot access MODULE_NAME before initialization'，补测实锤）"，故用 `Object.defineProperty(exports,…,{get})` 活绑定。

**宿主轨（sandbox.ts）没有同步这两个修复**——这就是 B3/B5 的全部根因，且修复答案在同仓另一条轨里已经写好了。
