## 一、问题解析

### 1.1 现象（浏览器实测，localhost:3000 生产环境）
角色扮演对话中，每条 AI 消息左侧的角色头像以 **原始尺寸（498×747px）** 渲染，把正文挤出可视区域。DOM 结构：

```html
<div class="mes ..." ch_name="我被猫娘包围了！">
  <div class="items-start flex w-full">
    <div class="mesAvatarWrapper">      <!-- 无任何尺寸约束 -->
      <div class="avatar">
        <img class="w-full h-full object-cover" src="data:image/png;base64,...">  <!-- 自然尺寸 498×747 -->
      </div>
    </div>
    ... 正文 ...
```

### 1.2 根因
- 当前运行的是**旧构建产物**（`frontend/dist/assets/index-CxPe8yzT.js`），其角色聊天消息头像渲染逻辑为：

```jsx
isCharacterChat
  ? <div className="mesAvatarWrapper"><div className="avatar"><img className="w-full h-full object-cover"/></div></div>
  : <div className="w-9 h-9 ...">…</div>
```

`mesAvatarWrapper` 无宽高约束 → `img.w-full.h-full.object-cover` 以自然尺寸渲染 → 头像巨大挤压正文。

- **当前源码（frontend/src）与 dist 不一致**：`Message.tsx` L902 条件为
  `!isUser && chatStyle !== 'document' && !isCharacterChat` —— 即当前源码在角色聊天中**完全不渲染头像**（仅显示 `ch_name` 角色名）。若直接重建，头像会完全消失，不符合用户「保留头像、只是改小 + 可开关」的诉求。

### 1.3 目标行为
| 场景 | 行为 |
|---|---|
| 角色扮演对话，开关默认开启 | 显示**小尺寸**角色卡头像（36px，与普通对话头像一致） |
| 角色扮演对话，开关关闭 | 不显示头像，仅显示角色名（现有 ch_name） |
| 普通对话（非角色扮演） | 不受影响，维持现状（w-9 h-9 头像） |

## 二、`a` 按钮（对话气泡）来源解析

- **来源**：第三方 SillyTavern 扩展 **「酒馆助手」（Tavern Helper）**，通过插件系统导入本项目（后端插件库中唯一插件，id=`eb1d50e9-…`）。
- **注入方式**：插件 `injectWandMenuItem()` 在 `#extensionsMenu` 内直接 `createElement('a')` 创建：
  ```js
  mi.id = 'bubble-avatar-wand-btn';
  mi.className = 'list-group-item';
  mi.innerHTML = '<span class="fa-solid fa-comments"></span> 对话气泡';
  ```
- **功能**：点击调用 `avatarManagerPanel.open()` —— 气泡头像管理面板（设置角色在对话气泡中显示的头像）。
- **结论**：**不是项目自己的代码**。项目仅提供挂载点 `#extensionsMenu`（`StPluginMountPoints.tsx`，`palink-st-extensions-menu-wand` 容器）。

## 三、修改方案（最小侵入）

### 3.1 Message.tsx（头像渲染 + 开关读取）
1. 新增常量：
   ```ts
   const CHARACTER_AVATAR_VISIBLE_KEY = 'palink-rp-character-avatar'; // 默认开启
   ```
2. `MessageInner` 内新增 state 与事件监听（仿照对比度增强开关模式）：
   - 初始值：`localStorage.getItem(KEY) !== '0'`（默认 true）
   - 监听 `palink-rp-character-avatar-changed` 事件 → 重读 localStorage → setState（设置页切换即时生效）
3. 修改 L902 渲染条件：
   ```tsx
   {!isUser && chatStyle !== 'document' && (!isCharacterChat || showCharacterAvatar) && (
   ```
   - 非角色聊天：恒显示（维持现状）
   - 角色聊天：开关开启才显示
   - 显示结构复用现有 `w-9 h-9 rounded-2xl overflow-hidden flex-shrink-0`（36px 小头像，**不再使用无约束的 mesAvatarWrapper**，从根源杜绝尺寸失控）

### 3.2 SettingsView.tsx（外观区块新增开关）
1. 新增 `Image` 图标导入（lucide-react）。
2. 新增 state `showCharacterAvatar`（初始化自 localStorage）+ `handleToggleCharacterAvatar`：
   - 写入 `localStorage.setItem('palink-rp-character-avatar', checked ? '1' : '0')`
   - 派发 `window.dispatchEvent(new CustomEvent('palink-rp-character-avatar-changed', ...))`
3. 在「亮色模式自动增强卡片对比度」行之后插入新 Switch 行（`border-b` 分隔）：
   - 图标：`Image`
   - 标题：`角色扮演角色卡头像`
   - 描述：`角色扮演对话中显示角色卡头像；关闭后仅显示角色名`
   - 控件：`<Switch checked={showCharacterAvatar} onCheckedChange={handleToggleCharacterAvatar} />`

### 3.3 明确不改的部分
- 不改 CSS、不改其他组件、不动 `mesAvatarWrapper`（旧代码里已不存在于当前 src）。
- 不修改插件（酒馆助手）本身的任何行为。
- 不引入任何新依赖。

## 五、风险与规避
- **开关状态丢失**：使用 localStorage 持久化，与现有 autoContrast 一致；读取失败回退默认开启。
- **影响 ST 插件**：头像结构从 `mesAvatarWrapper` 改为 `w-9 h-9` 小头像，酒馆助手等插件的头像 CSS 不再作用——但当前 src 本就无 `mesAvatarWrapper` 渲染，本次改动是「恢复小头像显示」，风险最低。
- **memo 缓存**：`Message` 是 memo 组件，但内部 setState 会正常触发重渲染，事件驱动开关生效无碍。
