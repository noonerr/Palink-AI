## 0. 一句话

原来"代码走了什么都没发生的路径"有三类后果：用户零提示、开发者零痕迹、下一个 agent 零线索。
现在每个静默点都会落一条带 **owner（该谁修）+ kind（哪种静默）+ name（被碰的东西）+ 位置 + 累计次数**
的记录，宿主侧一条汇总（不弹框），可一键下 JSON；`host_capability` 那类还自动归到 17 个 ST 缺口 id 上，
导出里直接给排行 —— 乙类要不要投入，从此看数据而不是看谁嗓门大。

## 3. 缺口排行机制（台账 §1 的第 2、3 件事）

- **id 清单 17 个**（台账 14 + 主控按包H §7.2 补 `script_button_store`/`model_list`/`chat_reorder`）。
  补这三族的理由写进台账：**不进台账它们在排行里恒为 `unknown`，而 `unknown` 不能派单**。
- **键名逐条抄自两份已入库报告**（包H §3 的 D 类行 + §7.2 的 14 个改判键；包F §4.2 的逐族命令名），
  不做名字猜测；名单外的未实现名一律 `unknown`，不自造归族。
- **口径**：只有 `owner=host_capability` 参与聚合，其它归属 `missingStSubsystem=''`
  ⇒ 兼容层自己的 bug 不会混进"向 ST 学习"的排行里。
- **排行按事件数**（`count` 累计，不是记录条数），同数按 id 字典序 ⇒ 两次跑出来的表可比。

守门测试 `st-gap-ledger-guard.test.ts` 16 例，双向部分：A 台账 §2 的 id ↔ 代码 `ST_GAP_IDS` 集相等；
B `[ST-GAP:<id>]` token 双向在场（扫 `frontend/src` + `backend/app`，跳过 `__tests__`）；
C 每个键名必须在 `th134-names.json` 或 `st289-names.json` 里、且两侧不重名；
D 包H §3 每一行 D 类键都不得静默落 `unknown`；E 字段与排行行为。

## 4. 中断现场收尾时我改了前人三处（逐条实测，不默认他做全了）

1. **栈位置解析取错了行**：V8 的栈第一行是 `Error: 消息`，位置在后面的 `at … :81:1`。
   直接取首行 ⇒ `filename` 恒空（真机 rejection 轨那条就是这样丢的位置）。改后新增 `palinkDiagLocationLine`，
   并加 `palinkDiagLocationCore` 剥 `at ` 与 `fn@` 前缀（不剥实测会拿到 `execute@about:srcdoc`）；
   只在 `@` 前那段像标识符时才剥，避免把 `http://user@host/...` 切坏。因此变成死码的
   `palinkDiagFirstStackLine` 已删。
2. **语法类错误归属与包V 裁决冲突**：前人把帧内脚本错误一律记 `frame_compat`，
   而包V 已裁决 `about:srcdoc:81:1` 归卡。现按报错文本定 owner，并把注释里自相矛盾的"同归 frame_compat"订正。
3. **守卫测试自己跑不起来**：`await` 写在非 async 回调里 ⇒ esbuild 拒绝转换 ⇒ **整文件 0 用例**
   （也就是说"看起来有个测试"其实是零断言）；另有一条 Firefox 形态栈断言按旧解析器不可能成立。
   修完后 28/28 绿。⚠️ 教训：**模板串/字符串类产物 `tsc` 不检查内部**，测试文件本身也必须在
   合并态真跑一遍才知道能不能用。

## 6. 怎么用（无脑三步，不需要配置）

1. 在**本机站点**（`localhost:16000` / `127.0.0.1` / 内网段）打开角色页——记录器默认就开着，外部站点默认关。
2. F12 控制台里任一：
   - `__palinkDiagSummary()` → 一行汇总（各归属计数 + 前三名）；
   - `__palinkDiagRecords()` → 数组，每条带 `owner/kind/name/count/filename/lineno/missingStSubsystem`；
   - `__palinkDiagExport()` → 直接下载 JSON（里面已经算好 `stGapRanking`）。
3. 把那个 JSON 丢给下一个 agent，它按 `owner` 认领、按 `name` 定位、按 `missingStSubsystem` 看是不是 ST 缺口。

强开/强关：`__palinkDiagSetEnabled(true|false|null)`，或 localStorage `palink.diag.enabled = '1'|'0'`（`null` 回落到"按站点判定"）。

## 7. 未做与限制（诚实清单，别当已完成）

- **没做 UI**：只在控制台与导出里可见。报错卡（用户已裁定"顶部常驻、不写进 messages"）属另一件事，本包不碰。
- **`__palinkDiagRanking()` 没挂全局**：排行目前只能从 `__palinkDiagDump()`/导出的 JSON 里读。一行的事，跟下一批一起上。
- **自然排行还没有真数据**：需要卡真的去调用 D 类键才会出条目；本轮只有 1 条自然记录（`window.context`）。
  ⛔ 所以**"乙类按排行决定"这条裁定仍然没到可执行的时候**，别拿本轮读数当排行。
- **语法类错误的 owner 判据是文本模式**（`SyntaxError` / `Unexpected token`）。
  若将来我们自己往帧里拼脚本拼坏了，会被误归 `card_authored` ⇒ 判据的前提是"帧内 runtime 正文由 parse-guard 逐字节验过"。
- **帧内 `__palinkDiagDump()` 不带 `stGapRanking`/`missingStSubsystem`**（归类在父侧做）。
- **未授信帧仍是 opaque origin**：帧内 DOM 读不到，所有帧内数据只能靠 `st:diagnostic` 上送。
- 本包**不改变任何返回值语义**：未实现命令仍折成空串、未实现键仍走 `requestParent('unknownApiCall')`。
