## 2. ST 语义锚点（参照树 `d:/SillyTavern-release`，2026-10-21 复核）

### 2.1 作者注位置（`extension_prompt_types`）

`public/script.js:483-488`：

```js
export const extension_prompt_types = {
    NONE: -1,
    IN_PROMPT: 0,
    IN_CHAT: 1,
    BEFORE_PROMPT: 2,
};
```

UI 文案锚点 `public/index.html:7753-7766`：

| 值 | ST UI 文案 | 本仓 UI 文案 | 行为（`roleplay_prompt_assembly.py:3546-3564`） |
|---|---|---|---|
| `-1` | 无独立单选（`authors-note.js:351-356` 在 interval≤0/无对话时内部置 NONE） | 停用（NONE，不注入） | 直接跳过 |
| `0` | After Main Prompt / Story String | 场景后 | 追加到 system prompt 末尾 |
| `1` | In-chat @ Depth（默认，`authors-note.js:273`） | 聊天内 @ 深度 | 按 depth 插入历史 |
| `2` | Before Main Prompt / Story String | 场景前 | 前插到 system prompt 开头 |

**结论：取值与 ST 完全一致。** `-1` 是 ST 的枚举值（NONE），只是 ST 面板没有把它做成一个单选；
本仓把它显式做成"停用"，语义等价、且比 ST 更可达（ST 要清空 frequency 才停用）。

### 2.2 作者注频率（Insertion Frequency）——**这里与 ST 不一致，已在 UI 明说**

`public/index.html:7775-7779`：`Insertion Frequency`，提示 `(0 = Disable, 1 = Always)`，`min=0 max=9999`。
`public/scripts/authors-note.js:347-361`：`interval === 1` 恒注入；`lastMessageNumber <= 0 || interval <= 0` 停用；
否则按**用户发言数**取模。

本仓（`backend/app/services/roleplay_prompt_assembly.py:3606-3619`）：

- `frequency <= 1` ⇒ **恒注入**（0 与 1 等价）；
- `frequency > 1` ⇒ 按**会话总消息数**（含 assistant）取模；
- 停用只能靠 `position = -1`。

**判定**：取值范围（0-9999）与 N 的语义（每 N 条一次）一致；**`0` 的含义与取模基数不一致**。
本批**不改装配**（`author_note_frequency` 的列默认值与 GET 默认值都是 0，把 0 改成"停用"
会让所有存量用户默认不再注入，属行为破坏），改为在 UI `desc` 里如实写明
（`PromptSettings.tsx:228-234`）。另有一处同源偏差：`api/silly_tavern.py:507` 向 ST 扩展设置
回填 `interval=0`，在 ST 语义里是"停用"——本轮同样未动，登记在 §6-②。

### 2.3 作者注深度

`public/index.html:7764`：`input#extension_floating_depth type=number min=0 max=9999`，默认 `4`
（`authors-note.js:272`）。深度输入框嵌在 `In-chat @ Depth` 单选的 `<label>` 里
（`index.html:7761-7766`），即**只有该位置才有意义**。
本仓 UI 与之一致：`position !== 1` 时深度控件禁用（不隐藏），范围 0-9999，默认 4。

## 6. 否证主脑（盘点报告 / 任务书里被本次实测推翻或修正的说法）

**① `UserSettingUpdate` 注释里的位置枚举"已经写了一种"——那一种是错的，不可作为语义依据。**
任务书提示"位置枚举的取值含义在 `UserSettingUpdate` 注释里已经写了一种"。
实测改前 `backend/app/schemas/user.py:20-22` 写的是
`0 = in story, 1 = after post-history, 2 = last in chat, 3 = inactive` ——
这是**迁移 0056 之前的旧 Palink 值域**，与 ST `script.js:483-488`、与
`models/system.py:27-33`、与装配实际读取（`roleplay_prompt_assembly.py:3546-3564`）
**三方都不一致**。若照它做 UI，四个选项会全部错位（例如"停用"会写成 3，而装配只认 -1）。
已订正注释（`schemas/user.py:20-36`），UI 以 ST 源码为准。

**② "作者注四项已按 ST 对齐"只对了一半：频率的 0 与取模基数都不一致。**
