## 1. 测试方法（如何做到"不发给 API 提供商"）

探针 `.tmp_probe/probe-*.js`（Playwright，`run-code`）：

```js
const BLOCK = [/\/api\/chat(\/|$)/i, /generate/i, /\/api\/openai\//i, /\/api\/backends\//i,
  /\/api\/summarize/i, /\/api\/translate/i, /\/api\/extra\//i, /\/api\/caption/i,
  /\/api\/sd\//i, /\/api\/speech\//i, /\/api\/tts/i, /\/api\/vectors\//i, /\/api\/memory\//i];
await page.route('**/*', route => {
  if (BLOCK.some(re => re.test(route.request().url()))) {
    blocked.push(url);
    return route.fulfill({ status: 200, body: '{"blocked":true}' }); // 本地返回，不转发
  }
  return route.continue();
});
```

- 卡片来源：`GET /api/characters?limit=100` 全量拉取后，按 `extensions.tavern_helper.scripts`
  与 `extensions.regex_scripts` 非空筛出 ⇒ 5 张带脚本的卡（全库仅 7 个角色）。
- 入口：**`/characters/:characterId`**（`/chat?character_id=` 是死路，5 张卡 bodyLen 都≈312，同一空壳页）。
- 无需点击「开始对话」：`/characters/:id` 会**自动载入该角色最近会话**。

## 3. 猫娘卡 —— 我上一轮的"裸标签未处理"是误判，已修正

上一轮我看到页面出现 `&lt;猫神（从黑暗边缘悠`，判定"卡内嵌正则没跑"。**这是错的**，DOM 取证纠正：

```
document.getElementsByTagName('猫神').length = 0      ← 正文里没有未解析的自定义标签
document.querySelectorAll('[class*="nk-msg"]').length = 1
  → <div class="custom-nk-msg"><div class="custom-nk-av">
      <img class="custom-nk-av-img" src="/api/image-proxy?url=…cdn.jsdelivr.net…">
注入的 CSS  = ".mes_text .custom-nk-msg { display:flex; gap:14px; align-items:center; … }"
```

两个关键点：

1. **类名是 `custom-nk-msg`，不是 `nk-msg`** —— 前缀 `custom-` + 选择器前缀 `.mes_text `
   正是 ST 的 CSS 作用域做法。我上一轮用 `querySelectorAll('.nk-msg')` 精确匹配，恒为 0，
   据此得出"正则没跑"是**探针口径错误**（与之前读 `commands` Map 那次是同一类错误）。
2. 那行 `&lt;猫神（从黑暗边缘悠` 来自 **角色卡面板的预览摘要**（`<p class="text-xs … line-clamp-1">`），
   不是消息正文。预览显示原始文本是正常行为。

**0 iframe 是正确行为，不是缺陷**：`Message.tsx:916` 明确 `isGreetingMessage = messageIndex === 0`
时不注入 `<StatusPlaceHolderImpl/>`（对齐 ST：开场白本身不含状态栏）。开场白经正则后只产出
CSS + `<div>`，被 `looksLikeSmartCardHtml` 判为 false ⇒ 走内联 `html-display`，
ST 也是把结果 `innerHTML` 进 `.mes_text`。**两边一致。**

## 4. 新发现缺陷（P2）：同一份 CSS 被重复注入 15 份，无去重

猫娘卡主文档实测：

```
document.querySelectorAll('style').length            = 22
其中含 nk-msg 的                                      = 15
  uniqueContents = 1        ← 15 份内容**完全相同**
  perCopyBytes   = 3,156
  totalBytes     = 47,340
  parentElement  全部为 BODY（无 id / 无 class）
```

- **不随时间增长**：t≈8s / t≈23s / t≈29s+滚动 三次采样恒为 15 ⇒ 一次性重复注入，不是持续泄漏。
- **露缇雅没有此问题**：主文档只有 6 个 `<style>`，重复统计 `dupStyles = []`。
- 差异归因：猫娘卡走的是「内联 html-display + 样式抽出来注入 body」，露缇雅走的是 iframe。
  ⇒ 缺陷定位在**内联渲染路径的样式注入没有去重**（同一份正则 CSS 每渲染一遍就 append 一份）。

**建议（未动手）**：内联路径注入 `<style>` 前按内容 hash 去重（`data-palink-css-hash` 标记 + 复用），
预计省 47KB 重复 CSS。属于 P2 性能/整洁项，不影响功能。

## 5. 需要用户决策的架构取舍：卡内脚本只在 iframe 内执行

实测：

| 卡 | iframe | 主帧 `window.Mvu` | 主帧 `window.TavernHelper` |
|---|---|---|---|
| 猫娘（仅开场白） | 0 | **undefined** | **undefined** |
| 露缇雅（7 帧） | 7 | undefined（在帧内 = 6） | undefined（在帧内 = 76） |

- Palink：卡内 `tavern_helper.scripts` **只在智能卡 iframe 内执行** ⇒ 没有 iframe 就没有 MVU 注册。
- ST：卡内脚本由**酒馆助手扩展在页面级执行**（注册 MVU schema 与是否渲染 iframe 无关）。

⇒ 差异是**真实存在**的，但是 Palink「iframe 沙箱」架构的固有取舍（用隔离换脚本执行能力）。
若要求"无 iframe 也执行卡脚本"，等于把 untrusted 卡代码放进主页面，与 P1-1 沙箱红线冲突。
**不建议改**，建议记录在案。

## 8. 验收口径提醒（给后续复测）

- 判"卡内脚本执行"用**帧内** `window.Mvu` / `window.TavernHelper`，不是主帧。
- 判"正则美化生效"用 `[class*="nk-msg"]`（前缀是 `custom-`），**不能用 `.nk-msg` 精确匹配**。
- 判"智能卡"数**门** `[data-palink-card-gate-id]`，不是数 `iframe`（本次 7 iframe 对应 5 门）。
- 复测入口固定 `/characters/<cid>`，`/chat?character_id=` 无效。
