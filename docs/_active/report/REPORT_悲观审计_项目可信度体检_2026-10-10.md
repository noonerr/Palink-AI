## ⚠️ 订正 2：`mermaid` 判定错误（2026-10-10 追加）

**订正对象**：本报告「前端其余硬伤」表格里的「`mermaid` 完全未使用」一行，
以及「如果只做五件事」里的「卸掉 `mermaid`」。

**错在哪**：我当时的判据是 `grep -rn "from 'mermaid'" frontend/src` → 零命中。
但 `mermaid` 是通过**动态 import** 使用的：

```
frontend/src/components/ui/custom/CodeBlock.tsx:149
  const mermaid = (await import('mermaid')).default;
```

`CodeBlock.tsx:293-333` 在 `language === 'mermaid'` 分支里真的执行
`mermaid.initialize()` → `mermaid.render()` → `DOMPurify.sanitize(svg)` 并渲染 SVG；
配套样式在 `index.css:1594-1621`，`vite.config.ts:100-109` 还有针对 mermaid chunk 的 manualChunks 调优。
`frontend/dist/assets/` 里那批 mermaid chunk **正是这条路径的产物，不是遗留垃圾**。

**后果评估**：删掉依赖**不会立刻报错**（本地 `node_modules` 还在），
但下次 `npm ci` / 干净重建时 `await import('mermaid')` 解析失败 → **构建炸在延迟引爆点**，是最难查的那类。

**处置**：**不删 `mermaid`**。若要减包，正路是在 `vite.config.ts` 里把它彻底移出首屏，
而不是删依赖。SPEC 第 5.4 条同步作废。

**教训**：查「某依赖有没有被用」，`from 'x'` 零命中**不等于**没用 —— 还要查
`import('x')` / `require('x')` / 字符串拼接式加载。我漏了动态 import 这一整类。

## P0-1 · 「门禁」日志自己写着 84 errors，然后它被叫做 gate

**这是全篇最硬的一条证据，因为它不需要推理，只需要读文件的最后一行。**

```

1903 passed, 48 skipped, 384 warnings, 84 errors in 131.06s

backend/pytest_gate2.log（最后一行）
2 failed, 1981 passed, 51 skipped, 384 warnings in 140.58s
```

`grep -c "ERROR at setup" pytest_gate3.log` = **84**。这 84 个是 **setup 阶段就崩了**，测试体一行都没执行：

```
_______ ERROR at setup of TestCounting.test_messages_counting_and_empty _______
E   AssertionError
______ ERROR at setup of TestFindModelContract.test_find_model_returns_provider_and_model_data _
E   AssertionError
```

一个叫 `gate` 的产物，连续两次带着 84 errors / 2 failed 被存档，且这两个日志就躺在 `backend/` 根目录。

**为什么这很糟**：`1903 passed` 这个数字在组织内被当成通行信号。但"84 个测试连跑都没跑起来"和"1903 个通过"出现在同一个文件里，读数的人只取了后半句。**这不是门禁，这是安慰剂。**

### 配套三件套：让"绿"彻底失去意义

| 检查项 | 结果 |
|---|---|
| CI（`.github/workflows` / `.gitlab-ci.yml` / `.circleci`） | **不存在** |
| `fail_under` / `cov-fail-under` / `coverageThreshold` | 全仓 **0 处** |
| `pytest-cov` | `requirements.txt` 只有 `pytest==9.1.1`，**无** |
| `vitest.config.ts` coverage 字段 | **无**（29 行配置只有 environment + setupFiles） |
| `package.json` test 脚本 | `vitest run`，**无 `--coverage`** |

**推论**：**没有任何一行代码会因为你删掉实现而让测试变红**（只要它没被 import 到）。

### 三把静默跳过伞

1. **38 个测试文件「导入失败 = 整文件静默跳过」**，统一模板：
   ```python
   except Exception as exc:  # pragma: no cover
       _IMPORT_OK = False
   pytestmark = pytest.mark.skipif(not _IMPORT_OK, reason=f"依赖缺失，跳过: {_IMPORT_ERROR}")
   ```
   任何一次重命名/移动模块 → 从「1900 passed」变成「1900 passed - N skipped」，**依旧全绿**。这不是防御性编码，这是把编译错误降级为 skip。

2. **46 处「源码文件不存在就跳过」**——Python 测试在 grep 前端源码：
   ```python
   # backend/tests/test_p2_fixes.py（36 处）、test_p1_fixes.py（9 处）
   pytest.skip("runtime.ts 不存在")
   pytest.skip("CharacterCardRenderer.tsx 不存在")
   ```
   **测的是「文件在不在」，不是「行为对不对」。**

3. **28 个世界书核心用例是写着 docstring 的 `pytest.skip` 空壳**，且 **skip 理由是假的**：
   ```python
   # backend/tests/test_worldbook_st_semantics.py:1031
   class TestConstantEntry:
       def test_constant_entry_always_activates(self, constant_entry):
           """常量条目应始终激活，无论 recent_messages 内容。"""
           pytest.skip("requires DB session")
   ```
   但 `backend/tests/conftest.py:84` **明明提供了 `db_session` fixture**，全仓 **55 个测试文件正在正常使用它**。注释自己承认是「占位以保留测试场景覆盖」——翻译：**为了让报告里的测试数量好看而写的空函数**。世界书最关键的递归激活、概率、sticky/cooldown/delay、分组加权、预算裁剪（:1063-1131）**全是空壳**。
