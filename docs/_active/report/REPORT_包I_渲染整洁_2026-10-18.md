### 6.1 剩余项（谁做、为什么不在本包做）

1. **`Failed to fetch` 型外链失败仍会弹 toast**（本包口径之外，不是漏修）。
   今天露缇雅那条死链的自然失败在浏览器里是 `TypeError: Failed to fetch`
   （动态 `import()` 的形状），reason 不是 Event、target 不是资源元素 ⇒ 按任务书「唯一切分口径 = 形态」
   必须留在 reportDiagnostic 路径里（累计观察器实测：旧 dist 与 dev **都读到 1 条 `Failed to fetch` toast**，
   `I2_controlled_*.txt` 两发的 `toastTitlesNatural`）。
   ⇒ 若主控判断"动态 import 死外链也算资源失败"，需要**新增一条按 stack/URL 判据的切分**，
   那是猜语义、且要动包G 的 libs 懒加载链，风险与红线上都不该由本包擅自扩。
2. **`window` 的 `error` 监听拿不到真实资源失败**（浏览器事实）：资源 `error` 事件不冒泡，
   非捕获监听器只有卡自己 `import()`/`onerror` 转成 rejection 时才可能命中 ⇒ 生产里
   `window_error` 分支基本是**防御性代码**（已用 A2/A3 的合成事件把它测到了），真正起作用的是 rejection 分支。
   如需覆盖"卡写 `s.onerror = rej`"以外的路径，得改成**捕获阶段** `document.addEventListener('error', …, true)` ——
   那会同时改变既有 script-error 的接收面，本包按「真脚本错误行为完全不变」的红线没动。
   ⚠️ 本包受控实验里"真发一次死链请求"（`s.onerror = rej`，不 catch）在 6~8s 窗口内**没有**触发：
   `curl` 实测该域名 12s 超时（exit=28），浏览器侧连接挂得更久 ⇒ 自然形态的取证会晚于 14s 采样点，
   这也是"单点 14s 采样"这类验收线不可靠的原因（本包改用累计观察器 + 同形态派发双轨取证）。
3. **legacy shim 的 7 条 `unknown error` 取证噪声**（`part-a.ts:329`，改前改后一致）：
   归属包J（插件 CSS 守护）或单独立项，本包不碰 legacy-st-sim。
4. **上线动作（归主控）**：重建前端 dist（按 MEMORY 的 `VITE_OUT_DIR=dist_new` 姿势，别跑 `npm run build`），
   然后回 `:16000` 复跑 `.tmp_probe/probe-i1-style.js`（把 TARGET 换成 16000）与 `.tmp_probe/probe-i2-diag.js`，
   以那次读数（nk style 份数、`__palinkFrameErrors` 条数、toast 条数）为准才算生效。
