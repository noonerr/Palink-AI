# 诊断：变量形状漂移 → 卡片状态栏回落到默认值（0 / 100 / 0）

- 日期：2026-10-05
- 触发：用户反馈「数值增长/变化后，角色面板完全乱套，直接进入默认值 0 或 100 或 0」
- 结论：**既不是「另一个 agent 没做完」，也不是「最新代码没上」。是数据形状被写歪，而我们后端缺一层「按卡片 schema 归一化」的自愈机制 —— 属存量设计缺口，最早可复现于 2026-10-04 20:11。**

---

## 1. 一句话结论

卡片的 schema 要求 `露缇雅.状态.爱意`（三层），但库里这份数据变成了
`露缇雅.状态 = "一段描述文本"` 且 `爱意` 被**提到 `露缇雅` 下当兄弟键**。
卡的状态栏用 `_.get(vars, 'stat_data.露缇雅.状态.爱意', 0)` 取值，
穿不过一个字符串 → 返回默认值 → 你看到的 **0 / 100 / 0**。

## 4. 为什么它不会自己恢复（两个设计缺口）

### 缺口 1：我们只「应用补丁」，不「按 schema 校验/归一化」

- `mvu_engine.apply_patches` 对 JSON Patch 是**逐条照做**：
  `_pointer_set` 会为不存在的中间路径**凭空创建对象**，对类型不做任何检查。
- 对比 **ST 的 MVU**：它在应用命令后会跑卡片注册的 **zod schema**
  （`prefault` / `transform` / `clamp`），结构不对会被修回来。
  **我们没有这一层** —— 我们只在**初始化**时用 schema 默认值（
  `MvuEngine.init_session_variables` / `extract_schema_defaults`），
  之后每一轮全靠模型自觉。
- 所以模型一旦发出 `/露缇雅/状态` = 字符串 + `/露缇雅/爱意` 这种补丁，
  错误结构就**永久落库**。

### 缺口 2：喂给模型的变量结构是「压平文本」，层级边界丢失 → 自我强化

`roleplay_prompt_assembly._flatten_stat_data` 把 stat_data 渲染成：

```
露缇雅：状态=爱意=5，魔力值=60，饥饿度=60，当前位置=哥哥的卧室，当前动作或体位=…；穿着=…；…
```

`状态=爱意=5，魔力值=60` 这种写法**看不出 `状态` 是对象还是文本**。模型据此
很容易判断「`状态` 是个文本字段」，于是把 `爱意/魔力值` 写成 `露缇雅` 的直接子键。
写歪之后，这个**错误结构又被压平喂回去** → 模型继续照着错的写 → **锁死**。

附带问题：`_flatten_stat_value` 里 `if _depth > 1: return ""`
会把**三层以上的嵌套静默丢弃**，也会误导模型对结构的判断。

### ⚠️ 诚实标注（推断 vs 实证）

- **实证**：形状事实（§2.3 对账、§3 时间线）、schema 与状态栏代码原文、我们无 zod 校验层（读码确认）。
- **推断**：20:11 那次生成的**原始 `<UpdateVariable>` 文本没能拿到**
  （正文里的标签在存储前已被剥离，且当时还没有 `msg.extra["mvu_patch"]` 留存）。
  「模型写歪了扁平结构」是由数据形状反推的，未能逐字核对那一轮的补丁。

## 6. 建议的修复方向（需拍板）

| 方案 | 内容 | 风险 |
|---|---|---|
| **A（推荐）加 schema 归一化层** | 每轮应用补丁后，按卡片 schema 的**形状**对齐：错位的键搬回 schema 定义的位置、类型不符按 schema 强制（`coerce`/`clamp`）、缺失补 `prefault`。等于把 ST 的 zod 语义在 Python 侧重实现（我们已有 `extract_schema_defaults` 的解析结果可用） | 中。要处理 `partialRecord`（如「穿着」是开放键集）这类不固定结构；改的是核心变量链路，需完整反证 |
| **B 补丁准入校验** | path 不在 schema 形状内 → 拒绝该补丁 + 告警（**不静默丢弃**） | 低，但单独用会「丢更新」；应与 A 配套 |
| **C 修这一份数据** | 把 `露缇雅.{爱意,魔力值,饥饿度,…}` 搬回 `露缇雅.状态.*`，并把 `状态` 从字符串恢复成对象 | 中。**需你决定**：`状态` 里那段描述文本（"依赖加深，对魔纹的指向性感到困惑与不安"）挪去哪？丢弃 / 存到别处 / 忽略 |
| **D 改压平输出** | `_flatten_stat_data` 保留层级（如点号路径 `露缇雅.状态.爱意=5` 或缩进），从源头降低漂移概率 | 低～中。会改变提示词内容与 token 量，可能影响别的卡 |

**我的建议顺序**：先做 **C**（把用户手上这份数据救回来，立竿见影）→ 再做 **A+B**（防止复发）
→ 最后评估 **D**（降低触发概率）。
