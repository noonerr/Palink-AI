## 2. 改写假设的否证过程

### 2.1 报错脚本的身份

真机帧内（`page.frames()` + `frame.evaluate()`，未授信帧父侧 `contentDocument` 恒 null）读到的 11 段脚本里，唯一 `brace=-1 paren=-1` 的那段是：

```
i=9  type="module"  data-palink-card-script-id=2d6bd520-2356-4559-90b5-c44ee68c6f22
     len=3054  lines=87  brace=-1  paren=-1  fw=0  db=0  qWrap=0  第81行="});"
```

`data-palink-card-script-id` 直接对上卡里 `extensions.tavern_helper.scripts[0].id`（name「变量结构」）。
控制台堆栈也指到同一处：

```
[卡内错误] 脚本错误 @9bc613: Uncaught SyntaxError: Failed to execute 'appendChild' on 'Node':
    Unexpected token '}' @ about:srcdoc:81:1
    at about:srcdoc:168:14  at Array.forEach  at execute (about:srcdoc:155:13)
```

`execute` 就是 `frontend/src/lib/sillytavern/card-script-runner.ts` 的帧内卡脚本接收器
（`buildCardScriptFrameBootstrap` 内），它对脚本正文只做一件事：`patchInitEvent`
（`DOMContentLoaded` → `palink-card-init`，16 字符换 16 字符，**长度不变**）。
这条链路走 postMessage + structured clone，**根本不经过显示管线**。

### 2.2 断点早在卡里，不在 Palink 里

`.tmp_probe/T_pngextract.js` 从角色 `avatar` 的内嵌 PNG 里取出 `tEXt/chara`（作者原始卡数据，172,472 字 JSON），与落库副本逐字节对比：

| 对象 | PNG 原文 | 落库 `extensions` | 落库 `palink_raw_card_data` |
|---|---|---|---|
| `tavern_helper.scripts[0]` | 3,054 / 87 / brace −1 / paren −1 | **完全相同** | **完全相同** |
| `tavern_helper.scripts[1]`（MVU） | 90 / 1 / 0 / 0 | 相同 | 相同 |
| `regex_scripts[4].replaceString` | 48,958 / 1,202 / 0 / 0 | 相同 | 相同 |

把 PNG 里的脚本正文原样写成 `.mjs` 交给 V8 自己判：

```
$ node --check .tmp_probe/t_help_src.mjs
SyntaxError: Unexpected token '}'   ← .tmp_probe/t_help_src.mjs:81   });
```

**同一行号、同一 token、同一句话。** 这就是"离线复现"——不需要 Palink 的任何代码参与。

### 2.3 −1 不是数数数出来的假象

裸数 `{`/`}` 会被字符串与注释里的括号骗。所以补了一遍**词法级**扫描
（`.tmp_probe/T_lexdepth.js`：跳字符串 / 模板串 / 正则字面量 / 两种注释，只数代码态括号）：

```
code-state final brace= -1  paren= -1  bracket= 0
first code-state negative line: {"line":81,"bd":-1,"pd":-1}
  line  78 brace=1 paren=1 | 头像発情: z.string().prefault(''),
  line  79 brace=0 paren=0 | }).prefault({}),
  line  81 brace=-1 paren=-1 | });
```

第 79 行已经把第 3 行开的 `z.object(` 全部闭合，第 81 行的 `});` 是**多出来的一个闭合**。
原文里全角引号 0 个、`{{ }}` 0 处、`<q>` 0 处 —— 没有任何"被改写"的痕迹可指认。

> 这张卡的这条脚本，在真 ST + TavernHelper 下同样编译不过。Palink 的忠实投递没有错。

### 2.4 帧内那 18 个全角引号是谁的

`i=0`（7,119 字 / 6 行）与 `i=2`（7,407 字 / 11 行）各有 18 个全角引号与 2~4 处 `{{ }}`。
整张卡（含 `palink_raw_card_data` 副本）里带 `<script` 的字符串只有两处：`regex_scripts[4]`
与 `tavern_helper.scripts[0]` —— 而这两段在帧内是 `i=8` 与 `i=9`。
所以 `i=0` / `i=2` **不是卡脚本**，是 Palink 自己的启动脚本（`buildShim` /
`buildSillyTavernCompatRuntimeV2Shim`），里面的全角引号是**卡正文作为数据**嵌进字符串字面量的结果，
`qWrap=0`（没被 `<q>` 包过），与语法错误无关。

## 4. 真正的问题在哪（已修）

`wrapSillyTavernQuotedText`（`frontend/src/lib/sillytavern/formatting.ts`）把成对英文引号包成 `<q>…</q>`
做正文着色，它的保护分支只有 `<style>`、``` 围栏、`` 与 ` —— **没有 `<script>`**。
`extractHtmlBlocks` 的保护名单（同文件 `HTML_BLOCK_TAGS`）里同样**没有 `script`**。

离线实测（真函数，非重写逻辑）：

```
wrap: inputBodyLen=122 outBodyLen=164  qCount=6
  MUT=  const label = <q>"状态"</q>;
        const map = { <q>"a"</q>: 1, <q>"b"</q>: 2 };
  → 注进沙箱 iframe 即 SyntaxError
```

它今天**没有**咬到这张卡，靠的是上游一个总闸：`looksLikeRenderableCardHtml` 把任何含 `<script>`
的消息整体短路进 smart-card 分支（不跑 Showdown）。10 种产出形态实测全部 `identical=true`。
但这个总闸正是本任务**明令禁止**的修法（整段跳过会连带废掉正则与宏），而且形态扫描暴露出它的对偶问题：
卡正则产出「裸 script 片段」「style+script 片段」时 `kind` 掉到 markdown / html-display，脚本**整段消失**（`len 99->0`）。

**修法 = 区域保护**：在 `extractHtmlBlocks` 的 `<style>` 保护之后，同批把
`<(script|noscript)\b…</\1>` 收进保护区（`+22` 行，含注释）。
于是 markdown 层再也拿不到脚本正文，而正则与宏的执行范围一字未改
—— 状态栏面板恰恰要先靠正则[4]把 `<StatusPlaceHolderImpl/>` 换成 HTML 才存在。
