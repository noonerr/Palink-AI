## 0. 结论

**整体方向成立、三个 Task 都能做，但 SPEC 里有 4 处会在施工中途炸掉的口径缺口，必须先补再动工。**

| Task | 结论 | 说明 |
|---|---|---|
| **T1 家族识别 + 渲染 + 模板库** | ✅ 做，且价值比 SPEC 写的更高 | 它不只是"增强"，是在修一条**今天必失败**的路径（见 P0-4） |
| **T2 副 AI 场景画像** | ⚠️ 可做，建议降级为"开关默认关" | 目标模型 Qwen-Image-2.1 **自带提示词增强 LLM**，副 AI 增益被覆盖一部分；代价是每次出图多一次付费调用 + 30s 延迟（会撑破 120s 预算，见 P1-2） |
| **T3 设备路由** | ⚠️ 拆成两半 | 「手机不抢任务」今天就能低成本做完；「电脑在后台也能接单」**不受代码控制**，取决于浏览器节流，属于实测才能定案的部分 |

**施工顺序建议改为**：`T1` → `T3a（只做能力过滤）` → `T2` → `T3b（后台接单，待实测）`。

## 1. 阻塞级问题（P0，必须先在 SPEC 里改口径）

### P0-1 家族识别的判定输入，在 ComfyUI 场景下是空的

- SPEC §1.1 的启发表按**模型名**匹配（`qwen-image|…|flux|pony|illustrious|…`）。
- 现实：`ImageGenerationTab.tsx:221-241` 只有 `type === 'openai_compatible'` 才显示「模型名」输入框；`comfyui` / `sd_webui` 卡片**没有**模型名框。
- ComfyUI 场景下真正的模型身份是 **checkpoint 名**（工作流里的 `ckpt_name`），即 SPEC §1.3 才引入的新字段 `checkpoint_name`。
- **后果**：启发表在用户的主力拓扑（托管部署 + ComfyUI + Qwen-Image）上永远命中不了 `qwen-image`，一律掉到 SPEC §1.1 兜底规则 `comfyui/sd_webui → {danbooru, sdxl}` → Qwen 被套上 Pony 质量前缀 + SDXL 模板 → **CheckpointLoaderSimple 直接加载失败**。而且它和使用 T2 与否无关，T1 上线当天就会炸。

**改法**：
1. `detect_family` 的启发输入改为 **`checkpoint_name` 优先、`model` 次之**（两个拼接/依次尝试）；
2. 设置页「Checkpoint」下拉选中后，**自动回填 family**（下拉值同步更新），用户仍可手动覆盖；
3. family 下拉不再是可选装饰，而是 ComfyUI 卡片的**必填项**（默认由 checkpoint 推出）。

### P0-2 自定义工作流是裸字符串占位符替换，会被提示词撑破

- SPEC §1.3：`{{PROMPT}}` 等占位符做**字符串级替换**后 `json.loads`。
- **后果**：中文/英文提示词带英文双引号、反斜杠、换行是常态 → 替换后 JSON 非法 → 出图时 400。设置页保存时的校验用的是字面量占位符，**永远通过**，问题只在运行时爆。
- **改法**：占位符替换前对注入值做 JSON 字符串转义（`json.dumps(value)[1:-1]`），替换后立即 `json.loads` 校验，失败给 400 并带出错位置。

### P0-3 设备心跳 TTL 15s 与后台标签页节流直接冲突

- SPEC §3.1：`DeviceInfo` TTL **15s**，过期即淘汰。
- SPEC §3.3 自己承认：隐藏标签页可能被浏览器钳到**分钟级**轮询。
- 两者叠加：一旦 provider 设备的页面被切到后台，心跳间隔 > TTL，设备被判离线 → 任务继续 pending → 超时后 SPEC §3.2 会报「**没有在线的算力设备**」，而实际上电脑一直开着。**这是 SPEC 自我矛盾，且这恰好是「手机操控、电脑出图」的主场景。**
- 另：`frontend/src/hooks/useChatWebSocket.ts:233` 的 `connect()` 是**按需调用**（进入会话时），不是挂载即连，因此 SPEC §3.3 押注的「有活跃 WebSocket 的页面豁免 Chrome 强化节流」**不是无条件成立**。

**改法**：
1. “没有在线设备”的判定不要依赖 15s TTL，改为「**本用户从未有任何 provider 心跳**」或「最近心跳 > 任务超时」才走这句文案；
2. TTL 放宽到 ≥ 轮询上限（建议 90s），15s 只在 visible 场景有意义；
3. T3b（后台接单）在真机实测出结论前，**不写进用户可见文案**。

### P0-4 SDXL 模板的 checkpoint 名是硬编码 `"model.safetensors"`

- `backend/app/services/image_generation_service.py:1166`：`"inputs": {"ckpt_name": "model.safetensors"}`。
- 现实：这不是"兼容性兜底"，是**任何真实 checkpoint 都必失败**（ComfyUI 会报 checkpoint 找不到）。
- **含义**：T1 的「Checkpoint 下拉」不是可选增强，是整个本地出图闭环的必需补丁。估里的优先级应该提前。

## 2. 需要补进 SPEC 的口径（P1）

| # | 问题 | 证据 |
|---|---|---|
| P1-1 | **T2 配置根本存不进去**：`defaults` 的合并是**逐字段白名单**（`image_generation_service.py:341-344`），schema 里 `ImageGenerationDefaults` 只有两字段（`schemas/image_generation.py:39-41`），前端类型同（`types/imageGeneration.ts:34-37`）。三处不改，新字段被静默丢弃。 | 见行号 |
| P1-2 | **副 AI 开关没有任何 UI 入口**：`ImageGenerationTab.tsx:144-170` 的「全局」组只有 enabled + 当前服务商，连 `prompt_template` 都没有默认值区。加进 defaults 后管理员只能**手改 JSON 文件**才能启用副 AI。SPEC §1.4 也没列这一项。 | 见行号 |
| P1-3 | **超时预算断言不成立**：`message_media_service.py:39` `PENDING_TIMEOUT_SECONDS = 120`。SPEC §7 称副 AI 的 30s「在超时预算内」——30s 副 AI + 出图 120s = **150s > 120s**，前端骨架会先显示失败。建议副 AI 超时压到 ≤10s，或跳过。 | 见行号 |
| P1-4 | **P4 工具路径会被重复加工**：模型已经给了完整画面描述（`model_prompt`），SPEC §2.2 仍让它进素材再走一次副 AI → 每次自发出图多一次付费调用，还可能把模型原文改走样。建议 `model_prompt` 路径直接作为 `scene.natural`。 | `image_generation_service.py:823` |
| P1-5 | **缺家族默认参数**：现有 provider 默认 `steps=20 / cfg=7 / euler`（`schemas/image_generation.py:33-36`）。Qwen-Image-2.1 官方把默认步数从 50 压到 40 —— 20 步会明显欠曝。T1 应给每个家族一组默认 steps/cfg/sampler/scheduler。 | 官方发布信息 |
| P1-6 | **nl 风格静默吞掉用户填的负面词**：`render_prompt` 的 nl 分支丢弃 `provider.negative_prompt`。用户在设置页填了却不生效，UI 需明示。 | SPEC §1.2 |
| P1-7 | **新增后端口 `/comfyui/models` 只在 server 模式有用**：用户实际拓扑是 browser 模式，必须走前端直连 `/object_info/CheckpointLoaderSimple`。此外 SSRF 守卫 `_is_safe_mcp_url`（`image_generation_service.py:271`）对新端点**必须显式复用**，否则等于开了个 admin 任意 GET。 | 见行号 |
| P1-8 | **两套 TTL 容易混**：现有任务回收 `_CLAIM_TTL_SECONDS = 45`（`local_image_bridge.py:37`）与新增设备心跳 TTL 是两件事，建议改名区分（`_DEVICE_HEARTBEAT_TTL_SECONDS` vs `_CLAIM_TTL_SECONDS`）。 | 见行号 |
