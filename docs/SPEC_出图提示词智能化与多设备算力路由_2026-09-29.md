## 0. 目标与非目标

**目标**：
- B1：出图提示词从"聊天长句直喂"升级为「副 AI 场景画像 → 按模型家族渲染」，工作流按家族可切换，支持用户自定义 workflow 覆盖与 checkpoint 选择；
- B2：同账号多设备下，出图任务只派给**在线且具备算力的设备**（手机当遥控器，电脑出图），并修掉手机抢任务必死的竞态。

**非目标（保持拍板记录）**：本地 LLM 聊天主回答；自动端口扫描；浏览器扩展/桌面壳；Web Push 唤醒后台执行；per-user 级的副 AI 模型个性化（全局配置先行）。

## 1. B1-T1：模型家族识别 + 渲染器 + 工作流模板库（后端可独立先行）

### 1.1 家族模型

```
detect_family(provider) -> {style: "nl" | "danbooru", workflow: "sdxl" | "flux" | "qwen_image"}
```

- **判定优先级**：provider 配置的显式 `family`（用户手选）> 文件名/模型名启发表 > 默认。
- **启发表**（`image_prompt_service.py` 内常量，小写 contains 匹配）：
  - `qwen-image|qwen_image|gpt-image|dall-e|flux|seedream|hunyuan-image` → `{nl, 对应 workflow}`（flux 名同时定 workflow=flux，qwen 名定 workflow=qwen_image，其余 nl 默认 workflow 由 provider 类型定）；
  - `pony|illustrious|noobai` → `{danbooru, sdxl}`；`xl|sdxl` → `{danbooru, sdxl}`；`v1-5|sd15|1.5` → `{danbooru, sdxl}`（SD1.5 复用 sdxl 模板渲染，steps/cfg 由配置覆盖）；
  - 认不出：openai_compatible → `{nl, 按类型}`（云端几乎全 NL 派）；comfyui/sd_webui → `{danbooru, sdxl}`（本地默认装动漫模型的概率最高，且用户可手改）。
- provider 配置新增两个字段（schema + `_validate_provider` 归一化，非法回落 `auto`）：
  - `family: "auto" | "nl" | "danbooru"`（显式覆盖 style；`workflow` 由名字单独推，见 1.3）
  - `checkpoint_name: str`（comfyui 用，默认空 = 模板内置兜底，消灭 `"model.safetensors"` 硬编码）

### 1.2 渲染器（确定性代码，不劳驾 LLM）

```
render_prompt(style, scene, provider) -> (positive, negative)
```

- **style=danbooru**：`positive = 家族质量前缀 + scene.tags`；`negative = 家族负面预设 + provider.negative_prompt`。
  - 质量前缀内置：pony → `score_9, score_8_up, score_7_up`；illustrious/noobai/sdxl → `masterpiece, best quality, very aesthetic, absurdres`（常量表，供设置页展示可改）。
  - 负面预设内置：`lowres, bad anatomy, bad hands, watermark, worst quality, low quality`（EasyNegative 风格起步；用户负面追加在尾部）。
- **style=nl**：`positive = scene.natural`（原样）；`negative = ""`（Qwen/Flux 基本不吃负面，渲染器**直接丢弃**，provider.negative_prompt 仅在用户显式填写时保留——如实写注释）。
- 输入 `scene` 结构见 1.4；T1 阶段副 AI 未上，`scene` 由降级路径构造：现有 `build_message_image_prompt` 产出的长句 → `scene.natural`，`scene.tags` 为空 → danbooru 渲染时 tags 为空则回退 natural（**T1 不改质量，只加前缀/负面/工作流**）。

### 1.3 工作流模板库

`_build_comfyui_workflow` 重构为按 workflow 键分发，占位符全量下放：

- 模板键：`sdxl`（= 现有 CheckpointLoaderSimple/KSampler 那张，`ckpt_name` 从 `provider.checkpoint_name` 取、空则回落 `model.safetensors` 保持现状兼容）、`flux`、`qwen_image`。
- flux/qwen_image 模板骨架按 ComfyUI 官方示例工作流整理（分离模型/编码器加载节点），**节点名以真机标定为准**（见 §7 待实测），SPEC 不锁死节点图。
- **用户自定义覆盖**：provider 配置新增可选 `workflow_json: str`（ComfyUI API 格式导出的 JSON 文本）。非空时以它为底，做字符串级 `{{PROMPT}}/{{NEGATIVE}}/{{CKPT}}/{{WIDTH}}/{{HEIGHT}}/{{SEED}}/{{STEPS}}/{{CFG}}` 占位符替换后 `json.loads` 校验；解析失败 → 报 400 带原因（设置页保存时即校验，不在出图时爆）。`/object_info` 导出节点的 seed 随机化：占位符未包含 `{{SEED}}` 时后端不注入（用户工作流自己管随机）。
- seed 逻辑不变：后端定死 used_seed 并回传（仅内置模板路径）。

### 1.4 设置页增量（`ImageGenerationTab.tsx`）

- ComfyUI 卡片「检测本机 ComfyUI」扩展：探测成功后追加拉取模型列表——浏览器模式前端直连 `GET {base}/object_info/CheckpointLoaderSimple`（取 `inputs.required.ckpt_name[0]` 数组）；服务器模式走新后端端点 `GET /api/image-generation/comfyui/models`（admin，复用 get_comfyui_provider + httpx，受既有 SSRF 守卫）。
- 新增「Checkpoint」下拉（列表来自上一步）+「模型家族」下拉（自动 / Qwen-Image / Flux / SDXL / Pony / Illustrious / NoobAI，选非自动时同时定 style 与 workflow）。
- 新增「自定义工作流 JSON」文本域（保存时后端校验占位符与 JSON 合法性）。
- sd_webui 卡片同获 family 覆盖与负面/前缀展示（workflow 模板不适用，仅渲染层）。

## 2. B1-T2：副 AI 场景画像

### 2.1 配置（放 `image_generation_config.json` defaults，**免 DB 迁移**）

```jsonc
"defaults": {
  "...现有字段...": "",
  "secondary_prompt_enabled": false,      // 出图副 AI 总开关
  "secondary_prompt_model": ""            // 网关模型名；空 = 未配置（即便开关开着也降级）
}
```

不挂在 UserSetting 列上的理由：出图配置本就是 admin 级 JSON 面（PUT /config 已有），避免 alembic 迁移；与 MVU 副 AI（per-user 列，`models/system.py:71-73`）**同模式不同存储**，注释里写明差别。

### 2.2 调用契约（`image_prompt_service.py` 新文件）

- 入口：`compose_scene(db, user, message, context_messages, character, model_prompt) -> Scene`，`Scene = {tags: str, natural: str}`。
- **素材**：复用 `build_message_image_prompt` 的素材收集逻辑（抽公共函数 `collect_scene_material(...)` 返回 context 行数组，模板与副 AI 共用）；P4 工具路径的 `model_prompt` 作为「指定画面描述」一并进素材。
- **提示词要点**（写进 SPEC 的 system 内容）：输出**严格 JSON** `{"tags": "...", "natural": "..."}`；tags 用英文 danbooru 风格逗号分隔字段（人物数/发色/瞳色/发型/服饰/动作/表情/构图/场景/光线，15~30 个，不用质量词——质量前缀由渲染器加）；natural 是一段可直接给 NL 模型的完整描述（80~150 词）。解析：剥 code fence → 找首个 `{...}` → `json.loads`；失败/超时/未配置 → **降级**（见 2.3）。
- 超时 30s；调用走既有网关客户端（同 `run_secondary_mvu` 的取模型方式，`services/mvu_secondary.py` 为参照）。
- **降级链**：副 AI 未启用/未配模型/调用失败/JSON 解析失败 → `scene.natural = 现有模板长句`、`scene.tags = ""`（= T1 行为，**永不比现状差**）。降级时 `logger.info` 一行，不 toast（出图是异步侧挂，别打扰聊天）。

### 2.3 接线点（唯一动 `generate_image_for_message` 的地方）

```
prompt = prompt or build_message_image_prompt(...)          # 现状保留（降级素材）
scene = await compose_scene(...)                             # T2 新增：内部自带降级
positive, negative = render_prompt(detect_family(provider).style, scene, provider)
# positive/negative 传入 _generate_image_via_* / _generate_image_via_local_browser
# media item 的 prompt 字段存 positive（渲染后终稿，前端已有展示位）
```

浏览器桥接不受影响：副 AI 是服务端对网关的调用，只有"执行"在用户浏览器。

## 3. B2-T3：多设备算力路由

### 3.1 设备登记（`local_image_bridge.py` 内扩一张内存表）

```python
_devices: dict[int, dict[str, DeviceInfo]]   # user_id -> device_id -> {last_seen, capability}
# DeviceInfo.capability: "provider"(有算力，可接单) | "controller"(遥控器，不接单)
# 心跳 = 认领请求本身；TTL 15s，清扫协程顺手淘汰过期设备
```

- 认领端点 `GET /local-tasks/pending` 增 query 参数 `device_id` + `capability`（前端 localStorage 生成随机 uuid `palink_device_id`，可重置；无指纹含义）。
- `claim_pending_tasks(user_id, device_id, capability)`：登记心跳后，**仅当 capability == "provider" 时返回任务**；controller 恒返回空列表（手机不会再来抢）。
- 派单不给"无在线 provider"特殊处理——任务继续 pending，由等待协程超时兜底（3.2）。

### 3.2 失败文案分级

`await_local_task` 超时分支区分两态：
- `task.dispatched_at is None`（从未被任何 provider 认领）→ 504，detail = **「没有在线的算力设备——请在装有所需服务的电脑上打开 Palink 并保持页面开启」**；
- 已认领未回传 → 现文案「本机 ComfyUI 未在时限内回传结果」。
前端 `MessageMedia` 失败态原样展示 error，无需改动。

### 3.3 前端执行器节奏（`executor.ts` / `use-image-task-executor.ts`）

- **capability 判定**：localStorage `palink_image_compute_role`：`auto | provider | controller`；`auto` = 桌面（pointer fine）→ provider、移动 → controller。设置页 ImageGenerationTab 顶部加「本设备角色」三选（自动/提供算力/仅遥控）。
- **executor 启动条件**：`bridgeEnabled && role==provider`（controller 设备**零轮询**——它靠既有 SSE/WS 事件看结果，`useImageGenerationAvailability` 照常）。
- 轮询节奏：visible 2.5s（现状）；hidden 时仍保持 interval 但**如实接受浏览器节流**——Chrome 对隐藏页 timer 钳制（持有活跃 WebSocket 的页面豁免强化节流，角色聊天页 WS 常驻、后台接单可用；普通聊天页可能被钳到分钟级）。§7 列待实测。
- 认领请求带 `device_id` + `capability=provider`；设置页「本设备角色」改动后 executor 重挂（依赖现有 bridgeEnabled effect 链）。

### 3.4 语义澄清（写进代码注释与向导文案）

- 「消息同步」不参与调度：图落在服务端 `extra.media`，所有设备天然可见；调度只关心"哪个设备的浏览器去打本机服务"。
- 多台电脑同账号：先到先得 = 天然负载均衡；同机多标签：in-flight 去重 + 回传幂等已兜底。
- device_id 是随机 uuid 非设备指纹；capability 自报不强制（不读 UA 硬判，auto 只是默认建议值）。

## 6. 工作量与施工顺序

| Task | 内容 | 估量 |
|---|---|---|
| T1 | 家族识别 + 渲染器 + 模板库 + 模型选择器/自定义工作流 | 1~1.5 天 |
| T2 | 副 AI 场景画像（配置/调用/降级/接线） | 0.5~1 天 |
| T3 | 设备路由（登记/派单过滤/节奏/文案） | 0.5~1 天 |

顺序建议 T1 → T2 → T3（T1 独立可交付：即便副 AI 后上，Pony 用户已受益）；每 Task 独立提交。

## 7. 已知限制与待实测

- [ ] flux/qwen_image 工作流模板节点图需真机标定（以用户本机 ComfyUI 实际可用节点为准；Qwen-Image 为分离加载，现有 CheckpointLoader 模式不适用）
- [ ] 隐藏标签页接单时延实测（角色页 WS 豁免强化节流 vs 普通聊天页分钟级钳制）——文案按实测定稿
- [ ] tag 渲染对 SD1.5 的 77-token 窗口：tags 串控制在 ~60 token 内（渲染器做长度截断保护，超长丢尾部非权重字段）
- [ ] Pony/Illustrious 质量词内置默认值靠社区惯例，最终以用户实测微调为准（常量表可改）
- 已知限制照旧生效：骨架 120s 渲染收敛（副 AI 增加的一次调用在超时预算内，不触碰该约束）、Safari 不可用、后端重启丢任务。
