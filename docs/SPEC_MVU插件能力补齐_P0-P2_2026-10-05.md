### ② 副模型参数放开 + 重试（P2，但零冲突故提前）

**现状**：`mvu_secondary.py:127-128` 写死 `temperature=0.2`、`max_tokens=2048`，无重试，
且**四种失败都返回 `([],[])`**（`:117` 守卫跳过 / `:131` 异常 / `:136` 空内容 / `:141` 无块）——
调用方无法区分「真失败」与「模型认为没变化」。

**改法（3 步）**

1. **签名扩参**（`mvu_secondary.py:96`）：
   `run_secondary_mvu(..., temperature: float = 0.2, max_tokens: int = 2048, retries: int = 1)`
   透传给 `complete_text_completion`（`inference_dispatcher.py:340` 已支持这两个参数，**不用改它**）。

2. **改三态返回**（关键，否则 ① 的重试与通知都无从判断）：
   目前返回 `tuple[dict, list[str]]`。建议**加第三个元素** `status: str`，
   取值 `'ok' | 'skipped' | 'failed' | 'no_change'`：
   - `skipped`：`:117` 守卫（无 schema 且无 stat_data）→ **不重试**
   - `failed`：`:131` 异常 / `:136` 空内容 → **可重试**
   - `no_change`：`:141` 有输出但没解析出块 → **不重试**（模型真的认为没变化）
   > 兼容：调用方只有 `character_ext.py:6323` 与（已死的）`websocket.py:564`，
   > 改成三元组只需同步 `character_ext.py:6323` 一处解包。

3. **重试只对 `failed`**，指数退避，上限 `retries`（建议默认 1、夹紧 0–3）。

**设置字段（3 处，另需 1 个 migration）**

| # | 文件 | 改动 |

| 1 | `backend/app/models/system.py:73-74` 旁 | 加 `mvu_secondary_temperature`(Float) / `_max_tokens`(Integer) / `_retries`(Integer)，均 `nullable=True`（留空 = 用内置默认） |

**自动生成链路的两个方案**

- **方案甲（纯前端，零后端改动）**：生成结束后，若角色卡有 schema 但本轮变量无变化 →
  提示"本轮未检测到变量更新"。**优点**：不用碰被占用的文件。**缺点**：有误报
  （模型本来就可能不给变量块），建议做成可关闭的轻量提示。
- **方案乙（真信号）**：后端在 final 事件带 `mvu_status: ok|failed|no_change`
  （② 的三态 status 正好就是它），前端加一个 case。**优点**：准确。**缺点**：需改被占用文件。

**建议**：先上方案甲的手动部分（①）+ 等交回后上方案乙。
